Norm・LayerNorm・RMSNorm：確率の正規化ではない
層の式で、Normは正規化の関数を表します。LayerNormは、通常、一つのトークンの特徴から平均を引き、標準偏差で割り、拡大縮小と平行移動を行います。RMSNormは、通常、平均を引かず、二乗平均平方根で拡大縮小します。どちらもsoftmaxとは異なります。独立した小さな例で、分母を安定させる小さい正数εと学習可能な倍率を無視すると、LayerNorm([1,3])=[-1,1]、RMSNorm([1,3])=[1/√5,3/√5]です。
pre-norm / post-norm：正規化を置く位置
pre-normは、先に正規化してからサブレイヤーに入り、残差を元の入力から直接足します。post-normは、サブレイヤーの結果と元の入力を足してから正規化します。これは演算の順序であり、学習前後の二段階ではありません。独立した構造の比較：x+F(Norm(x))とNorm(x+F(x))は、一般には等しくありません。Fは、ここで囲まれているサブレイヤーの関数です。

Concat・split・chunk：連結と分割
Concatは、複数の配列を指定した軸に沿って連結し、要素は足しません。splitやchunkは、定めた境界でグループ分けします。連結しないすべての軸は、互換である必要があります。ここのchunkは配列のブロックを指し、ネットワークのchunkはバイトの断片です。独立した例：二つのヘッドが、それぞれ[2,3]なら、特徴の軸で連結すると[2,6]です。位置の軸で連結すると[4,3]となり、意味がすでに異なります。

この後、何度も出てくる Q=N1@Wq。@は、新しい神秘的な計算ではなく、多くの「対応する位置を掛けてから足す」を、まとめて行うものにすぎません。Qの出所を理解するには、まず一つの出力マスに、どの入力を使ったかを確認します。

この課では、全工程を通すモデルの実際のパラメーターを使い、別の乗算モデルは設定しません。第0サンプルのt=2で、元のXは [-0.2, 0.8, 0, 0.45]です。基礎編では、RMSNormの結果N1=[-0.425787, 1.70315, 0, 0.958022]を、すでにマスごとに計算しました。ここでは、この一行は所与のものとして、Wqとの乗算に注目します。これは同じXに特徴軸に沿ってRMSNormを適用した結果であり、詳しい計算は基礎編の正規化の節を参照してください。

内側の次元が同じでなければならない理由

一行の4個の入力数を、一列の4個の係数と組み合わせます。係数の列が3個の数だけなら、一つの入力に対応項目がありません。そのため、 [T,4]@[4,4]→[T,4]となり、バッチも含めると [B,T,4]@[4,4]→[B,T,4]です。同じWを、各サンプルの各位置で使います。この手順では、異なるトークンを混ぜていません。

一般的な線形層は、次のように書けます： y=xW+b。このモデルにはbがありません。線形投影は固定の係数で入力を組み替えます。負の係数も有効で、係数の合計は1でなくてもよいため、すべてを「それぞれ何パーセントか」とは解釈できません。

この設問で先に理解することQは現在の位置が求める一致を表す数値、Kは各候補の比較対象の数値、Vは割合に従って集める内容です。三つとも、通常、同じ入力の異なる変換から得られます。

中心となる回答

QとKは共同で「ある位置が、見える位置からどう情報を取るか」を決め、Vは「取れる内容」を決めます。学習可能な投影に由来し、意味を人が「質問・キーワード・答え」に固定したものではありません。アテンション出力はValueの重み付き混合であり、直接の単語生成でも、データベースの厳密な検索でもありません。[TR]

さらに考える：Self-Attentionの「self」は、自分だけを見るという意味か？

違います。QとK/Vが同じ系列や同じ表現の出所に由来することを表し、系列内の異なる位置も互いに読み取れます。その範囲はmaskが決めます。Cross-Attentionでは、通常、Qが一つの系列から、K/Vが別の系列から来ます。例えば、デコーダーがエンコーダーの出力を読む場合です。decoder-onlyのチャットモデルでは、各層にCross-Attentionが必要なわけではありません。

インターフェースが計算のどの段階にあるかを、まず明確にする

Q=XWqのQは、投影済みのQueryです。高水準のMultiheadAttentionインターフェースは、投影前の入力を受け取り、内部で投影する場合があります。低水準のSDPAは、投影済みでヘッドの次元に整理したQ/K/Vを受け取ります。両方を「attention」と呼んでも、この境界は省けません。入力形状・パラメーターテーブルの所属・スケーリングの責任を読んでから、呼び出し側がどの手順を行うかを決めます。[MHA] [SDPA]

第一の例：正方行列が、転置の誤りを気付かれずに通す

教材では、右乗算の記法でX @ Wと書き、Wの形状は[in,out]です。PyTorch Linearのパラメーターは[out,in]で保存します。この教材ではX=[[1,2]]、W=[[1,3],[2,4]]とします。正しい出力は[5,11]ですが、誤ってもう一度転置すると[7,10]です。Wは2×2なので、どちらも掛けられ、形状のテストではまったく検出できません。

テストには、非対称で、できれば非正方の重みを使い、具体的な値を照合する必要があります。重みの変換・ヘッドの分割・ヘッドの結合などの経路は、単位行列だけでなく、このような「実行できても等価でない」小行列でテストするべきです。単位行列は、多くの転置の誤りを隠します。

第二の例：スケーリングの責任の重複

既定のSDPAは、内部で内積に1/√d_kを使います。呼び出す前にすでにQを√d_kで割り、さらに既定のSDPAを使うと、スコア全体は元の1/d_kまで小さくなります。これはsoftmax分布を変えるため、無害な並べ替えではありません。scaleパラメーターを独自に設定したなら、現在のバージョンの意味を確認する必要があります。テンソルと関数の選択肢の両方で、一回ずつ処理してはいけません。[SDPA]

第三の例：model.eval()は、単独の関数の引数を管理しない

Moduleのevalモードはモジュールの振る舞いを変えますが、任意の関数の引数を魔法のように0にはしません。PyTorchドキュメントは、SDPAがdropout_pに従ってdropoutを適用すると明記しています。推論では、呼び出し側が0を渡す必要があります。[SDPA]

# 独自のModule.forwardで、学習状態を明示的に結び付ける
out = torch.nn.functional.scaled_dot_product_attention(
    q, k, v, attn_mask=allowed,
    dropout_p=self.dropout if self.training else 0.0,
)

ローカルのテストでは、独自のモジュールをevalにしても0.5を渡すと、乱数シードを変えた後の出力が変わりました。0を渡すと固定されます。これは実際のPyTorch2.10 CPU関数の確認であり、商用モデルのランダム性の説明ではありません。

さらに考える：seedを固定すれば十分か？

seedの固定は無作為な経路の特定を助けますが、誤って有効にしたdropoutを隠すために使うべきではありません。カーネル・精度・バッチ形状によって、数値計算の経路が異なる場合もあります。まず本来不要な無作為な操作を無効にし、その後に許容誤差で比較します。ビット単位の再現が本当に必要な場合にだけ、デバイスと決定的なアルゴリズムを追加で制約します。

さらに考える：アテンションの重みを返すと、遅くなる場合があるのはなぜか？

重み全体を要求すると、実装は、本来なら省ける大きな中間量を実体化しなければならない場合があり、利用できる高速な経路まで変わる可能性があります。診断では、need_weights・学習状態・dtype・マスクの型・バックエンドを記録し、関数名だけを比較してはいけません。性能の結論は、対象のハードウェアで測定する必要があります。

中心となる回答

アテンションは位置間の情報のやり取りを、FFNは位置ごとの非線形変換を担い、残差は情報と勾配の直接の経路を提供し、Normは特徴のスケールを制御します。解決する問題は異なり、FFNを省いてもよい飾りと呼んだり、残差を学習の失敗を完全に防ぐ仕組みと呼んだりしてはいけません。[TR][V3]

まず、ここで使う対象と記号を知る
∂・∇：偏導関数と勾配
∂L/∂wは、他の独立変数を固定し、wをわずかに変えると、損失Lがどう変わるかを問います。複数のパラメーターについて、この変化率をまとめたものが勾配∇Lです。これらは導関数の記号であり、通常の二つの数を直接割ることではありません。独立した小さな例：L=w²なら、w=3での勾配は6です。最も単純な更新w←w−η×6のηは、学習率です。
Jacobian：複数出力の導関数の表
関数に複数の入力と出力がある場合、Jacobianは、各入力に対する各出力の偏導関数を表に記録します。J_Fは、関数Fのこの表であり、学習データ内の新しい行列ではありません。独立した小さな例：F([x₁,x₂])=[2x₁,3x₂]なら、J_F=[[2,0],[0,3]]です。残差x+F(x)の導関数の表は、I+J_Fです。

この構造では、残差の主経路のXをアテンション出力で直接置き換えず、モデルは既存の表現に何を加えるかを学習します。逆伝播では、∂U/∂Xが恒等項Iを含むため、勾配が比較的直接の経路で戻れます。これは深い層の最適化の難しさを緩和しますが、勾配全体は、各分岐のJacobian・学習設定・数値の状態の影響も受けます。

BatchNormは、通常、同じ特徴/チャンネルについて、バッチと適用する空間の軸に沿って統計量を計算します。LayerNormは、指定したサンプル内部の特徴次元に沿って計算します。BatchNormは、学習時と評価時で、異なる出所の統計を使う場合があり、具体的には設定にもよります。Normという語だけを見て、異なる正規化層の統計を取る軸を混同してはいけません。これを理由に、独立した二人のユーザーの会話コンテキストを共有するべきではありません。

LayerNormは、各位置の特徴から平均を引き、標準偏差で割ってから、学習可能なスケール/シフトを適用します。RMSNormは通常、平均を引かず、二乗平均平方根でスケーリングし、学習可能な重みを適用します。これらはbatch全体をまたいで統計を計算するものではありません。そのため、ここでのNormは、画像ネットワークでよく使うBatchNormと異なります。pre-normは正規化してからサブ層に入り、post-normは、残差加算の後に正規化します。最適化の振る舞いは異なります。

要素ごとの積は、形状を合わせた後、同じ位置の数を掛け、さらにある次元に沿って足すことはしません。式で行列を並べた表記や@は、通常、行列積を表します。両者を置き換えることはできません。独立した小さな例：[1,2]⊙[3,4]=[3,8]で、内積なら11です。ゲーティング付きフィードフォワードの⊙は、特徴ごとに別の経路を調整します。
