Teacher forcingは何を「与える」のか

第t位置を学習するときは、モデルに先に単語を抽出させてから、その誤りを続けて入力するのではなく、データセットの実際の接頭辞を使います。このように、実際の履歴を条件にする学習方法をteacher forcingと呼びます。一つのバッチで、多数の位置の損失を並列計算できます。

推論時には実際の次の単語がないため、選んだばかりの結果を使って続けるしかありません。そのため、学習時の低い損失だけでは、長文生成の安定性を自動的に証明できません。推論時にモデルが出会う接頭辞は、自分で作った誤りの組み合わせで、すでに学習分布から外れている可能性があります。

交差エントロピーは、一つの正しい候補から始める

正しい次のトークンがcで、モデルがその確率を0.8とすると、よく使う損失の一つは−ln(0.8)≈0.2231です。0.2しか与えなければ、−ln(0.2)≈1.6094となり、誤りが大きくなります。

誤解しやすい点：交差エントロピーは「スコアから正しいラベルのIDを直接引く」操作ではありません。

正しい目標の負の対数確率は、正しいラベルが一つの場合の交差エントロピー損失です。確率が1に近いほど損失は0に近づき、実際のラベルに与える確率が小さいほど、ペナルティーは大きくなります。

まず、ここで使う対象と記号を知る
Σ：添字に沿って各項を足す
Σは加算の略記です。添字は、どの項が変わるかを示します。加算しない添字は固定します。追加のパラメーターでも、配列の連結でもありません。独立した小さな例：Σᵢ xᵢyᵢで、x=[1,2]、y=[3,4]なら、1×3+2×4=11です。

正しい候補をone-hotで表す、つまり語彙と同じ長さの一行の0のうち、正解だけが1となるものをyとすると、一般式はL=−Σ_i y_i ln p_iです。他のy_iは0なので、最後には正解の項目だけが残ります。

まず、ここで使う対象と記号を知る
∂・∇：偏導関数と勾配
∂L/∂wは、他の独立変数を固定し、wをわずかに変えると、損失Lがどう変わるかを問います。複数のパラメーターについて、この変化率をまとめたものが勾配∇Lです。これらは導関数の記号であり、通常の二つの数を直接割ることではありません。独立した小さな例：L=w²なら、w=3での勾配は6です。最も単純な更新w←w−η×6のηは、学習率です。

交差エントロピーの式をlogsumexpで書ける理由

ある行のlogitsをz、目標IDをyとします：

pᵧ = exp(zᵧ) / Σⱼ exp(zⱼ)
−ln(pᵧ) = −ln(exp(zᵧ)) + ln(Σⱼ exp(zⱼ))
        = −zᵧ + logsumexp(z)

logsumexp(z)「各logitのlogを取って足す」のではなく、各logitの指数を取り、足してからlogを取ります。安定性のため、実際には次の形で書きます： m+ln(Σ exp(z−m))で、m=max(z)です。softmaxと同じ平行移動に対する不変性を保ち、先に極小の確率を計算してからlogを取ることによる数値の問題も避けられます。

根拠：tiny_model.py:101–107；対応するパラメーター、順伝播、勾配の記録。

勾配がp−onehotになる理由：結論を暗記するだけでは足りない

あるスコアzⱼに対して、第一項 −zᵧ の導関数は、j=yなら−1、それ以外は0です。第二項のzⱼに対する導関数は、まずlnの導関数から 1/Σ exp(z)、次に指数の和の導関数から exp(zⱼ)が得られ、掛け合わせるとちょうどpⱼになります。

したがって、ある一問のzⱼに対する導関数は pⱼ−1[j=y]です。この学習のlossは十問の平均なので、各問にさらに1/10を掛けます。ここでのonehotは「どの列が実際の目標か」を表すだけで、Token Embeddingではなく、コードで先に明示的に構成する必要もありません。

正しい候補のマスの勾配は負なので、勾配降下はそのlogitを高める方向に働きます。他のマスは通常、正なので、下げる方向に働きます。ただし、実際に調整するのは共有パラメーターであり、この一行のlogitを直接、永続的に変更するのではありません。異なる学習問題から、同じパラメーターへの勾配も重なります。

根拠：tiny_model.py:101–107；対応するパラメーター、順伝播、勾配の記録。

logitsの平行移動と、勾配の行の和の関係

この行のGzを足すと0になるはずです。確率の和は1、onehotの和も1なので、引いてからNで割っても0です。すべてのlogitsに同じ数を一斉に加えても、確率と損失は変わりません。そのため、「すべて1の方向」に沿った変化率は0です。有用な数値の自己点検ですが、通過してもモデル全体の実装が正しいとは証明できません。

勾配累積は、まずいくつかの小さなバッチで勾配を計算・累積し、その後一回更新することで、大きな有効バッチを模擬する方法です。単一の極端に長い入力の活性化の保存領域が、自動で不要になるわけではありません。勾配のスケーリング方法は、損失の平均方法に対応させる必要があります。

重要な違い：一回の学習更新には明確な順序があります。勾配累積では、特にゼロへのリセットとスケーリングが重要です。

誤解しやすい点：手順図で、勾配をゼロにする操作とパラメーターを更新する操作を入れ替えてはいけません。

Adamが追加の状態を保存する理由

この節の学習の表記：gは現在のパラメーターの勾配、mは勾配の移動平均、vは勾配の二乗の移動平均、β₁・β₂は設定する平滑化係数、tは最適化ステップの番号です。m̂のようなハット記号は、バイアス補正済みを表します。ここでの小文字vはアテンションのValueではなく、βもLayerNormのシフトパラメーターではありません。m/vは学習ステップとともに更新され、追加の保存領域を使います。今回の入力のトークン特徴ではありません。

まず、ここで使う対象と記号を知る
オプティマイザー、Adam、AdamW
オプティマイザーは、勾配をパラメーターの更新に変換します。Adamはさらに、各パラメーターの勾配の移動平均mと、勾配の二乗の移動平均vを保存します。これらは学習状態であり、アテンションのValueではありません。AdamWは、重み減衰と適応的な勾配更新を切り離します。独立した初回の例：g=2、mの旧値=0、β₁=0.9なら、mの新値=0.2で、バイアス補正後はm_hat=2です。0.2を、そのまま完全な更新量として扱ってはいけません。

最も単純な勾配降下は、現在の勾配gだけを使います。Adamは、勾配の平滑化平均mと、勾配の二乗の平滑化平均vも保存し、各パラメーターの歩幅の調整に使います。模式的な式は次のとおりです：

m新 = β1×m旧 + (1−β1)×g
v新 = β2×v旧 + (1−β2)×g²

βは0から1の間の平滑化係数であり、モデルが学習した語の意味ではありません。初期値は通常0なので、最初の平均は小さめになり、そのためバイアス補正を行います。例えば最初のステップでg=2、β1=0.9なら、m=0.2で、1−0.9で割ると補正後の2が得られます。

その後、補正済みのmを、補正済みのvの平方根で割って更新します。AdamWは、重み減衰を分離した操作として扱います。完全な式は上級の章にあります。この課ではまず「mとvを追加で保存する理由」を説明します。これは、学習時のVRAMを重みだけで見積もれない理由でもあります。

どの段階でモデルが実際に変わるかを、まず明らかにする

loss.backwardは勾配を計算し、optimizer.stepは更新を適用します。通常は二つの呼び出しです。勾配を計算しただけでstepしなければ、「モデルが答えを見た」からといって、生成の振る舞いが自動で変わることはありません。

最も単純なSGDの規則は w_new=w_old−ηgで、ηは学習率、gは現在のパラメーターの勾配です。負のgはwを増やし、正のgはwを減らします。「降下」はlossを小さくしようとすることであり、すべてのパラメーターを小さくすることではありません。

各パラメーターのマスに、二つの履歴状態が対応します。mは勾配の指数移動平均、vは勾配の二乗の指数移動平均です。通常、βが1に近いほど履歴を多く残します。vが保存するのは勾配の二乗であり、パラメーターの分散でもValue行列でもありません。

m_t = β1 m_(t−1) + (1−β1) g_t
v_t = β2 v_(t−1) + (1−β2) g_t²
m̂_t = m_t / (1−β1^t)
v̂_t = v_t / (1−β2^t)
w_t = (1−ηλ) w_(t−1) − η m̂_t / (sqrt(v̂_t)+ε)

eval()は勾配を無効にする操作ではない

model.eval()は、モジュールのtrainingフラグを切り替えます。例えばDropoutは無作為な除外をやめ、BatchNormは対応する評価時の振る舞いを使います。autogradのスイッチではありません。torch.no_grad()とtorch.inference_mode()は、勾配の記録や、より厳格な推論の最適化を制御します。すべてのモジュールを自動でevalに切り替えるわけでもありません。

このモデルにはDropoutもBatchNormもないため、train/evalの数値は一致しますが、実際のすべてのモデルで一致するという意味ではありません。同梱の独立したDropoutテストでは、no_gradを加えただけなら無作為にゼロにし続け、evalならDropoutの動作が恒等写像になり、evalでも勾配計算を有効にできることを示します。

根拠：tiny_model.py:101–107；対応するパラメーター、順伝播、勾配の記録。

Dropoutで「同じ入力なら同じ出力」が変わる理由

独立した規則です。学習時には、確率pで一部の活性化をゼロにし、残す項目を通常1/(1−p)でスケーリングして、期待値を保ちます。評価時には、無作為にゼロにせず、拡大も続けません。一回の無作為な順伝播と、Dropoutのない順伝播に、マスごとの一致を要求してはいけません。

SDPAは関数インターフェースであり、dropout_pは呼び出し側が渡します。外側のモジュールがevalでも、無効にするには正しい値0を渡す必要があります。関数が外側の状態を自動で読むと考えてはいけません。

根拠：tiny_model.py:101–107；対応するパラメーター、順伝播、勾配の記録。

勾配累積で分母を間違えやすい理由

独立した損失の例です。マイクロバッチAは有効な問題が2問、総損失が4、平均が2です。マイクロバッチBは有効な問題が8問、総損失が8、平均が1です。全体10問の正しい平均は (4+8)/10=1.2ですが、二つの平均を平均すると (2+1)/2=1.5です。対応する勾配の相対的な重みも変わります。

分子と分母は、同じ有効な目標の集合に対応させる
手順 / 対象このステップで実際に変わること
マイクロバッチA有効なトークンは2個、損失の合計は4。
マイクロバッチB有効なトークンは8個、損失の合計は8。
正しい統合分子4+8、分母2+8で、平均は1.2。
誤った統合先にそれぞれ平均し、次に2と1を同じ重みで平均すると、1.5になります。

これは独立した計算の比較例であり、全工程を通すモデルの、実際の学習ステップのlossではありません。

分散学習では、勾配同期が和を求めるか平均を求めるか、フレームワークがすでにスケーリングしているかも把握する必要があります。ワールドサイズや累積ステップ数で、余分にもう一度割ってはいけません。Hugging Faceは、このような勾配累積の正規化の修正を公開で説明したことがあります。教材では歴史的な教訓として扱い、現在のライブラリにその欠陥がまだあるとは主張しません。

根拠：tiny_model.py:101–107；対応するパラメーター、順伝播、勾配の記録。

モデルが先読みしていないと分かるために、何を検証するか

接頭辞を固定し、それより後のトークンを変えても、接頭辞の位置のlogitsは変わらないはずです。同じサンプルを単独で実行した場合と、独立したバッチに入れた場合の結果は一致し、バッチの順序を交換すると、結果も対応して交換されるはずです。これらは因果性とサンプルの分離を確認するもので、意味を扱う能力の評価ではありません。

このモデルの負の対照では、因果maskを意図的に無効にし、「未来を変えても接頭辞に影響しない」というテストが誤りを検出できると確認します。正しい実装が通るだけでは不十分で、誤った実装に対してテストが失敗すると知る必要もあります。

根拠：tiny_model.py:101–107；対応するパラメーター、順伝播、勾配の記録。

検証セット・過学習・本実験の限界

本格的な学習には、分離した検証タスク・データ漏洩の制御・対象領域の評価・再現可能なデータ処理が必要です。全工程を通すモデルは二つの文を繰り返し使い、信頼できる汎化の成績はありません。この教材では、同じ二つの文の続きを生成する正答率を、検証セットの成功率として見せることはしません。

根拠：tiny_model.py:101–107；対応するパラメーター、順伝播、勾配の記録。

さらに考える：パラメーターWは、言語データからどう「教わる」のか？

一つの文から、複数の実際の接頭辞と次のトークンのラベルができます。現在のWは順伝播の確率に影響し、交差エントロピーはラベルの確率を評価し、逆向きの連鎖律はWの各マスがこのlossに与える局所的な影響を計算し、オプティマイザーはその影響に基づいて段階的に更新します。語の意味を表すテキストを、一列のラベルに直接書き込む単独の手順はありません。

根拠：tiny_model.py:178–258；対応するパラメーター、順伝播、勾配の記録。
