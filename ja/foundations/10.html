調整可能な一つの規則から「モデル」を理解する

次を考えます：y=w×x+b。xは毎回変わる入力で、wとbは計算規則を決める数です。w=2、b=1なら、入力3から7が得られます。wを4に変えると、同じ入力から13が得られます。

重要な違い：パラメーターは調整可能な写像の規則を決めます。推論時は通常、既存のパラメーターを使います。

誤解しやすい点：入力が変わっても、モデルがたった今パラメーターの学習を終えたという意味ではありません。

パラメーターは、wやbのように学習で調整できる数です。ハイパーパラメーターは、層の幅・学習率・バッチサイズなど、学習や構造の設定であり、通常、同じ勾配の手順で自動的に学ぶものではありません。活性化の値または中間表現は、今回の7のように、ある順伝播で計算する一時的な数です。

ユーザーの新しい入力が変えるのはxです。通常の推論では、それによってwが自動で変わることはありません。

一つの係数wから、パラメーターテーブルWへ

上のw=2は一つの数だけですが、入力と出力にそれぞれ複数の特徴があるときは、多くの係数を保存し、行列Wに並べます。小文字のwはよく単一のパラメーターを、大文字のWはパラメーターテーブル全体を表します。 W1・W2という表記は、第1段と第2段の変換を区別するもので、Wに1や2を掛ける意味ではありません。

重要な違い：「パラメーターテーブル」には、学習で得た係数が入ります。今回の入力に対する乗算と加算で、中間値が得られます。

誤解しやすい点：Wとhは同じ種類の対象ではありません。Wはパラメーターで、hは今回の活性化の値です。

バイアスbもパラメーターの一組ですが、行列積の後にマスごとの加算を行います。Xと隠れ状態hは各入力の計算で生じる数で、Wとbはその数の変換方法を決めます。通常の推論では、重みファイルからW・bを読み込んで使います。ユーザー入力が変わったからといって、自動で学習による更新を実行するわけではありません。

この後はまず、同じ一組の所与のパラメーターで順伝播を計算します。第52—53課で「損失・勾配・オプティマイザー」の概念を身に付けてから、パラメーターの調整方法を説明します。パラメーターを係数の表として理解するために、学習アルゴリズムを先にすべて学び終える必要はありません。

全位置でパラメーターを共有しても、出力が異なる理由

同じWqを全B×T行に使いますが、各行の入力が異なるため、Queryも異なります。この共有によって、位置ごとにWq一式を保存し直す必要がなくなります。Pの行は位置、Eの行はトークンの同一性で選びます。共有パラメーターを使う複数の箇所では、学習の逆伝播時に勾配を足し合わせます。システムの仕組みの対応する導出で、この点を追います。

根拠：tiny_model.py:33–46；対応するパラメーター、順伝播、勾配の記録。

途中に非線形関数が必要な理由

行列の乗算とバイアスの加算だけを続けると、複数の線形変換やアフィン変換は一つにまとめられます。層数を増やすだけで、異なる種類の表現力が自動的に得られるわけではありません。ReLUのように単一の線形変換では表せない操作が非線形性を与え、ネットワークがより複雑な関係を表せるようにします。

途中に非線形関数が必要な理由：項目ごとに区別
方式／対象A線形層の積み重ね
方式／対象B途中にReLUを挿入
方式／対象C異なる関数の形を表現可能

重要な違い：非線形性のない複数の線形層は、一回のアフィン変換にまとめられ、表現力が制限されます。

誤解しやすい点：ReLUは「負数を消すためだけ」の、任意の飾りではありません。

まず、ここで使う対象と記号を知る
SiLU：入力にゲーティング係数を掛ける
SiLU(x)=x×sigmoid(x)です。まずxを0と1の間に写像し、元のxを掛けて、非線形性を作ります。負数がReLUのように一律0になるわけではありません。独立した小さな例：SiLU(0)=0、SiLU(1)は約0.731059、SiLU(-1)は約-0.268941です。
GELU：入力の大きさに応じて滑らかに調整する
一般的な定義はGELU(x)=xΦ(x)で、Φは標準正規分布の累積分布関数です。負の入力と正の入力を、異なる程度で残すものであり、ランダムな抽出ではありません。実装では近似式を使う場合もあります。独立した小さな例：Φ(0)=0.5なので、GELU(0)=0です。ここでΦは、モデルの学習可能なパラメーターテーブルではありません。

実際のTransformerは、GELU・SiLU・ゲート付きのフィードフォワード構造をよく使います。まず「非線形性が必要な理由」を理解してから、具体的な関数を読めばよく、初めて名前に出会った時点で全数式を暗記する必要はありません。

隠れ状態は、隠れた中国語の下書きではない

上の例のh=[3,0]は一回の計算結果であり、隠された「答えが分かった」という文ではありません。言語モデルでは、トークンがある層を通って得る数の列も隠れ状態と呼びます。後続の計算に役立つ情報を持ちますが、各座標をそのまま中国語の説明文に翻訳することはできません。

隠れ状態は、隠れた中国語の下書きではない：項目ごとに区別
方式／対象A隠れ状態：実行中に計算
方式／対象Bモデルの重み：学習後に保存
方式／対象C出力テキスト：デコードで取得

重要な違い：内部の数値表現、固定パラメーター、人が読める文は、異なる段階に属します。

誤解しやすい点：隠れ状態を「モデルがすでに書いた中国語の下書き」と説明してはいけません。

dは各位置の隠れ幅を表し、Lは通常、層数を表します。総パラメーター数は、全行列のサイズと共有方法に関係します。d=4096でも、パラメーターが4096個しかないわけではありません。一つの4096×4096行列だけでも16,777,216個のマスがあります。

重みの共有とパラメーターの凍結

同じWを、同じバッチの各入力・各トークン位置に適用することを、重みの共有と呼びます。位置ごとの計算結果を共有する意味ではありません。入力が違えば、中間状態も異なります。

「パラメーターの凍結」は、学習時に特定のパラメーターを更新しないことです。「推論で固定した重みを使う」は、今回の計算では更新を実行しないことです。別の時点で新版を学習するモデルサービスもありますが、通常の対話での訂正をオンライン学習と同一視してはいけません。

アテンションの前で、まず数の列を処理する理由

隠れ状態の数値の尺度は変化します。正規化層は、各位置内の特徴の統計量で尺度を調整し、後続のモジュールへ、より制御された入力を渡します。この列を確率に変えたり、四つの数の和を1にしたりするものではありません。RMSNormの正規化範囲は特徴軸であり、文全体でもバッチ全体でもありません。

本モデルはpre-normを使います。先にXへRMSNormを適用し、次にアテンションへ渡します。残した残差の主経路は元のXのままで、正規化後の値に直接置き換えません。

根拠：tiny_model.py:48–51；対応するパラメーター、順伝播、勾配の記録。

「爱」の行を一通り計算する

固定 x=[-0.2, 0.8, 0, 0.45]、d=4、ε=0.00001で、初期スケーリングg1はすべて1です。

  1. 四つの数を、それぞれ二乗します。
  2. 足してから4で割り、二乗の平均を得ます。
  3. εを加えて平方根を取り、rを得ます。
  4. 元の各値をrで割り、対応する学習可能なスケーリングg1[j]を掛けます。
mean(x²) = (0.04 + 0.64 + 0 + 0.2025) / 4
         = 0.220625
r = sqrt(mean(x²)+0.00001) = 0.469718001
N1[j] = g1[j] × x[j] / r

rは今回の入力から計算する中間値、εは数値安定性のために設定する定数、g1は学習するパラメーターです。三つは出所が異なります。次に入力が変わるとrは再計算されますが、通常の推論ではrが変わってもg1を更新しません。

根拠：tiny_model.py:48–51；対応するパラメーター、順伝播、勾配の記録。

LayerNormの「平均・分散」がさらに行うこと

以下は独立した二数の比較です。統計の規則を比べるためだけのもので、通しのモデルは引き継ぎません。入力は [1,3]に固定し、別の数の組には変えません。平均μ=2、偏差は[-1,1]、二乗偏差は[1,1]で、母分散はその平均の1です。標準偏差は、εを加えなければ1です。

LayerNormはまずμを引き、次に sqrt(var+ε)で割ります。初期gamma=1、beta=0なら約[-0.999995,0.999995]です。RMSNormは平均を引かず、二乗の平均は5で、結果は約[0.447213,1.341639]です。このため、RMSNorm後も全要素が正のままの場合があります。平均がゼロになるとは約束していません。

根拠：tiny_model.py:48–51；対応するパラメーター、順伝播、勾配の記録。

softmaxとして扱えない理由

softmaxは候補軸に沿って非負の割合を作り、和は1です。RMSNormは負数も許し、和が1である必要もありません。アテンションの行のsoftmaxは可視のKeyに読み取りの割合を配分し、出力のsoftmaxは語彙候補に予測確率を配分します。どちらも「正規化」と呼ばれることがありますが、目標も軸もまったく異なります。

根拠：tiny_model.py:48–51；対応するパラメーター、順伝播、勾配の記録。

学習と推論で統計量を再計算するか

本モデルでは、どちらも各位置の現在の四特徴からrを計算します。RMSNormとLayerNormは、BatchNormのようなサンプル間の移動平均には依存しません。.eval()は統計量の計算を止める意味ではなく、実際に学習／評価で振る舞いが異なるモジュールのモードを切り替えるだけです。

逆伝播ではrもxに依存するため、定数と見なして次だけを計算してはいけません： g/r。システムの仕組みの対応する導出で、勾配に項が一つ増える理由を説明します。まず、xは自身の分子にも、全特徴が共有する分母にも影響すると覚えてください。

根拠：tiny_model.py:48–51；対応するパラメーター、順伝播、勾配の記録。

さらに考える：LayerNorm・RMSNorm・softmaxはいずれも正規化なのに、入れ替えられないのはなぜか？

正規化の軸、統計量、出力の性質が異なります。normは各位置の隠れ特徴の尺度を処理し、softmaxは位置のスコアや候補のスコアを、和が1の非負の分布へ変えます。入れ替えると、順伝播も勾配も変わります。

根拠：tiny_model.py:178–258；対応するパラメーター、順伝播、勾配の記録。

教材で重みを先に示し、後から学習を説明できる理由

内部の動きを理解するため、まず既知の重みで順伝播を一通り進めます。大量の例から重みを得る方法は、第52—54課で説明します。既存の計算機が結果を求める方法を先に理解し、その後、設計の方法を知るようなものです。

小型モデルの数値例は、演算の理解を示せますが、言語データで学習しておらず、意味のある回答は生成できません。手計算のネットワークを「大規模モデルの知能の再現」と呼んではいけません。

限界と反例。ReLUの例は二層のスカラーネットワークにすぎず、完全なTransformerではありません。各ステップを明確に計算するため、小さなネットワークを選んでいます。
