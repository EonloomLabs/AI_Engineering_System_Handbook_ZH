A worked calculation: how two sentences pass through one model layer

On this page
1. Fix every parameter first, leaving no matrix hidden2. Intermediate values at every layer for 我爱学习3. Intermediate values at every layer for 你爱4. Actually feed the newly generated token back inSelf-check: why can we not use another sentence's cache directly
Reading toolabout 3.3k characters

One vocabulary, one parameter set and two labeled inputs: from numerical representations to probabilities, then one cached decoding step.

Read Lessons 35—58 first. Every table states which token each row and which feature each column represents. Displayed values use six decimal places; calculations use unrounded values. This example does not require meaningful Chinese generation.

Worked example · X01

Carry 我爱学习／你爱 through a complete one-layer calculation

Input and conditions. The two sentences still use a six-row, four-column embedding table. Specify an untrained teaching model: one layer, hidden width 4, two attention heads of width 2 each, pre-LayerNorm, residuals, a SwiGLU feed-forward network and output projection tied to the embedding. To reduce variables, this example has no positional encoding, bias or dropout.

Steps and objectsInternal actionIntermediate result / new state
1 Look up each sentence separately我／爱／学习 takes rows 1, 2 and 3; 你／爱 takes rows 4 and 2The sentences have shapes 3×4 and 2×4. PAD is only for batch display; the numerical witness processes valid tokens separately for each sequence.
2 Normalize each positionSubtract the mean and divide by the standard deviation for each row of 4 numbersNormalization neither mixes the sentences nor averages different tokens into one sentence.
3 Compute two-head attentionEach head produces scores, a causal mask, probabilities and a Value mixtureEach head produces 2 numbers at every position; concatenate them into 4 and add back the original embedding.
4 Pass through the feed-forward layerNormalize again, then compute 0.25×SiLU(z)×z and add the residualEvery position has 4 updated numbers; only the final position predicts this round's next token.
5 Project back to the vocabularyDot the final position's 4 numbers with each vocabulary row, then apply softmaxDecoding explicitly forbids PAD here; at the end of 我爱学习, the highest-probability item is 爱, about 0.307383.
6 Continue onceFeed the newly chosen 爱, ID 2, alongside the old K/VThe incremental final state matches full recomputation of 我／爱／学习／爱, with numerical error below 1e−12.

Join the steps up. The tables below show every intermediate tensor and every matrix value. Do not understand the model merely as "it predicted 爱"; observe how the same input passes through each operator.

Limits and counterexamples. All weights are manually specified; repeatedly predicting 爱 does not demonstrate language capability. This simplified model without positional encoding also does not represent a modern commercial model's complete architecture.

Every LayerNorm uses 4 numbers per row, ε=0.00001, scale 1 and bias 0. The attention output projection is the identity matrix. The feed-forward network uses Wgate=Wup=I and Wdown=0.25I, so each output component is 0.25×SiLU(z)×z. A final LayerNorm follows, with E transposed for output projection. No training, positional encoding or dropout. These are explicit conditions of this example, not a vendor model's parameters.

Self-check: why can we not use another sentence's cache directly

The final token of the second sentence, 你爱, is also 爱. Can the first sentence's three-position cache be attached to the second sentence? Decide for yourself first.

Show the answer

No. Identical token IDs mean only identical initial embedding rows, not identical prefixes. K/V retain that layer's computations for the corresponding prefix; mixing sentences injects 我／爱／学习 history into 你／爱, changing visible information and results.
