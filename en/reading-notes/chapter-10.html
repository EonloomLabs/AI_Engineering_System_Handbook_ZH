Skills are professional work packages expanded as needed

Skills organize capabilities through names, descriptions, main text and resources. Discovering metadata first, loading relevant main text next, then reading scripts or references as needed follows progressive disclosure. It does not add model parameters or guarantee program-like execution of every step.[S121][S122]

A hypothetical path-checking skill may include applicable situations, path semantics, necessary tests and counterexamples. Its description handles routing, main text supplies methods, resources supply evidence, and scripts perform deterministic operations. Even expert main text cannot help this turn if it is not selected.

Responsibilities at each extension layer

Instructions express lasting constraints; Skills provide task methods; Tools execute or obtain evidence; Hooks run programs at event points; custom agents organize roles and model / tool configuration; plugins package and distribute them. Product support varies.[S072][S080][S079]

Start with the objects and symbols used here
SQL, SQLite and the transaction object
SQL is the language for working with relational data; SQLite is a database engine that embeds into an application. Writing operational state into a database is a persistence action by the harness; it does not modify the model's neural network parameters. One transaction can save the business row in this database together with a pending-send record, but that does not let you infer that the mail service committed atomically along with it.

Original choices: put global code style in guidance, migration-specific checks in skills, SQL execution in tools, pre-commit static checks in a Hook or CI, and reserve a dedicated agent for truly independent tasks. Mandatory prohibitions cannot live only in a skill.

Routing is not single-label classification

A task may need several skills or none. Retrieve necessary capabilities while avoiding useless loading. Boundary cases should include adjacent fields, explanation rather than implementation, explicit selection, cross-domain tasks and insufficient evidence.

Original examples: "optimize caching" may refer to Prompt Cache or Redis. Keywords alone cause misrouting. Identify the object and goal first, obtaining a little evidence to resolve ambiguity if necessary, rather than loading every candidate at once. Include routing cost in evaluation.

Multi-agent benefits come from task structure

Independent research, parallelizable tasks and valuable independent review may benefit. Several agents editing the same function invite conflict. Anthropic's multi-agent research demonstrates coordinator–worker patterns; Agentless offers a simple-process counterbaseline. Neither supports "more is always better" or "agents are never needed".[S124][S128]

Parallel gains depend on dependencies, context copying and integration costs. Two agents investigating platform-specific paths may help; three agents repeating the same summary may add no independent evidence.

Engineering mechanisms and failure boundaries

The break-even point of parallelism

In sequence A4+B6+summary 2=12, against an ideal parallel 8; adding 5 units of handoff makes it 13. Record the actual repeated reading and merge errors.

Key boundary: independent research and edits to shared files need different coordination strategies.

Follow it further through the source or the engineering basis: compute wall-clock time, and maintain the shared objects and the result contract. Do not check only the path that goes well; check the behavior on cancellation, on a version change, and when the result is unknown.

For the full mechanism and a continuous example see How do several agents run in parallel, and how is loss at handoff avoided?; this section keeps its own derivation and experiment, and the two accounts work at different levels rather than replacing each other.

Evidence and the limits of understanding: A sub-agent receiving a message does not mean the task has started or finished; the inheritance of context, tools, permissions and usage must each be checked separately.

Handoff and agents as tools

Start with the objects and symbols used here
Handoff and agent-as-tool
A handoff gives control to another agent; agent-as-tool treats a sub-agent as a callable component whose result returns to the current controller. An orchestrator is the coordinating program or agent responsible for distributing and integrating the work. Delegation needs the task, the boundaries, the evidence and the completion conditions; it does not require copying the whole history of the main session across.

Handoff often means transferring control; when an agent acts as a tool, the caller usually retains outer control; multi-agent conversation is another collaboration form. Specific SDKs differ in semantics and state filtering.[S126][S127][S129]

Transferring customer support to a specialized workflow and having the main agent request a read-only review suit different organizations. Frameworks do not automatically make handoff information minimal yet complete; check what is passed, how original evidence is obtained and how errors return.

Use ablation experiments to judge value

An original experiment compares one agent, then adds a skill, parallel investigation and independent review, changing only one item at a time. Report simple and complex tasks separately so averages do not hide regressions. If routing reduces missed skills but greatly increases irrelevant loading, judge actual loss rather than hit rate alone.

Self-check: does agreement among agents mean independent evidence? No. Is parallelism always faster? No; coordination and dependencies may cancel the gains. Are longer skills more professional? No; judge whether necessary knowledge is used correctly at the right time.

A 10.1 · Progressive skill loading

Related material: Equipping Agents with Agent Skills

The Agent Skills article proposes organizing expertise through progressive disclosure: show metadata first, expand relevant main text, then read resources as needed. This changes information supply, not model parameters through training.

Skill entry points need clarity for discovery, main text needs actionable methods, and resources need trustworthiness and freshness. Failure at any layer can make a skill ineffective.

A 10.2 · Skill specifications and resource organization

Related material: Agent Skills Open Specification

The open skill specification defines conventions for files, metadata and resource organization. Format compliance helps interoperability, but does not guarantee identical loading, permission or execution behavior in every client.

Specification compliance differs from correct skill content. A validly formatted skill may still have vague scope, stale steps or invalid references.

Start with the objects and symbols used here
Skill, JIT and the trigger description
In a capability-loading setting, a Skill is a reusable set of guidance and resources; JIT means loading only when needed, and does not necessarily mean a compiler's just-in-time compilation. A trigger description helps the model judge whether something applies; it does not grant tool permissions by itself. First judge whether the task needs a given skill, then read the details; a loaded skill is not the same as its requirements having actually been carried out.

A 10.4 · Scope of Copilot skills

Related material: Copilot Agent Skills

Copilot skills provide task-specific guidance and resources. They differ from persistent repository instructions; do not add every skill body to every task by default.

Differences across interfaces require checking the execution environment first. Successful installation and loading this turn are separate facts; neither proves the other.

Start with the objects and symbols used here
IDE, CLI, UI and DOM
IDE is the integrated development environment, CLI the command-line interface, UI the user interface, and DOM the tree of structural objects of a web document. The code, selection and page information that each entry point attaches automatically can differ. The model seeing the selected function in the IDE does not mean the same task in the CLI has received that function; check this turn's input objects first.

B 10.6 · Choosing the right extension layer

Related material: Customization Cheat Sheet

When returning to the customization comparison table, focus on eliminating overlapping responsibilities. Global rules, expertise, tools, event checks and role orchestration should each have a clear authoritative source.

A 10.7 · The main agent and parallel researchers

Related material: Multi-Agent Research System

Multi-agent research systems use coordinators and workers for separable research directions. Gains come from parallel exploration and task structure, alongside coordination, duplicate search and integration costs.

Research-task successes cannot be extended directly to several agents editing one file. Shared state and write conflicts may cancel parallel gains.

Start with the objects and symbols used here
DAG, dependencies and the critical path
A DAG is a task dependency graph that is directed and has no cycles. The arrow A→B means B depends on A finishing; the critical path is the longest dependency chain, the one that fixes the earliest finishing time given the task durations and dependencies. Independent example: A takes 2 seconds, B and C depend on A, take 3 and 5 seconds and can run in parallel, so finishing both after A takes at least 7 seconds — not 2+3+5=10 read as wall-clock time.
