The timeline of one request

Prefill processes known input, while Decode generates new tokens step by step. The former can process an existing sequence in parallel; the latter has autoregressive dependencies. Their computation and memory-access needs differ, so response time cannot be estimated from total input and output tokens alone.[S036][S040]

总耗时 ≈ 排队 + 输入处理 + 生成 + 工具执行
        + 网络往返 + 编排等待 + 重试恢复

This is an original diagnostic breakdown; parallel operations overlap, so all span durations cannot be added directly. 8,000 input tokens with 200 output tokens differs from 200 input tokens with 8,000 output tokens; models, caches, hardware and serving schedules also affect the result.[S044]

Decoding and sampling

Start with the objects and symbols used here
Top-k, Top-p and renormalization
Top-k keeps the k items with the highest probability; Top-p sorts by descending probability and keeps the leading candidates until the cumulative probability reaches a threshold. When used for sampling, the kept candidates have to be renormalized over the remaining total mass. Here k is a number of candidates and p a cumulative-probability threshold; k is not the attention Key table K, nor the representation width d_k.

Greedy selection chooses the highest score, Sampling draws from the distribution, and Beam Search maintains multiple candidates. Temperature often adjusts sharpness through softmax(logits/T); T=0 is usually a special greedy mode of the interface, not mathematical division by zero. Top-k retains a fixed number of candidates; Top-p retains a set whose cumulative probability reaches the threshold.[S034][S035]

Original calculation: with probabilities 0.60, 0.25 and 0.15 and p=0.8, keep the first two and renormalize to about 0.706 and 0.294. Removing the tail does not verify the first two candidates as correct. Normal completion, truncation, refusal and tool calls must be distinguished.

KV cache and VRAM

A KV cache reuses Keys and Values from past positions to reduce repeated computation during generation. A simplified estimate for standard attention is:

字节 ≈ 2 × 层数 × 批大小 × 序列长度
      × KV头数 × 每头维度 × 每元素字节数

2 represents K and V. The formula excludes allocation waste, alignment and metadata, and does not apply directly to every specialized architecture. A teaching example with 32 layers, 1 sequence, 8,192 tokens, 8 KV heads, width 128 and 2 bytes gives about 1 GiB. With 32 KV heads the estimate is about 4 GiB; this does not mean end-to-end execution is four times slower.[S036][S013]

Dynamic, static, quantized and offloaded caches trade off space, compilation, precision and transfers. Weights fitting in memory does not mean long contexts at high concurrency also fit. Quantized or offloaded caches may also add computation.

Prompt cache is not compaction

Prompt Caching reuses computation for matching prefixes; compaction changes the information actually supplied. A cache hit does not remove the input from the context window, and losing a cache does not mean history was deleted. Stable prefixes favor reuse, but large amounts of irrelevant rules should not be kept for caching alone.[S039][S094]

Original examples: fixed rules occupy 6,000 tokens and new evidence adds 500 tokens per turn. Inserting a changing timestamp at the very beginning may shorten the matching prefix. Savings depend on actual billing, hit coverage and task quality, not just one ratio.

Three server-side acceleration approaches

Start with the objects and symbols used here
FlashAttention: changing how intermediate data is stored and read
By means such as tiling and online normalization, it avoids keeping the full attention score/weight matrix in slower VRAM for long; the target is still the same attention computation, and floating-point rounding can vary with the order of operations. It does not compress tokens permanently, and it does not skip any Key. Keep "not writing the whole table to VRAM" apart from "not doing this arithmetic at all".
PagedAttention: managing K/V storage in pages
Store a logically contiguous K/V sequence in several physical blocks, located through a block table. It mainly changes how the storage is managed and shared; it does not replace the attention formula with an algorithm that means something else. Independent example: logical positions 0—3 are in physical block 7 and 4—7 in block 2; logical position 4 need not physically follow position 3.

FlashAttention optimizes data movement in attention computation; the original work focuses on IO efficiency for exact attention. PagedAttention improves KV memory organization and sharing; vLLM is a related serving implementation ecosystem. Speculative Decoding proposes draft candidates for verification by a target model and preserves the target sampling distribution under the corresponding algorithmic conditions. They optimize different bottlenecks and cannot replace one another.[S040][S041][S042][S043]

Continuous batching improves resource utilization, but higher average throughput does not guarantee lower tail latency for every user. Speculative decoding depends on draft acceptance rate; when tools dominate elapsed time, GPU acceleration may have limited benefit for the whole task.

Performance attribution exercise

Record one exclude task's per-turn inputs and outputs, tool durations and total elapsed time. If a full test suite consumes the time, changing sampling does not help; if long plans recur, check orchestration; if the entire repository is read each turn, check retrieval; if insufficient reasoning causes rework, cutting the budget may cost more.

Self-check: does a higher cache-hit rate mean optimization succeeded? No; quality must not regress, and total cost or duration must improve. Is a short output always efficient? No; omitted verification may transfer costs to the user.

A 3.1 · Text generation and decoding strategies

Related material: Generation Strategies

Generation strategies determine how tokens are selected from the model distribution. Greedy selection, sampling and beam search have different goals; high sequence probability does not guarantee more natural or factual open-ended answers.

Length, stopping and repetition controls also change results, and support varies across models. Truncated code must be recognized as incomplete; the last returned text is not necessarily a valid program.

A 3.2 · Text degeneration and nucleus sampling

Related material: The Curious Case of Neural Text Degeneration

Research on text degeneration examines repetitive or unnatural results that high-probability search may produce in open-ended generation; nucleus sampling forms a dynamic candidate set by cumulative probability. Top-p does not retain a fraction p of the vocabulary.

Peaked distributions produce fewer candidates and flatter ones more; truncation needs renormalization. Tail filtering controls sampling, not candidates' factual correctness.

A 3.3 · KV cache strategies

Related material: KV Cache Strategies

A KV cache reuses Keys and Values from past positions to reduce repeated decoding computation. Dynamic, static, quantized and offloaded caches trade off space, speed, precision and transfers.

An estimate must include layers, sequences, batch size, KV heads and precision; the query-head count cannot be substituted for every model. Specialized architectures may also change the representations.

A 3.4 · Using reasoning-model APIs

Related material: Reasoning Models

Reasoning-model interfaces may offer reasoning effort or budgets and distinguish the final visible answer from extra computation. Check parameter support, state format and fees for the particular model and interface.

Protected or opaque reasoning state cannot be fabricated or concatenated arbitrarily. A short final answer may still use substantial internal computation, and reasoning may continue between tool calls.

B 3.5 · Limits on the use of reasoning models

Related material: Reasoning Best Practices

Guidance for reasoning models emphasizes clear goals, constraints and verification methods rather than mechanically demanding lengthy derivations. Models may respond differently to examples and instruction organization.

Complex tasks need sufficient information, simple tasks can use less fixed planning, and tool-verifiable conclusions should actually be verified. Best practices are a starting point, not a substitute for your own evaluation.

B 3.6 · Prefill and Decode

Related material: CS336 Inference

Prefill processes known input; Decode extends the sequence. They differ in parallelism and memory access, so their durations should not all be attributed to a vague "model speed".

Long input affects the first token; long output adds serial generation; multiple tool rounds also add network and environment waits. Different bottlenecks need different optimizations.

A 3.7 · Prompt prefix caching

Related material: Prompt Caching

Prompt Caching reuses computation for identical prefixes meeting its conditions, without changing context content itself. Thresholds, retention times and billing are product rules, not universal constants to remember without a version.

Stable rules in stable positions favor reuse, and dynamic data may belong later; correct organization of instructions and evidence takes precedence over caching. An irrelevant long prefix occupies window space even on a hit.

B 3.10 · Speculative decoding

Related material: Speculative Decoding

Speculative decoding uses a cheaper draft to propose candidates for batch verification by the target model. Under the corresponding algorithmic conditions, it can preserve the target sampling distribution; it does not simply replace the target model with a small one.

Benefits depend on candidate acceptance rate, draft cost and verification efficiency. If the draft differs too much, frequent rejection reduces acceleration; short outputs or other bottlenecks may also affect value.

C 3.12 · End-to-end latency optimization

Related material: Latency Optimization

Latency optimization examines request count, generation length, caching, parallelism, tools and user perception. Reducing unnecessary round trips may help, but deleting necessary verification harms task success.

A faster first sentence differs from faster final completion. Parallelism suits only independent steps; dependent edits and reads must not be reordered arbitrarily for speed.

Continue the step-by-step calculation: Q098 · A slow first token, fast later tokens and a slow overall task can coexist

Basis and scope of use:[DERIVE]. The example input and setting are stated explicitly by this book.

Start with the objects and symbols used here
DAG, dependencies and the critical path
A DAG is a task dependency graph that is directed and has no cycles. The arrow A→B means B depends on A finishing; the critical path is the longest dependency chain, the one that fixes the earliest finishing time given the task durations and dependencies. Independent example: A takes 2 seconds, B and C depend on A, take 3 and 5 seconds and can run in parallel, so finishing both after A takes at least 7 seconds — not 2+3+5=10 read as wall-clock time.

Original exercise: record a task's critical path and separately estimate the effects of removing one call round, reducing logs and parallelizing two searches. Change just one mechanism before remeasuring, so multiple changes are not conflated as causes.

Completion means optimizing total time per successful task rather than an isolated token metric. If the model mainly waits for the test environment, changing sampling or caching strategy may not be the most valuable change.
