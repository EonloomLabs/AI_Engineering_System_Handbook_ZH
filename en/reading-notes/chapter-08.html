Retrieval starts from evidence needs

RAG connects external retrieval with generation. The original paper's training and inference design differs from today's broad practice of "search, then put it in the prompt". Engineering systems also include ingestion, chunking, indexing, querying, candidate retrieval, reranking and assembly. An error at any layer can distort an answer.[S095]

First distinguish whether the task needs exact symbols, semantic material, historical changes or execution results. With stale source documents, retrieval only finds stale facts faster; when chunking loses conditions, semantic similarity is insufficient to support a conclusion.

Term-based, dense and late-interaction retrieval

Start with the objects and symbols used here
BM25 and N, df, k₁, b
BM25 is a scoring formula for term-based retrieval. In the usual notation N is the total number of documents, df the number of documents containing the term, tf the term frequency in the current document, |D| the length of the current document and avgdl the average length; k₁ and b are the settings for term-frequency saturation and length correction. k₁ is not the Key vector k₁, and b is not a neural network bias. The score only orders candidates; 8.2 cannot be read as 82% accuracy.
bi-encoder, cross-encoder and reranking
A bi-encoder encodes the query and the document separately, so document vectors can be stored in advance; a cross-encoder processes a query and a document together for a finer judgment, usually computing every pair. Reranking only orders candidates that have already been recalled. A correct document that was missed is not in the candidate set, and no reranker, however strong, can put it first; the recall has to be fixed first.
ColBERT and MaxSim
ColBERT-style methods keep several token vectors for the query and for the document, then interact them late. The usual MaxSim takes, for each query token, the highest similarity with any document token, and then aggregates. It is not dual-encoder retrieval where "the whole document has only one vector", and it is not the self-attention output of each layer of a generative model.
Start with the objects and symbols used here
DPR, DPI and coordinate units
DPR usually means the ratio of device pixels to CSS pixels; DPI means dots per inch. Screenshot pixels, the interface's logical coordinates and screen coordinates need not share a unit, and there may also be scaling, cropping and offsets. In an independent example where DPR=2 is stated and the other mappings agree, a CSS x-coordinate of 100 corresponds to 200 device pixels; this conditional relationship cannot be carried straight over to every screenshot.

Term-based methods such as BM25 use term occurrences and statistical importance; dense retrieval encodes queries and documents as vectors; DPR demonstrates bi-encoder retrieval for Q&A; ColBERT uses finer-grained token representations and late interaction. Vector distance is not factual accuracy; include and exclude they may be close yet mean opposite things.[S096][S098][S099]

Chunk around understandable units; code can be split by function / class while retaining paths and signatures. Too small loses conditions; too large adds interference. Overlap helps at boundaries but creates duplicates, which still need removal during assembly.

Contextual Retrieval

Anthropic's approach adds brief context grounded in the original text to each chunk, then combines terms, vectors and reranking. An isolated "the default changed from false to true" needs its field, project and version; added context can help retrieval, but incorrect additions also contaminate the index. The original text and provenance must be retained.[S096]

This does not mean inventing plausible context for every chunk. For code with complete symbols and paths already specified, extra long descriptions may not help; measure an exact-retrieval baseline first. The article's experimental results apply only to its test conditions, not as guaranteed efficiency gains for any repository.

Fusion, reranking and query rewriting

Start with the objects and symbols used here
RRF: fusing by rank
For a document's rank r on each recall path, RRF contributes 1/(c+r), and these are added. c is a smoothing constant and r usually starts at 1; a candidate that did not appear on a path does not receive that path's contribution out of nowhere. Independent example: with c=10 and a document ranked 1 and 3 on two paths, it gets 1/11+1/13, about 0.167832. This is not adding the raw BM25 and cosine scores together.

RRF adds contributions across different rankings using 1/(k+r), avoiding direct addition of BM25 and cosine scores with different scales. Rank fusion cannot recover documents missed by every retriever. A reranker judges candidates more finely at higher cost and is usually used on a smaller set.[S097]

Start with the objects and symbols used here
HyDE: the hypothetical text is only used to find material
Have the model generate a hypothetical answer or document and use its representation for retrieval. That generated text is an aid to finding evidence, not a source of facts already found. The model guesses "it may be cache invalidation", which is reason enough to widen the search; before there is real evidence it must not be written up as "cache invalidation confirmed".
GraphRAG, RAPTOR and hierarchical organization
GraphRAG-style methods use organizational information such as entity relationships and communities; RAPTOR uses hierarchical clustering and summaries to support retrieval. They introduce extra derived information, and with it problems of updating, provenance and error propagation. When the source document changes, an old summary or a relationship in the graph may be out of date. Changing the original text is no proof that every derived index has been updated with it.

HyDE generates hypothetical documents to help retrieval, but hypotheses are not evidence. RAPTOR builds hierarchical summary indexes, while GraphRAG organizes relationships and global information. They suit different needs and add extraction errors and maintenance costs.[S100][S101][S120]

Engineering mechanisms and failure boundaries

Fused ranking and independent evidence

Compute RRF for the fixed D1/D2/D3, then add a duplicate block of D2's original text and check that the duplicate cannot be counted as independent support.

Key boundary: source deduplication, version filtering and relevance ranking each solve a different problem.

Follow it further through the source or the engineering basis: after fusing the rankings you still have to check version, permission, coverage and contradiction. Do not check only the path that goes well; check the behavior on cancellation, on a version change, and when the result is unknown.

For the full mechanism and a continuous example see Relevant is not the same as usable: from recall to evidence closure; this section keeps its own derivation and experiment, and the two accounts work at different levels rather than replacing each other.

Evidence and the limits of understanding: a high rank does not mean the evidence covers the question. The small RRF worked example in this book is not an official production query; chunk context and the original evidence have to be kept apart.

Verification basis:[A08] [A02] [A03]. The source is limited to commit 86e17e98c7f9 and the paths actually read; article experience, public documentation and original teaching experiments are labeled separately. See how it was obtained, what was read, and the limits.

Code retrieval should use structure

Paths, regular expressions, GitHub Code Search and ripgrep suit exact location. Tree-sitter provides syntax trees and incremental parsing; LSP provides language services such as definitions, references, symbols and diagnostics. An AST does not automatically contain every type or runtime meaning, and LSP also depends on the language server and project configuration.[S102][S103][S104][S105]

Original investigation sequence: configuration field → parsing point → filter function → caller arguments → tests → change history → minimal reproduction. A same-named symbol may not lie on the actual execution path. Git descriptions can explain historical reasons, but current behavior must still be judged from current source and runtime evidence.

RepoCoder studies iterative retrieval and generation; RepoBench and CodeSearchNet evaluate different repository-context tasks. Completion, search and issue repair are different capabilities; their metrics cannot be converted directly.[S106][S107][S108]

Retrieval metrics and downstream success

Start with the objects and symbols used here
Precision, Recall, MRR and nDCG
Precision looks at how many of the returned results are relevant; recall looks at how many of the relevant items that should have been found were found; MRR averages the reciprocal rank of the first correct item; nDCG takes the degree of relevance and the position in the order into account, and normalizes against the ideal ordering. Independent example: 5 documents should be found, 4 are returned and 3 of them are relevant, so precision is 3/4 and recall 3/5. Do not swap these two denominators.
Precision@k = 前k条相关数 / k
Recall@k = 前k条相关数 / 全部相关数
MRR = 各查询首条相关结果排名倒数的平均

MAP accounts for where relevant results appear; nDCG supports graded relevance, applies position discounts and normalizes. If the relevant set is unknown, recall itself is hard to measure precisely.[S110]

Original examples: evidence from both A and B is required, but results are A, X, Y, giving Recall@3 of 1/2 and Precision@3 of 1/3. If compatibility cannot be judged without B, finding A is not task success. Truncation or misinterpretation after retrieval still causes failure. BEIR reminds us that cross-domain generalization needs independent evaluation.[S109]

Failure diagnosis order

Check whether sources are correct and fresh → whether the index contains them → whether the query is accurate → whether candidates were retrieved → whether reranking removed them incorrectly → whether assembly truncated them → whether the model interpreted them correctly. Filter permissions before returning evidence, rather than letting the model see it and relying on voluntary secrecy.

Self-check: is the highest similarity the most trustworthy? No. Does good retrieval make testing unnecessary? No; retrieval supplies evidence, while tests check behavior.

A 8.1 · Foundations of retrieval-augmented generation

Related material: Retrieval-Augmented Generation

The original RAG research combines a parametric generative model with nonparametric document memory, using retrieved evidence for knowledge-intensive tasks. Engineering uses of RAG are broader today; not every "search then answer" system is a complete implementation of the original paper.

Retrieval supplies candidate evidence, and generation uses it to form output; both can fail. Stale documents, missing chunk conditions and model misreadings can all cause wrong answers.

A 8.2 · Context-enhanced hybrid retrieval

Related material: Introducing Contextual Retrieval

Contextual Retrieval adds brief context from the original text to chunks before indexing, then combines terms, vectors and reranking. It helps isolated chunks retain references and background; it does not permit the model to invent situations for documents.

For example, "this field is off by default" needs the field, version and document position. Adding this information helps retrieval but may contaminate the index through summary errors, so original content and provenance must be retained.

A 8.3 · Reciprocal rank fusion: RRF

Related material: Reciprocal Rank Fusion

RRF fuses ranks from different retrieval results; a common form sums across lists 1/(k+rank). It avoids directly adding raw scores on different scales, but cannot recover documents missed by all retrievers.

The smoothing constant affects the weight of rank differences; merge duplicates by actual document identity rather than title alone. Permissions should also be filtered before fusion.

B 8.4 · Dense passage retrieval: DPR

Related material: Dense Passage Retrieval

DPR uses dense representations for passage retrieval, with queries and documents encoded separately. Precomputing document vectors helps retrieval efficiency, but quality depends on training data, encoders and task distribution.

Similar meaning can match different expressions but also confuse negation, versions or same-named entities. Exact terms and metadata filters remain useful.
