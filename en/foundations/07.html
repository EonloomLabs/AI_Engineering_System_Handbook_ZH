Matrix multiplication is like filling in a recipe result cell by cell

The number in one output cell: which input cells does it actually come from?

Do not start by memorizing shape rules. Fix your eye on one output cell: it takes one row of the input and one column of the coefficient table. Multiply each pair of numbers, then add the products up. Repeat the same action for every output cell and you have the whole result table.

Dot product two equal-length rows of numbers multiplied position by position and then summed.
Parameter table W the coefficients that control how the components of the input are combined.
Linear projection Here this means multiplying each row by W; it need not reduce the dimension.

Input and conditions of use: Reuses this section's main "matrix multiplication" worked example, X=[[1,2,3],[4,5,6]], W=[[1,0],[0,1],[1,1]]; it is not the independent two-dimensional worked example that comes later.

1 / 4 · Fill row 0, column 0 of the output

Step 1 of 4

On a narrow screen you can swipe the figure sideways, or tap "Enlarge figure". The text explanation follows right after it.

Take row 0 of X and column 0 of W, pair them up across the three features, multiply, then add. Every other output cell is computed on its own and must not mix in another row.

Y[0,0] = 4

1×1 + 2×0 + 3×1 = 4

Still by default. Use "Next step" to finish reading an explanation before going on; playback stops automatically at the last step. With keyboard focus on the player, the arrow keys step through it and the space bar plays and pauses. Color in the figure helps tell things apart; every meaning is stated in words as well.

Why it is needed

A batched operator handles many multiply-adds of the same kind at once, but the mathematical definition of each cell is unchanged.

How to implement it

Get one cell right first, then use a matrix library and the GPU for the whole table.

Possible costs and misreadings

Even with the right shape you can still take the wrong axis or misuse element-wise multiplication.

How to tell whether it was done right

The four results should be 4, 5, 10 and 11 in that order; then compare them with the matrix multiplication in the code.

Start from the average you already know

The ordinary average of 2 and 6 is (2+6)/2=4, which can also be written 0.5×2+0.5×6. If you think the second number should take a larger share, you can write 0.25×2+0.75×6=5, and this is called a weighted average. When the weights are non-negative and sum to 1, it expresses "what share each one takes".

Key difference: Multiply by the weights first, then add: 0.25×2+0.75×6=5. A weight is a share of the contribution.

Easy to misread: Only weights that are non-negative and sum to 1 can properly be read as "shares".

For the two rows of numbers [2,0] and [0,4], the computation still goes position by position:

0.25×[2,0] + 0.75×[0,4]
= [0.25×2+0.75×0, 0.25×0+0.75×4]
= [0.5,3]

The result is still a row of numbers; no sentence of text has been chosen. This is used directly in attention.

How a dot product turns two rows of numbers into one number

A dot product requires the two rows to be the same length: multiply them position by position, then add.

Key difference: Computing 1×4+2×5+3×6 ends with one number.

Easy to misread: A dot product does not keep each position separately as three rows of results.

[1,2,3] · [4,5,6]
= 1×4 + 2×5 + 3×6
= 32
Start with the objects and symbols used here
Σ: sum term by term over the subscript
Σ is shorthand for addition. The subscript says which term varies; a subscript that is not summed over stays fixed. It is not an extra parameter, and it does not mean concatenating arrays. Independent micro-example: Σᵢ xᵢyᵢ with x=[1,2] and y=[3,4] is just 1×3+2×4=11.

The formulaΣ_i x_i y_i simply writes the three multiplications and the addition above as a general rule. A dot product gives a scalar, not three rows of numbers. It can be used to compare directions or to produce a score, but a raw dot product is also affected by vector length, so it cannot be called a pure semantic similarity without qualification.

Matrix multiplication is "many dot products at once"

This passage names two objects first: X is the current table of input numbers; W is the table of coefficients that decides how those numbers are combined. W is specified by hand for now; F10 explains how it becomes a trainable parameter inside the model. The letters only identify objects; they add no new arithmetic operation.

Key difference: One row of X pairs with one column of W to fill one cell of Y; repeating that gives 2 rows and 2 columns.

Easy to misread: The inner dimensions have to match, and matrix multiplication is not cell-by-cell multiplication.

Take two tables:

X = [[1,2,3],       W = [[1,0],
     [4,5,6]]           [0,1],
                         [1,1]]
X形状[2,3]         W形状[3,2]

Computation Y=XW: every cell of Y is the dot product of one row of X with one column of W.

Y[0,0] = [1,2,3]·[1,0,1] = 4
Y[0,1] = [1,2,3]·[0,1,1] = 5
Y[1,0] = [4,5,6]·[1,0,1] = 10
Y[1,1] = [4,5,6]·[0,1,1] = 11
所以Y = [[4,5],[10,11]]，形状[2,2]

The inner sizes have to match:[m,n]×[n,p]→[m,p]. m is the number of rows of the first table, n the length paired in each dot product, and p the number of output columns. There is no freedom here to "multiply all the numbers however you like".

What act is it, exactly, when a token goes from 4096 numbers to another 4096 numbers

If a row of numbers x of length 4096 is multiplied by a [4096,4096] weight matrix, every output column is a weighted sum of the 4096 input numbers. The output is still 4096 numbers, but the values and the way they are combined have changed. This process is usually called a linear projection; "projection" here need not be the same as a three-dimensional object projected onto a wall, and it does not necessarily reduce the dimension.

Key difference: Every output feature comes from a weighted combination of the 4096 input features; the count can stay the same while the content has changed.

Easy to misread: A "projection" does not have to make the dimension smaller.

With several inputs, the last axis is usually treated as the feature axis. The same W acts on every position, so [B,T,d]×[d,k]→[B,T,k]. It changes the width of each position; it does not directly mix two samples or neighboring tokens.

How a transpose helps "compare one row of numbers against many rows"

A transpose swaps the rows and columns of a table. For example:

Key difference: After the transpose every Key becomes a column, which lets one Query take the dot product with all the Keys at once.

Easy to misread: The ᵀ in Kᵀ means transpose, not the sequence length T.

K = [[1,2],       Kᵀ = [[1,3,5],
     [3,4],             [2,4,6]]
     [5,6]]

K in this passage is only the name given to three rows of numbers to be compared: it has 3 rows with 2 numbers each. There is also a row of numbers q to compare against them, also of length 2; to take the dot product of q with each of K's 3 rows, K can be turned into 2 rows and 3 columns, so that [1,2]×[2,3]→[1,3] gives the three comparison scores at once. Only in F11 are this receiving representation and this candidate representation introduced as Query and Key, with a full explanation of where their parameters come from.

Note that the superscriptᵀmeans transpose, not the sequence length T; Kᵀis not K to the power of T either.

Matrix multiplication and element-wise multiplication must not be mixed up

In the common Python numeric libraries,@means matrix multiplication, and*usually means multiplying matching cells element by element. On two 2×2 matrices both operations run and both output 2×2, yet the results are entirely different. A correct shape is only a necessary check; it does not mean the operation means the right thing.

When reading a formula, ask in turn: what is each axis of the input, along which axis does the operation run, how is each output cell computed, and is the result a score or a feature. This is more reliable than just remembering that "QKV are all matrices".

Start with the objects and symbols used here
⊙: element-wise multiplication, not matrix multiplication
Elementwise multiplication multiplies the numbers at the same position once the shapes are aligned; it does not then sum along any dimension. Matrices written side by side in a formula, or @, usually mean matrix multiplication, and the two are not interchangeable. Independent micro-example: [1,2]⊙[3,4]=[3,8], whereas the dot product is 11. The ⊙ in a gated feed-forward network modulates one path with the other, feature by feature.

Telling dot product, matrix multiplication and element-wise multiplication apart in one table

An independent matrix-multiplication comparison: below we switch to a single two-dimensional input row and do not continue with the three-column X above; this table uses the x and W given here throughout. Input and conditions. Take an input row x=[1,2], and a weight matrix W=[[3,4],[5,6]]. A row vector times a matrix means computing one new feature from each column of W.

Steps and objectsInternal actionIntermediate result / new state
1 Take column 1[1,2]·[3,5]1×3+2×5=13.
2 Take column 2[1,2]·[4,6]1×4+2×6=16.
3 Assemble the outputPut the two dot products side by sideGives [13,16]; this is xW.
4 Element-wise comparison[1,2]⊙[3,5]Gives [3,10], which has not been summed and cannot stand in for the dot product 13.
5 Two inputsAdd x2=[0,1] in as well[[1,2],[0,1]]W=[[13,16],[5,6]], with the same weights at every position.

Join the steps up. Matrix multiplication involves no mysterious new act: it pairs things up as prescribed and repeats "multiply, then add". A legal shape is no guarantee that the axes mean the right thing.

Limits and counterexamples. The weights are constructed and carry no trained meaning. This example uses the row-vector convention; with a column-vector convention the formulas have to be transposed consistently.
