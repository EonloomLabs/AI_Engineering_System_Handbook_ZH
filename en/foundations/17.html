Post-training changes behavior; a reward is not an arbiter of fact

Since the model will go on to the next token anyway, why are SFT and preference training still needed?

"Able to continue text" is not the same as "able to answer what the user meant". Supervised fine-tuning supplies demonstration answers and preference training compares candidate behaviors; a reward is only an evaluation signal that someone designed. A model may learn ways of pushing the score up, so truthfulness, task completion and risk still have to be checked independently, and a rising reward must not be equated with a gain in every capability.

SFT Continue supervised training with demonstration inputs and target answers.
Policy The probabilistic rule by which the model chooses its output in a given context.
Reference model the frozen baseline against which relative change is measured.
KL A quantity that compares the difference between two distributions; it is not a literal edit distance.

Why it is needed

Shapes instruction following and task behavior on top of existing language ability.

How to implement it

Keep the four objects — demonstration, preference, reward and reference policy — apart, and state which training objective is being used.

Possible costs and misreadings

A preference is not a fact; reward loopholes, distribution shift and over-converged behavior all occur.

How to tell whether it was done right

Keep independent tasks, different grading sources and the failure cases, and report the change in actual behavior.

One and the same "better" has at least three meanings

Language pre-training usually learns which token follows which in text; supervised fine-tuning, SFT uses task examples to teach the model how to answer; preference or reward optimization compares which behaviors fit a given objective better. These objectives may be related, but they are not the same loss.

The same word "better" has at least three meanings: the items distinguished
Object oneCorrectness: whether it matches the facts
Object twoPreference: which of two answers is better
Object threeReward: the score that forms the training signal

Key difference: Alignment methods often draw on human or AI preference, but a high preference score is no guarantee of factual truth.

Easy to misread: A reward model must not be treated as an external fact checker.

One answer may be preferred by the raters because it is clearer, or because it is more ingratiating. Where the score and factual correctness disagree, optimizing the score is no automatic guarantee of real capability.

Fix one main line that will not change

The worked model demonstrates next-token supervised training only. A real LLM usually learns the conditional distribution over a large body of text first, then goes on to instruction- or preference-related training. The stages differ, yet each still needs a forward pass, an objective function, gradients and parameter updates; "feeding it more prompts" is not post-training on its own.

Pre-training usually learns the predictive regularities of a broad corpus; supervised fine-tuning demonstrates how the model is wanted to respond, using the desired answers; preference methods compare different answers or use a reward signal so that certain behaviors come out more readily. Their training data, loss and sampling differ.

What DPO compares is not the bare size of two answer probabilities

DPO takes a preferred answer y⁺ and a worse answer y⁻ under the same prompt, and compares the difference in log probability relative to a reference policy. Definition:

a = [log πθ(y⁺|x) − log πref(y⁺|x)]
  − [log πθ(y⁻|x) − log πref(y⁻|x)]
L_DPO = −log sigmoid(βa)

π stands for the conditional probability of a complete answer, usually obtained by adding up the log probabilities of the answer's tokens; β is a loss setting, not Adam's β1/β2. sigmoid is 1/(1+exp(−u)), not a softmax over several candidates.

An independent numeric comparison: the reference model gives the preferred and the worse answer probabilities of 0.2 and 0.4; the current model gives 0.3 and 0.3, so a=ln(0.3/0.2)−ln(0.3/0.4)=ln2. With β=1, sigmoid(a)=2/3 and loss=−ln(2/3)≈0.405465. The two answers having equal probability under the current model does not mean there is no improvement relative to the reference.

Why RLHF and DPO cannot be swapped on the strength of one name

A common RLHF pipeline may include a reward model, policy sampling, advantage estimation, a KL constraint and policy optimization; DPO builds a direct optimization objective out of preference pairs, leaving out some of the explicit online RL steps. Different methods do not amount to "the model gets smarter if it explains at length", and the result in one paper cannot guarantee an improvement on an arbitrary engineering task.

The extra thinking tokens of a reasoning model are one way of using the inference-time compute budget; training that capability may use reinforcement learning or similar methods. The process of training the capability and the process of consuming more reasoning tokens at deployment have to be kept apart.

Which part LoRA actually trains

Let the frozen base weight be W[4,4], and let A[4,r] and B[r,4] express the increment ΔW=AB. The forward pass uses XW+s(XA)B; training updates only the selected parameters such as A and B, and W still takes part in the forward pass, but no update for it is computed or applied.

With r=1 that adds 8 numbers; it does not delete W's 16 numbers from the system. What is saved is the parameters chosen for updating together with their gradients and optimizer state; the base weights and the activations are still needed. If B starts at 0, A's first gradient can be 0 while B can still receive a gradient first; that alone is no reason to judge the implementation wrong.

Do not learn reward, policy and trajectory as a string of abbreviations

A policy is the probability rule for choosing an action given the current conditions. For a language model the action can be the next token; over one complete tool task, many actions make up a trajectory.

Key difference: A comparison has to share the same context conditions; a reward is not a lone number sealed off from reality.

Easy to misread: When preferences are compared across different tasks, comparability needs care.

A reward is a score given to a result or a step. Whether code passes a hidden test can serve as one reward signal, but if the test is too weak the model may "get around the exam question" without really meeting the goal.

Start with the objects and symbols used here
PPO,GRPO,advantage
These are concepts from policy optimization. PPO commonly limits the update with a ratio of new to old action probabilities, plus clipping; GRPO-style methods build the advantage by comparing rewards within a group. An advantage is performance relative to a baseline, not the probability that an answer is correct. Independent raw-difference example: rewards [0,1,1] minus the group mean of 2/3 give [-2/3,1/3,1/3]. An algorithm may normalize them again, so the two forms must not be mixed.

The advantage roughly expresses how much better one performance is than a baseline. If a group of answers has rewards [0,1,1], the mean is 2/3, so the raw differences from the mean are [-2/3,1/3,1/3]. A particular algorithm may also normalize these or use a different baseline, so this teaching difference must not be equated with every implementation.

What the probability ratio actually compares

The old policy gives some choice 0.1 and the new policy gives it 0.2, so the ratio of 2 says "relative to the old policy, it is more willing to make this choice". It does not say the choice is correct, nor that the whole system's performance has doubled.

What the probability ratio actually compares: the items distinguished
Approach / object AThe old policy πref
Approach / object BThe new policy πθ
Approach / object CThe probability ratio for the same reply

Key difference: Only the change in probability of the same reply under the two policies expresses a relative leaning.

Easy to misread: A probability ratio is not "the ratio of the lengths of the model's answers".

The probability of a whole answer can be formed by multiplying the next-token conditional probabilities. Multiplying many small probabilities together easily drives the value extremely small, so log probability is commonly used: multiplication becomes a sum of logarithms. When answers are compared, the effect of length also needs watching.

Why KL divergence is like a "do not stray too far from the original" constraint

Start with the objects and symbols used here
Σ: sum term by term over the subscript
Σ is shorthand for addition. The subscript says which term varies; a subscript that is not summed over stays fixed. It is not an extra parameter, and it does not mean concatenating arrays. Independent micro-example: Σᵢ xᵢyᵢ with x=[1,2] and y=[3,4] is just 1×3+2×4=11.

Given two distributions p and q over the same candidate set, KL divergence is commonly writtenΣ_i p_i ln(p_i/q_i). It measures the difference between p and q, and the result can differ with the direction.

Key difference: KL supplies one constraint on how far the distribution moves, keeping the pursuit of one kind of reward from pushing behavior too far.

Easy to misread: KL is not the character difference between two Chinese answers.

For example, with p=[0.5,0.5] and q=[0.25,0.75]:0.5ln2+0.5ln(2/3)≈0.1438. It is not the sum of the absolute differences of the two probabilities, and it is not a physical distance.

In training, a constraint of this kind can keep the policy from drifting too far from the reference model. A stronger coefficient tends to be more conservative, but the actual effect has to be evaluated; "a stronger constraint" is not an unconditional improvement in quality.

Explain the DPO formula with two answers first

There is one question, a preferred answer w and a worse answer l. What DPO compares is this: relative to the reference model, does the new model lean towards w rather than l? Write the log difference as:

Key difference: Preference methods such as DPO compare the relative standing of whole-reply probabilities under a given input.

Easy to misread: Do not take "the better answer" as the one correct label for the next token.

Start with the objects and symbols used here
sigmoid: maps a single number into the range between 0 and 1
The function rule is sigmoid(x)=1/(1+exp(-x)). It computes number by number and does not require one row of results to sum to 1, so it cannot stand in directly for a softmax over several candidates. Independent micro-example: sigmoid(0)=0.5; computing two zeros separately gives [0.5,0.5], which is only a coincidence — for the input [1,1] the two terms already sum to more than 1.
π, π_ref and β: the symbols of a preference objective
In policy and preference optimization, π denotes a conditional-probability policy and π_ref a fixed reference policy; β is a coefficient that sets the scale of the objective or the strength of the constraint. The probability of a complete answer is built from the conditional probability of each token.π here is not the circle constant, and β is not the LayerNorm offset parameter. The w/l in the DPO expression mark the preferred and the non-preferred answer, not a weight w and a layer count L.
s = β × [(lnπ(w)−lnπ(l)) − (lnπref(w)−lnπref(l))]
损失 = −ln sigmoid(s)
sigmoid(s) = 1/(1+exp(−s))

π is the current model's probability for a complete answer, πref is the reference model, and β is a coefficient that is set. If the current model gives w and l 0.2 and 0.1, the reference gives both 0.1, and β=1, then s=ln2, sigmoid(s)=2/3, and the loss is about 0.4055.

The formula takes its training signal from preference pairs, which does not mean that no "standard of better and worse" is needed at all. Nor can it be treated as a prompt trick that one API call will implement.

Why PPO and GRPO cannot be swapped on the strength of an abbreviation

Start with the objects and symbols used here
RLHF, the reward model and the policy
RLHF refers broadly to processes that train behavior using human feedback. A reward model scores behavior such as an answer; the policy is the probability model that actually produces actions. Their jobs differ, and a high reward is not automatically factual correctness. Independent example: if the reward model prefers long answers, the policy may learn to write at length without being more accurate; the reward criterion therefore needs to be validated.

PPO is a family of policy-optimization methods that commonly control the update with mechanisms such as the probability ratio between the new and the old policy, and clipping; some RLHF pipelines train a reward model and a value estimate. GRPO-style methods form the advantage from within-group comparison of several samples for the same question, and the implementation details and the reward design still matter.

"Outcome reward" judges the final result; "process supervision" judges the intermediate steps. A long intermediate process is not the same as a correct one, and extra reasoning is not free. Having got this far, read advanced Q021—Q086 next: you should be able to say where each quantity comes from, rather than only that "reinforcement learning was used".

Which two probability ratios preference training actually compares

Input and conditions. This starts a fresh set of teaching probabilities; it does not continue the 0.2/0.1 formula demonstration earlier in this section, and the two arrive at the same relative advantage independently. Binomial, standard error and the Wilson interval
The binomial model is commonly used for a fixed number of independent success/failure trials; the standard error describes the scale on which an estimator fluctuates; Wilson is one way of constructing an interval for a proportion. McNemar looks at disagreement in both directions among paired classification results. KL divergence: the same two sets of probabilities give a different value when the direction is swapped

Local check example: the input below follows the conditions listed for this example, and its intermediate values cannot be joined to the calculation record of the worked model.

Input and conditions. The distributions over two candidate words are p=[0.8,0.2] and q=[0.5,0.5]. Natural logarithms are used, and the computation follows KL(p||q)=Σpᵢln(pᵢ/qᵢ).
