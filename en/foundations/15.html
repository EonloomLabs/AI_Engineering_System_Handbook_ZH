Step-by-step figures · Lesson 52

A gradient is like a slope; the learning rate is like step size

Why does "gradient descent" sometimes make a parameter larger?

Imagine standing on the loss curve and wanting to go downhill. The gradient gives the local slope where you are; the update goes in the opposite direction. Where the slope is negative, going right is lower, so subtracting a negative gradient increases the parameter. It only guarantees local direction information for a small enough step; it does not guarantee that a step of any size is right.

Loss A number measuring how far the current prediction is from the target.
Gradient The local rate of loss change when a parameter increases slightly.
Learning rate A coefficient determining step size in the update direction.

Input and conditions of use: Use the main example with x=2, target 4, w=1 and squared-error loss. The first three frames use learning rate 0.2; the final frame explicitly resets w=1 and changes only the learning rate to 0.6.

Why it is needed

A large number of parameters has to be adjusted systematically, rather than guessing one new number at a time.

How to implement it

The forward pass computes the loss, backpropagation obtains the gradients, the optimizer updates, and then a new forward pass checks the result.

Possible costs and misreadings

Too large a step, a wrong gradient or a wrong way of accumulating can all send the loss up; lowering the training loss is not the same as improving performance on unseen data.

How to tell whether it was done right

Here the baseline loss goes 2→0.08; the large-step counterexample goes 2→3.92, and the gradient −4 is checked against a finite difference.

A derivative asks: if the input changes a little, how does the result change

For f(x)=x², the result at x=3 is 9. Change x to 3.01 and the result is 9.0601; the result increases by 0.0601 while the input increases by 0.01, a ratio of about 6.01.

Key difference: The local derivative is approached using "change in result / change in input" for a very small change.

Easy to misread: A slope taken over one large span cannot be used directly as the derivative at an arbitrary point.

As the change gets smaller and smaller, this ratio approaches 6, which is called the derivative of f at x=3. The formula df/dx=2x expresses "the local rate of change of x squared with respect to x". It is not a new input variable, and it is not f divided by x.

Local matters: a rate of change near 3 does not mean the same slope can predict accurately when x goes from 3 to 100.

Why training parameters needs a rate of change

The model gives a prediction, and we measure how far it is from the target with one number, called the loss. Training aims to find parameters that lower the loss. The gradient tells us, for a small increase in each parameter, which way the loss moves and how fast.

Why training parameters needs a rate of change: item-by-item distinctions
Object onePrediction y
Object twoTarget value y*
Object threeLoss L(y,y*)

Key difference: The training objective is not to maximize the predicted value, but to reduce the loss as it is defined.

Easy to misread: The loss has to be defined before there is any "which direction is better".

Start with the objects and symbols used here
∂, ∇: partial derivative and gradient
∂L/∂w asks how the loss L changes when w changes a little while the other independent variables are held fixed. These rates of change across many parameters make up the gradient ∇L. They are derivative notation, not two ordinary numbers divided by each other. Independent micro-example: for L=w², the gradient at w=3 is 6. In the simplest update w←w−η×6, η is the learning rate.

With only one parameter it is the derivative; with many parameters, lining up the local rates of change with respect to each parameter gives the gradient. The symbol∂L/∂w denotes the rate of change of the loss L when only w changes and the other parameters are held fixed for the moment.

Work one complete update by hand with a single parameter

Model预测=w×x, with x=2, target y=4 and initial w=1. The prediction is 2. Define the loss as L=0.5×(预测−目标)², which gives 0.5×(-2)²=2.

Key difference: The loss falls from 2 to 0.08; a negative gradient updates the parameter in the increasing direction.

Easy to misread: "Gradient descent" does not mean that every parameter value is bound to fall.

Now compute the rates of change along the chain:

w -> 预测=w×2 -> 差值=预测−4 -> 损失=0.5×差值²
损失对预测的变化率 = 预测−4 = -2
预测对w的变化率    = x = 2
损失对w的变化率    = -2×2 = -4

This is the chain rule: the rates of change of each small segment are multiplied together, carrying the influence back to the earlier parameters.

Let the learning rate be η=0.2, that is, how large a step is taken along the gradient each time. Using the simplest gradient descent:

w新 = w旧 − η×梯度 = 1 − 0.2×(-4) = 1.8
新预测 = 1.8×2 = 3.6
新损失 = 0.5×(3.6−4)² = 0.08

The loss falls from 2 to 0.08. Note that the gradient is negative, and subtracting a negative number increases w; "gradient descent" does not say that every parameter gets smaller.

First understand "the rate of change of the loss with respect to one number"

∂L/∂w asks: with the other independent parameters held still for the moment, how will L change if w alone is increased a little? It is not L divided by w, and it is not a new parameter value. A positive gradient means that locally increasing w increases the loss; a negative gradient means that locally increasing w lowers it.

An independent scalar warm-up, not using the worked model yet: the prediction ŷ=2w, target 4, loss L=0.5(ŷ−4)². At w=1, ŷ=2 and L=2. The rate of change of the loss with respect to ŷ is ŷ−4=−2, the rate of change of ŷ with respect to w is 2, and multiplying the two segments gives −4. With a learning rate of 0.2, w←1−0.2×(−4)=1.8, and the new loss is 0.08. This example only explains the chain rule; it does not replace M's AdamW training.

From one number to a whole table

If every cell of an intermediate table Z affects the total loss, the rates of change of all the cells are put together in the same shape, written G_Z=∂L/∂Z. This book does not use "dZ" for both a small forward change and a stored gradient, so as to avoid confusion.

The notation for the gradient table Gz is established here first. The next section, F16, works Gz[2,5,8] out from the ten correct labels and the actual average loss; lesson 55 of the system mechanisms then propagates that real gradient back group by group. Knowing the derivative of cross entropy before it has been explained is not required here.

Basis: tiny_model.py:117–130; Matching parameters, forward pass and gradient records.

Look at a single product first, then at the sum

For the single row z_v=Σⱼ F_j U_jv: changing U[j,v] changes only this one term, and the rate of change is F_j; changing F_j may change all eight candidates, so their separate effects on the loss have to be added up. Hence:

∂L/∂U[j,v] = Σ_b Σ_t F[b,t,j] × Gz[b,t,v]
G_F[b,t,j] = Σ_v Gz[b,t,v] × U[j,v]

The first expression sums over samples and positions, over all the points where a shared parameter is used; the second sums over vocabulary candidates, gathering the effects back into the same hidden feature. The axes they accumulate along are different.

Basis: tiny_model.py:117–130; Matching parameters, forward pass and gradient records.

How addition, reuse and branching pass the gradient on

If H=R+D, R and D each have a direct derivative of 1 with respect to H, so G_H passes to both routes. If R is also the input to D, then R finally receives two contributions, one "straight down the main path" and one "through the D branch", and they have to be added.

If a parameter is used in two places, the effects along each path have to be accumulated too. A repeated token using the same embedding row, several positions sharing a W, several losses depending on the same position — all are relationships of this kind. Automatic differentiation handles this reuse along the graph; it is not "each parameter learns once from one token".

How automatic differentiation, finite differences and backpropagation relate

An automatic differentiation framework stores the dependencies between operations and applies local derivative rules; backpropagation is one efficient way of computing these effects. Finite differences, by contrast, actually compare L(w+δ) with L(w−δ), estimating the derivative by dividing by 2δ, which suits checking a small model and is not suited to training a billion parameters.

These three are not three different training objectives. The program shipped with this book first writes the analytic backward pass for the whole model by hand, then compares it with PyTorch autograd parameter table by parameter table, and also applies finite differences to selected parameters. They have to be compared under the same structure, the same input, the same loss denominator and the same parameter snapshot.

Basis: tiny_model.py:117–130; Matching parameters, forward pass and gradient records.

Backpropagation and the optimizer are not the same step

Start with the objects and symbols used here
Optimizers, Adam and AdamW
An optimizer turns gradients into parameter updates. Adam also keeps, for every parameter, a moving average m of the gradient and a moving average v of the squared gradient; these are training state, not attention values. AdamW decouples weight decay from the adaptive gradient update. Independent first-step example: with g=2, old m=0 and β₁=0.9, the new m is 0.2, and after bias correction m_hat=2. The 0.2 cannot be taken as the full size of the update.

Backpropagation computes the gradient of each parameter backwards along the computational dependencies; the optimizer takes those gradients and updates the parameters by its own rule. Running backward does not necessarily mean a parameter update has already happened.

Key difference: Backpropagation computes rates of change; the parameter update happens in the optimizer step.

Easy to misread: Calling backward does not necessarily mean the weights have already been modified.

A computational graph is a record of the dependencies, of which operations produce which results. An automatic differentiation system applies known derivative rules according to that record; it does not actually try countless tiny perturbations for every parameter.

When the same parameter is used in several places, the effects of each path of use on the total loss have to be combined. If the code accidentally cuts the computational graph, or forgets to clear the gradients accumulated in the previous round, the gradients may not match the intent of this training run.

How finite differences check an analytic gradient

It can be computed approximately as [L(w+ε)−L(w−ε)]/(2ε), where ε is a very small positive number, and compared with the gradient obtained from backpropagation. This is called a finite-difference check.

Key difference: A numerical perturbation is used to verify a derivative formula, which suits small models and debugging.

Easy to misread: If ε is too small it is affected by floating-point error, and if it is too large it is not local enough.

It suits small-scale debugging and is not suited to computing a billion parameters one by one. Too large an ε makes the approximation insufficiently local; too small, and floating-point rounding error becomes important. ReLU also needs special handling at its kink. So "the two numbers are not exactly the same" is not necessarily an error; a reasonable input and tolerance have to be chosen.

Why gradients vanish or explode

Many rates of change smaller than 1 multiplied along the chain can make what travels back smaller and smaller; many rates of change greater than 1 can make it larger and larger. The network structure, the normalization, the initialization and the optimization strategy all affect this.

These are real computational and numerical problems, not a case of "the model being too lazy to learn". Recognizing this is what makes it clear, when reading the deeper derivation of the attention backward pass and of training stability, what the formulas are trying to solve.

Compute one gradient, then see whether the loss really falls

Input and conditions. This is an independent training example, and it does not carry over the example conditions earlier in this section, "target y=4, loss with a 0.5". Here the model is y=w×2, y=6 is wanted, and the initial w=1. The loss is set explicitly as (y−6)²(with no 0.5 factor), and the learning rate is 0.1.

Steps and objectsInternal actionIntermediate result / new state
1 Forward pass firsty=1×2=2Loss (2−6)²=16.
2 Differentiate the loss with respect to y2(y−6)That gives −8, which says that increasing y a little helps lower the loss.
3 Pass it back to w through the multiplicationdy/dw=2Gradient dL/dw=−8×2=−16.
4 Update the parameterw_new=1−0.1×(−16)w becomes 2.6.
5 Forward pass againy=5.2New loss (5.2−6)²=0.64, which really is smaller than 16.

Join the steps up. Backpropagation finds the local information of "where to change and which way"; the optimizer carries out the parameter update. The two are not the same action.

Limits and counterexamples. Switching to too large a learning rate can overshoot the optimum and raise the loss; the decrease in this example is no guarantee that every step decreases.

No. It computes and accumulates the gradients. Only a later update operation such as optimizer.step() changes the parameters. Conversely, forgetting to clear the gradients can let the gradients of several steps accumulate unintentionally.
