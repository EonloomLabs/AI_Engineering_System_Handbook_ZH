What does an inverted index help with, and what does a vector index help with?

An inverted index is like the index at the back of a book: from one word you jump to the pages that contain it. Vector retrieval instead tries to place content worded in similar ways close together, which helps find candidates when you do not know the exact name. Neither of them confirms permissions, versions or factual correctness for you; the evidence still has to be read and checked.

Index A data structure built to find candidates quickly.
Recall Find potentially relevant candidates in a large collection.
Approximate search Check fewer candidates for speed, potentially missing true nearest neighbors.

Input and conditions of use: The three documents are constructed for this book; the inverted relationships can be checked exactly. Semantic search only illustrates the process, without inventing measured scores from a vector service.

Retrieval first answers "where to find candidates"

Retrieval finds items that may be relevant to a question among a collection of material. An index is an organizational structure prepared for this purpose, like the word index at the end of a book, but it can include positions, statistics and permissions.

Key difference: retrieval is only the first half of finding evidence; a relevant passage may not be enough to support a specific conclusion.

Easy to misread: do not treat a retrieval score as a measure of factual truth.

Offline indexing means preparing material and indexes before a query arrives; it does not mean the machine must be disconnected from the network. Online querying means retrieving when a user's question arrives; it does not necessarily mean accessing the public internet either.

The original organization is "document → words it contains". The inverted organization becomes "word → documents it appears in". For example:

Easy to misread: synonymous expressions that do not match may need semantic retrieval as a supplement.

A search for "directory exclude" can first visit the document lists for these words, without reading all documents from the beginning every time. Exact error codes, function names and configuration keys are often a good fit for this kind of term matching.

Start with the roles of TF, IDF and BM25

Start with the objects and symbols used here
TF, DF, IDF: term statistics
TF counts how often a term occurs in the current document; DF counts how many documents contain it; IDF uses whole-corpus statistics to lower the contribution of common words and raise that of rarer, more discriminating ones. All three are statistics, not the model's learning rate. If only 2 of 10 documents contain a word, DF=2; if the word occurs 3 times in one of them, TF=3 for that document. The two numbers are not interchangeable.

TF (term frequency) describes how many times a term appears in a document. DF (document frequency) describes how many documents contain the term; IDF (inverse document frequency) usually gives greater weight to rare terms that distinguish documents more strongly.

Start with the roles of TF, IDF and BM25: item by item
Object oneTF: how often the term appears
Object twoIDF: how rare the term is
Object threeBM25: combines term matches

Key difference: term frequency and rarity help with ranking, but they do not score the truth of the article's content.

Easy to misread: a BM25 score is not inherently a probability from 0 to 1.

If every document says "description", this word does little to distinguish the target; if only a few documents contain a particular error code, that code is more useful for locating it.

Start with the objects and symbols used here
BM25 and N, df, k₁, b
BM25 is a scoring formula for term-based retrieval. In the usual notation N is the total number of documents, df the number of documents containing the term, tf the term frequency in the current document, |D| the length of the current document and avgdl the average length; k₁ and b are the settings for term-frequency saturation and length correction. k₁ is not the Key vector k₁, and b is not a neural network bias. The score only orders candidates; 8.2 cannot be read as 82% accuracy.

BM25 combines term frequency, rarity, document length and other factors into a ranking score. The gain from term frequency often saturates: 10 occurrences need not have 10 times the value of 1 occurrence; the effect of length must also be considered for longer documents. Advanced Q058 expands the full formula term by term.

A ranking score is not a probability. A BM25 score of 8.2 does not mean 82% correctness, nor does it guarantee that scores from different queries can be compared directly.

Why vector retrieval can find synonymous expressions

A retrieval model turns a question or document into a row of numbers, aiming to place related content closer together in vector space. A query for "program crash" can therefore match a document saying "abnormal process exit" even though the words differ.

Key difference: vector retrieval can find material with different wording but similar meaning, but it is affected by the embedding model.

Easy to misread: nearby vectors do not mean the document actually answers the question.

One of the most common comparisons is cosine similarity: the dot product divided by the product of the lengths of the two vectors. Length is the square root of the sum of squared components, or the norm. If x=[1,0] and y=[2,0], the cosine is 1; if y=[0,1], the cosine is 0. Zero vectors need special handling; division by zero is not allowed.

This compares the directions of representations; it does not automatically determine factual logic. "Access allowed" and "access not allowed" may concern very similar topics but reach opposite conclusions.

Exact and approximate nearest neighbors

Nearest neighbors are the vectors ranked highest by the chosen distance or similarity. Comparing all N records one by one gives an exact result, but the cost is high at very large scale.

Key difference: ANN gives up some retrieval accuracy for performance at scale; it should still be evaluated on the specific data distribution.

Easy to misread: with very strict filters, there may be too few candidates after ANN.

Start with the objects and symbols used here
ANN and HNSW: approximate retrieval structures
ANN here means approximate nearest-neighbor search, not artificial neural networks in general. HNSW is a structure that narrows the search using a hierarchical graph of near neighbors; its parameters affect recall, speed and memory. Finding something quickly is no guarantee of finding the exact nearest neighbors; nor does ANN recall equal the correctness of the final answer.

ANN (approximate nearest neighbors) uses additional structures to reduce the search space, giving up some recall for speed. HNSW navigates a hierarchical nearest-neighbor graph: first it jumps toward a nearby region in a sparser layer, then it expands the candidates in finer layers. The advanced chapters explain the process in detail.

An approximate algorithm's "recall" measures whether it finds all the exact neighbors, not whether an answer is factually correct; these are two different levels of evaluation.

Why chunking, cleaning and versions come before ranking

Long documents are usually split into chunks (content fragments). Chunks that are too small may lose conditions and exceptions; chunks that are too large may include much irrelevant content. Headings, table headers, applicable dates and code scope may all need to accompany a chunk.

If an old rule has not been deleted or marked invalid, even excellent retrieval may find it accurately. If unauthorized content has already been given to the model, hiding its citation at the end may still allow a leak. Index structure, permissions and versions together determine which candidates may be used.

Connecting the ideas

How one document becomes two kinds of index

A document is parsed first, then split into chunks. A lexical index records where terms occur; a vector index maps chunks into comparable vectors. A chunk ID should lead back to the source document, version, permissions and position. A query vector having the same length as the index vectors only shows shape compatibility; it does not show that they come from the same model space. Changing the embedding model usually requires matching re-encoding and an index switch.

Once this page's concrete objects are clear, go on to the system mechanism: Relevant is not the same as usable: from recall to evidence closure. Knowing the full source first is not required; being able to retell from the state table what happened at each step is.

Evidence and the limits of understanding: a high rank does not mean the evidence covers the question. The small RRF worked example in this book is not an official production query; chunk context and the original evidence have to be kept apart.

Self-check 1

Are an inverted index and a vocabulary the same thing?

Show the answerHide the answer
No. A vocabulary maps tokens to IDs; an inverted index maps terms to documents or positions containing them. They serve different purposes.
Self-check 2

If vector cosine similarity is very high, can we directly confirm that two sentences reach the same conclusion?

Show the answerHide the answer
