A mask is a visibility table, not extra meaning

How do you keep it from reading the future, or from reading PAD as content?

Read attention's score table as a seating plan of "who may read whom". Rows are the receivers and columns the providers; a forbidden cell may not take part in the probability denominator. The causal restriction and the PAD restriction can both be present, but one is responsible for time order and the other for valid content, and neither can stand in for the other.

Causal the current position does not read future positions.
Additive mask adds 0 where it is allowed, and excludes equivalently with −∞ where it is forbidden.
Absolute position The position once the earlier prefix is counted, not the row number in the current mini-batch.

Input and conditions of use: The first three frames use three valid positions; frame 4 is an explicit comparison with the masked values; frame 5 sets past=3 and new=2 separately to show the cache offset. The current conditions are marked in the figure throughout.

Position is not a contest of numeric size. The causal rule lets the current query read only itself and earlier keys; later positions cannot be read even when they are already in the training input array.

Why it is needed

Stops training from peeking at the target, and leaves out the padding that exists only for batching.

How to implement it

Build the relation from the actual positions and the valid lengths first, then check the boolean mask semantics of the API being used.

Possible costs and misreadings

True can mean allowed in one API and forbidden in another; a row with no visible key at all needs an explicit policy, and plain softmax must not simply be applied.

How to tell whether it was done right

Using data that can expose leakage from the future, compare the result of the correct mask with that of a deliberately wrong offset.

Start with a definition of the mask that is not mysterious

A mask is a marking that controls which elements may take part in an operation. In attention, a row is a query position and a column is a position being read. A cell therefore answers "may this row read this column".

Start with a definition of the mask that is not mysterious: item-by-item distinctions
Object oneA mask is a table of rules
Object twoAn attention score is the model's computation
Object threeValue is the content mixed in

Key difference: a mask does not stand for new meaning; it limits which positions' scores can take part in the softmax.

Easy to misread: taking a mask for a new word vector confuses the rule with the content.

Padding markers, attention readability and the positions scored by the training loss can all be called a mask, yet they are put to different uses. When you see the word mask, ask first what it controls, rather than just memorizing a set of 0s and 1s.

How the causal restriction prevents reading the future

For three positions 0, 1 and 2, the usual allowed relationship in the causal attention used by autoregressive training and inference is:

Key difference: a causal mask forms a lower-triangular "visibility table" that stops future information from leaking.

Easy to misread: with a real cache, alignment must follow absolute position, not reuse the upper-left triangle mechanically.

Query position \ key position 0 1 2
0 Allowed Forbidden Forbidden
1 Allowed Allowed Forbidden
2 Allowed Allowed Allowed

It is called "causal" because the current position cannot depend on later tokens that have not happened yet, not because the model is claimed to have learned causal relationships in the real world. During training the whole answer can be fed in at once; the mask limits each position to its prefix, and the target is usually to predict the next token.

Why the whole sentence is in memory and yet the answer is not peeked at

Feeding every input position to the device at once is for parallel computation. The causal mask lays down that row t can read only the positions s≤t as its keys. At row t=2, which predicts 学习, the 学习 at t=3 is in the same batch of tensors but cannot be read by this row through attention. The per-position RMSNorm and FFN do not mix across positions either, so there is no detour through those modules to peek at the future.

Having the data ready at the same time is not the same as every position being able to read all of it

Do not merge PAD, the attention mask and the loss mask

Both training inputs in this book are 5 long, so there is no PAD for the moment. To handle different lengths another implementation can pad, and then three things have to be right separately: not reading the padding keys, recording the semantic positions correctly, and keeping the padding labels out of the loss. Not computing loss on PAD does not automatically forbid other tokens from reading PAD.

This implementation uses ignore_index=-100 to ignore a loss label; -100 is not a vocabulary item and cannot be used to look up an embedding. Some libraries shift the labels automatically inside, so read the interface's contract when using them, and do not shift already-shifted labels a second time.

Basis: tiny_model.py:14–21; Matching parameters, forward pass and gradient records.

How the padding restriction and the causal restriction go together

Continuing with the second input [4,2,0]. The first two positions are real content and the third is PAD. For the real queries 0 and 1, a readable column has to satisfy both "not PAD" and "not in the future". Their relationship is:

How the padding restriction and the causal restriction go together: item-by-item distinctions
Approach / object AValid tokens: 1,1,1
Approach / object BPAD positions: 1,1,0
Approach / object CThe intersection of the causal and the PAD restriction

Key difference: the two masks restrict for different reasons and can exist at the same time.

Easy to misread: the allowed set is what both allow at once, not a sum that automatically widens the range.

query0 -> key0允许，key1禁止，key2禁止
query1 -> key0允许，key1允许，key2禁止

A PAD query row is not itself a meaningful output this time: it is not used to carry on generating, and its prediction is not counted in the normal loss. How a real kernel avoids the numerical problem of a fully masked row has to follow the semantics of the interface; do not blindly fill a whole row with negative infinity.

Batched input also has sample boundaries: sample 0 must not read sample 1 merely because they share a batch. If several samples are packed into one sequence, the cross-sample readability has to be handled separately; inserting an end token on its own does not create isolation in the matrix by nature.

What "forbidden" actually does to softmax

One common way to express it mathematically is to add negative infinity to the score at a forbidden position, so that its exponential is 0, and to add 0 at an allowed position, keeping the original score; one row is then normalized.

Key difference: the exp of a forbidden entry becomes 0, and the remaining entries are then renormalized.

Easy to misread: when every entry is forbidden there is a risk of an invalid normalization, which has to be handled specially.

Running softmax over every position first and then zeroing the forbidden entries without renormalizing leaves the remaining weights summing to less than 1, which is usually not the attention that was wanted.

When a whole row has no allowed entry, softmax has no ordinary finite candidates to normalize over, and a naive computation may produce NaN, that is, "not a valid number". An engineering implementation has to handle or avoid such a row explicitly, rather than letting a NaN quietly travel on.

A different API may use boolean True for allowed, or for masked out, and may also accept an additive floating-point mask. Do not take the 1=allowed of this text as any library's general boolean convention.

Why the table is no longer a small square once there is a cache

Start with the objects and symbols used here
Query, Key, Value: three intermediate numeric representations
q is one row of query representation for the position receiving information; k is one row of matching representation offered by a readable position; v is one row of content representation that position contributes to the mix. Capital Q/K/V collect several rows into tables. They are computed from the input and the parameters, and they carry the separate jobs of scoring and of supplying content. One q dotted with two k gives two scores; softmax turns them into two shares; those shares multiply the two rows of v, and the results are added. Nothing here generates a search term, and nothing here picks an answer directly.

For now, take a cache to be "intermediate results computed earlier"; the details are in F19. Suppose 3 past positions are already there and 2 new positions are being computed. There are only 2 queries this time, but 5 keys can be read:

Key difference: each new query can see its own absolute position and the earlier ones; it does not see only the upper-left 2×2.

Easy to misread: the shape can be right and the alignment still wrong, especially when the Q length and the K length differ.

新位置3：[允许，允许，允许，允许，禁止]
新位置4：[允许，允许，允许，允许，允许]

So the table is [2,5]. The first row does not read only the first column, because its real position is already 3. The rule is "the logical position of the key is not greater than the logical position of the current query", not simply drawing a little triangle in the upper-left corner of a 2×5 table.

And what is a loss mask

When a training sample contains both a question and an answer, loss may be computed only for the next-token predictions in the answer part. loss mask decides which predictions are scored; attention mask decides which conditions are read. Not computing loss on the user's question does not mean the model cannot read it.

This difference is used later to explain training: the model can use the question to predict the answer, even when the question itself is not what this batch scores directly.

Follow-up: training already knows the answer, so why is a causal mask still needed?

What knows the answer is the training data and the loss computation; the forward pass responsible for the prediction at a position cannot read the future token it is supposed to predict. Otherwise training would depend on information that is not available at inference, and a low loss would not mean the real autoregressive prediction is good.
