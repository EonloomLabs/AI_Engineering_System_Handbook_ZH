Start from concrete objects and small examples, to understand the computation and the conditions under which it applies.

Along the same four-dimensional worked model, this joins the current input, the three parameter tables, the read shares and the mixed result into one complete chain of computation. The initialized parameters are still in use here; training updates come in later Foundations lessons.

This section first fixes six objects

Input X=E[input_ids]+P[position_ids] is "token representation + position representation"; N1=RMSNorm(X) is the normalization result already computed in the previous lesson. Wq、Wk、Wv are three different trainable coefficient tables, each of shape [4,4]. Multiplying the same row of N1 by each of them is what produces the Q, K and V of this run. A parameter table is not the shares of which positions are currently read; the shares are computed separately, once Q and K have been matched.

Below, training input 0 is fixed as [BOS,我,爱,学习,！], and position 2, 爱 ("love"), is the one watched. That row can read only the three positions 0, 1 and 2; 学习 and ！ are in the tensor, but the current position is not allowed to peek at them. Every number comes from the same set of initialized weights, and is not mixed with the two-dimensional demonstration or with weights after training.

What problem it is trying to solve

A token is first turned into a row of numbers by the embedding table, but that is not enough. "Apples taste good" and "Apple released a computer" have to draw on different contexts. Attention is a stretch of numeric computation: for the current position it computes how much information to take from each readable position, and then mixes the information by those shares. It is not the model's eyes, and it is not three more agents that talk.

Hold on to two things first: what is used to score the matching, and what is actually taken to be mixed once the scoring is done. Query, Key and Value are simply the numbers that carry those two separate jobs. What follows gives where they come from, and then works the whole process out. Source: the mechanism described in the original attention paper.

What each of query, key and value does

Now connect the names to the objects:

Name What object it is Its job in the current computation What it is not
Query, the query vector q A row of numbers produced by the position currently receiving information Compared with the key at each position, to score "how much to read" Not a question typed by the user, and not a search string
Key, the key vector k A row of numbers produced by each readable position Takes the query's comparison, supplying the matching features for this position Not a cryptographic key, and not a keyword lifted straight out of the text
Value, the value vector v Another row of numbers produced by each readable position Once the shares are fixed, supplies the content that actually enters the weighted sum Not the correct answer, and not the final output token

One position can be a receiver and a supplier of information at the same time. When the new representation for position 2, 爱, is computed, for instance, its query is compared with the keys of BOS, 我 and 爱, and the values of those three positions are then mixed by the resulting shares.

Lowercase q, k and v are one row; uppercase Q, K and V are the tables made by laying out every position's own row. In the worked model each table has shape [2,5,4]: two samples, five positions, four features per position. They are intermediate representations obtained from the same N1 through different parameter transformations.

So the three computations are:

Q = N1 @ Wq     归一化表示 × 查询参数表 → 所有位置的查询表示
K = N1 @ Wk     归一化表示 × 键参数表   → 所有位置的匹配表示
V = N1 @ Wv     归一化表示 × 值参数表   → 所有位置的内容表示

"Split into three sets of parameters" does not mean the mathematics forbids them from happening to be equal. Some teaching cases do set them to the same matrix, and some research architectures share parameters too. But the usual separate design lets the three paths learn different transformations. Whether the numbers are the same, and whether they are shared, has to be read off the particular example or model.

What exactly is in hand when this step begins

We already have the whole batch X, and the first normalization N1 was computed in the RMSNorm example of F10. There is no user-question string "Query" here, no database key "Key", and no final answer "Value"; all that is in hand are tables of numbers. To compute "which positions the current position reads, and which features it takes back", the model multiplies that same N1 by each of three parameter tables.

ObjectSourceShapeWhat it does
WqA parameter that is initialized and then trained[4,4]Turns the current features into a query
WkA second, independent parameter[4,4]Turns a readable position's features into a key
WvA third independent parameter[4,4]Turns a readable position's features into a value
Q / K / VThis run's result of multiplying N1 by each of the parameters above[2,5,4] eachUsed, respectively, to score, to be compared, and to supply the content for mixing

The subscripts q, k and v on the parameters are only names for their use; they do not mean multiplying by another lowercase letter. Here Q=N1Wq, not X multiplied by Wq without normalization. Some conceptual formulas call "the representation fed into attention" X across the board, which can leave a reader thinking it must be the original embedding; this book always says which table it is.

Why it is not three copies of the original row of numbers

The three parameter tables differ, so the feature combinations they produce differ. The model can learn separately which features suit judging relevance and which suit passing information on. The division of labor is fixed by the computation path; what the particular numbers do is formed by training — an engineer does not hard-code "syntax", "subject" or "emotion" into some dimension.

"q is like a request, k like the matching tag on the thing being looked up, and v like the content that can be read" only explains the division of labor. Nothing actually generates a search term in words first, and nothing looks up a database key by an exact string match. What comes next is a dot product giving continuous scores, and then several values mixed by their shares — not one single hit taken on its own.

Basis: tiny_model.py:63–66; Matching parameters, forward pass and gradient records.

The difference between one row and the whole table

At row t=2 of sample 0, one q is compared with every visible k of that sample. The other positions, meanwhile, each have a q of their own; stacking all the q together is what makes Q. The batch axis of Q/K/V must not cross over: sentence 0 cannot read sentence 1. For a single head, note the shape for now as [B,T,d], and when multiple heads are introduced it is split explicitly into [B,H,T,d_head].

Basis: tiny_model.py:63–66; Matching parameters, forward pass and gradient records.

What the self in self-attention refers to

It means that Q, K and V come from the representation of one and the same sequence; it does not mean each position can see only itself. In a causal decoder, seeing only itself and earlier positions comes from an additional causal mask. Cross-attention can have Q from one sequence and K/V from another, a different relationship between the data sources, so this model's cache is no proof that it carries over unconditionally.

Basis: tiny_model.py:63–66; Matching parameters, forward pass and gradient records.

Putting the two kinds of "axis" on the table first

The q at the current position t=2 has 4 features. Every visible k has 4 features too. The four features are dotted along the feature axis, giving the score for one pair of positions; the different pairs form a row of scores, and softmax then runs along the key-position axis. The two sums run over different ranges.

The five positions of the first input are BOS, 我, 爱, 学习 and ！. Row 2 is building the representation for the prefix "BOS 我 爱", so s=0, 1 and 2 may be read and s=3 and 4 are forbidden.

The first score is not a guess

dot(q[t=2], k[s=0])
= (-0.106447)×(-0.532036) + (0.15967)×(-0.453216) + (-0.65997)×(0.177345) + (-0.393853)×(-0.394101)
≈ 0.022444

The four products are added and then divided by 2. Dividing by sqrt(d_key) controls the scale of dot-product scores as the dimension grows; it does not turn the scores into probabilities. A real network does not always strictly satisfy the independent-and-identically-distributed conditions of that intuitive derivation, yet this implementation still scales once, by the stated formula.

Mask the future first, then normalize

In this model the allow table is defined as allowed[t,s] = (s≤t). The score of a forbidden entry is set to negative infinity, so that its exponential contributes 0. It is not a matter of multiplying a forbidden score by 0: were it turned into 0, exp(0)=1, so it would still be given a share.

The shares answer "where to read from", not "what the answer is"

This row has three non-zero shares, for the values at BOS, 我 and 爱. It makes no choice among the 8 vocabulary candidates, and it is not a confidence that the model's answer is right. Predicting 学习 still has to pass through the mixing, the output projection, the residual, the feed-forward network, the final normalization and the vocabulary head.

Two error boundaries to know from the very start

If a whole row is masked, an ordinary softmax implementation meets the undefined numbers that all-−∞ produces. Do not expect "it automatically becomes all zeros" to be guaranteed by every interface; this implementation rejects such input explicitly.

Libraries can take the opposite convention for a boolean mask. Here True means allowed, which is also the convention of PyTorch SDPA; another interface may have True mean forbidden. Confirm it with a very small two-position counterexample before handing over a large tensor. The matching derivation under System mechanisms checks another kind of misalignment in a non-square cache mask.

Basis: tiny_model.py:68–80; Matching parameters, forward pass and gradient records.

This is not another embedding lookup

We already have the value table produced by N1×Wv, and the read shares A just computed in this section. What takes part in the mixing is the Value of the current layer, not the original token IDs and not the original characters. Each row of Value is 4 wide; after mixing for one query it is still 4 wide.

Basis: tiny_model.py:81–84; Matching parameters, forward pass and gradient records.

Every output feature is mixed with the same shares

For t=2 the five position shares are [0.376593, 0.297862, 0.325545, 0, 0]. For cell j of the mixed output:

mix[t,j] = A[t,0]×V[0,j] + A[t,1]×V[1,j]
         + A[t,2]×V[2,j] + A[t,3]×V[3,j] + A[t,4]×V[4,j]

The shares are arranged by source position s; cell j takes the same feature j from each row of Value. The share of a forbidden position is 0, so its value contributes nothing this time.

≈ -0.445025

Why the result is not "a word has been selected"

As long as several shares are non-zero, several positions can contribute together; values are both positive and negative, so contributions to one feature can cancel. The largest share is not the largest contribution in absolute value, and it certainly cannot explain the final answer on its own. What comes out here is a new four-dimensional numeric representation, not a discrete token.

Basis: tiny_model.py:81–84; Matching parameters, forward pass and gradient records.

self does not mean "look only at itself"

In the worked model Q, K and V are all produced from the N1 of one and the same sequence, which is why it is called self-attention. Each position can still read the other positions the rule allows. "self" speaks of where they come from, not of being able to see only itself.

Cross-attention, by contrast, can have the query come from one sequence and the key and value from another. A translation system, for instance, uses the target-side representation it is generating to read the representation the source-sentence encoder supplies. Two inputs like this are a different structure, and the same-X formula above must not be quietly substituted in.

Decoder is a class of network structure responsible for generating the following tokens step by step; Encoder is a class of structure that turns a given input into a representation. Here we only get to know their jobs; the actual network structures are opened up in Systems. The causal read rule comes from the design of the generation task; it is not a function the letters Q/K/V carry with them.

Why three sets of representations are needed instead of comparing and mixing X directly

Matching on the raw X and mixing X directly would amount to restricting how the matching features and the content read can be transformed. Three projections let the model learn "how to receive", "how to be matched" and "what content to supply" separately. This is a design choice between expressive power and parameter count, not a claim that the mathematics of every task requires three distinct tables.

Two explicitly separate comparisons can be made along this example, each returning to this section's baseline first:

Comparison Held unchanged What alone is changed The predictable effect
Change the content read X,Wq,Wk Multiply the whole of Wv by 2 The current Q/K and the read shares are unchanged, and the whole of the current O is multiplied by 2
Change the matching rule X,Wk,Wv Alter one coefficient in Wq The query may change, and so may the shares and the mixed result

"The shares are unchanged" applies only to this one attention branch; once the output changes, the layers after it may change with it. A local comparison must not be stretched into the rest of the model never being affected.

During training the error travels back along the computation dependencies "O→A and V→Q and K→each W", adjusting the coefficients. The gradients in F15 and the optimizer in F16 will show how the update is computed. For now it is enough to keep them apart: W holds rules that can be learned; Q/K/V hold the result of applying those rules to this input.

Before going on to multiple heads, scaling and the source code

One head is a single computation path of "match query to key, then mix value". Multiple heads use several such paths and combine their results; it is not the model opening several chat windows at once. Once the results of the heads are laid side by side, they can be multiplied by another parameter table, Wo, which converts the mixed result back to the width the main network needs. Wo is the attention output projection, not the language model output head that finally scores the vocabulary candidates.

Dividing by √d_k controls the scale of the dot-product scores. The derivation needs variance, and F14 explains that statistic first; it is not a necessary part of the definition of softmax, and it does not change the number of candidates. To learn this step by step, treat it in this section as a fixed scaling rule for this example, and press for the reason behind it in Q007.

Some libraries' high-level attention interfaces also name the input before projection query/key/value, and multiply by W only internally; other low-level interfaces take Q/K/V already projected. The same name does not mean the same stage of computation. Before reading source code, check whether the interface is responsible for the projection, so that you do not multiply by W once yourself and have the library multiply again. PyTorch's linear layer also stores its parameters as [输出宽度,输入宽度] and transposes them when computing; the hand calculations in this book use the [输入宽度,输出宽度] right-multiplication convention, and the two can express the same transformation once transposed. Basis for the interface and the shapes.

The numbers above carry on from unrounded results; the decimals on the page are for display only. You can watch the intermediate values with this section's parameter experiment, or recompute them by running the packaged concepts/verify_concepts.py. It verifies the teaching formulas and their premises; it does not prove that a real model has learned Chinese.

An independent two-dimensional check: not the next step of the four-dimensional model above

The full matrix formula for the two-dimensional comparison

An independent two-dimensional model is set up afresh below, with no normalization and no position representation. Fix X=[[1,1],[1,-1]], Wq=[[0.5,0.5],[-0.5,0.5]], Wk=[[0.5,0.5],[0.5,-0.5]] and Wv=[[5,10],[5,-10]]; two receiving positions are computed from these new conditions. It does not continue the four-dimensional run above:

Q = [[0,1],        K = [[1,0],        V = [[10,0],
     [1,0]]             [0,1]]             [0,20]]

QKᵀ = [[0,1],     行：接收信息的位置（Query）
       [1,0]]     列：提供信息的位置（Key）

The superscript ᵀ means transpose: each of K's original rows becomes a column, so that all the "query row with key row" dot products can be computed at once. It is not the sequence length T, and it is not K raised to a power.

Position 0, 我, cannot read the 爱 that lies in the future. Negative infinity is added at the forbidden score positions, written −∞, whose exponential is taken as 0 in the limit. 0 is added at the allowed positions. Call this kind of additive mask table M:

M = [[0,−∞],      第0行只能读“我”
     [0, 0]]      第1行能读“我”和“爱”

S = QKᵀ/√2 + M = [[0,−∞],
                   [0.7071067812,0]]
A = 每行softmax(S) ≈ [[1,0],
                      [0.6697615493,0.3302384507]]
O = AV ≈ [[10,0],
          [6.6976154933,6.6047690135]]

S is the score table, A the read-share table, and O the table of mixed output. All three are results of this computation, not model parameters loaded from somewhere else. Row 0 has only one legal position, its share is 1, and so its output is simply its own value.

Only all these actions together are written as this compact formula:

Q=XWq，K=XWk，V=XWv
O=softmax(QKᵀ/√d_k + M)V
Symbol What the object is Shape in this example How it is obtained in this inference
X This input's representation [2,2] Supplied by the previous step
Wq/Wk/Wv The three projection parameter tables each [2,2] Preset for this example; in practice the trained parameters are loaded
Q/K/V Three sets of intermediate representations each [2,2] X multiplied by each matching W
M The constraint on readable positions [2,2] Built from the sequence, the positions and the read rule
S Each row's score against each column [2,2] Q dotted with K, scaled, plus M
A Each row's read shares [2,2] softmax over S along the key columns
O The new representation of each receiving position [2,2] A times V

Every shape in this example happens to be the same, which is no ground for deciding that all the objects are interchangeable. In general a single head has n queries and m keys, with Q [n,d_k], K [m,d_k], and V [m,d_v], so the scores and the shares are [n,m], and the output [n,d_v]. d_v is how many numbers each value has, and need not equal d_k; it is the lengths of query and key that have to pair up for the dot product.

What follows checks the local mechanism of "score — share — mix" using just two features. Its input and parameters are given separately for this example, and its output cannot be joined to the four-dimensional tables above.

Worked example · Lesson 46

From two pieces of content to one mixed vector, not to picking one sentence

Input and conditions. This table checks only the two-dimensional comparison just set out; it does not carry over the four-dimensional worked model. X=[[1,1],[1,-1]]; Wq=[[0.5,0.5],[-0.5,0.5]]; Wk=[[0.5,0.5],[0.5,-0.5]]; Wv=[[5,10],[5,-10]]. From these, q₁=[1,0], k₀=[1,0], k₁=[0,1], v₀=[10,0] and v₁=[0,20]; when the 爱 position is computed, both positions can be read.

Steps and objectsInternal actionIntermediate result / new state
1 MatchCompute the dot product of q with each of the two KeysGives [1,0].
2 Scaleboth scores are divided by √2approx. [0.707107,0].
3 NormalizationSoftmax over the two visible positionsapprox. [0.669762,0.330238].
4 Mixing the 1st featureWeight cell 1 of the two Values0.6697615493×10+0.3302384507×0≈6.697615.
5 Mixing the 2nd featureWeight cell 2 of the two Values0.6697615493×0+0.3302384507×20≈6.604769.
6 Gives the outputPut the two cells side by sideapprox. [6.697615,6.604769], which is none of the original Value rows.

Join the steps up. The match score decides what share is read and the Value decides what is mixed. Change only the Value and the shares read can stay exactly the same while the output changes.

Limits and counterexamples. This example is teaching attention with one head, two positions, no bias and no positional rotation; it is not a trained language model. All the Q/K/V come from actually multiplying the same X by the three parameter tables. If any parameter or input is changed, recompute from the corresponding step.

End-of-lesson self-check

Self-check 1

What does the dot product of Q and K give, and what is V responsible for?

Show the answerHide the answer
The dot product gives the scores for the readable positions; V supplies the content vectors that are aggregated by the normalized weights.
Self-check 2

If two keys score exactly the same and both are readable, what are the weights?

Show the answerHide the answer
0.5 each. The output is the dimension-by-dimension average of the two values, not one value picked at random.
Self-check 3

Which of Wq and Q actually holds the model parameters?

Show the answerHide the answer
Wq holds the multiplication coefficients. Q is the intermediate representation obtained by multiplying this X by Wq. In ordinary inference a different input changes Q, but it does not thereby run a training update on Wq.
Self-check 4

How does x₁=[1,-1] in this example produce v₁=[0,20]?

Show the answerHide the answer
With the fixed Wv=[[5,10],[5,-10]]: the first cell is 1×5+(-1)×5=0, and the second is 1×10+(-1)×(-10)=20. This step only works on that position; it mixes in no other token.
Self-check 5

Must each row of Q and K be the same width as each row of V?

Show the answerHide the answer
No. Q and K need the same width so that the dot product can be computed; K and V need to correspond to the same readable positions. V may have a different width d_v, and the aggregated result then has d_v features too.

Mechanism basis:[TR]. Unless noted otherwise, the numbers and settings in this section are original teaching examples; the source does not replace the explanation here.

If Wv is altered while Wq/Wk and the input stay the same, must the read shares of this layer change?

Show the answer
The current attention scores are formed by Q and K alone, so the shares of this layer do not change this time; the values and the mixed output do. In a multi-layer network the input of the later layers may change as a result, so this cannot be stretched into "no attention anywhere changes in the end".

Each of the 5 rows of the attention table has shares that sum to 1, so should the whole table sum to 1 as well?

Show the answer
No. The five rows are the independent distributions of five queries, so the whole table sums to 5. Normalizing over the whole table by mistake would make the positions compete for one total budget, and the computation would already have changed.
