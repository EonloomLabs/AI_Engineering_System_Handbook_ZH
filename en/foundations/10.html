A network layer rearranges numbers; it does not produce hidden sentences

Why is a nonlinear function still put between the layers?

The first layer combines the input into a row of intermediate numbers, a rule then changes them, and finally the second layer combines them again. If every layer were only a linear transform, many layers could be merged into a single linear transform; the nonlinearity is what keeps it from being equivalent to one larger linear table. The "filtering" here refers only to the numeric rule of ReLU and must not be read as the model understanding which words matter.

ReLU Negative numbers become 0; non-negative numbers keep their value.
Hidden state the vector computed for this input between two layers.
Parameter a fixed coefficient that controls the computation, such as W or a bias.

Getting to know a "model" through one adjustable rule

Consider y=w×x+b. x is the input that changes each time; w and b are the numbers that fix the computation rule. With w=2 and b=1, an input of 3 gives 7. Change w to 4 and the same input becomes 13.

Key difference: the parameters fix an adjustable mapping rule; inference usually uses the parameters it already has.

Easy to misread: a change of input does not mean the model has just finished training its parameters.

Parameters are numbers such as w and b that can be adjusted by training; hyperparameters are settings of the training or of the structure — the width of a layer, the learning rate, the batch size — and are usually not learned automatically by the same gradient step; activations, or intermediate representations, are the temporary numbers one forward pass computes, such as the 7 obtained here.

A new input from the user changes x; normal inference does not change w automatically because of it.

From a single coefficient w to a parameter table W

The w=2 above is a single number; when the input and the output each have several features, many coefficients have to be stored, arranged into a matrix W. Lowercase w usually stands for a single parameter, and uppercase W for a whole parameter table. Writing W1 and W2 distinguishes the first transformation from the second; it does not mean multiplying W by 1 or by 2.

Key difference: a "parameter table" stores coefficients obtained by training; multiplying and adding this input gives the intermediate values.

Easy to misread: W and h are not the same kind of object: W is a parameter, h is this round's activation.

The bias b is a set of parameters as well, except that it is added cell by cell after the matrix multiplication. X and the hidden state h are numbers produced by computing each input; W and b decide how those numbers are transformed. Normal inference loads W and b from the weight file and then uses them; it does not run a training update automatically because some user input changed.

What follows first computes the forward pass with one given set of parameters. How the parameters are adjusted is explained once lessons 52–53 have established the ideas of "loss, gradient, optimizer". Understanding that a parameter is a table of coefficients does not require learning the whole training algorithm first.

All positions share the parameters, so why do the outputs still differ

The same Wq is used for all B×T rows, but the input of each row differs, so the queries differ. This sharing means the model does not have to store a whole fresh Wq for every position. The rows of P are selected by position, the rows of E by token identity. On the backward pass during training, the several places a shared parameter is used add their gradients, and the matching derivation under System mechanisms follows that through.

A complete numeric example with two layers

Input x=[1,2], and the matrix W1 and the bias b1 of the first layer are:

Key difference: multiply by the matrix first, then add the bias, then pass through the nonlinearity. Every step has to keep the operations in the right order.

Easy to misread: a layer should not be written as a direct "input → answer" with the intermediate state left out.

W1 = [[1,-1],[1,1]]     b1 = [0,-2]
xW1 = [1×1+2×1, 1×(-1)+2×1] = [3,1]
xW1+b1 = [3,-1]

Then apply the ReLU activation function: any number below 0 is replaced by 0, and anything else is kept. That gives the hidden representation h=[3,0].

The second layer uses W2=[[2],[1]], giving hW2=3×2+0×1=6. This computation from input to output is called the forward pass, and may be shortened to the forward.

A "layer" is not an abstract box on a screen but a set of operations that transform data by a rule. A complex model strings many layers together, and the result of one step becomes the input of the next.

Why a nonlinear function is needed in between

If all that ever happens is multiplying by a matrix and adding a bias, several linear or affine transformations can be merged into one, and more layers do not automatically bring a different kind of expressive power. An operation such as ReLU, which cannot be expressed as a single linear transformation, supplies the nonlinearity that lets the network represent more complex relationships.

Key difference: without a nonlinearity, several linear layers can be merged into one affine transformation, which limits the expressive power.

Easy to misread: ReLU is not an arbitrary decoration "just there to delete the negative numbers".

Start with the objects and symbols used here
SiLU: the input times a gating coefficient
SiLU(x)=x×sigmoid(x). The input is first mapped to between 0 and 1, then multiplied back by x itself, which makes it nonlinear. Negative numbers do not all become 0 as they do with ReLU. Independent micro-example: SiLU(0)=0; SiLU(1) is about 0.731059; SiLU(-1) is about -0.268941.
GELU: a smooth adjustment according to the size of the input
The common definition is GELU(x)=xΦ(x), where Φ is the cumulative probability function of the standard normal distribution. It keeps negative and positive inputs to different degrees; it is not random sampling. An implementation may also use an approximate formula. Independent micro-example: Φ(0)=0.5, so GELU(0)=0. Φ here is not a learnable parameter table of the model.

Real Transformers commonly use GELU, SiLU or a gated feed-forward structure. Understand "why there has to be a nonlinearity" first and read the particular function afterwards; there is no need to memorize every formula the first time you meet the name.

The hidden state is not a hidden draft in words

In the example above, h=[3,0] is the result of one computation, not a hidden "I have thought of the answer". In a language model, the row of numbers a token comes out with after passing through a layer is also called a hidden state. It carries information useful to the computation that follows, but each coordinate cannot be translated directly into a sentence of explanation.

The hidden state is not a hidden draft in words: item-by-item distinctions
Approach / object AHidden state: computed while running
Approach / object BModel weights: saved after training
Approach / object COutput text: obtained by decoding

Key difference: the internal numeric representation, the fixed parameters and the sentence a person can see belong to different stages.

Easy to misread: a hidden state must not be read as "a draft the model has already written out in words".

d is the hidden width at each position; L usually stands for the number of layers; the total number of parameters depends on the sizes of all the matrices and on how they are shared. d=4096 does not mean there are only 4096 parameters. A single 4096×4096 matrix alone has 16,777,216 cells.

Weight sharing and freezing parameters

The same W can be applied to every input in a batch and to every token position; that is called weight sharing. It does not mean the computed results are shared between positions. With different inputs, the intermediate states still differ.

"Freezing parameters" means some parameters are not updated during training; "inference uses fixed weights" means this computation performs no update. Some model services do train a new version at some other time, but correcting a mistake in an ordinary conversation is not the same thing as online training.

Why a row of numbers is processed before attention

The numeric scale of a hidden state varies. A normalization layer adjusts that scale from the feature statistics inside each position, so that the modules after it face a more controlled input; it does not turn the row into probabilities, and it does not make the four numbers add up to 1. The range RMSNorm normalizes over is the feature axis, not the whole sentence, and certainly not the whole batch.

This model uses pre-norm: RMSNorm is applied to X first and the result is fed into attention; the residual main path that is kept is still the original X, which is not replaced outright by the normalized values.

Working the row for 爱 through once in full

In the pinned source, x=[-0.2, 0.8, 0, 0.45], with d=4, ε=0.00001, and the initial scaling g1 all ones.

  1. Square each of the four numbers.
  2. Add them and divide by 4 to get the mean of the squares.
  3. Add ε and take the square root to get r.
  4. Divide each original value by r, then multiply by the matching learnable scaling g1[j].
mean(x²) = (0.04 + 0.64 + 0 + 0.2025) / 4
         = 0.220625
r = sqrt(mean(x²)+0.00001) = 0.469718001
N1[j] = g1[j] × x[j] / r

r is an intermediate value computed from this input; ε is a constant set for numerical stability; g1 is a parameter that takes part in training. The three come from different places. With the next input, r is computed again; ordinary inference does not update g1 because r changed.

Basis: tiny_model.py:48–51; Matching parameters, forward pass and gradient records.

What the "mean and variance" of LayerNorm do beyond that

What follows is an independent two-number comparison, only for comparing the statistical rules; it does not continue the worked model. The fixed input is [1,3], and is not changed to another set of numbers. The mean is μ=2, the deviations are [-1,1], the squared deviations [1,1], and the population variance is their mean, 1; the standard deviation is 1 when ε is not added.

LayerNorm subtracts μ first, then divides by sqrt(var+ε), which with the initial gamma=1 and beta=0 gives about [-0.999995,0.999995]. RMSNorm does not subtract the mean; the mean of the squares is 5, and the result is about [0.447213,1.341639]. That is why everything can still be positive after RMSNorm: it never promised a zero mean.

Basis: tiny_model.py:48–51; Matching parameters, forward pass and gradient records.

Why it must not be treated as a softmax

softmax produces non-negative shares along the candidate axis that sum to 1; RMSNorm allows negative numbers and requires no sum of 1. The softmax over an attention row distributes the read shares among the visible keys; the softmax at the output distributes predicted probability among the vocabulary candidates. Both may be called "normalization", yet their goal and their axis are entirely different.

Basis: tiny_model.py:48–51; Matching parameters, forward pass and gradient records.

Whether training and inference recompute the statistics

In this model both compute r from the four features the position currently has. RMSNorm and LayerNorm do not depend on a cross-sample running mean of the kind BatchNorm uses..eval() does not mean they stop computing statistics; it only switches the mode of those modules that really do behave differently in training and in evaluation.

On the backward pass r depends on x as well, so it cannot be treated as a constant and computed as just g/r. The matching derivation under System mechanisms explains why there is an extra term in the gradient. For now, hold on to this: x affects its own numerator, and it also affects the denominator shared by every feature.

Basis: tiny_model.py:48–51; Matching parameters, forward pass and gradient records.

Follow-up: LayerNorm, RMSNorm and softmax are all normalization, so why are they not interchangeable?

Normalization differs in its axis, its statistics and the nature of its output. A norm handles the scale of the hidden features at each position; softmax turns position scores or candidate scores into a non-negative distribution that sums to 1. Swapping them changes both the forward pass and the gradient.

Basis: tiny_model.py:178–258; Matching parameters, forward pass and gradient records.

Why a textbook can give the weights before it teaches training

To follow what happens inside, take known weights and walk one forward pass through to the end. How those weights come from a large number of examples is explained in lessons 52–54. It is like understanding how an existing calculator produces its result before understanding how it was designed.

A numeric example on a small model can show that you understand the operations, but it has not been trained on language data and cannot produce a meaningful answer. Do not call a network worked by hand "a reproduction of large-model intelligence".

3 Another input, x=2Compute 2×2−3=1h=1, and the output is y=5.
4 Observe the shared parametersBoth times use the same 2, −3, 4 and 1The result changed because the input changed, not because the network has just updated its weights.
5 Suppose a training objectiveAt x=2 we want y to be close to 4The loss and the gradient still have to be computed before it can be decided which way to update the parameters.

Join the steps up. The forward pass computes a result under the rules it already has; training changes those rules, guided by a target and an error. The h in between is a number, not a passage of hidden explanation.

Limits and counterexamples. The ReLU example is only a two-layer scalar network, not a complete Transformer; a small network was chosen so that every step could be worked out exactly.

Basis and scope of use:[DERIVE]. The example input and setting are stated explicitly by this book.

End-of-lesson self-check

Self-check 1

When the input x changes, must w change along with it?

Show the answerHide the answer
Usually not, during inference. w is a parameter the model already has; what changes is the intermediate state and the output. Only training updates the parameters, according to the loss.
Self-check 2

In the two-dimensional network in the main text, with x=[1,2], pre-activation values [3,-1] in the first layer and W2=[[2],[1]] in the second, what is the output once ReLU is removed? (Not the scalar worked run.)

Show the answerHide the answer
The hidden values are [3,-1], and the second layer gives 3×2+(-1)×1=5. This shows that the activation function really does change the computation.

Is taking the RMS over all T×d numbers of a sample together the same as taking the RMS along d at each position?

Show the answer
No. The first lets one position's scale be influenced by other positions, even by future content, which changes the structure of the model and its causal character. This model takes the statistics along the four features separately, for each sample and each position.
