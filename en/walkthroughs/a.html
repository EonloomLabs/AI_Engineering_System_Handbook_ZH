A.1｜A sentence in the user interface is not the model's entire input

Suppose the user says "Explain function foo". The frontend also holds the selected function text; the harness loads repository rules and available tools to form message objects. These may be strings, structured content blocks, image references or tool definitions, not neural-network tensors yet.

用户输入：“解释函数foo”
前端附件：选中源码、文件位置
宿主配置：系统规则、仓库指引、工具列表
会话状态：此前消息、当前任务进展
                 ↓ 上下文选择与序列化
模型可接收的消息与工具结构
                 ↓ 模型模板与Tokenizer
Token ID序列、位置、注意力约束

Who retrieves the source? It may be a frontend attachment, automatic harness retrieval or a tool called by the model first. The final answer cannot establish that the model read the whole repository. Inspect actual request lists and tool traces to confirm.

Templates convert roles and content into a form the model learned to handle in training. Writing "system:" inside a string does not create an actual system role. Products may also use dedicated control Token or structured channels. This experiment starts from three already encoded IDs [1,2,3] without inventing an actual correspondence to a Chinese phrase.

A.2｜After IDs, what is the first floating-point object

The token embedding matrix E has shape [8,4]; the three IDs select three rows, giving [3,4]. In the usual batch notation, this is [1,3,4]; the program omits the batch axis, which is always 1.

This experiment adds a fixed position term at each position: for position p, add to feature j 0.1·sin((p+1)/(j+1)). This is a teaching choice for checking position offsets, not RoPE, nor a claim that modern LLMs all add sine terms directly to embedding.

The first tensor H therefore combines token identity and position. An ID is not a semantic floating-point vector; embedding parameters determine its computable representation. In inference this is a lookup, not a temporary call to a separate embedding retrieval service.

Three numbers must remain separate: vocabulary 8 means 8 kinds of token; sequence 3 means 3 positions this time; width 4 means 4 features per position. Confusing sequence length with hidden width directly breaks matrix multiplication.

A.3｜Enter layer 0: normalize, then generate Q/K/V

This experiment uses pre-LN. Compute mean and variance separately at each position, then normalize:

Start with the objects and symbols used here
Σ: sum term by term over the subscript
Σ is shorthand for addition. The subscript says which term varies; a subscript that is not summed over stays fixed. It is not an extra parameter, and it does not mean concatenating arrays. Independent micro-example: Σᵢ xᵢyᵢ with x=[1,2] and y=[3,4] is just 1×3+2×4=11.
Start with the objects and symbols used here
σ: tell the function symbol from the statistic
In σ(XW+b), σ usually stands for whatever nonlinear function this layer has chosen; it may be ReLU or another, and σ alone does not make it a sigmoid. In statistical formulas σ usually means the standard deviation and σ² the variance. They are not the same object. Independent example: if σ is specified as ReLU, σ(-1)=0; if it is specified as sigmoid, the value is about 0.268941. The function has to be defined before any result can be computed.
均值 μ = (x₁+x₂+x₃+x₄)/4
方差 σ² = Σ(xⱼ−μ)²/4
LN(x)ⱼ = (xⱼ−μ)/sqrt(σ²+ε)
Start with the objects and symbols used here
Norm, LayerNorm, RMSNorm: not a probability normalization
In a layer formula, Norm stands for a normalizing function. LayerNorm usually subtracts the mean over one token's features, divides by the standard deviation, then scales and shifts; RMSNorm usually does not subtract the mean and scales by the root mean square. Neither of them is softmax. Independent micro-example, ignoring the small positive ε that stabilizes the denominator and the learnable scaling: LayerNorm([1,3])=[-1,1]; RMSNorm([1,3])=[1/√5,3/√5].

Learnable scale and shift are omitted here only for brevity; this does not imply a complete LayerNorm lacks them. Normalization is across features, not all three tokens together; otherwise new tokens could change old-position values and invalidate the later cache proof's premise.

Start with the objects and symbols used here
Wq / W_Q: the query projection parameters
This is the parameter matrix that turns the input representation into the query, not the query itself. Under this book's right-multiplication convention, each input row has d numbers and Wq has d rows and d_k columns, so after Q=XWq each row has d_k numbers. The subscript q marks what it is for; it does not mean multiplying by another q. One Wq can handle many positions; each position gets its own q. F11 gives X, Wq and every multiply-add result.
Wk / W_K: the key projection parameters
This is the model parameter table that produces the key representation. The X in K=XWk comes from the current attention input, and K is the result computed this time; Wk is not a table that stores document keywords or secret keys. Q and K have to have the same row width for a dot product to be possible. In F11, x₁=[1,-1] times Wk gives k₁=[0,1]. The original token IDs are not taken as keys.
Wv / W_V: the value projection parameters
This is the model parameter table that produces the value content vectors from the input. After V=XWv, attention mixes the rows of V by the share in which each is read. The value width d_v may differ from the query/key width d_k; it is not the final answer over the vocabulary. In F11 the same x₁=[1,-1] times Wv gives v₁=[0,20], which then takes part in the weighted sum.
Query, Key, Value: three intermediate numeric representations
q is one row of query representation for the position receiving information; k is one row of matching representation offered by a readable position; v is one row of content representation that position contributes to the mix. Capital Q/K/V collect several rows into tables. They are computed from the input and the parameters, and they carry the separate jobs of scoring and of supplying content. One q dotted with two k gives two scores; softmax turns them into two shares; those shares multiply the two rows of v, and the results are added. Nothing here generates a search term, and nothing here picks an answer directly.

Each normalized row is multiplied separately by Wq,Wk,Wv, all three of which are [4,4] in this experiment. Q, K and V each have shape [3,4]. They share an input but use different weights, so they are not one vector with different names.

Q asks which direction the current query should match, K supplies matching directions, and V supplies aggregated content. This is a functional explanation, not a claim that dimensions inherently correspond to human-readable concepts. Training adjusts these projections together to improve the final prediction objective.

A.4｜How to keep position 1 from seeing position 3

The score matrix for the three positions is QKᵀ/√4, with shape [3,3]. Row i scores query i against every Key. The causal mask is:

位置0：[允许，禁止，禁止]
位置1：[允许，允许，禁止]
位置2：[允许，允许，允许]

For forbidden positions, softmax takes negative-infinity inputs, giving zero probability; this does not apply softmax to every position and then arbitrarily zero some, which may leave the remaining mass unnormalized and still leak future information through other paths.

Training can compute all three positions together because inputs are already supplied and the mask restricts dependencies. Generation has no future tokens yet and must obtain them incrementally. Computing positions in parallel and permitting access to the future are different problems.

Besides the mask, there may also be padding constraints. In a left-padded batch, logical positions and array indices need not match; array length alone cannot stand for position. This experiment has no padding, isolating causality and caching.

A.5｜What one attention row does: the full hand calculation

To see the numbers clearly, use a smaller local two-dimensional example, separate from the four-dimensional decoder:

当前Q = [1,1]
历史K = [[1,0], [0,1], [1,1]]
历史V = [[1,2], [3,4], [4,6]]

Dot products are 1, 1 and 2; divided by √2, about 0.707107, 0.707107 and 1.414214. Subtract the same maximum for stability, making exponentials exp(−0.707107),exp(−0.707107),1. Normalizing gives:

a = [0.24825508, 0.24825508, 0.50348984]

The first output component is 0.24825508×1+0.24825508×3+0.50348984×4≈3.00697968; the second is 0.24825508×2+0.24825508×4+0.50348984×6≈4.51046952. The numeric program in the package gives complete floating-point results.

This output is a feature vector, not a token or a selection of the third word. Although the third weight is largest, the first two still contribute; the vector next passes through output projection and later layers. Attention intensity alone therefore cannot fully explain the final answer.

Draw the contributions of A.5's three positions separately

Uses A.5's independent two-dimensional example exactly: q=[1,1], K=[[1,0],[0,1],[1,1]], V=[[1,2],[3,4],[4,6]]. These are not the four-dimensional decoder's hidden states.

Each share multiplies its own Value; the position with the largest share is not copied wholesale. Inspect contributions to each output coordinate, then add contributions for the same coordinate.

Position three has the largest share, but the first two still contribute. Explaining the final word also requires Wo, residuals, the feed-forward network and the vocabulary output head.

A.6｜What follows attention, and why text cannot be output directly

Start with the objects and symbols used here
Wo / W_O: the attention output projection
The parameter matrix that concatenates the attention heads' outputs and then converts them to the width the main network needs. It is still a table of coefficients: not the shares from softmax, and not the vocabulary output head Wout. If two heads each output 2 numbers, the concatenation is 4 wide; multiplying on the right by Wo of shape [4,6] gives 6 numbers, matching the residual width. This is an independent example about shapes.
SwiGLU, Wg/Wu/Wd: two transformation paths, then combined
This is a gated feed-forward structure. Wg produces the path that goes through SiLU, Wu produces the other content path, the two are multiplied element by element, and Wd maps the result back to the original width. These Ws are three sets of parameters, not three agents. To read (SiLU(XWg)⊙XWu)Wd, compute XWg and XWu first, then SiLU, then ⊙, and finally multiply by Wd. Every position uses the same set of parameters independently.

Back to the four-dimensional decoder: each position's aggregated vector multiplies Wo, giving width 4, then adds the layer's original input through a residual connection. A second normalization follows, then a 4→8→4 feed-forward network. This experiment uses ReLU, followed by another residual addition. Actual models may use SwiGLU and other structures.

H0
  ↓ LN → QKV → attention → Wo
  + H0
  = R0
  ↓ LN → Wup → ReLU → Wdown
  + R0
  = H1

Layer 1 receives H1 and runs the same structure with different weights. Layer 1 K/V does not copy layer 0 K/V; it comes from deeper contextual representations, so every layer needs its own cache.

FFN operates at each position without directly mixing different tokens here, but transforms features already aggregated. Saying "Attention handles understanding and FFN is an irrelevant extra" is inaccurate. Final capability comes from joint training of the entire network.

A.7｜Where the first output token comes from

After two layers, the final normalized representation multiplies the language-model output matrix [4,8], giving 8 logits at each position. The three input positions yield [3,8], with the last row predicting the first output token immediately after the input.

The actual last row from the package run is approximately:

[-0.052135, -0.102202, -0.101966, -0.051542,
  0.024250,  0.088107,  0.108598,  0.075637]

With greedy decoding, the maximum is at ID6, so the first output token is 6. No initial "empty decode" is needed to obtain it: Prefill has already produced the final position's prediction distribution.

Start with the objects and symbols used here
Top-k, Top-p and renormalization
Top-k keeps the k items with the highest probability; Top-p sorts by descending probability and keeps the leading candidates until the cumulative probability reaches a threshold. When used for sampling, the kept candidates have to be renormalized over the remaining total mass. Here k is a number of candidates and p a cumulative-probability threshold; k is not the attention Key table K, nor the representation width d_k.

Sampling also transforms the distribution using temperature, top-k/top-p and other rules. Temperature changes the distribution, not the historical K/V already computed. If a token corresponds to a text-byte fragment, the display layer must handle multibyte characters and control tokens correctly, rather than treat every token as a complete Chinese character.

The cache length is still 3, not 4. The network has just processed input [1,2,3]; ID6 was selected from the output distribution and has not passed through the layers, so it has no K/V of its own yet.

A.8｜The second token: input only the newly selected ID6

Feed ID6 back next at logical position 3. Embedding lookup plus the position term gives [1,4]. Layer 0 computes new Q/K/V only for this position, appends new K/V after the existing 3 rows, and the cache becomes [4,4].

New Q has shape [1,4] and multiplies transposed K from past and current positions, with shape [4,4], giving scores [1,4] rather than regenerating the entire [4,4] query-score matrix. Then softmax, V aggregation, residuals and FFN lead into layer 1. Layer 1 repeats this with its own historical cache.

The actual new logits are approximately:

[0.232867, -0.009785, -0.247622, -0.363579,
 -0.300585, -0.089644, 0.165419, 0.339064]

Greedy selection chooses ID7 as the second output. Cache length is now 4 and covers [1,2,3,6], excluding the newly selected 7. To predict the third output, feed ID7 back at position 4, growing each layer's cache to 5. The experiment can continue directly; the point here is the timeline, not portraying these nonlinguistic IDs as an actual answer.

Start with the objects and symbols used here
BOS / EOS: sequence boundary markers
BOS is usually the special token for the start of a sequence and EOS the one for the end; a particular model or message template may use different names, counts and end markers. They are symbols in the input/output protocol, not proof of semantic correctness. Meeting an EOS does not automatically cut attention between two training samples; isolating the reads still needs a mask, or a sample boundary the implementation supports.

If the caller passes the entire [1,2,3,6] with the old cache to an interface accepting only new tokens, the prefix may be appended twice; resetting positions to 0 makes positional encoding wrong; blindly executing tools after generating EOS confuses language stopping with execution state.

Some frameworks automatically trim cached input, but that is an interface contract. An implementation must specify whether it accepts full input or an incremental suffix, rather than guess. Cache objects must also bind model/adapter identity; reusing old state after changing weights produces inconsistent results.

A.10｜Why the mask is not a small ordinary triangle when processing two new tokens

There are P=3 cached positions and C=2 new tokens. Q is [2,4], K is [5,4], and scores are [2,5]. The correct mask is:

新位置3：[1,1,1,1,0]
新位置4：[1,1,1,1,1]

Directly generating tril(ones(2,5)) instead gives [1,0,0,0,0] and [1,1,0,0,0], hiding most history and the new queries themselves. This bug need not trigger a shape error; it silently changes output, making a useful interview follow-up: why can runnable code still be wrong?

The correct condition is key_position ≤ past_length + query_index, combined with padding or sliding-window constraints. Package tests compare full forward passes with single-token/two-token incremental passes and deliberately use wrong positions to produce differences. This shows they detect a specific error, not only that the program avoids crashing.

How the two new queries should read the five keys

Uses A.10 exactly: 3 existing positions and 2 new positions. Shows visibility only, without inventing new Value numbers for the four-dimensional decoder.

A Query numbered 0 in the current array is not necessarily at sequence position 0. Adding past_length=3 makes it position 3.

The correct rule is Key absolute position≤Query absolute position. Wrong visibility silently changes output even when matrix shapes are correct.

A.11｜How to prove a cache implementation correct beyond plausible generated sentences

Start with the objects and symbols used here
Dropout: the rule that randomly zeroes values during training
The common inverted dropout zeroes elements at random during training with drop probability p, and divides the kept ones by 1-p so that the expected scale is preserved. Evaluation mode usually turns this random operation off; the underlying function may require the caller to pass p=0 explicitly. Independent example: with p=0.5, a value of 2 comes out as 4 if it is kept in a given mask and as 0 if it is dropped. This is not training permanently deleting the corresponding model parameter.

Fix weights, disable random dropout and use the same token sequence. Run full and segmented cached forward passes, compare logits at matching positions, and set a reasonable floating-point tolerance. Also cover different segment lengths, position offsets and prefix edits.

For mismatches, check in order: repeated input, position offsets, mask alignment, each layer's cache, the stage where position transforms apply to K, and batch/padding confusion. Do not start with sampling temperature; the error occurs before distribution generation.

Package tests also check the analytic gradient of attention with respect to Q using finite differences. This verifies a local backward formula, not complete training correctness. State the scope clearly: forward consistency, gradient checks, training convergence and task generalization are four different kinds of evidence.

A.12｜What must be added when moving this example to an actual model

Start with the objects and symbols used here
MHA, MQA, GQA: how heads are shared
An attention head is one path that matches and then aggregates content. MHA usually gives every query head its own K/V head; MQA has several query heads share one group of K/V; GQA sits between them, sharing by group. These are structural choices, not a switch to be flipped at run time. Independent shape example: 8 query heads and 2 K/V heads, grouped evenly, means every 4 query heads share 1 group of K/V; the cache is accounted for by the number of K/V heads.
Start with the objects and symbols used here
MLA: a learned low-dimensional K/V representation
MLA refers to a family of multi-head latent attention architectures. It organizes the content behind K/V jointly in a lower-dimensional latent representation and handles the positional part by design. It changes the model's representation and parameter structure; it is not just ZIPping an ordinary KV file. In c=xW_down, c is the latent vector for this computation and W_down the learned table of dimension-reducing coefficients; how it is later reconstructed or absorbed into a projection has to be explained for the specific architecture.

Actual systems need larger parameter sets, multiple heads or GQA/MLA, actual Tokenizers, trained weights, model-appropriate normalization and activations, correct positions, batching, precision and device kernels. Serving also manages request cancellation, paged KV, prefix sharing and resource limits.

Start with the objects and symbols used here
FlashAttention: changing how intermediate data is stored and read
By means such as tiling and online normalization, it avoids keeping the full attention score/weight matrix in slower VRAM for long; the target is still the same attention computation, and floating-point rounding can vary with the order of operations. It does not compress tokens permanently, and it does not skip any Key. Keep "not writing the whole table to VRAM" apart from "not doing this arithmetic at all".

The diagnostic method stays the same: define interface contracts and each step's objects, perform small controlled comparisons, then measure performance. Calling a technique FlashAttention does not justify skipping numeric checks; a correct KV formula does not establish enough VRAM for all concurrency either.

The standard for this example is explaining, without the figure, messages to IDs, IDs to layer tensors, final logits to sampling, and new tokens to incremental caches, while stating every boundary between already computed and not yet computed.
