Before reading a formula, sort out the five kinds of object

A formula is not an acronym contest. One symbol may be this input, a model parameter, a computed intermediate value, a size or a subscript, an execution rule or a function. Classify the objects first, then read how they relate. The examples below only explain notation; they are independent micro-examples about symbols, and they do not replace the main worked example of any lesson.

Category Usually supplied by Changes with this input? Typical objects
Input and labels User data, the tokenizer or training samples Yes Input IDs, X, the correct next token
Model parameters The initialization routine, training, a saved weight file Usually not updated in ordinary inference The embedding table, Wq/Wk/Wv, biases, normalization parameters
Intermediate computed results The current turn's forward computation Usually yes Q/K/V, the scores S, the shares A, hidden states, logits
Structure and sizes The model design and the length of the current request Some are fixed, some change with the request The number of layers, the number of heads, the width per head, the current effective length
Operations and state constraints The program, the protocol and the task rules Constructed according to the specific conditions The Norm function, softmax, a mask, execution state

"Weight" has two common senses. The weights in the parameter matrix W are coefficients the model has saved; the weights in the attention table A are shares of information computed from the current input. Both take part in multiplication, but their origin and life cycle differ. The word "parameter" has two levels too: model parameters are numbers that were learned, whereas the parameters of a tool call are fields of one request, and the two must not be conflated.

Read XW through in one plain sentence first, then look at the matrix sizes

Y=XW is read as: "take each row of X and combine it by the coefficients that each column of W supplies, producing each column of Y." For example, X has two rows of three numbers each and W has three rows of two numbers each:

X[2,3] @ W[3,2] → Y[2,2]
Y[i,j] = X[i,0]W[0,j] + X[i,1]W[1,j] + X[i,2]W[2,j]

Here i selects which row of X, and j which column of the output. i and j are not being passed to another model. If X stands for the positions of two tokens, the origin of one output cell can still be traced back to the three features at that same input position. Mixing across tokens takes a further operation along the position axis, such as multiplying the table of attention shares by the Value table.

Wq, W_Q and, in some sources, W^Q can all be used to name the query projection parameters. They are ways of writing the notation, not three separate algorithms. Conversely, a letter that looks the same may carry a different role in another chapter, so this book does not let the look of a letter stand in for a local definition.

If a chapter moves from "the vectors of two tokens" to "the retrieval ranking of ten documents", it should establish the new input explicitly. Both sets of numbers can be summed mathematically, which does not mean they come from the same run.

A function name is not another mysterious data table

Norm(X) means calling the normalizing operation; FFN(X) means calling the feed-forward network; softmax(S) means turning scores into shares along the axis designated. A function may use learnable parameters inside it, but the function name itself is not a row of weights.

Take U=X+Attention(Norm(X)) as an example: it should be read in order — first normalize X, let Attention process that result, add the attention output to the original X, and finally call the whole result U. U is only a name for a temporary result. Another formula using U as well does not mean the numbers are shared automatically. Where a continuous worked example carries U over, it points explicitly at the line above.

A high-level interface may also give the data before projection the names query/key/value; the parameter of the same name in a low-level interface may instead be the data after projection. Checking "whether the interface has already done the W transformation inside" matters more than reading the parameter name alone. A formula and a program may also take different layouts, one right-multiplying the parameter table and the other storing the weights transposed; align the layouts first, then compare the numbers.

"The model remembered" also has at least three levels: a set of K/V in the inference cache, facts and summaries within the current session, and long-term memory retrieved across sessions. Ask which kind of object it saved, when that was written and when it expires, instead of treating all three levels as an update to the model parameters.

The dependency path from the basics to the system

The model computation path: numeric containers and shapes → token IDs and embeddings → row-by-column multiplication → parameters and intermediate results → Query/Key/Value → scores and read shares → masks and position → multiple heads, the output projection, residuals and the feed-forward network → output tokens and the cache.

The training path: the forward result → the correct labels and the loss → derivatives and the chain rule → the gradient for each parameter → optimizer state and updates → post-training objectives. Without derivatives you can still start by understanding how W takes part in the forward pass; "the weights come from training" must not be mistaken for "every reinforcement learning algorithm has to be understood first".

The agent path: requests and structured data → model output items → tool call identifiers → permissions and execution → events and state → reassembling the context → recovery after compaction → multi-agent collaboration.

The knowledge and quality path: original evidence → chunking and indexing → recall and reranking → versions and permissions → generation and citation → the memory life cycle → task results you can check → statistical comparison and running cost.

When you come to a new mechanism, be able to answer "which object is the input, where do the parameters come from, what is actually computed, and which step uses the result" before going into the formula. Linear projection and the weight matrix

A projection is the operation that recombines the input features by coefficients; W is the model parameter table that stores those coefficients. The input X is this data, and XW is the result computed this time. The parameter table is usually updated during training, and in ordinary inference it stays fixed once loaded from the weight file.

Independent micro-example: x=[1,2], W=[[3],[4]], xW=[11]. W is not the 11 itself, nor the ID of the word.

Go to the matching full lesson

Wq / W_Q: the query projection parameters

This is the parameter matrix that turns the input representation into the query, not the query itself. Under this book's right-multiplication convention, each input row has d numbers and Wq has d rows and d_k columns, so after Q=XWq each row has d_k numbers. The subscript q marks what it is for; it does not mean multiplying by another q.

One Wq can handle many positions; each position gets its own q. F11 gives X, Wq and every multiply-add result.

Go to the matching full lesson

Wk / W_K: the key projection parameters

This is the model parameter table that produces the key representation. The X in K=XWk comes from the current attention input, and K is the result computed this time; Wk is not a table that stores document keywords or secret keys. Q and K have to have the same row width for a dot product to be possible.

In F11, x₁=[1,-1] times Wk gives k₁=[0,1]. The original token IDs are not taken as keys.

Go to the matching full lesson

Wv / W_V: the value projection parameters

This is the model parameter table that produces the value content vectors from the input. After V=XWv, attention mixes the rows of V by the share in which each is read. The value width d_v may differ from the query/key width d_k; it is not the final answer over the vocabulary.

In F11 the same x₁=[1,-1] times Wv gives v₁=[0,20], which then takes part in the weighted sum.

Go to the matching full lesson

Query, Key, Value: three intermediate numeric representations

q is one row of query representation for the position receiving information; k is one row of matching representation offered by a readable position; v is one row of content representation that position contributes to the mix. Capital Q/K/V collect several rows into tables. They are computed from the input and the parameters, and they carry the separate jobs of scoring and of supplying content.

One q dotted with two k gives two scores; softmax turns them into two shares; those shares multiply the two rows of v, and the results are added. Nothing here generates a search term, and nothing here picks an answer directly.

Go to the matching full lesson

Wo / W_O: the attention output projection

The parameter matrix that concatenates the attention heads' outputs and then converts them to the width the main network needs. It is still a table of coefficients: not the shares from softmax, and not the vocabulary output head Wout.

If two heads each output 2 numbers, the concatenation is 4 wide; multiplying on the right by Wo of shape [4,6] gives 6 numbers, matching the residual width. This is an independent example about shapes.

Wout, LM head: the vocabulary scoring parameters

The parameter layer that turns the final hidden representation into a score for every vocabulary candidate. The input width is d, the vocabulary has Vocab entries, and the right-multiplied parameter shape is [d,Vocab]. Producing probabilities means normalizing these scores as well.

Attention's Wo outputs hidden features; Wout outputs scores over vocabulary candidates. Both names contain "output", but what they output is different.

I: the identity matrix

In a matrix formula I is usually the identity matrix: 1 on the diagonal and 0 everywhere else. At a compatible size, multiplying a vector or a matrix by I leaves the numbers unchanged. Wq=Wk=I is a special case chosen deliberately; one cannot infer from it that the projections of a real model are all the same.

Independent micro-example: I=[[1,0],[0,1]], and [3,-2]I=[3,-2]. I here is not the position subscript written as the letter i.

b / bias: the additive bias

A bias is a row of parameters added on top of the result of the linear multiplication, aligned with the output features. It is learnable just as W is, but what it performs is addition. Leaving the bias out means that example or that layer has no such addition; it does not mean a matrix multiplication was forgotten.

Independent micro-example: xW=[3,1], b=[0,-2], xW+b=[3,-1].

Σ: sum term by term over the subscript

Σ is shorthand for addition. The subscript says which term varies; a subscript that is not summed over stays fixed. It is not an extra parameter, and it does not mean concatenating arrays.

Independent micro-example: Σᵢ xᵢyᵢ with x=[1,2] and y=[3,4] is just 1×3+2×4=11.

ᵀ, transpose: swapping a matrix's rows and columns

Transposing turns the original rows into columns. The point of QKᵀ is to have each row of Q take a dot product with each row of K. For a higher-dimensional tensor, usually only the two axes named explicitly are transposed. The superscript ᵀ is not the sequence length T, and it is not a power.

Independent micro-example: [[1,2],[3,4]]ᵀ=[[1,3],[2,4]]; it is not the same as a reshape that keeps the order.

⊙: element-wise multiplication, not matrix multiplication

Elementwise multiplication multiplies the numbers at the same position once the shapes are aligned; it does not then sum along any dimension. Matrices written side by side in a formula, or @, usually mean matrix multiplication, and the two are not interchangeable.

Independent micro-example: [1,2]⊙[3,4]=[3,8], whereas the dot product is 11. The ⊙ in a gated feed-forward network modulates one path with the other, feature by feature.

ReLU: keeping the positive numbers, cell by cell

ReLU is a function whose rule is max(0,x): negatives become 0 and non-negatives are kept. Applied to a row of numbers, it runs cell by cell. It is not a parameter table, and it does not need information from any other token.

Independent micro-example: ReLU([3,-1])=[3,0]. Remove it and [3,-1] is kept, so the multiplication that follows comes out different.

sigmoid: maps a single number into the range between 0 and 1

The function rule is sigmoid(x)=1/(1+exp(-x)). It computes number by number and does not require one row of results to sum to 1, so it cannot stand in directly for a softmax over several candidates.

Independent micro-example: sigmoid(0)=0.5; computing two zeros separately gives [0.5,0.5], which is only a coincidence — for the input [1,1] the two terms already sum to more than 1.

SiLU: the input times a gating coefficient

SiLU(x)=x×sigmoid(x). The input is first mapped to between 0 and 1, then multiplied back by x itself, which makes it nonlinear. Negative numbers do not all become 0 as they do with ReLU.

Independent micro-example: SiLU(0)=0; SiLU(1) is about 0.731059; SiLU(-1) is about -0.268941.

GELU: a smooth adjustment according to the size of the input

The common definition is GELU(x)=xΦ(x), where Φ is the cumulative probability function of the standard normal distribution. It keeps negative and positive inputs to different degrees; it is not random sampling. An implementation may also use an approximate formula.

Independent micro-example: Φ(0)=0.5, so GELU(0)=0. Φ here is not a learnable parameter table of the model.

SwiGLU, Wg/Wu/Wd: two transformation paths, then combined

This is a gated feed-forward structure. Wg produces the path that goes through SiLU, Wu produces the other content path, the two are multiplied element by element, and Wd maps the result back to the original width. These Ws are three sets of parameters, not three agents.

To read (SiLU(XWg)⊙XWu)Wd, compute XWg and XWu first, then SiLU, then ⊙, and finally multiply by Wd. Every position uses the same set of parameters independently.

FFN / MLP: the position-by-position feed-forward network

In the Transformer setting it usually means the sub-network that applies, separately at each position, a linear transformation, a nonlinearity and another linear transformation. It works on the features; at this step it does not weight other token positions directly.

Independent shape example: [B,T,4]→[B,T,8]→[B,T,4]. The number of positions T does not change; what changes is the representation at each position.

Norm, LayerNorm, RMSNorm: not a probability normalization

In a layer formula, Norm stands for a normalizing function. LayerNorm usually subtracts the mean over one token's features, divides by the standard deviation, then scales and shifts; RMSNorm usually does not subtract the mean and scales by the root mean square. Neither of them is softmax.

Independent micro-example, ignoring the small positive ε that stabilizes the denominator and the learnable scaling: LayerNorm([1,3])=[-1,1]; RMSNorm([1,3])=[1/√5,3/√5].

γ, β, ε: keep the parameters and the stabilizing constant apart

In the LayerNorm expression, γ is a row of learnable multiplicative coefficients and β a row of learnable additive ones; ε is a small positive number set by hand, placed in the term involving the denominator to avoid division by zero and similar problems. The mean μ and the variance σ² that are computed are in turn statistics of this data.

γ=1 and β=0 usually mean that every feature uses 1 and 0; they are not the meaning of an input word. The β in DPO refers to a coefficient of the objective function, and the sense it has here does not carry over.

pre-norm / post-norm: where normalization goes

pre-norm normalizes first and then enters the sub-layer, with the residual added straight from the original input; post-norm adds the sub-layer result to the original input and normalizes after that. This describes the order of operations, not two phases before and after training.

Independent structural comparison: x+F(Norm(x)) and Norm(x+F(x)) are not generally equal. F stands for the sub-layer function being wrapped here.

Residual connection: addition keeps the main path

The residual output is the original input plus the result the sub-layer computed. F(x) is the array that branch produced, not another historical document. The shapes on both sides, and what their features mean, have to be suitable for addition.

Independent micro-example: x=[1,2] and F(x)=[0.3,-0.1] give [1.3,1.9]; overwriting x with F(x) would replace the function.

√ / sqrt: the square root

For a non-negative a, √a is the non-negative number whose square is a. sqrt(a) is the usual way to write it in code. Dividing by √d_k scales the scores by the square root of the number of Query/Key features; it is not a second softmax.

Independent micro-example: √4=2; √2 is about 1.414214. With d_k=2, a score of 1 divided by √2 is about 0.707107.

d_k, d_v, Dh: the width of each row of representation

d_k is how many components one Query/Key vector has; d_v is how many components one Value vector has. Dh, or d_h, is the single-head width in some chapters. They are size integers, not the k-th Key or some Value number.

Shape micro-example: with Q[2,3], K[5,3] and V[5,4], the scores are [2,5] and the output [2,4]. A pairing width of 3 for Q/K with a Value width of 4 is still legitimate.

MHA, MQA, GQA: how heads are shared

An attention head is one path that matches and then aggregates content. MHA usually gives every query head its own K/V head; MQA has several query heads share one group of K/V; GQA sits between them, sharing by group. These are structural choices, not a switch to be flipped at run time.

Independent shape example: 8 query heads and 2 K/V heads, grouped evenly, means every 4 query heads share 1 group of K/V; the cache is accounted for by the number of K/V heads.

RoPE, rotary position encoding

Pair up the features of Query and Key into two-dimensional groups, rotate them by an angle that the position decides, and then compare them. R is the rotation matrix and θ an angle or an angular frequency; position IDs are not token IDs.

Independent two-dimensional example: rotating [1,0] by 90° gives [0,1]. Real models usually set a different rotation frequency for different pairs of features, rather than 90° throughout.

MoE, experts and the router

MoE is a model structure that contains several sub-networks; the router selects or weights a few experts for the current token's representation. An expert is usually a numeric sub-network, not a chat agent given a prompt such as "math teacher".

Independent example: with 4 experts and 2 chosen per token, one pass activates only 2 of the expert paths; the parameters and routing state that the model design requires still have to be stored.

∂, ∇: partial derivative and gradient

∂L/∂w asks how the loss L changes when w changes a little while the other independent variables are held fixed. These rates of change across many parameters make up the gradient ∇L. They are derivative notation, not two ordinary numbers divided by each other.

Independent micro-example: for L=w², the gradient at w=3 is 6. In the simplest update w←w−η×6, η is the learning rate.

Jacobian: the table of derivatives for several outputs

When a function has several inputs and outputs, the Jacobian records in one table the partial derivative of every output with respect to every input. J_F denotes that table for the function F; it is not a new matrix in the training data.

Independent micro-example: F([x₁,x₂])=[2x₁,3x₂], J_F=[[2,0],[0,3]]. The derivative table of the residual x+F(x) is I+J_F.

loss, cross entropy, negative log likelihood

The loss is the scalar that measures, during training, how far the prediction is from the target. For a single correct token label, the cross entropy equals its negative log probability, −ln p_target. It is the value of the objective function, not another token the model has output.

Independent micro-example: with a probability of 0.8 on the correct item the loss is about 0.223144; with a probability of 0.2 it is about 1.609438. The further the probability is from the correct item, the heavier the penalty.

Labels, teacher forcing and shift

A label is the correct target to compare against; next-token training lines each input position up with the token after it. Teacher forcing computes with the real prefix from the data rather than replacing it with what was just sampled.

Independent example: for the full sequence [a,b,c,d] the input [a,b,c] can be paired with the labels [b,c,d]. When the interface already shifts them, do not shift them a second time outside it.

Optimizers, Adam and AdamW

An optimizer turns gradients into parameter updates. Adam also keeps, for every parameter, a moving average m of the gradient and a moving average v of the squared gradient; these are training state, not attention values. AdamW decouples weight decay from the adaptive gradient update.

Independent first-step example: with g=2, old m=0 and β₁=0.9, the new m is 0.2, and after bias correction m_hat=2. The 0.2 cannot be taken as the full size of the update.

π, π_ref and β: the symbols of a preference objective

In policy and preference optimization, π denotes a conditional-probability policy and π_ref a fixed reference policy; β is a coefficient that sets the scale of the objective or the strength of the constraint. The probability of a complete answer is built from the conditional probability of each token.

π here is not the circle constant, and β is not the LayerNorm offset parameter. The w/l in the DPO expression mark the preferred and the non-preferred answer, not a weight w and a layer count L.

SFT: supervised fine-tuning

Take task inputs and the answers expected of them as training samples, and go on adjusting the parameters of an existing model. It is a training process, not stuffing examples into one prompt for the occasion.

Independent example: the input is "convert the time to UTC", the label gives the correct conversion, and training computes the loss against the label and changes the parameters. Showing an example in the conversation alone is context prompting.

RLHF, the reward model and the policy

RLHF refers broadly to processes that train behavior using human feedback. A reward model scores behavior such as an answer; the policy is the probability model that actually produces actions. Their jobs differ, and a high reward is not automatically factual correctness.

Independent example: if the reward model prefers long answers, the policy may learn to write at length without being more accurate; the reward criterion therefore needs to be validated.

DPO: building a training objective from preference pairs

From the better and the worse answer to the same input, together with a reference policy, DPO builds a preference training loss directly. It changes the model parameters; it is not a prompt that says "think again".

First sort out the probabilities the current policy gives the two answers, the probabilities from the reference policy, and the preference label; then see how they enter the log ratio.

PPO,GRPO,advantage

These are concepts from policy optimization. PPO commonly limits the update with a ratio of new to old action probabilities, plus clipping; GRPO-style methods build the advantage by comparing rewards within a group. An advantage is performance relative to a baseline, not the probability that an answer is correct.

Independent raw-difference example: rewards [0,1,1] minus the group mean of 2/3 give [-2/3,1/3,1/3]. An algorithm may normalize them again, so the two forms must not be mixed.

KL divergence: a difference between distributions that has a direction

For distributions p and q over the same candidate set, KL(p∥q)=Σpᵢln(pᵢ/qᵢ). It measures the difference between distributions and is usually not symmetric; where p has positive probability and q is 0, the cost even becomes infinite.

Independent example: with p=[0.5,0.5] and q=[0.25,0.75] it is about 0.143841; do not take it for a Euclidean distance or a probability.

LoRA, low rank and r

LoRA represents part of a weight increment as the product of two smaller matrices instead of retraining the whole large matrix. r is the inner dimension, and it bounds the maximum rank of that product. Where sources use a row-vector or a column-vector convention, the left-right order of A and B can differ.

Micro-example in the right-multiplication convention: with W[4,6], the increment A[4,2]B[2,6] is still [4,6]; r=2. A here is not the table of attention shares.

Quantization, scale and zero point

Quantization approximates the original floating-point numbers with integers of fewer bits plus metadata such as a scale. The scale maps the integer steps back to real numbers, and the zero point maps the real 0 to some integer. It does not turn semantic features into one-hot.

Independent symmetric example: with scale=0.1, 0.26 rounds to the integer 3, and dequantizing gives about 0.3 — an approximation error already.

FP32, FP16, BF16: formats for storing numbers

These names describe how the bits of a floating-point representation are allocated. FP32 is usually 4 bytes per number, FP16 and BF16 2 bytes per number; the two 16-bit formats differ in exponent range and mantissa precision. A number of bits is not the model's hidden dimension.

Independent size example: the data itself for 100 FP16 numbers is 200 bytes, not counting object, allocator and alignment overhead.

Mixed precision, loss scaling and master weights

Mixed precision uses different numeric formats for different computations or states. A master copy of the weights can be kept at higher precision as the baseline for updates; loss scaling enlarges the loss before the backward pass and then scales the gradients back down, lowering the risk of underflow at some low precisions.

This is not multiplying the learning rate up at will. Whether master weights or loss scaling are actually needed depends on the precision format, the optimizer and the implementation.

checkpoint: you must look at the object that was saved

A model checkpoint saves weights or training state; activation checkpointing saves a few intermediate nodes so they can be recomputed on the backward pass; an agent task checkpoint saves how far execution has got. The three share a name, but what they restore is entirely different.

When you see "checkpoint", first ask whether it restores parameters, recomputes activations, or continues a task. An agent saving a summary does not update model weights.

KV cache and prompt cache

A KV cache stores the K/V numbers of each layer under the conditions of a particular model, prefix and position; a prompt cache is the mechanism by which a service reuses the computation of an identical prefix when the conditions are met. Neither of them is long-term memory of facts.

When a new token is appended and the old causal prefix has not changed, the old K/V can be reused; rewriting the history as a summary usually changes the input, and must not be treated as leaving the original cache untouched.

Prefill / Decode: two phases of computation

Prefill processes a stretch of input that has already been given, forming the representation and the cache; decode feeds in the new token just selected and predicts the one after that. The new token selected only produces its own K/V at the next forward pass.

Independent sequence: [a,b,c] is processed first and d is selected, at which point the cache covers the 3 positions processed; only after d is processed does it cover 4, and then e is selected.

FlashAttention: changing how intermediate data is stored and read

By means such as tiling and online normalization, it avoids keeping the full attention score/weight matrix in slower VRAM for long; the target is still the same attention computation, and floating-point rounding can vary with the order of operations.

It does not compress tokens permanently, and it does not skip any Key. Keep "not writing the whole table to VRAM" apart from "not doing this arithmetic at all".

PagedAttention: managing K/V storage in pages

Store a logically contiguous K/V sequence in several physical blocks, located through a block table. It mainly changes how the storage is managed and shared; it does not replace the attention formula with an algorithm that means something else.

Independent example: logical positions 0—3 are in physical block 7 and 4—7 in block 2; logical position 4 need not physically follow position 3.

HBM, SRAM and bandwidth

HBM here means the larger high-bandwidth memory on a GPU; the related on-chip SRAM is usually smaller and closer to the computation. Bandwidth is how many bytes can be moved in a given time; arithmetic intensity is the ratio of computation to data moved.

Independent accounting: 100 operations against 10 bytes moved is about 10 operations per byte. It is not a measurement of real hardware performance.

FLOPs and FLOP/s: a count and a rate

FLOPs usually means a number of floating-point operations; FLOP/s means a rate of operations per second. Papers and vendors may count a multiply-add as one operation or two, so the basis has to be fixed.

Dividing total operations by the theoretical peak is no promise of real elapsed time: movement, queueing, communication and actual utilization cost something too.

DP, TP, PP, ZeRO and FSDP

Data parallelism lets several copies of the model process different samples and synchronize their gradients; tensor parallelism splits the parameters and the computation of a single operator; pipeline parallelism puts different layers on different devices. ZeRO/FSDP-style techniques also shard parameters, gradients or optimizer state.

What they split differs: dividing one layer's matrix in two is not the same as giving two independent user tasks to two agents.

temperature / τ: the temperature of the generating distribution

A positive temperature τ is usually used to divide the logits by τ before the softmax. A small τ makes the distribution more concentrated and a large τ flattens it; subtracting the same constant from every score, by contrast, does not change the distribution mathematically.

Independent comparison: at τ=2, [2,1,0] first becomes [1,0.5,0]; the probabilities for τ=1 must not be joined on as the result of this step.

Top-k, Top-p and renormalization

Top-k keeps the k items with the highest probability; Top-p sorts by descending probability and keeps the leading candidates until the cumulative probability reaches a threshold. When used for sampling, the kept candidates have to be renormalized over the remaining total mass.

Here k is a number of candidates and p a cumulative-probability threshold; k is not the attention Key table K, nor the representation width d_k.

Speculative decoding: the draft and verification by the target

A cheaper draft mechanism proposes several tokens first, and the target model then verifies them. An algorithm that preserves the target distribution has to specify the acceptance probability and the corrective distribution used after a rejection, rather than only checking that the text "looks right".

One verification can check the conditional distribution of several candidates; whether it speeds anything up depends on the acceptance rate and on computation and scheduling costs. A teaching example about distributions is not a real throughput test.

Harness / the harness

This is the program that runs around the model: it prepares the request, parses the model output, checks tool permissions, carries out actions, saves state and calls the model again. It is not a layer inside the model parameters.

For the same sentence "read the file", what the model produces is call data; it is the harness that calls the file interface and puts what actually came back into the next turn's input.

API, SDK and the call boundary

An API is an agreed interface that programs can call between them; an SDK is a set of libraries that make calling those interfaces easier. Installing an SDK does not train a model, obtain a permission or guarantee that a task is right.

The request "read the path a.py" and the return "the bytes of that file" are two objects interacting across an interface.

Schema and Structured Outputs

A schema is a set of structural rules about fields, types and the like; a structured-output mechanism makes it easier for the model to return data that follows those rules. Valid fields still do not mean that the target file exists, that access has been granted, or that the request is right for the business.

Independent example: path is required to be a string; {"path":3} does not match the type rule, and {"path":"missing.py"} follows the structure yet may still find no file.

SSE, chunk, delta: different layers of fragmentation

SSE is the text protocol for server-sent events; a network chunk is the stretch of bytes received this time; a delta is the incremental content of one output item. Their boundaries are not guaranteed to coincide. One complete event does not necessarily mean complete tool arguments either.

The arguments may arrive first as {"path":"a and then as .py"}; they have to be assembled and the protocol's completion condition awaited — seeing a fragment is no reason to execute.

call_id,item_id,request_id

These are identifiers for objects at different layers: a tool call, an output item, a request or a response. They match increments and results back to the right object; they are not the token IDs of the model input, and they are not business idempotency keys by nature.

Two read_file calls can carry c1 and c2; when the results come back in the reverse order they are still paired by call identifier, not guessed by tool name.

MCP,Host,Client,Server

MCP is a protocol by which an AI harness connects to tools and resources. The Harness is the application, the Client is the protocol connection participant inside it, and the Server provides the capability. Connecting, discovery, exposing something to the model, authorization and the actual call are separate steps.

A tool existing on the Server does not mean its description is already in the sub-agent's request, nor that the current user may run it.

JSON-RPC, stdio and HTTP

JSON-RPC lays down how a method, its arguments, an identifier and a result are represented in JSON; stdio communicates over a process's standard input and output; HTTP is a network request protocol at another layer. The name of a protocol carries no permission with it.

When stdout carries protocol messages, ordinary debug logs should be kept out of that stream and usually go to stderr; otherwise even legitimate logs can break message parsing.

OAuth, scope and authorization

In an authorization setting, OAuth lets an application obtain access credentials according to what was granted; a scope declares one class of access range, and the resource service should still check the specific permission. In a memory or task setting, scope can instead mean only the range over which something applies, and must not be conflated with a login credential.

Being granted "read the calendar" is not being granted the deletion of every event; a successful connection is no proof that an operation was approved.

Assembling context and the budget

Select content from the instructions, the task, retrieved evidence, tool results and the current state, and arrange it into this model request. The budget is the limit on how much input fits and how much output is reserved; it does not make the model remember all the material for good.

A piece of evidence should enter the request together with its source, the version it applies to and the key conditions; keeping only the one-line conclusion can change what it means.

Compaction: a lossy reduction of context

When the context has grown too long, replace part of the history with a summary, a selection or a particular compacted state. The representation it keeps is not every original detail; recoverable execution state and the original evidence should still be managed separately.

"Not tested" cannot be compacted into "the tests passed"; "the call timed out, the effect is unknown" cannot be compacted into "the call failed" either.

Thread, turn, session: the levels of a run

These are usually the harness's divisions of a conversation and of units of work, not layers of a neural network. A thread can mean one conversation, and a turn can contain the several model and tool cycles needed to answer one user task; where the boundaries fall depends on the product.

"This turn is done" cannot be equated with "every external tool has finished"; that takes looking at the actual events and results.

State, events and the reducer

State says what is known and done now; an event records what happened; a reducer is the program rule that combines the old state and an event into a new state. It need not call the model. Event sourcing can rebuild the state from the events.

Independent example: the old state is pending and becomes succeeded once a confirmation event carrying the operation_id arrives; without that confirmation the state must not be changed on the strength of a generated summary alone.

unknown / reconcile: verify first when confirmation is missing

unknown means the observer cannot yet confirm the effect; it does not mean the action half-succeeded in reality. Reconciling is verifying against the actual state of the target system, the operation identifier and so on, so that the record agrees with the facts again.

The response is lost after a file write: the file may already have changed. Read it back and verify, instead of reading the timeout as "it certainly was not written" and appending a second time.

Idempotence and the idempotency key

Idempotence means that repeating the same logical operation has, under the stated semantics, the same expected effect as performing it once. An idempotency key identifies one and the same intended operation; the system has to deduplicate at a reliable boundary and check what the request means.

Setting a value to 10 can be designed to be idempotent; adding 10 to a value accumulates when it runs again. If every retry takes a new key, the original key can no longer be used to deduplicate.

CAS, version checks and TOCTOU

CAS is a controlled operation that updates only after comparing that the expected version or value still matches. TOCTOU is the race in which something changes between the check and the use: a separate "look at the version, then write" is not automatically equivalent to an atomic CAS.

If a patch was produced from version 7 and the version is already 8 at commit time, overwriting directly should be refused and the work redone; a concurrent insert between the comparison and the write has to be prevented as well.

ACID, transactions and isolation

A transaction puts a group of database operations inside a defined commit boundary. ACID stands for atomicity, consistency, isolation and durability; the guarantee you actually get also depends on the isolation level, the configuration and the resource boundary.

A database transaction committing does not mean another mail service commits along with it. Writing the two operations into the same function does not automatically make a cross-system transaction.

WAL, fsync and atomic replacement

WAL is the idea of writing a log first and then updating the data by protocol; fsync asks for a file's data to be synchronized to storage; an atomic rename, where it is supported, keeps readers from seeing a half-finished replacement. Visibility and durability after a crash are not the same guarantee.

One file renaming successfully does not mean several files and a database committed together; durability also has to be checked against the platform, the directory and the storage behavior.

Outbox, saga and compensation

An outbox persists the business change together with the message waiting to be sent, and a dispatcher forwards it afterwards; a saga organizes steps across services into a process that can be compensated. They are designs for reliability across a boundary, not a natural guarantee that the far end runs exactly once.

An email already sent usually cannot make the recipient "not have seen it". Compensation may mean sending a correction; it is not the same as really undoing what has already taken effect.

Backoff, jitter and cancellation

Backoff makes the interval between retries grow; jitter adds a random perturbation so that requests do not all retry at the same moment. A cancellation signal is notice that a stop has been requested; it does not withdraw external side effects already committed.

A read-only request whose connection fails temporarily can be retried; when the result of a write request is unknown, verify first. "Retry for longer" is no substitute for permission or idempotence design.

TF, DF, IDF: term statistics

TF counts how often a term occurs in the current document; DF counts how many documents contain it; IDF uses whole-corpus statistics to lower the contribution of common words and raise that of rarer, more discriminating ones. All three are statistics, not the model's learning rate.

If only 2 of 10 documents contain a word, DF=2; if the word occurs 3 times in one of them, TF=3 for that document. The two numbers are not interchangeable.

BM25 and N, df, k₁, b

BM25 is a scoring formula for term-based retrieval. In the usual notation N is the total number of documents, df the number of documents containing the term, tf the term frequency in the current document, |D| the length of the current document and avgdl the average length; k₁ and b are the settings for term-frequency saturation and length correction.

k₁ is not the Key vector k₁, and b is not a neural network bias. The score only orders candidates; 8.2 cannot be read as 82% accuracy.

RRF: fusing by rank

For a document's rank r on each recall path, RRF contributes 1/(c+r), and these are added. c is a smoothing constant and r usually starts at 1; a candidate that did not appear on a path does not receive that path's contribution out of nowhere.

Independent example: with c=10 and a document ranked 1 and 3 on two paths, it gets 1/11+1/13, about 0.167832. This is not adding the raw BM25 and cosine scores together.

Norms and cosine similarity

The usual L2 norm of a vector is the square root of the sum of the squares of its components. Cosine similarity is the dot product divided by the product of the two norms, so it mainly compares direction; if either vector is zero, that case has to be handled explicitly.

Independent example: [1,0] and [2,0] have a dot product of 2 and a norm product of 2, so the cosine is 1. It is not attention's raw dot product before normalization.

ANN and HNSW: approximate retrieval structures

ANN here means approximate nearest-neighbor search, not artificial neural networks in general. HNSW is a structure that narrows the search using a hierarchical graph of near neighbors; its parameters affect recall, speed and memory.

Finding something quickly is no guarantee of finding the exact nearest neighbors; nor does ANN recall equal the correctness of the final answer.

bi-encoder, cross-encoder and reranking

A bi-encoder encodes the query and the document separately, so document vectors can be stored in advance; a cross-encoder processes a query and a document together for a finer judgment, usually computing every pair. Reranking only orders candidates that have already been recalled.

A correct document that was missed is not in the candidate set, and no reranker, however strong, can put it first; the recall has to be fixed first.

ColBERT and MaxSim

ColBERT-style methods keep several token vectors for the query and for the document, then interact them late. The usual MaxSim takes, for each query token, the highest similarity with any document token, and then aggregates.

It is not dual-encoder retrieval where "the whole document has only one vector", and it is not the self-attention output of each layer of a generative model.

RAG and the evidence behind generation

Retrieval-augmented generation is an application flow: obtain external material first, then have the generating model answer from it. Retrieved material is not a new instruction from the user; even with a citation, you still have to check whether the citation really supports the claim.

Finding an "overview of retries" is not enough to answer "can a write operation in this version be retried automatically"; that also takes the conditions of use, the version and the exceptions.

HyDE: the hypothetical text is only used to find material

Have the model generate a hypothetical answer or document and use its representation for retrieval. That generated text is an aid to finding evidence, not a source of facts already found.

The model guesses "it may be cache invalidation", which is reason enough to widen the search; before there is real evidence it must not be written up as "cache invalidation confirmed".

GraphRAG, RAPTOR and hierarchical organization

GraphRAG-style methods use organizational information such as entity relationships and communities; RAPTOR uses hierarchical clustering and summaries to support retrieval. They introduce extra derived information, and with it problems of updating, provenance and error propagation.

When the source document changes, an old summary or a relationship in the graph may be out of date. Changing the original text is no proof that every derived index has been updated with it.

AST, LSP and call relationships

An AST is the syntactic structure tree of code; LSP is the protocol by which an editor and a language service exchange definitions, references, diagnostics and the like. A syntax tree can be parsed from the code, while semantics across files usually also needs the language and the project environment.

A string with the same name appearing somewhere does not mean the same function is called; dynamic behavior such as string concatenation and reflection can also go beyond what static analysis is able to settle.

TTL, valid time and record time

A TTL is an expiry setting on storage or a cache; valid time is when a fact applies; record time is when the system came to know it. An expiry policy cannot stand in for verifying the fact and its source.

A rule that takes effect on October 1 is only read on October 10: the business valid time counts from the 1st, while the time the system knew about it counts from the 10th.

semantic, episodic and procedural memory

Semantic memory keeps facts, episodic memory keeps experiences, procedural memory keeps conditional methods; working memory serves the current task. CoALA is a framework for analyzing this kind of cognitive architecture, and MemGPT studies how a limited context and external storage are organized.

"Patch p7 failed because a test was missing" is an experience; "Windows has to be supported for now" is a fact; "check the separator when changing path rules" is a conditional procedure, and must not be promoted straight into running the full test suite for every task.

Skill, JIT and the trigger description

In a capability-loading setting, a Skill is a reusable set of guidance and resources; JIT means loading only when needed, and does not necessarily mean a compiler's just-in-time compilation. A trigger description helps the model judge whether something applies; it does not grant tool permissions by itself.

First judge whether the task needs a given skill, then read the details; a loaded skill is not the same as its requirements having actually been carried out.

DAG, dependencies and the critical path

A DAG is a task dependency graph that is directed and has no cycles. The arrow A→B means B depends on A finishing; the critical path is the longest dependency chain, the one that fixes the earliest finishing time given the task durations and dependencies.

Independent example: A takes 2 seconds, B and C depend on A, take 3 and 5 seconds and can run in parallel, so finishing both after A takes at least 7 seconds — not 2+3+5=10 read as wall-clock time.

Handoff and agent-as-tool

A handoff gives control to another agent; agent-as-tool treats a sub-agent as a callable component whose result returns to the current controller. An orchestrator is the coordinating program or agent responsible for distributing and integrating the work.

Delegation needs the task, the boundaries, the evidence and the completion conditions; it does not require copying the whole history of the main session across.

oracle, assertions and mutation testing

An assertion compares the actual result with what was expected; the oracle is the reliable criterion that expectation comes from; property testing checks a general rule; mutation testing puts small errors in deliberately, to see whether the tests fail.

An exclude function that always returns True can pass a single positive example; it takes the counterexample "src/a.py should not be excluded" to expose it.

Precision, Recall, MRR and nDCG

Precision looks at how many of the returned results are relevant; recall looks at how many of the relevant items that should have been found were found; MRR averages the reciprocal rank of the first correct item; nDCG takes the degree of relevance and the position in the order into account, and normalizes against the ideal ordering.

Independent example: 5 documents should be found, 4 are returned and 3 of them are relevant, so precision is 3/4 and recall 3/5. Do not swap these two denominators.

pass@k and pass^k

pass@k-style metrics usually care about at least one success in k attempts; pass^k-style metrics stress succeeding every time. The exact basis of an estimate depends on the benchmark, and stopping after one success must not be conflated with being reliable every time.

Under an independent, equal-probability assumption of p=0.8, at least one success in 3 attempts is 0.992 and all 3 succeeding is 0.512. If real tasks are correlated or differ in difficulty, it has to be computed differently.

Bootstrap, paired comparison and the confidence interval

Bootstrap resamples an existing sample with replacement to watch how a metric fluctuates; a paired comparison should draw the A/B results of the same task together. A confidence interval comes from a specified sampling procedure; it is not how confident the model is about its answer.

Breaking the A/B pairing of tasks mixes differences in question difficulty in as well; and more resampling cannot fix a task set that does not represent the real business.

Binomial, standard error and the Wilson interval

The binomial model is commonly used for a fixed number of independent success/failure trials; the standard error describes the scale on which an estimator fluctuates; Wilson is one way of constructing an interval for a proportion. McNemar looks at disagreement in both directions among paired classification results.

Dependent samples, a mixture of task difficulties or hand-picked questions change how far the result can be read; a statistical formula is not evidence that "the improvement must come from this change".

Trace,Span,Log,Metric

A trace strings together the operations that belong to one task, a span records the time and attributes of one of those operations, a log records the details of an event, and a metric aggregates many runs. They record observable execution, which is not the model's real inner thinking.

The durations of parallel spans cannot be added up blindly into the user's waiting time; look at the dependencies and the start and end times.

TTFT, TPOT, p95 and throughput

TTFT is the latency from the request to the first output token; TPOT describes the statistics of the time per token after that; p95 is the quantile that about 95% of observations in a given window do not exceed; throughput is the amount completed per unit of time. Say where the timing starts and stops.

A fast first character does not mean a fast task: tool execution may still take a long time. Nor does theoretical peak throughput equal the latency one user sees.

SLI, SLO and the error budget

An SLI is a service level indicator that is actually measured; an SLO is the target for that indicator; the error budget is the room for failure that target allows. They are objects of service operation, not model parameters.

"The API returned 200" may not be success for the user; some businesses should define the indicator as the proportion of tasks completed correctly within a bounded time.

Little's law: L=λW as local notation

In queue accounting, L is the average number of tasks in the system, λ is the average arrival rate and W is the average time spent in it; under applicable conditions such as stability, L=λW. Here W is not a projection matrix, and L is not the number of model layers.

Independent example: with 2 items arriving per second on average and an average stay of 3 seconds, about 6 items are in the system on average; an instantaneous spike cannot simply stand in for the long-run average.

Prompt injection, sandboxes and permissions

Prompt injection is an attempt to change the model's behavior through content that enters the context. A sandbox limits the resources a program can reach; authorization decides what is actually allowed. Labeling text "untrusted" is not the operating system having isolated it.

"Send the key out", read from a document, is still the content of that document, not a new authorization from the user. The tool execution boundary should judge the permission independently.

Patch, image channels and the visual projection

A patch in an image is a small block cut out of it, and RGB is the 3 channels red, green and blue; a patch in software engineering is a code patch — the same word for both. An image block, once flattened, can become a vector through a learnable transformation; it is not a lookup in a text vocabulary.

Independent image example: one 16×16×3 block holds 768 numbers, and after projection it can become d features. d is fixed by the model design.

CLIP and image-text contrastive learning

Contrastive learning uses an objective that makes paired representations easier to match and keeps unpaired ones relatively distinct. CLIP-style training learns the association between image and text; it does not automatically provide full chat generation or reliable desktop operation.

One image with its correct caption can serve as a positive pair and the other captions as the contrast; training for relevance does not mean every generated conclusion is factually correct.

SAE, activations and interpretable features

SAE stands for sparse autoencoder: it reconstructs a model's activations from a combination of relatively few active features. An activation is an intermediate number from this computation, not a complete record of natural-language reasoning. A successful reconstruction does not by itself prove that a feature has a unique causal meaning.

Seeing a feature change together with the output is a clue; judging causation also takes control of other conditions, intervention and a comparison.

Calibration, confidence and abstention

Calibration checks whether the stated confidence of a prediction matches how often it is actually correct; measures such as ECE and Brier do the accounting differently. A local token probability, the word "certain" in a sentence, and the correctness rate of a whole answer are not the same object.

Independent example: 100 items are all marked 80% confident and about 80 of them are correct; that supports the statistical calibration of this group only, and does not prove that every item is right.

σ: tell the function symbol from the statistic

In σ(XW+b), σ usually stands for whatever nonlinear function this layer has chosen; it may be ReLU or another, and σ alone does not make it a sigmoid. In statistical formulas σ usually means the standard deviation and σ² the variance. They are not the same object.

Independent example: if σ is specified as ReLU, σ(-1)=0; if it is specified as sigmoid, the value is about 0.268941. The function has to be defined before any result can be computed.

G, dQ, dW: the intermediate gradients in backpropagation

G=∂L/∂O is usually the gradient of the loss with respect to the current output O, passed back from the computation that follows. The backward pseudocode writes ∂L/∂Q as dQ and ∂L/∂W as dW; their shapes match the objects being differentiated, and are not the feature dimension d times Q.

Only after the forward pass O=AV, and once G has arrived, can dV=AᵀG and dA=GVᵀ be computed; dA changes the share path, dV the content path.

Concat, split and chunk: joining and splitting

Concat joins several arrays along a chosen axis; it does not add their elements. split or chunk groups them at specified boundaries. Every axis that is not being joined has to be compatible. chunk here means a block of an array, whereas a chunk in networking is a slice of bytes.

Independent example: two heads of [2,3] each, joined along the feature axis, give [2,6]; joined along the position axis they would give [4,3], which already means something different.

Dropout: the rule that randomly zeroes values during training

The common inverted dropout zeroes elements at random during training with drop probability p, and divides the kept ones by 1-p so that the expected scale is preserved. Evaluation mode usually turns this random operation off; the underlying function may require the caller to pass p=0 explicitly.

Independent example: with p=0.5, a value of 2 comes out as 4 if it is kept in a given mask and as 0 if it is dropped. This is not training permanently deleting the corresponding model parameter.

logsumexp: sum the exponentials first, then take the logarithm

logsumexp(z)=ln(Σexp(zᵢ)). A stable implementation subtracts the maximum m first and then computes m+ln(Σexp(zᵢ-m)). It is a single scalar, usable for computing log-softmax and cross entropy; it is not another round of random sampling.

Independent example: with z=[0,0], logsumexp=ln2 and both log-softmax values are −ln2. The result here can be negative, whereas a softmax probability cannot.

BatchNorm: statistics across samples, unlike LayerNorm

BatchNorm usually computes its statistics for one feature or channel along the batch axis and the applicable spatial axes; LayerNorm computes along the feature dimensions designated inside one sample. BatchNorm may use statistics from different sources in training and in evaluation, and the details still depend on the configuration.

The word Norm alone is no reason to mix up the statistics axes of different normalization layers; nor should two independent users come to share one session context because of it.

C(n,k), !: the number of combinations and the factorial

n! means the integers from 1 to n multiplied together, with 0!=1; C(n,k)=n!/(k!(n-k)!) is the number of ways to choose k of n distinct objects without replacement and without regard to order. It is not a model confidence C.

Independent example: C(4,2)=6. With n=10, c=3 and k=2, 1−C(7,2)/C(10,2)=24/45, about 0.533333.

O(·): the order of growth with size

Big O expresses an upper bound on the order of growth with size, usually leaving constants and smaller terms out. It has to be said which variables are growing, and whether the count is for a single step or for the whole sequence. O here is not the attention output matrix.

When the length doubles, the leading term T² becomes four times as large; but the time actually taken also depends on fixed overhead, memory and hardware utilization, so big O alone is no promise of a measured speed.

E, Π, ∼, ∝: common notation in probability expressions

x∼p means sampling from the distribution p, E means taking the expectation under the stated distribution, Π means multiplying the stated terms together, and ∝ means the two sides differ by a common factor rather than being equal already. Here E is not the embedding parameter table.

Independent example: pᵢ∝exp(zᵢ) still has to be divided by the sum of the exponentials over all candidates; where ∝ is written, an unnormalized value must not be read straight off as a probability.

BOS / EOS: sequence boundary markers

BOS is usually the special token for the start of a sequence and EOS the one for the end; a particular model or message template may use different names, counts and end markers. They are symbols in the input/output protocol, not proof of semantic correctness.

Meeting an EOS does not automatically cut attention between two training samples; isolating the reads still needs a mask, or a sample boundary the implementation supports.

JSON: structured text, not an action being executed

JSON is a text format that expresses data as objects, arrays, strings, numbers and so on. A braced object maps field names to values; a bracketed array keeps the order of its items. Parsing JSON only yields data; it does not automatically run a tool name inside it.

Independent example: {"path":"a.py","limit":3} has two fields; "3" is a string while 3 is a number, and a schema can require either one.

LF, CRLF and EventSource

LF is the line-feed character, and CRLF is a carriage return followed by a line feed. SSE lays down how event lines and blank lines are interpreted; EventSource is the browser's interface for receiving SSE. Teaching code that parses only one kind of separator is not a complete protocol implementation.

Real network fragments may happen to deliver CR and LF separately, so a parser should assemble them by the protocol rules it implements and must not take every network fragment for one event.

These are program type names from the cited snapshot of the Codex source. ResponseItem stands for one model response; ToolCall stands for the data of a call waiting to be made; ToolInvocation combines the call with execution context such as the session and cancellation; ToolRouter is responsible for the relevant tool path.

These objects are constructed and dispatched by the program; they are not tensors of the kind the model uses internally for Q/K/V. Field and permission handling must follow the pinned source cited, not be inferred from the names.

HEAD, working tree, ETag and content fingerprint

Git's HEAD marks the commit or branch currently checked out; the working tree may still hold uncommitted changes. An ETag is a validator for an HTTP representation, and what it guarantees depends on the service. A content fingerprint is computed over the bytes; these kinds of version identity are not interchangeable.

When the index comes from commit v7 but the file has been modified locally, the same file name does not mean the same content. Applying a patch or citing evidence should be checked against the version actually present.

IDE, CLI, UI and DOM

IDE is the integrated development environment, CLI the command-line interface, UI the user interface, and DOM the tree of structural objects of a web document. The code, selection and page information that each entry point attaches automatically can differ.

The model seeing the selected function in the IDE does not mean the same task in the CLI has received that function; check this turn's input objects first.

DPR, DPI and coordinate units

DPR usually means the ratio of device pixels to CSS pixels; DPI means dots per inch. Screenshot pixels, the interface's logical coordinates and screen coordinates need not share a unit, and there may also be scaling, cropping and offsets.

In an independent example where DPR=2 is stated and the other mappings agree, a CSS x-coordinate of 100 corresponds to 200 device pixels; this conditional relationship cannot be carried straight over to every screenshot.

MLA: a learned low-dimensional K/V representation

MLA refers to a family of multi-head latent attention architectures. It organizes the content behind K/V jointly in a lower-dimensional latent representation and handles the positional part by design. It changes the model's representation and parameter structure; it is not just ZIPping an ordinary KV file.

In c=xW_down, c is the latent vector for this computation and W_down the learned table of dimension-reducing coefficients; how it is later reconstructed or absorbed into a projection has to be explained for the specific architecture.
