Prerequisites for this chapter

A mask states which positions are visible, position encoding helps tell the order apart, and multiple heads process the representation in groups; backpropagation, meanwhile, traces how the final error travels back along the original computation. They solve different problems and cannot be guessed at together from one architecture diagram.

Each question in this chapter lists the groundwork it needs. You can take the matching Foundations lesson first, or use the self-check to confirm how well you have it.

This chapter takes apart dimensions and concepts that look alike: the sequence index, the logical position and the cache slot are not the same thing, and neither are the number of Q heads and the number of KV heads. Q077｜How are the causal mask, the padding mask and the chunked-decoding mask actually constructed?

What to know first for this question A causal mask forbids future positions and a padding mask excludes placeholder entries; with an existing cache the number of query rows and the number of readable columns differ, so a square triangular table cannot simply be copied.
Lesson 38 · Batching and paddingLesson 47 · A mask is not a black boxLesson 58 · KV cache explained from scratch

Core answer

The causal mask forbids reading future positions; the padding mask excludes padded positions that hold no real content; chunked decoding must also map a new chunk's local indices onto global positions after the existing prefix. Whether a key may be read is judged from the logical position and from validity, not by drawing a triangle in the top-left corner.[TR][CACHE]

Look at the full input first, then at the cache case

A 4-Token sequence, with rows as query positions and columns as key positions, where 1 means reading is allowed:

       k0 k1 k2 k3
q0     1  0  0  0
q1     1  1  0  0
q2     1  1  1  0
q3     1  1  1  1

The lower triangle appears here because the queries and the keys both start from the same global position 0. Now suppose 3 tokens are already cached and 2 new tokens arrive. The Q length is 2 and the K length is 5; the new queries are at global positions 3 and 4, so the correct mask is:

       old0 old1 old2 new3 new4
new3     1    1    1    1    0
new4     1    1    1    1    1

The general form is key_position ≤ past_length + local_query_index. Creating tril(ones(2,5)) directly makes the first row see only old0 and the second only old0 and old1, wrongly hiding most of the history. It is still a legal 2×5 matrix, so a shape check will not expose the problem.

Now add padding. Two sequences are 3 and 5 long, and the shorter one is padded when they are batched. A padded key position should receive no attention weight; a padding query position may still be computed by the operator, but it must not be used as a valid answer or as a training target. With left padding the array index and the real token position come apart more easily, so position IDs should follow the model's and the implementation's conventions rather than the array index alone.

The mask for cached decoding has to be filled in by absolute position; the small triangle cannot simply be copied

Conditions for this example: an independent cache example: old positions 0, 1 and 2 have been processed and the new queries are at 3 and 4; the keys cover 0—4. The "readable=1" in the figure below only states the logically permitted relation, which is then converted for the target API.

How to read the changes in the figure

Write out each Query's real position on paper first, then check key_pos≤query_pos column by column. All that is needed here is comparing two integers; there is no need to memorize framework parameter names first.

When PAD is present, the key must also be real content; the causal constraint and the padding constraint are a logical "and", not a choice between the two.

In PyTorch SDPA a boolean True means take part, while in some MHA masks True means blocked. The 1 in the figure is not a notation that carries across interfaces, and has to be converted before the call.

Do not conflate: a tensor of shape [2,5] can be entirely correct while a wrong triangle quietly drops part of the history. Besides shape, the allow table and the output have to be tested.

Drawing the causal, padding and loss masks on one and the same sequence

Input and conditions. The second sentence in the batch is [你,爱,PAD]. The validity of the three positions is [1,1,0]; right padding is used, and the real token positions are 0 and 1.

Join the steps up. All three masks may look like tables of 0s and 1s, but they restrict different things: what may be read, which data is real input, and which positions take part in scoring.

Limits and counterexamples. The 0s and 1s here are this example's notation for "visible / not visible"; a particular library's boolean mask may use the opposite convention.

Worked example · X07

One and the same "allow table", and why its boolean values are reversed between interfaces

Input and conditions. The causal visibility of two tokens is: row 0 can see only column 0, and row 1 can see both columns. Define the semantic allow table first, as [[true,false],[true,true]].

Steps and objectsInternal actionIntermediate result / new state
1 Write the semantics firstTrue means "this example wants access allowed"This definition is independent of any API.
2 Pass it to scaled_dot_product_attentionPer that interface's documentation, boolean True means taking part in attentionPass [[True,False],[True,True]] as it stands.

Follow-up: if the whole answer is fed in at once during training, is that not peeking at the answer?

No, as long as the visible range at each position is right. The hidden state at position i can read only x≤i, and it is used to predict x(i+1). A label existing in the batch does not mean the forward pass may read it. Predictions for several positions can be computed at the same time, because the correct prefix is already supplied by the training data. With the mask removed the training loss may look unusually good while the task being learned does not match the conditions of deployment.

Follow-up: if two documents are concatenated for training, does a single EOS isolate them completely?

Start with the objects and symbols used here
BOS / EOS: sequence boundary markers
BOS is usually the special token for the start of a sequence and EOS the one for the end; a particular model or message template may use different names, counts and end markers. They are symbols in the input/output protocol, not proof of semantic correctness. Meeting an EOS does not automatically cut attention between two training samples; isolating the reads still needs a mask, or a sample boundary the implementation supports.

Not necessarily. EOS is a marker in the sequence's content; it does not automatically stop attention from crossing a document boundary. If the goal is to isolate the samples strictly, a segmented attention mask is needed, with the positions and the loss range handled consistently. If cross-document context is allowed, a different strategy is possible; what matters is being clear about the training objective, and not taking "a separator appeared" for definite isolation.

Follow-up: how do you write a test that catches a mask error?

Start with the objects and symbols used here
Dropout: the rule that randomly zeroes values during training
The common inverted dropout zeroes elements at random during training with drop probability p, and divides the kept ones by 1-p so that the expected scale is preserved. Evaluation mode usually turns this random operation off; the underlying function may require the caller to pass p=0 explicitly. Independent example: with p=0.5, a value of 2 comes out as 4 if it is kept in a given mask and as 0 if it is dropped. This is not training permanently deleting the corresponding model parameter.

Fix the weights, switch dropout off and save the prefix output first; then change only the future tokens, and the prefix's corresponding logits should not change. Then compare the outputs of whole-sequence inference, token-by-token inference and several chunked variants: all three should agree within a reasonable floating-point tolerance. Removing the mask or resetting the positions on purpose should make the test fail; if it does not, the test very likely does not cover the error it is aimed at.

Engineering deep dive · E05 · continues Q009

A boolean mask has the opposite meaning, and once a cache is added is_causal can also align to the wrong edge

Prerequisite: Lesson 46 · Lesson 47 · Lesson 58. Reading order: confirm the run contract first, then look at the counterexamples and the fix, and finally test the limits.

Two correct APIs can still be wrong in combination

In PyTorch's SDPA, boolean True means the position may take part; in MultiheadAttention's attn_mask, True means the position is forbidden. This is not a small naming difference: reusing the same block of boolean data directly inverts the visibility relation.[SDPA] [MHA]

Locally, identity projections line MHA up with the low-level SDPA: pass ~allowed to MHA and pass allowed to SDPA, and the outputs agree; without the inversion they do not. This test isolates "what the mask means" specifically, and should not be mixed with the previous section's asymmetric-matrix test of projection transposes.

The second pitfall: a non-square triangle needs absolute positions

The cache already holds 3 positions and 2 new queries arrive, so K/V are 5 long in total. The new queries are at absolute positions 3 and 4, not 0 and 1. The correct allow table is:

            Key位置 0  1  2  3  4
新Query位置3       1  1  1  1  0
新Query位置4       1  1  1  1  1

PyTorch 2.10 SDPA's is_causal=True aligns a non-square mask to the top left, so a 2×5 triangular table comes out as 10000 / 11000. It restricts history that should not be restricted; this is an interface contract with a clear version behind it, not "the model forgetting the context".[SDPA]

A numeric counterexample makes the error obvious at a glance

Set both Q and K to 0 so that every legal position has the same score, and let V take the values 1, 2, 3, 4 and 5. The correct two rows average 2.5 and 3.0; the top-left triangle gives 1.0 and 1.5. This book ran both paths with the real SDPA.

q_positions = torch.arange(3, 5)   # 本轮绝对位置
k_positions = torch.arange(5)      # 历史 + 当前
allowed = k_positions[None, :] <= q_positions[:, None]
out = F.scaled_dot_product_attention(q, k, v,
                                     attn_mask=allowed,
                                     dropout_p=0.0)

This passage is an explicit absolute-position mask scheme. Do not switch on an automatic causal option that conflicts with it at the same time. A real model adapter may already have handled the offset, so check the call boundary and avoid correcting it twice.[CACHE]

Follow-up: what if the history lengths within a batch differ?

Stop using one global P to generate the offsets for every sample. Combine each sample's real visible positions with the padding and the cache layout. An unwritten slot in a static cache must not be treated as history already read, and a sliding window also has to bound the lower end. Broadcasting succeeding over the dimensions does not mean every sample has the same read rule.

Follow-up: will switching to FlashAttention fix it?

The name of a low-level implementation is no promise about alignment. Different interfaces may use different causal-alignment conventions, and a model's wrapper layer may add an offset of its own. Fixing one explicit allow table with a cache and comparing its numbers against a whole-sequence forward pass without a cache is the correctness check that transfers.

Q078｜How does RoPE let attention know position? Why can the cached positions not start from zero each turn?

What to know first for this question Position is not token identity. RoPE rotates a pair of coordinates by an angle that depends on the position, so that a relative-position relation appears in the dot product; it does not add the position number to the vocabulary ID.
Lesson 42 · The arithmetic a model does mostLesson 48 · Position IDs and RoPE

Core answer

RoPE rotates each pair of components of Q/K by a position-dependent angle, so that after both positions have been rotated the dot product contains the difference in position. It does not simply add the position integer to the Token ID. Cached inference has to keep the logical positions of the old and new tokens continuous, or follow a specified position policy; otherwise the relative relation is changed.[ROPE]

Deriving relative position from a two-dimensional rotation

For the two-dimensional vector x=[a,b], position p and frequency θ give:

R(pθ) x = [a cos(pθ) − b sin(pθ), a sin(pθ) + b cos(pθ)]

With Q at position p and K at position t, the dot product is (R(pθ)q)ᵀ(R(tθ)k). Using R(pθ)ᵀ=R(-pθ) and the composition property of rotations gives qᵀR((t-p)θ)k. So the position information enters the relevance through the difference t-p. A high-dimensional vector applies a different frequency to each pair of components, which provides position variation at several scales.

This does not mean attention depends on the difference in position alone: q and k themselves are still determined by the text content and by the previous layer's representation. RoPE supplies the relative-position structure, while content matching remains the job of the learned projections. Nor can it be said to make the model generalize naturally to any length; phase combinations beyond the training distribution can still degrade it.

Suppose the prefix length is P=100, so the new token belongs at position 100. If its Q/K are wrongly rotated as position 0 while the old K is still stored as positions 0 to 99, the "distance" the model reads is no longer the real distance. The tensor length, the dtype and the cache concatenation axis may all be right, yet the logits have already drifted away from the whole-sequence forward pass.

What RoPE keeps is the relative angle, not a position that starts over each turn

Follow-up: can every position be shifted at once?

In an ideal pure RoPE dot product, adding the same offset to both the Q and the K position preserves the relative difference. A full model, though, may have other position-dependent mechanisms, sliding-window rules, special positions or a scaling strategy; and an already-rotated cache cannot be transformed consistently by changing one position counter. The mathematical shift property is not in itself a safety proof for any given cache-truncation implementation.

Follow-up: how is long-context extension done?

Common approaches include position interpolation, frequency scaling, adjusting particular frequency bands, and continued training on long sequences. They try to bring position patterns beyond the original training length closer to a learnable range while keeping local distinctions. Local precision and long-range coverage may have to be traded off, so real tasks such as retrieval, combining across segments and locating code have to be tested — not just "whether the interface accepts more tokens".

Follow-up: why is it usually Q/K that are rotated rather than V?

This design puts the relative-position signal mainly into the computation of the read weights, while Value still supplies the content being mixed. Other architectures may take other approaches; this implementation choice must not be inflated into a theorem that every model is mathematically obliged to follow. When reading source code, check whether the cache holds K before or after rotation, and whether reuse rotates it again.

Engineering deep dive · E06 · continues Q010

Position IDs, cache slots and RoPE: all called position, and not the same number

Prerequisite: Lesson 47 · Lesson 48 · Lesson 58. Reading order: confirm the run contract first, then look at the counterexamples and the fix, and finally test the limits.

First, list the three kinds of count

The logical position describes where a token sits in the model's sequence; the physical cache slot describes which array cell holds its K/V; the valid length describes how much non-PAD content there is. In a simple example with no PAD and no sliding window they happen to be equal, but that is no reason to merge the fields in engineering. The pinned version of the Transformers cache documentation distinguishes cache_position from padding content explicitly.[CACHE]

For instance, physical slots 0 and 1 are left PAD and slots 2, 3 and 4 hold "我/爱/学习". Some adapters record the position_ids of the three valid tokens as 0, 1 and 2 while the cache's current physical length is 5. The valid length 3 must not be used directly as the next cache write slot. How a particular generator represents a PAD cache has to be read from its implementation; what is given here is a teaching layout that states explicitly that the objects may differ, not a uniform template.

Positional rotation must not be applied again when the cache is reused

A common RoPE implementation rotates Q/K first and caches the rotated K. Rotating the old K again by its original position when it is read on the next turn amounts to adding the angle twice. This book's two-dimensional counterexample: [1,0] rotated by 90° gives [0,1], and another 90° turns it into [-1,0]. The shape is identical and the meaning entirely different. Other implementations choose to cache the unrotated values, which reverses the responsibility; the cache's representation format is part of the contract.

A sliding window must not wind absolute positions back to zero

Once a sliding window has evicted old slots the stored length can stay constant, but the next token's logical position normally keeps growing. Treating the slot index as the position and starting from 0 each time changes the position phase and the visibility. Changing the RoPE scaling configuration, the position offset or the adapter can also make an existing cache no longer applicable.

Which invariants detect these errors

Build a short sequence and compare the last position's output from "one forward pass over the whole thing" with the output from "segment-by-segment forward passes plus a cache"; cover no PAD, left PAD, a batch of differing lengths, increments of more than two tokens, and crossing the sliding-window boundary. The comparison should use the same model parameters, the same precision and dropout switched off. When a difference appears, check in turn the token identities, the absolute positions, the allow table, the write slot and the number of rotations, instead of simply loosening the error threshold.

Follow-up: why can an identical token prefix still not share a cache?

Changing the model weights, a LoRA, the position configuration, the image encoding and so on all change K/V; hashing the token list alone is not enough. vLLM's design uses prefix dependency plus extra hash information to identify blocks that can be reused.[PREFIX] This does not mean that every system handles a change of external adapter for you automatically.

Follow-up: can clearing the cache "fix" the problem?

It is a valuable comparison: if the whole sequence is right and the incremental path is wrong, suspecting the cache path is well founded. But disabling the cache permanently only avoids the symptom, and it can raise costs considerably. Once you have found which identity or position contract was broken, fix it and keep a regression test for the consistency of the two paths.

What to know first for this question Multiple heads group the representation; MQA and GQA let several query heads share fewer K/V heads. Count how many groups are queried and how many are stored separately.

Core answer

Start with the objects and symbols used here
MHA, MQA, GQA: how heads are shared
An attention head is one path that matches and then aggregates content. MHA usually gives every query head its own K/V head; MQA has several query heads share one group of K/V; GQA sits between them, sharing by group. These are structural choices, not a switch to be flipped at run time. Independent shape example: 8 query heads and 2 K/V heads, grouped evenly, means every 4 query heads share 1 group of K/V; the cache is accounted for by the number of K/V heads.

MHA usually gives each Q head its own K/V head; MQA lets several Q heads share one set of K/V; GQA sits between the two, letting a group of Q heads share one K/V head. It mainly reduces the K/V projection output and the amount cached; it does not make all the query heads share one attention distribution.[GQA][CACHE]

Follow-up: can a trained MHA model be turned into GQA just by changing the configuration?

Start with the objects and symbols used here
checkpoint: you must look at the object that was saved
A model checkpoint saves weights or training state; activation checkpointing saves a few intermediate nodes so they can be recomputed on the backward pass; an agent task checkpoint saves how far execution has got. The three share a name, but what they restore is entirely different. When you see "checkpoint", first ask whether it restores parameters, recomputes activations, or continues a task. An agent saving a summary does not update model weights.

Changing the head count alone is not enough. The parameter shapes, the weight combinations and the learned functions all change. The GQA paper studied converting from a multi-head checkpoint and continuing training; an equivalent model is not obtained by editing one configuration. A deployment has to match the weights to the architecture.

Follow-up: why does some GQA code still repeat KV out to H heads?

This may be to stay compatible with an ordinary attention interface, expanding it conceptually. Physically copying a long cache cancels the memory saving; an efficient implementation should share the data through a mapping, a view or a dedicated kernel. When reading code, look at the actual memory allocation and the stride, rather than only at a comment that says "shared".

Follow-up: MQA has the smallest cache, so why not use MQA everywhere?

More sharing changes the capacity of the representation and the quality of the model, and the hardware gain also depends on the workload. GQA is one compromise among quality, training cost and inference resources. There is no number of KV heads that is always best without regard to the model and the task.

Q081｜How does attention backpropagate? Why does working autograd not mean the model is implemented correctly?

What to know first for this question Backpropagation computes gradients step by step along the forward computation; a transpose carries a change in the output back into the input's dimensions, and softmax's candidates are coupled to one another by the normalization.
Lesson 42 · The arithmetic a model does mostLesson 44 · Probability, exponentials and softmaxLesson 52 · Only the calculus you will actually useLesson 53 · One training run end to end

Core answer

Backpropagation carries the output error back along the Value content path and along the Q/K weight path. Autograd computes the gradient of the current computation graph faithfully, but it cannot know whether your mask, labels or dimensions express the right task. The mathematical gradient check and the semantic invariance test have to be kept apart.[TR]

Differentiating step by step along the computation graph

Start with the objects and symbols used here
∂, ∇: partial derivative and gradient
∂L/∂w asks how the loss L changes when w changes a little while the other independent variables are held fixed. These rates of change across many parameters make up the gradient ∇L. They are derivative notation, not two ordinary numbers divided by each other. Independent micro-example: for L=w², the gradient at w=3 is 6. In the simplest update w←w−η×6, η is the learning rate.
Start with the objects and symbols used here
G, dQ, dW: the intermediate gradients in backpropagation
G=∂L/∂O is usually the gradient of the loss with respect to the current output O, passed back from the computation that follows. The backward pseudocode writes ∂L/∂Q as dQ and ∂L/∂W as dW; their shapes match the objects being differentiated, and are not the feature dimension d times Q. Only after the forward pass O=AV, and once G has arrived, can dV=AᵀG and dA=GVᵀ be computed; dA changes the share path, dV the content path.

Definition S=QKᵀ/√d, A=softmax(S), O=AV, and let the upstream gradient be G=∂L/∂O. Start with the last matrix multiplication:

dV = AᵀG
dA = GVᵀ

The first expression says that a historical Value accumulates error from every query position that reads it; the second measures how the loss changes when one read weight changes. Next comes softmax, where a row's probabilities a correspond to the upstream g:

Start with the objects and symbols used here
⊙: element-wise multiplication, not matrix multiplication
Elementwise multiplication multiplies the numbers at the same position once the shapes are aligned; it does not then sum along any dimension. Matrices written side by side in a formula, or @, usually mean matrix multiplication, and the two are not interchangeable. Independent micro-example: [1,2]⊙[3,4]=[3,8], whereas the dot product is 11. The ⊙ in a gated feed-forward network modulates one path with the other, feature by feature.
ds = a ⊙ (g − sum(a ⊙ g))

What is subtracted here is the weighted sum over the whole row, and it cannot be left out. Its components sum to 0, which matches the property that "adding a constant to a whole row of scores does not change softmax". Finally:

dQ = dS K / √d
dK = dSᵀ Q / √d

If Q/K/V are projected from the same X, the gradient of X is the sum of the three branches, each multiplied by the transpose of its projection, plus the gradient coming straight back along the residual. The transposing and concatenation of multiple heads have to go through the corresponding inverse transforms on the backward pass.

A useful diagnostic: let only the first position's output enter the loss. Under a causal mask the future K/V should get no gradient from that loss. A non-zero dependence on a future position points to a mask or indexing error. This test is about the task's semantics, not just numerical differentiation.

The backward pass is not the forward arrows played in reverse; it distributes "influence" along the dependencies

Follow-up: how does a finite difference check a gradient?

For an input dimension j, change it to xj+εand xj-ε, and use [L(x+εej)-L(x-εej)]/(2ε) approximates the derivative. A small matrix in float64 makes an error easier to locate. Too large an ε brings truncation error, too small and rounding error dominates; a test must not be made to pass by loosening the tolerance again and again.

Follow-up: if the finite difference passes, does that prove the model is right?

It proves that the analytic or automatic gradient agrees with the current forward function; if that forward pass wrongly allows the future to be seen, the two can still agree. Tests of label shifting, causality and whole-sequence-versus-cache consistency are needed as well. "The gradient is right" and "the objective is right" are therefore different pieces of evidence.

Follow-up: why is backpropagation not needed at inference?

Ordinary deployed generation uses fixed parameters: it computes a conditional distribution and chooses a token, with no loss to compute and no weights to update. Long reasoning, or many tool calls, adds forward computation and input information; it does not turn into gradient training by itself. A particular online-learning system may update parameters as well, but that has to be designed explicitly — it cannot be inferred from "the model understands the current task better and better" that training is taking place.
