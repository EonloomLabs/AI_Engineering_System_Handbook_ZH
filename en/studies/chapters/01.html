1. Distinguish five entirely different objects first

Start with the objects and symbols used here
JSON: structured text, not an action being executed
JSON is a text format that expresses data as objects, arrays, strings, numbers and so on. A braced object maps field names to values; a bracketed array keeps the order of its items. Parsing JSON only yields data; it does not automatically run a tool name inside it. Independent example: {"path":"a.py","limit":3} has two fields; "3" is a string while 3 is a number, and a schema can require either one.

User-visible strings, client message objects, server serialization templates, token ID sequences and floating-point tensors inside the model are different objects. The client may send JSON containing role and content; the service organizes roles, tool calls, images and other elements into representations established during model training, then encodes them accordingly. Open-model chat templates can be inspected directly; a closed-source service's complete final template is usually not disclosed to the client. An API request log cannot be called "the model's complete raw input".[N01][N13]

For example, the same "read config.py" string requests an action in ordinary user text, but is semantically external data in a tool-return field. Templates teach the model role distinctions, but roles are not CPU hardware permission bits. The executor must still check whether reading the file is actually allowed. Mistaking roles for permissions is a typical way a misunderstanding of fundamentals propagates into engineering risk.

To understand input, preserve three levels of observable evidence: the messages and tool versions submitted by the application, visible token usage, and tool execution results. Do not fabricate invisible server prompts or internal reasoning. Only when debugging a local open model can rendered templates and exact token sequences also be compared item by item.

2. What BPE actually does

Using UTF-8 bytes as initial symbols builds reversible encoding from the finest granularity. BPE training counts adjacent symbol pairs, merges a frequent pair into a new symbol, and repeats to form ordered merge rules. Inference applies trained rules rather than recounting user input to decide the vocabulary. The experiment's small implementation scans in rule order: a readable but inefficient teaching implementation. Production implementations also need pretokenization, special tokens, caches and efficient data structures.

Suppose training samples repeatedly contain routing, route, router; common fragments may become fewer symbols. This does not guarantee that arbitrary new identifiers use few tokens. A Chinese character may span multiple bytes; byte-level reversibility reconstructs original bytes without guaranteeing each token is a complete displayable character. Output streams may also end midway through a UTF-8 character, so incremental network decoding must maintain byte state independently; see Lesson 60.

This book's bpe_train and bpe_encode should not pass acceptance merely because its splits look reasonable; test mixed Chinese/English text, code, spaces and line breaks with decode(encode(text)) == text. Shortening repeated strings is a second property and cannot replace reversibility. Changing encoding may change the vocabulary, model input embeddings, output layer and interpretation of training data; it is not a string compressor that can be hot-swapped freely.

The merge order in BPE decides what can still be merged later

3. The autoregressive objective and training-label shifts

For the token sequence x₀,…,xT, the chain rule gives:

Start with the objects and symbols used here
Σ: sum term by term over the subscript
Σ is shorthand for addition. The subscript says which term varies; a subscript that is not summed over stays fixed. It is not an extra parameter, and it does not mean concatenating arrays. Independent micro-example: Σᵢ xᵢyᵢ with x=[1,2] and y=[3,4] is just 1×3+2×4=11.
P(x₀,…,xT) = P(x₀) × ∏(t=1…T) P(xt | x₀,…,x(t−1))
训练输入：x₀, x₁, …, x(T−1)
训练标签：x₁, x₂, …, xT
L = −Σt mask(t) log Pθ(x(t+1) | x≤t) / Σt mask(t)

Training processes many positions at once, with causal masks preventing each position from seeing future labels; during generation, input for the next position must wait for the previous step's sampled result. This explains why "training can parallelize across positions, while standard autoregressive generation has temporal dependencies". Training is not cheating by already knowing every answer; the mask prevents future information from leaking.[N07]

SFT often computes loss only at assistant-response positions. Here, loss mask and attention mask must be distinguished: the former determines which prediction errors contribute to optimization, while the latter determines which positions may be read. A user token can contribute no loss yet remain conditioning information for the assistant's answer. Conflating the two masks may unintentionally hide the user's question from attention.

Document concatenation also needs a boundary policy. Concatenating two independent samples directly may let the model use the first to predict the next; whether this is acceptable depends on the training objective. Strict sample isolation requires coordinated attention segmentation, positions, labels and loss, not merely inserting a separator string and claiming complete isolation.

Do not conflate: when accumulating over batches the number of valid targets differs, so averaging the per-batch means changes the weighting. Normalize by the total loss and the total number of valid targets.

4. From logits to cross entropy, deriving gradients step by step

The model's final output is a vector z of vocabulary size V. Stable softmax first subtracts the maximum m, because multiplying every numerator and denominator by exp(−m) leaves their ratios unchanged:

Start with the objects and symbols used here
∂, ∇: partial derivative and gradient
∂L/∂w asks how the loss L changes when w changes a little while the other independent variables are held fixed. These rates of change across many parameters make up the gradient ∇L. They are derivative notation, not two ordinary numbers divided by each other. Independent micro-example: for L=w², the gradient at w=3 is 6. In the simplest update w←w−η×6, η is the learning rate.
pi = exp(zi−m) / Σj exp(zj−m)
目标类别为y：L = log Σj exp(zj−m) + m − zy
∂L/∂zi = pi − 1[i=y]

The derivatives indicate that the target token's logit should increase, while other tokens are pushed down according to current probabilities; this does not store the entire answer as a database record. Gradients pass through the output projection, feed-forward layers, attention and input embeddings, updating many distributed parameters. Whether a fact can be reproduced consistently also depends on data frequency, interference, optimization and generalization.

Start with the objects and symbols used here
Labels, teacher forcing and shift
A label is the correct target to compare against; next-token training lines each input position up with the token after it. Teacher forcing computes with the real prefix from the data rather than replacing it with what was just sampled. Independent example: for the full sequence [a,b,c,d] the input [a,b,c] can be paired with the labels [b,c,d]. When the interface already shifts them, do not shift them a second time outside it.

numerics.cross_entropy returns the loss and analytic gradient. Finite differences check every dimension:(L(z+εei)−L(z−εei))/(2ε). If gradient error is large, first inspect label shifting, summation/averaging definitions, incorrect broadcasting and numerical overflow rather than immediately tuning the learning rate. Tests also verify that gradients sum to zero, because adding the same constant to every logit leaves the distribution unchanged. This test follows from a mathematical invariance and explains more than comparing one fixed floating-point array.

How to read the changes in the figure

With label B in the second slot, the model currently gives it only about 24.47% of the mass. Cross entropy directly penalizes the logarithm of this target probability, but all three logits are affected because they share a normalization denominator.

For the correct candidate, p−1 is negative, so updating along the negative gradient raises its score. For other candidates, p−0 is positive, so the same update lowers their scores. The three gradients sum to 0, matching "shifting all scores together leaves probabilities unchanged".

A real network usually updates the output matrix and earlier parameters rather than saving logits directly as long-term parameters. These dLogits must continue through the chain rule for matrix multiplication to determine how each weight should change.

Do not conflate: the target one-hot vector with the input embedding, or p−y with Wq's gradient; p−y belongs to the output-score layer.

5. Embeddings are not external retrieval vectors

The input embedding matrix usually has shape [V,d], and token IDs look up rows to obtain [B,T,d]. Embedding models for document search instead map entire passages to retrieval representations, usually with different training objectives and pooling methods. Arbitrarily averaging vectors from a language-model layer does not establish high-quality code-retrieval vectors.

The output layer may have separate weights or share the input embeddings; sharing reduces parameters, but check the specific architecture's implementation. Hidden dimension, vocabulary size and weight sharing affect VRAM estimates. For example, the teaching assumption V=100000,d=4096 gives one matrix with about 4.096 hundred million parameters; BF16 weights alone occupy about 0.819GB (decimal), before optimizer state. This is a size calculation, not a commercial model configuration.

How to read the changes in the figure

Rows two and four are both written as two numbers, yet they mean different things: one belongs to a single position, the other to a whole passage of material. The same shape is no guarantee of interchangeability.

The third row changes feature coordinates into candidate coordinates; softmax can only turn these candidate scores into a distribution over the next item, and cannot read an arbitrary intermediate vector directly as vocabulary probabilities.

Whether retrieval is useful depends on the training objective and the aggregation method; a vector must not be assumed suitable for cosine retrieval merely because it comes from some large model.

Do not conflate: feeding a four-dimensional embedding straight into an index that only accepts two-dimensional vectors is a shape error; and even padded to the same dimension, the semantic spaces may still not match.

6. An engineering diagnosis order for input problems

Start with the objects and symbols used here
Schema and Structured Outputs
A schema is a set of structural rules about fields, types and the like; a structured-output mechanism makes it easier for the model to return data that follows those rules. Valid fields still do not mean that the target file exists, that access has been granted, or that the request is right for the business. Independent example: path is required to be a string; {"path":3} does not match the type rule, and {"path":"missing.py"} follows the structure yet may still find no file.

When "identical" prompts behave differently, compare model identifiers, templates/system configuration, tool schemas, repository instructions, context history and sampling parameters first. Then check whether caches and services use different versions. Only with sufficiently aligned conditions should model randomness and numerical implementation differences be considered. Zero temperature is not a promise of bitwise determinism across hardware or service versions.

Prompt optimization should first remove ambiguity in goals and specify output objects and verification conditions, rather than pile up role adjectives. How gradients accumulate for one embedding row when 爱 appears twice

Input and conditions. 爱 has ID 2 in the vocabulary and appears at two positions in a batch. Let the gradients backpropagated to its embedding at those positions be [0.1,−0.2] and [0.3,0.4].

Steps and objectsInternal actionIntermediate result / new state
1 Look up the same rowBoth positions take row 2 of the tableThe forward values share parameters, not two independent trainable copies.
2 Backpropagate separatelyEach position produces its own gradient contributionThe two given vectors respectively.
3 Aggregate parametersSum contributions for the shared rowRow 2's gradient is [0.4,0.2].
4 Other rowsNot used in this lookupNo contribution from this pass through the pure input-embedding path.
5 UpdateWith learning rate 0.1 and old row 2 values [0.8,0.6]The new values are [0.76,0.58].

Join the steps up. Shared parameters receive the sum of gradients from multiple use sites; repeated occurrences of one word do not mean storing multiple rows.

Limits and counterexamples. This covers only the input-lookup path; if weights are tied to the output projection, other paths may contribute gradients. Rules such as padding_idx depend on the implementation.

7. Chapter acceptance and answers

Question: the first token of an assistant answer depends on the user's question, yet user positions have no SFT loss. Is this contradictory? Answer: no. The forward pass still reads user representations, and backpropagation follows the computation graph from assistant loss; the loss mask removes only direct loss terms at particular prediction positions.

Question: would making every character in a code path one token be more precise? Answer: representational precision is not task efficiency. Finer tokenization lengthens sequences, increases attention and generation costs, and changes the training distribution. Evaluate the choice on the same tasks, not character boundaries alone.

After this chapter, run cross-entropy finite differences and BPE reversibility tests, then deliberately remove the training-label shift. Loss may still fall, but the task becomes copying the current position rather than next-token prediction. Explain that the objective changed; low loss cannot count as success.
