Start with the objects and symbols used here
BM25 and N, df, k₁, b
BM25 is a scoring formula for term-based retrieval. In the usual notation N is the total number of documents, df the number of documents containing the term, tf the term frequency in the current document, |D| the length of the current document and avgdl the average length; k₁ and b are the settings for term-frequency saturation and length correction. k₁ is not the Key vector k₁, and b is not a neural network bias. The score only orders candidates; 8.2 cannot be read as 82% accuracy.
RRF: fusing by rank
For a document's rank r on each recall path, RRF contributes 1/(c+r), and these are added. c is a smoothing constant and r usually starts at 1; a candidate that did not appear on a path does not receive that path's contribution out of nowhere. Independent example: with c=10 and a document ranked 1 and 3 on two paths, it gets 1/11+1/13, about 0.167832. This is not adding the raw BM25 and cosine scores together.

Goal: design retrieval pipelines from corpus and query distributions and locate losses in retrieval, filtering, ranking or context selection. Experiment: retrieval.py, providing real BM25 and RRF rather than calling string matching an embedding.

1. Retrieval loses information stage by stage

A user question becomes a query; retrievers obtain corpus candidates; permission and version filters constrain visibility; ranking selects limited results; the context compiler trims again; finally the model uses evidence. If key material disappears at any stage, even a strong downstream model may answer wrongly.

RAG therefore needs more than a "vector database → LLM" diagram. Know chunking, index creation time, query encoding, result completeness and how evidence supports answers. Contextual Retrieval adds chunk context and combines retrieval signals, but gains must be remeasured on your own tasks.[N24]

Start with low-cost baselines: exact path / symbol retrieval and BM25. Add vectors, query rewriting or graphs only after real queries expose semantic gaps. Large frameworks are not prerequisites for retrieval quality.

2. BM25: term-frequency saturation and length normalization

Start with the objects and symbols used here
TF, DF, IDF: term statistics
TF counts how often a term occurs in the current document; DF counts how many documents contain it; IDF uses whole-corpus statistics to lower the contribution of common words and raise that of rarer, more discriminating ones. All three are statistics, not the model's learning rate. If only 2 of 10 documents contain a word, DF=2; if the word occurs 3 times in one of them, TF=3 for that document. The two numbers are not interchangeable.

This book uses a common nonnegative IDF form:

Start with the objects and symbols used here
Σ: sum term by term over the subscript
Σ is shorthand for addition. The subscript says which term varies; a subscript that is not summed over stays fixed. It is not an extra parameter, and it does not mean concatenating arrays. Independent micro-example: Σᵢ xᵢyᵢ with x=[1,2] and y=[3,4] is just 1×3+2×4=11.
idf(t)=log(1+(N−df(t)+0.5)/(df(t)+0.5))
score(q,d)=Σt∈q idf(t) × f(t,d)(k1+1)
                         / [f(t,d)+k1(1−b+b|d|/avgdl)]

Rarer terms usually have larger idf; repeated occurrences within one document give saturating gains, not linear rewards for a hundred repetitions. Length normalization reduces advantages from mere verbosity. Implementations differ in IDF and query-frequency handling; fix the specific formula for comparisons.[N32]

This transparent, testable teaching tokenizer is not a high-quality Chinese tokenizer. It often helps English code symbols but may lose Chinese phrase meaning. Measure recall on real queries rather than assume a BM25 implementation completes professional retrieval.

3. Dense Retrieval and vector spaces

Two-tower retrieval usually encodes queries and documents separately and scores relevance by dot product or cosine. Documents can be encoded offline and queries online; training positives, negatives and task instructions shape the similarity it supports. Similar descriptions need not mean identical facts; semantic approximation may hide opposite conditions, versions and exact identifiers.

Cosine commonly uses normalized dot products; if an inner-product index receives unexpectedly unnormalized vectors, norms affect ranking. Changing embedding models, dimensions, preprocessing or instruction templates usually requires rebuilding related indexes; do not mix different vector spaces in one collection.

Start with the objects and symbols used here
ColBERT and MaxSim
ColBERT-style methods keep several token vectors for the query and for the document, then interact them late. The usual MaxSim takes, for each query token, the highest similarity with any document token, and then aggregates. It is not dual-encoder retrieval where "the whole document has only one vector", and it is not the self-attention output of each layer of a generative model.

A Cross-encoder jointly encodes queries and documents for finer relevance judgments, but candidate-pair counts directly increase cost. It suits reranking small retrieved sets and cannot recover missing candidates. ColBERT retains multi-token representations with late interaction between single-vector efficiency and finer matching, with more complex storage and indexes.[N71]

Vectors with the same number of dimensions need not belong in the same similarity space

4. Why ANN is faster and why it may miss results

Start with the objects and symbols used here
ANN and HNSW: approximate retrieval structures
ANN here means approximate nearest-neighbor search, not artificial neural networks in general. HNSW is a structure that narrows the search using a hierarchical graph of near neighbors; its parameters affect recall, speed and memory. Finding something quickly is no guarantee of finding the exact nearest neighbors; nor does ANN recall equal the correctness of the final answer.

Exact vector search scans every vector, giving a straightforward correctness baseline. Approximate nearest-neighbor indexes trade controlled recall loss for speed or storage. HNSW navigates candidate neighbors through layered graphs; more search candidates usually improve recall at greater cost. IVF selects coarse-cluster buckets, then searches within them; too few probes miss results, too many approach scanning. PQ encodes vector blocks as codebook indexes, reducing storage while approximating distances.[N33][N95]

Start with the objects and symbols used here
Precision, Recall, MRR and nDCG
Precision looks at how many of the returned results are relevant; recall looks at how many of the relevant items that should have been found were found; MRR averages the reciprocal rank of the first correct item; nDCG takes the degree of relevance and the position in the order into account, and normalizes against the ideal ordering. Independent example: 5 documents should be found, 4 are returned and 3 of them are relevant, so precision is 3/4 and recall 3/5. Do not swap these two denominators.

Do not conflate ANN Recall@k with business-evidence recall. ANN metrics may only compare with exact vector rankings and show few neighbors lost; if the embedding never ranked the right document highly, even strong ANN recall cannot guarantee business success.

Start with the objects and symbols used here
Top-k, Top-p and renormalization
Top-k keeps the k items with the highest probability; Top-p sorts by descending probability and keeps the leading candidates until the cumulative probability reaches a threshold. When used for sampling, the kept candidates have to be renormalized over the remaining total mass. Here k is a number of candidates and p a cumulative-probability threshold; k is not the attention Key table K, nor the representation width d_k.

Metadata filters affect ANN behavior. Global top-k followed by permission filtering may leave only one or two items, withholding findable material from authorized users. Options include prefiltering, appropriate over-retrieval, partitioning or filter-aware indexes; measure recall and latency under strict ACLs and highly selective filters.

5. How hybrid retrieval fuses results

BM25 and cosine scores may differ in scale; direct sums risk domination by one signal. RRF uses only ranks: score(d)=Σr 1/(c+rank_r(d)). This simplifies cross-score calibration but discards score-gap information. c adjusts emphasis on top ranks; it is not a magic constant.

The experiment deduplicates each ranked list so repeated documents from one retriever cannot manufacture votes. Same-named documents at different versions need clear IDs rather than incorrect merging. Redundancy or coverage selection may follow fusion, but diversity must not remove a necessary second piece of evidence.

Start with the objects and symbols used here
HyDE: the hypothetical text is only used to find material
Have the model generate a hypothetical answer or document and use its representation for retrieval. That generated text is an aid to finding evidence, not a source of facts already found. The model guesses "it may be cache invalidation", which is reason enough to widen the search; before there is real evidence it must not be written up as "cache invalidation confirmed".

Query rewriting and HyDE broaden semantic retrieval by forming possible descriptions before searching. Hypothetical documents are query aids, not real evidence; generated false premises must not enter the final factual chain.[N72]

How to read the changes in the figure

BM25 may be in the tens while a cosine may be less than 1, so adding them directly hides an arbitrary weighting of the two scales. RRF uses only relative rank first, which avoids the mismatch of scales.

B does not win by having the highest absolute score on one path, but by having the better combined rank across both. The larger k is, the smaller the difference in contribution between adjacent ranks usually becomes.

If several near-duplicate chunks of one document are not deduplicated properly, they can be mistaken for several independent pieces of evidence; a fusion score does not in itself mean a fact was confirmed by several sources.

Do not conflate: a different k, window or weighting changes the result. Fix those parameters before comparing quality; two runs with different settings cannot be attributed to the retrieval model.

6. An index is a data product with a lifecycle

At ingestion, save source ID, content version, chunk position, embedding version, permissions and update time. Source edits or deletion should invalidate indexes and caches; document ACL changes need handling too. Incremental indexing includes replacing, deleting, merging and resolving conflicts, not just adding vectors.

retrieval.Index first filters by tenant, principal and version, then computes BM25 on the visible set; cache keys include these fields, and replacing the document set clears the cache. This actually tests cross-user cache isolation and version switching, but linear scanning establishes no million-item performance and implements no vector index. Production caches also need permission-group changes, index generations and short-term authorization revocation handled.

Deleting sensitive content requires more than hiding results. Derived content retained in summaries, answer caches or long-term memory also needs governance. Retrieval security concerns the whole dataflow, not one filter before display.

Worked example · X09

Why approximate graph search can miss the truly nearest point

Input and conditions. The query is at 0 on a number line. A=4,B=5,C=1, with only undirected edges A—B and B—C; start at A. C is clearly nearest, at distance 1.

Steps and objectsInternal actionIntermediate result / new state
1 Start strictly greedilyA is distance 4; its neighbor B is distance 5Moving only toward nearer points stops at A.
2 Local is not globalA has no better one-hop neighborThis does not mean no better point exists elsewhere in the graph.
3 Explore one step furtherTemporarily keep worse B, then visit its neighbor CFind C at distance 1 and replace the current best.
4 Connect to engineering parametersLarger candidate queues and exploration budgets increase visitsThey may improve recall, but this example does not guarantee finding the global nearest point under every budget.

Join the steps up. Approximate search is not "compute vectors and always find the right result". Distances may be completely correct while exploration misses candidates.

Limits and counterexamples. This is a graph-traversal counterexample, not the full HNSW algorithm or an exact parameter simulation; real implementations also contain layered graphs, construction strategies and queue rules.

Engineering case · D05

Retrieval diagnosis: representation space, authorized candidates, then fusion ranking

Do not let a generator hide upstream failures

When a retrieval system answers wrongly, temporarily supply correct evidence directly to the generator to test its use. This is a diagnostic experiment, not a deployment result. Restore the real index afterward, retain candidates by stage and locate the earliest error.

This book uses four independent, explicitly bounded experiments: mismatched old and new vector bases select wrong documents despite equal dimensions; global Top2 then tenant filtering yields nothing; duplicating one retrieval route changes RRF weights; version and tier mismatches prevent real citations supporting conclusions. Model cards, pgvector and Elastic documentation support the corresponding mechanisms separately.[E5] [PGVECTOR] [RRF]

Every stage needs its own oracle

Representation-contract checks cover model / prefix / pooling versions; ANN uses small-sample exact retrieval as reference; fusion checks candidate identity and windows; evidence checks proposition conditions. A plausible final answer cannot prove every preceding stage correct.

Verify permissions and freshness

Record authorization version, index generation and original-text fingerprint at query time. Distinguish "no permitted material exists" from "candidates were truncated" after filtering; bind final-answer caches to permissions and versions too. Answers from old summaries after revocation are a knowledge-supply-chain issue, not just a database-query issue.

Production measurement limits

This experiment runs no HNSW service or real embedding model, so it provides no ANN performance, real semantic recall or business Q&A success rates. It supplies falsifiable logical boundaries and a diagnostic order. Before release, add quality / latency / permission tests on your own data distribution.

Switching index generations

Build two indexes from the old and the new embedding model even though the vectors have the same dimension, and forbid mixing across generations; the query log records which index and which model version were used.

Key boundary: a dimension check can only prevent shape errors; it cannot prevent two inconsistent semantic spaces.

Keep tracing through the source or the engineering basis: track parsing, chunking, versioning, authorization and deletion along one and the same document. Do not check only the happy path; check the behavior on cancellation, on a version change and when the result is unknown as well.

7. Acceptance and measurement

Build queries covering exact symbols, synonymous descriptions, negations, cross-document combinations, old-version interference and no answers. Measure candidate-evidence Recall@k, ranking MRR/nDCG, final-answer support rate, latency and cost separately, and require zero unauthorized leakage. Keep the original chunks missed by retrieval rather than judge only whether the model guessed correctly.

Acceptance question: why might higher nDCG after a reranker upgrade accompany worse answers? Coverage may stay unchanged while evidence diversity falls, long-text trimming loses conditions, ranking favors fluent documents over current versions, or task scoring disagrees with retrieval labels. Diagnose stage by stage rather than add larger vector models.
