1. MoE: conditional computation does not use every parameter for every token

Start with the objects and symbols used here
Σ: sum term by term over the subscript
Σ is shorthand for addition. The subscript says which term varies; a subscript that is not summed over stays fixed. It is not an extra parameter, and it does not mean concatenating arrays. Independent micro-example: Σᵢ xᵢyᵢ with x=[1,2] and y=[3,4] is just 1×3+2×4=11.
MoE, experts and the router
MoE is a model structure that contains several sub-networks; the router selects or weights a few experts for the current token's representation. An expert is usually a numeric sub-network, not a chat agent given a prompt such as "math teacher". Independent example: with 4 experts and 2 chosen per token, one pass activates only 2 of the expert paths; the parameters and routing state that the model design requires still have to be stored.

A dense feed-forward layer applies the same parameter computation to every token; MoE routes to selected experts, expressible as y=Σe∈TopK gate_e(x) Expert_e(x). Total parameters therefore differ from activated parameters per token. Greater total capacity does not imply proportionately greater per-token computation, but expert-weight storage, cross-device communication and load balancing still cost resources.[N40]

Routing collapse overloads a few experts; capacity limits may affect token assignment; expert parallelism sends activations to the corresponding devices. Reported throughput gains depend on networks and kernels, not activated parameter counts alone. Switch-style research and later MoE reports use different balancing strategies; read their versions separately rather than combine an architecture that never existed.

This book does not reproduce large-scale MoE training; Lesson 51 explains distributed constraints, Lesson 59 computation / bandwidth, and Chapter 31 further discusses gradients and gating boundaries.

2. MLA and GQA take different approaches to caching

Start with the objects and symbols used here
MHA, MQA, GQA: how heads are shared
An attention head is one path that matches and then aggregates content. MHA usually gives every query head its own K/V head; MQA has several query heads share one group of K/V; GQA sits between them, sharing by group. These are structural choices, not a switch to be flipped at run time. Independent shape example: 8 query heads and 2 K/V heads, grouped evenly, means every 4 query heads share 1 group of K/V; the cache is accounted for by the number of K/V heads.
LoRA, low rank and r
LoRA represents part of a weight increment as the product of two smaller matrices instead of retraining the whole large matrix. r is the inner dimension, and it bounds the maximum rank of that product. Where sources use a row-vector or a column-vector convention, the left-right order of A and B can differ. Micro-example in the right-multiplication convention: with W[4,6], the increment A[4,2]B[2,6] is still [4,6]; r=2. A here is not the table of attention shares.
Start with the objects and symbols used here
MLA: a learned low-dimensional K/V representation
MLA refers to a family of multi-head latent attention architectures. It organizes the content behind K/V jointly in a lower-dimensional latent representation and handles the positional part by design. It changes the model's representation and parameter structure; it is not just ZIPping an ordinary KV file. In c=xW_down, c is the latent vector for this computation and W_down the learned table of dimension-reducing coefficients; how it is later reconstructed or absorbed into a projection has to be explained for the specific architecture.

GQA reduces caches through shared KV heads; MLA-style structures compact attention-related state into low-rank latent representations with particular positional designs. DeepSeek-V3 includes specific MLA and MoE approaches; it is not simply "GQA with fewer heads".[N40]

When K and V are projections of latent vectors, some matrices can be recombined during inference to reduce long-lived state; position–projection interactions limit direct combination. Draw training computation and inference-cache graphs, comparing stored tensors with those recovered on demand.

KV memory formulas differ by architecture; Lesson 50's GQA formula cannot be applied directly to MLA. Identify representations and cached contents before estimating memory, rather than copy context lengths and total parameter counts.

How to read the changes in the figure

GQA mainly changes what the heads share; a low-rank cache mainly changes how things are represented. Both can shrink the cache, but they are not one algorithm under two names.

"It can be compressed to low rank" usually comes out of the architecture and the training arrangement; one cannot truncate the KV of any off-the-shelf model at will and claim no loss.

The full cache, the projection computation, the position handling and the hardware kernels all have to be compared; you cannot just pick the latent size and show off a flattering ratio.

Do not conflate: the 8→3 in the figure is a teaching dimension, not a measured compression ratio from the DeepSeek report, and it cannot be used to estimate the VRAM of a real service.

3. Comparing GPT, Llama, Qwen and DeepSeek reports

Separate architecture, data, training budget, post-training, inference modes, tool interfaces and evaluation conditions. Public weights do not imply public training data or all production-serving details; technical reports are bounded evidence too.

Few-shot learning shows adaptation through context examples, not parameter updates on every inference call. Vocabularies, data and training objectives jointly shape multilingual ability. Gains on a reported code dataset do not prove equal gains on your languages, frameworks and repositories.

Further reading covers related GPT-3, Llama 3, Qwen3 and DeepSeek-V3 topics. Topic Chapters 01—06 explain shared mechanisms; understand report-specific architectures separately rather than infer mechanisms from model names or leaderboards.

4. CoT, self-consistency, ToT and ReAct occupy different layers

CoT methods change intermediate-reasoning generation; self-consistency aggregates sampled answers; ToT organizes candidate intermediate states into a search tree for generation, evaluation and selection; ReAct loops between reasoning and environmental actions. The first two mainly affect reasoning paths; the latter two involve more explicit search or external feedback.[N59][N67]

Search costs grow with branching, depth and evaluation. Keeping b candidates per level and expanding d levels can make a naive full tree grow rapidly; pruning needs reliable evaluators or may discard correct paths early. Methods useful for verifiable puzzles may not suit business workflows with irreversible actions.

Toolformer explores learning when to use tools; runtime Function Calling protocols handle call encoding and execution. Training research and interface engineering differ. Lesson 55 explains learning objectives; Chapters 07—08 cover protocols and execution.

5. Which gaps each RAG extension addresses

Start with the objects and symbols used here
ColBERT and MaxSim
ColBERT-style methods keep several token vectors for the query and for the document, then interact them late. The usual MaxSim takes, for each query token, the highest similarity with any document token, and then aggregates. It is not dual-encoder retrieval where "the whole document has only one vector", and it is not the self-attention output of each layer of a generative model.
HyDE: the hypothetical text is only used to find material
Have the model generate a hypothetical answer or document and use its representation for retrieval. That generated text is an aid to finding evidence, not a source of facts already found. The model guesses "it may be cache invalidation", which is reason enough to widen the search; before there is real evidence it must not be written up as "cache invalidation confirmed".
Start with the objects and symbols used here
DPR, DPI and coordinate units
DPR usually means the ratio of device pixels to CSS pixels; DPI means dots per inch. Screenshot pixels, the interface's logical coordinates and screen coordinates need not share a unit, and there may also be scaling, cropping and offsets. In an independent example where DPR=2 is stated and the other mappings agree, a CSS x-coordinate of 100 corresponds to 200 device pixels; this conditional relationship cannot be carried straight over to every screenshot.

Classic RAG combines documents with generation; DPR studies dense passage retrieval; ColBERT uses multi-token late interaction; HyDE rewrites queries through hypothetical documents. These primarily affect candidate retrieval or matching, not automatic source authorization and updating.[N69][N70][N71][N72]

Start with the objects and symbols used here
GraphRAG, RAPTOR and hierarchical organization
GraphRAG-style methods use organizational information such as entity relationships and communities; RAPTOR uses hierarchical clustering and summaries to support retrieval. They introduce extra derived information, and with it problems of updating, provenance and error propagation. When the source document changes, an old summary or a relationship in the graph may be out of date. Changing the original text is no proof that every derived index has been updated with it.

RAPTOR builds hierarchical representations through clustering and recursive summaries for cross-chunk understanding; GraphRAG uses entities / relationships and community summaries for some global questions. They add summarization and graph-extraction costs, including extraction errors, provenance and invalidation after updates.[N73][N46]

Self-RAG learns / generates retrieval and reflection behavior; adding "reflect for yourself" before an ordinary model is not reproducing it. Corrective RAG methods evaluate evidence quality and decide on further retrieval, but evaluators may also fail.[N56]

Classify questions first: exact facts, natural-language location, cross-document combination, global topic summary or insufficient evidence. Retrieval structures differ; a repository-wide summary graph for locating one function may be slower and less reliable than exact retrieval.

How to read the changes in the figure

Behind the one keyword "enhanced RAG" there may be a change to the query, to the index, to the selection strategy or to the training; it cannot be treated as a single switch.

Use the smallest baseline to record which step fails, then pick the matching method. If the problem is a permission-filter error, moving to a more elaborate graph index need not help at all.

When evaluating, look at accuracy, traceability of evidence, timeliness, cost and maintenance burden together, rather than picking out the average score from a paper.

6. Dimensions for evaluating memory methods

Start with the objects and symbols used here
semantic, episodic and procedural memory
Semantic memory keeps facts, episodic memory keeps experiences, procedural memory keeps conditional methods; working memory serves the current task. CoALA is a framework for analyzing this kind of cognitive architecture, and MemGPT studies how a limited context and external storage are organized."Patch p7 failed because a test was missing" is an experience; "Windows has to be supported for now" is a fact; "check the separator when changing path rules" is a conditional procedure, and must not be promoted straight into running the full test suite for every task.

Generative Agents, MemGPT, A-MEM and Mem0 illustrate event streams / reflection, tiered storage, dynamic associations and engineered extraction respectively; their objectives are not identical. Long-conversation memory scores do not equal reusable coding-experience scores.

Start with the objects and symbols used here
TTL, valid time and record time
A TTL is an expiry setting on storage or a cache; valid time is when a fact applies; record time is when the system came to know it. An expiry policy cannot stand in for verifying the fact and its source. A rule that takes effect on October 1 is only read on October 10: the business valid time counts from the 1st, while the time the system knew about it counts from the 10th.

Evaluate write accuracy, updates, temporal reasoning, conflicts, forgetting and retrieval separately, then final task gains. LoCoMo and LongMemEval test long interactions differently; this book's Lesson 19 bi-temporal conflict model is an original engineering example, not a claimed implementation of these systems.[N35][N76][N77][N78]

7. Read benchmarks through capability boundaries

SWE-bench studies real issue repair; AgentBench, τ-bench and GAIA cover agent capabilities in different environments; LiveCodeBench addresses code evaluation and temporal change; OSWorld covers computer environments. Scores cannot be compared directly across different tasks, tools, budgets and acceptance criteria.[N48][N44][N80]

Lost in the Middle, LongBench and RULER distinguish nominal context capacity from actual task capability. One successful "needle in a haystack" retrieval does not establish reliable multi-evidence combination, conflict handling or long-task recovery. Lesson 15 therefore tests constraints and continued execution rather than one hidden middle number.

8. Read new papers without being led by conclusions
