1. Resource profiles of prefill and decode

Prefill processes the entire input prefix, usually with more parallel matrix computation; decode adds only a few positions per step but must read model weights and a growing KV cache. The bottleneck depends on the batch, model, precision and hardware; prefill is not always compute-bound, nor decode always bandwidth-bound. These are common analysis directions, not conclusions requiring no measurement.[N11]

For attention, a full prefix of length T has a score matrix of size T², and standard full-attention computation grows with T². Cached decoding scores one new position against T historical keys, making this part of one step grow roughly with T; a long sequence still accumulates its costs. KV caching does not mean history need never be processed again: it avoids recomputing old K/V, not reading the data required for attention to history.

2. Roofline thinking: compute or data movement

Start with the objects and symbols used here
HBM, SRAM and bandwidth
HBM here means the larger high-bandwidth memory on a GPU; the related on-chip SRAM is usually smaller and closer to the computation. Bandwidth is how many bytes can be moved in a given time; arithmetic intensity is the ratio of computation to data moved. Independent accounting: 100 operations against 10 bytes moved is about 10 operations per byte. It is not a measurement of real hardware performance.

Let an operation require F floating-point operations and M bytes moved, with device peak compute P and bandwidth W. A rough lower bound is时间≥max(F/P,M/W), with additional launch, synchronization, communication, scheduling and utilization losses in practice. Arithmetic intensity F/M helps identify optimization directions.

Start with the objects and symbols used here
FLOPs and FLOP/s: a count and a rate
FLOPs usually means a number of floating-point operations; FLOP/s means a rate of operations per second. Papers and vendors may count a multiply-add as one operation or two, so the basis has to be fixed. Dividing total operations by the theoretical peak is no promise of real elapsed time: movement, queueing, communication and actual utilization cost something too.

Reducing writes of intermediate matrices can improve memory-bound parts, potentially making them faster even with slightly more arithmetic. Conversely, extra recomputation may slow an already compute-saturated part. FLOPs or GPU utilization alone cannot identify a serving bottleneck; combine memory bandwidth, operator times, queues and request distributions.

3. Why FlashAttention need not store the full attention matrix

Start with the objects and symbols used here
FlashAttention: changing how intermediate data is stored and read
By means such as tiling and online normalization, it avoids keeping the full attention score/weight matrix in slower VRAM for long; the target is still the same attention computation, and floating-point rounding can vary with the order of operations. It does not compress tokens permanently, and it does not skip any Key. Keep "not writing the whole table to VRAM" apart from "not doing this arithmetic at all".

An ordinary implementation may write S=QKᵀ/√d and other T×T matrices, such as softmax probabilities, to high-bandwidth memory. A tiled algorithm processes blocks in closer on-chip storage and maintains normalization statistics so the result does not require the entire matrix to exist at once. FlashAttention organizes exact attention around this IO problem; it does not turn full attention into linear attention.[N10]

Start with the objects and symbols used here
Σ: sum term by term over the subscript
Σ is shorthand for addition. The subscript says which term varies; a subscript that is not summed over stays fixed. It is not an extra parameter, and it does not mean concatenating arrays. Independent micro-example: Σᵢ xᵢyᵢ with x=[1,2] and y=[3,4] is just 1×3+2×4=11.

For one query row, the maximum processed score m, exponential sum l and unnormalized weighted sum a are: l=Σexp(s−m), a=Σexp(s−m)v. On seeing a new block S, V:

m' = max(m, max(S))
l' = exp(m−m') l + Σ exp(S−m')
a' = exp(m−m') a + Σ exp(S−m') V
最终输出 O = a/l

Why rescale the old statistics? When the new block has a larger maximum, old l and a were computed relative to old m and must be converted to the scale relative to m'. Updating m alone without rescaling gives blocks incorrect weights, making results depend on the tiling. This is an error worth injecting deliberately.

Start with the objects and symbols used here
Dropout: the rule that randomly zeroes values during training
The common inverted dropout zeroes elements at random during training with drop probability p, and divides the kept ones by 1-p so that the expected scale is preserved. Evaluation mode usually turns this random operation off; the underlying function may require the caller to pass p=0 explicitly. Independent example: with p=0.5, a value of 2 comes out as 4 if it is kept in a given mask and as 0 if it is dropped. This is not training permanently deleting the corresponding model parameter.

This book's online_attention implements these identities and compares different block sizes with ordinary softmax attention. It has no CUDA kernel, shared-memory layout, backward operator or hardware performance measurement. During backpropagation, saved statistics can recompute some probabilities to save space by not storing the full matrix; production implementations must also handle masks, dropout, numeric types and batch layouts.

4. Paged KV caching addresses allocation and sharing

Start with the objects and symbols used here
PagedAttention: managing K/V storage in pages
Store a logically contiguous K/V sequence in several physical blocks, located through a block table. It mainly changes how the storage is managed and shared; it does not replace the attention formula with an algorithm that means something else. Independent example: logical positions 0—3 are in physical block 7 and 4—7 in block 2; logical position 4 need not physically follow position 3.

Long requests vary in length; reserving contiguous maximum KV space per request wastes capacity and fragments memory. PagedAttention maps logical token positions to fixed-size KV blocks that may be physically noncontiguous. Shared prefixes can reference shared blocks, with suitable sharing/copying rules when writes diverge.[N11]

Smaller blocks increase metadata, addressing and management costs; larger blocks increase internal fragmentation in the final block. Cache compression and quantization are separate techniques; paging alone does not automatically reduce K/V bytes per valid token. Sharing a physical prefix does not remove tenant isolation or cache-side-channel concerns.

Serving schedulers must know how much KV capacity can be allocated. Admitting too many long requests may cause preemption, swapping or failures; RPM limits alone cannot reflect this pressure. In-flight tokens, requests and output limits can be constrained separately, with service objectives considered in scheduling.

Paging changes physical placement, not the logical order of the tokens

This sequence does not need one large contiguous stretch of space; once it ends, it can be released block by block. A shared prefix also needs semantics such as reference counting and copy-on-write.

Paging mainly changes memory management. The position rules, the visible range and the Key/Value contents must still match the original sequence; tokens must not be reordered because the storage is scattered.

Do not conflate: the last block is only half used, so there is still internal fragmentation. Paging is not zero waste, and it is not ordinary disk swap standing in for VRAM.

5. Continuous batching and fairness

Static batching waits for a group of requests to finish together, preventing timely admission of new requests; continuous batching adds or removes requests at iteration boundaries to improve device utilization. But a long prefill can block short requests already decoding and affect per-token latency. Chunking prefill, separating stages or designing fair scheduling each adds complexity and hardware conditions.

Start with the objects and symbols used here
TTFT, TPOT, p95 and throughput
TTFT is the latency from the request to the first output token; TPOT describes the statistics of the time per token after that; p95 is the quantile that about 95% of observations in a given window do not exceed; throughput is the amount completed per unit of time. Say where the timing starts and stops. A fast first character does not mean a fast task: tool execution may still take a long time. Nor does theoretical peak throughput equal the latency one user sees.
SLI, SLO and the error budget
An SLI is a service level indicator that is actually measured; an SLO is the target for that indicator; the error budget is the room for failure that target allows. They are objects of service operation, not model parameters."The API returned 200" may not be success for the user; some businesses should define the indicator as the proportion of tasks completed correctly within a bounded time.

Keep metrics separate: TTFT measures first response, TPOT measures intervals between output tokens, and end-to-end time measures the user's task; multitenancy also needs tail latency. Raising batch size for throughput may hurt interaction, while running one request at a time for minimal latency may reduce utilization. An optimum exists only relative to the workload and SLO.

Start with the objects and symbols used here
Little's law: L=λW as local notation
In queue accounting, L is the average number of tasks in the system, λ is the average arrival rate and W is the average time spent in it; under applicable conditions such as stability, L=λW. Here W is not a projection matrix, and L is not the number of model layers. Independent example: with 2 items arriving per second on average and an average stay of 3 seconds, about 6 items are in the system on average; an instantaneous spike cannot simply stand in for the long-run average.

Little's law gives, in a stable system,在途量L=到达率λ×平均逗留时间W. It does not describe a particular queue's tail distribution, but helps check capacity-planning consistency. Latency rises nonlinearly near saturation; a low-load single-request benchmark cannot directly predict production peaks.

6. Prompt caching and KV caching are not one switch

A model's internal KV cache is inference state; a service prefix cache may reuse prefix computation across requests; the billing definition of a cache hit is a product contract again. Applications should keep reusable prefixes stable and avoid irrelevant timestamps at the start, without retaining incorrect or unauthorized content for cache hits. Security and correctness take priority over hit rates.[N01][N14]

Deleting intermediate history for compaction may change later prefixes and reduce reuse. Compare the remaining task's total cost, not only how much this compaction shortened input. Lesson 15 gives a method for calculating compaction gains and losses.

7. What a credible performance experiment should include

Save the model version, precision, hardware, serving configuration, input/output length distributions, concurrency and warm-up method first. Measure with/without caching, short/long prefixes and single-request/production concurrency separately. Report p50/p95 latency, throughput, failure rate, peak VRAM and task quality; do not hide tail problems behind one best-case point.

Acceptance question: NumPy tiled attention differs little from ordinary attention. Is the FlashAttention optimization complete? No. This verifies only a mathematical subproblem; GPU layouts, synchronization, actual IO and backward correctness remain to be implemented. Separating a mechanism's correctness from a production system's performance gain is a minimum standard for senior engineering study.
