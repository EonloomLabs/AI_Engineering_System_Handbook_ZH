Goal: derive gradients by hand along a computation graph, then verify them numerically, connecting how models learn with earlier inference mechanisms. Experiment: attention_gradients.py, providing analytic backpropagation and finite differences.

Every gradient object in a backward derivation must match its forward operator and shape; first trace how local changes propagate backward.

The fixed input for the figure below is declared under "Input and conditions of use". It serves to explain this chapter's mechanism and does not quietly continue the numbers of this chapter's other independent examples.

1. Start with single-head attention

Let Q be m×d, K n×d and V n×dv. Define S=QKᵀ/√d, apply row-wise softmax to obtain P, and output O=PV. Allow m to differ from n, covering new chunk queries against the full cached history. Let the upstream loss gradient with respect to output be G, of shape m×dv.

The forward pass has two steps: use Q/K to determine each row's weights, then mix V with them. The backward pass likewise has weight and content paths. This derivation uses matrix differentials and the softmax derivative, without anthropomorphizing attention.[N07]

2. Differentiate with respect to V and P first

From dO=dP·V+P·dV and the trace form of a scalar loss, we obtain:

Start with the objects and symbols used here
∂, ∇: partial derivative and gradient
∂L/∂w asks how the loss L changes when w changes a little while the other independent variables are held fixed. These rates of change across many parameters make up the gradient ∇L. They are derivative notation, not two ordinary numbers divided by each other. Independent micro-example: for L=w², the gradient at w=3 is 6. In the simplest update w←w−η×6, η is the learning rate.
∂L/∂V = Pᵀ G                    [n,dv]
∂L/∂P = G Vᵀ                    [m,n]

The first equation accumulates each Value's gradient from the query positions reading it. The second describes how changing one attention weight moves the output in the corresponding V direction and affects loss. Shape checks are part of the derivation, not merely memorized formulas.

The backward pass is not the forward arrows played in reverse; it distributes "influence" along the dependencies

Conditions for this example: an independent single-row calculation: the read shares are P=[0.25,0.75], with V0=[2,0] and V1=[0,4]; the output is O=[0.5,3], and the loss is defined as the sum of O's two cells, so the upstream gradient is dO=[1,1].

The last row has one negative and one positive entry: raising the second score gives more share to V1, whose total is larger, and squeezes out V0's share, so the two changes are coupled.

The softmax derivative must not be written as just p(1−p), ignoring the other candidates; subtracting the weighted baseline above is exactly what brings the coupling in.

Automatic differentiation correctly takes the gradient of "the program you wrote", but if the forward pass lets future positions in, it will faithfully differentiate that wrong forward pass too.

Do not conflate: a finite-difference check passing says only that the gradient agrees with the current forward pass; the mask, the target and the model's semantics still have to be checked independently.

3. The softmax Jacobian need not be built explicitly

Start with the objects and symbols used here
Jacobian: the table of derivatives for several outputs
When a function has several inputs and outputs, the Jacobian records in one table the partial derivative of every output with respect to every input. J_F denotes that table for the function F; it is not a new matrix in the training data. Independent micro-example: F([x₁,x₂])=[2x₁,3x₂], J_F=[[2,0],[0,3]]. The derivative table of the residual x+F(x) is I+J_F.
Start with the objects and symbols used here
G, dQ, dW: the intermediate gradients in backpropagation
G=∂L/∂O is usually the gradient of the loss with respect to the current output O, passed back from the computation that follows. The backward pseudocode writes ∂L/∂Q as dQ and ∂L/∂W as dW; their shapes match the objects being differentiated, and are not the feature dimension d times Q. Only after the forward pass O=AV, and once G has arrived, can dV=AᵀG and dA=GVᵀ be computed; dA changes the share path, dV the content path.

For one row p, the Jacobian is diag(p)−ppᵀ. Building an n×n matrix directly is wasteful; with upstream gradient g for that row, write:

Start with the objects and symbols used here
Σ: sum term by term over the subscript
Σ is shorthand for addition. The subscript says which term varies; a subscript that is not summed over stays fixed. It is not an extra parameter, and it does not mean concatenating arrays. Independent micro-example: Σᵢ xᵢyᵢ with x=[1,2] and y=[3,4] is just 1×3+2×4=11.
⊙: element-wise multiplication, not matrix multiplication
Elementwise multiplication multiplies the numbers at the same position once the shapes are aligned; it does not then sum along any dimension. Matrices written side by side in a formula, or @, usually mean matrix multiplication, and the two are not interchangeable. Independent micro-example: [1,2]⊙[3,4]=[3,8], whereas the dot product is 11. The ⊙ in a gated feed-forward network modulates one path with the other, feature by feature.
ds = p ⊙ (g − Σj pj gj)

Combining all rows: D_S=P⊙(D_P−rowsum(P⊙D_P)). Each row's score gradients now sum to zero, matching the softmax invariance to adding the same constant to a whole row.

A position excluded by a fixed mask has P equal to zero and should also have zero score gradient. A fully masked row has no valid probability distribution and is explicitly rejected here. Production kernels with other semantics must keep forward and backward behavior consistent.

4. Propagate back to Q and K

∂L/∂Q = D_S K / √d              [m,d]
∂L/∂K = D_Sᵀ Q / √d            [n,d]

Although K and V both come from historical positions, their gradient paths differ. Q/K affect selection weights; V affects aggregated content. Backpropagating only through V, not Q/K, may teach output content without correctly learning attention matching.

Start with the objects and symbols used here
Query, Key, Value: three intermediate numeric representations
q is one row of query representation for the position receiving information; k is one row of matching representation offered by a readable position; v is one row of content representation that position contributes to the mix. Capital Q/K/V collect several rows into tables. They are computed from the input and the parameters, and they carry the separate jobs of scoring and of supplying content. One q dotted with two k gives two scores; softmax turns them into two shares; those shares multiply the two rows of v, and the results are added. Nothing here generates a search term, and nothing here picks an answer directly.

If Q, K and V all come from one X through separate projections, X's gradient sums the three paths. Each projection-weight gradient is the transposed input times the corresponding output gradient. The residual branch also adds the upstream gradient directly back. Multiple heads add shape rearrangements and per-head computation, with a correct inverse transformation needed at the final merge.

5. Backward-pass intuition for RoPE, RMSNorm and gating

For fixed positions, RoPE is an orthogonal linear transformation; backpropagation uses the transposed rotation matrix, rotating the upstream gradient by the opposite angle. Fixed positional frequencies need no optimization; architectures learning related parameters have different computation graphs and must be treated separately.

Start with the objects and symbols used here
Norm, LayerNorm, RMSNorm: not a probability normalization
In a layer formula, Norm stands for a normalizing function. LayerNorm usually subtracts the mean over one token's features, divides by the standard deviation, then scales and shifts; RMSNorm usually does not subtract the mean and scales by the root mean square. Neither of them is softmax. Independent micro-example, ignoring the small positive ε that stabilizes the denominator and the learnable scaling: LayerNorm([1,3])=[-1,1]; RMSNorm([1,3])=[1/√5,3/√5].
γ, β, ε: keep the parameters and the stabilizing constant apart
In the LayerNorm expression, γ is a row of learnable multiplicative coefficients and β a row of learnable additive ones; ε is a small positive number set by hand, placed in the term involving the denominator to avoid division by zero and similar problems. The mean μ and the variance σ² that are computed are in turn statistics of this data.γ=1 and β=0 usually mean that every feature uses 1 and 0; they are not the meaning of an input word. The β in DPO refers to a coefficient of the objective function, and the sense it has here does not carry over.

For RMSNorm, let r=sqrt(mean(x²)+ε), y=γ⊙x/r. Define g=上游⊙γ; the input gradient is then g/r−x·mean(g⊙x)/r³. This is a direct term minus feedback from the normalization scale. Treating normalization as constant loses the second term, producing wrong gradients despite a normal-looking forward pass.

Start with the objects and symbols used here
SiLU: the input times a gating coefficient
SiLU(x)=x×sigmoid(x). The input is first mapped to between 0 and 1, then multiplied back by x itself, which makes it nonlinear. Negative numbers do not all become 0 as they do with ReLU. Independent micro-example: SiLU(0)=0; SiLU(1) is about 0.731059; SiLU(-1) is about -0.268941.
SwiGLU, Wg/Wu/Wd: two transformation paths, then combined
This is a gated feed-forward structure. Wg produces the path that goes through SiLU, Wu produces the other content path, the two are multiplied element by element, and Wd maps the result back to the original width. These Ws are three sets of parameters, not three agents. To read (SiLU(XWg)⊙XWu)Wd, compute XWg and XWu first, then SiLU, then ⊙, and finally multiply by Wd. Every position uses the same set of parameters independently.

SwiGLU uses multiplicative gates; each branch receives the other branch's value times the upstream gradient. SiLU also needs its own derivative. Verifying individual operators before combining a whole layer usually locates problems more easily than final training loss alone.

6. Combining finite differences with automatic differentiation

This book uses L=sum(O⊙G) to construct a scalar objective, adding and subtracting ε at every Q/K/V element to compare numerical and analytic gradients. This is affordable for small matrices; large models sample dimensions or check directional derivatives.

Large ε gives substantial truncation error; overly small ε amplifies floating-point rounding. float64, moderate values and explicit tolerances help find logic errors. The accompanying tests compare all three gradients under non-square masks and verify zero gradients for future K/V when only the first output row contributes to loss.

Automatic differentiation still needs verification. Wrong masks, labels or dimensions faithfully produce gradients of the wrong objective. Finite differences establish derivatives only relative to the current forward implementation, not correct forward semantics. Mathematical invariances, negative controls and task tests must therefore form evidence together.

7. How a dense retriever learns "relevance"

A dual-encoder retriever can compute contrastive loss for query q, positive d+ and multiple negatives dj:

L = −log exp(s(q,d+)/τ) / Σj exp(s(q,dj)/τ)

This makes the positive more similar relative to candidates, without giving absolute distance one universal business meaning. In-batch negatives improve efficiency but may include genuinely relevant documents, creating false negatives; hard negatives teach fine distinctions but may introduce label errors.[N70]

Training that distinguishes only topical relevance may miss new versus old versions or affirmation versus negation within one topic. Code retrieval needs positives, negatives and evaluation matching real tasks. More vector dimensions do not automatically repair a flawed objective.

Rerankers can learn finer query–document interactions, but training labels favoring long texts or particular formats also create bias. Retrieval training and the evaluation design in Lesson 14 must be considered together.

How to read the changes in the figure

The database only computes distances between numbers; it does not know whether the query and the document come from the same trained space. A passing shape check can still leave retrieval entirely distorted.

Training usually uses correct document pairs and negative examples to push the relevant item's score higher; that is not quite the same objective as "the sentences look similar in meaning".

Upgrading an index means recording the encoder ID, the normalization method, the dimension and the version; otherwise different coordinate systems can end up mixed into one index.

Do not conflate: high vector similarity is no substitute for checking the conditions — "allowed" and "not allowed" share many semantic features yet reach opposite conclusions.

Mechanism basis:[DPR] [COLBERT]. The numbers and harness setting in this example are an explicitly given teaching construction, not commercial model output or a production performance measurement.

8. How to use this appendix

Run the existing experiment, then deliberately remove the within-row subtraction term from the softmax derivative and observe finite-difference failure; remove the mask next and observe causal-gradient test failure. Finally compare automatic differentiation in PyTorch training with the hand derivation: one enables efficient implementation and the other verification and understanding; they do not compete.

Meeting this chapter's standard means explaining why a gradient follows its path, experimentally catching incorrect derivatives and knowing the experiment's logical limits. It does not establish mastery of complete distributed training or GPU backward-kernel implementation.
