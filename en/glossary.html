Reading guide and appendix

Terms and notation at a glance

Reading toolsapprox. 9.2 thousand characters

To understand what a symbol stands for and where it comes from, read Formulas, terms and where the objects come from. That page distinguishes parameters, inputs, intermediate results, dimensions and execution state, and provides independent micro-examples and entry points to the full lessons.

This is a quick reference, not foundational teaching reduced to definitions. Each item has examples and a link to the full prerequisite lesson; read the lessons first when learning, then use this page as a handy index.

Search for a term or question number

Model

A computation rule with learnable parameters that turns input representations into output scores or other results.

A concrete example: it cannot open files on your computer by itself; only the surrounding program can perform such actions.

Back to the full explanation in Lesson 35 →

Parameter

Numbers the model keeps over the long term and adjusts during training.

A concrete example: embedding tables and linear-layer weights are both parameters.

Back to the full explanation in Lesson 35 →

Training

The process of computing error from examples and a target, then adjusting parameters.

A concrete example: this book's scalar training updates w=1 to 1.8.

Back to the full explanation in Lesson 35 →

Inference

The process of using existing parameters to process input and produce output.

A concrete example: one chat usually does not permanently change the model's weights.

Back to the full explanation in Lesson 35 →

Function

An operation that maps input to output according to a rule.

A concrete example: f(x)=2x means input 3 gives output 6.

Back to the full explanation in Lesson 35 →

Scalar

A single numeric value.

A concrete example: 7, or one loss value.

Back to the full explanation in Lesson 36 →

Vector

An ordered row of numbers.

A concrete example: [0.2,-0.1,0.7,0.4] has 4 components.

Back to the full explanation in Lesson 36 →

Matrix

A regular table of numbers with rows and columns.

A concrete example: a table with two rows and three columns has shape [2,3].

Back to the full explanation in Lesson 36 →

Tensor

A data object used in machine-learning programs to store regularly arranged numbers.

A concrete example: [2,3,4] can be read as two tables of three rows and four columns.

Back to the full explanation in Lesson 36 →

Shape

The length of each axis, not the data's contents.

A concrete example: the contents [[1,2],[3,4]] have shape [2,2].

Back to the full explanation in Lesson 36 →

Axis

One indexing direction in a tensor.

A concrete example: the three axes of [B,T,d] are sample, position and feature.

Back to the full explanation in Lesson 36 →

Rank (axis count)

In tensor contexts, this often means the number of axes, which differs from matrix rank in linear algebra.

A concrete example: [2,128,4096] has 3 axes; see F20 for matrix rank.

Back to the full explanation in Lesson 36 →

Index

A way to locate data by position; this book's code counts from 0.

A concrete example: H[1,0] takes the first position of the second input.

Back to the full explanation in Lesson 36 →

Slice

Take data over a range, or from a set of positions while keeping an axis.

A concrete example: H[1,:,2] takes the third component at every position of the second input.

Back to the full explanation in Lesson 36 →

B

Batch size: the number of inputs organized for computation together.

A concrete example: B=2 means two inputs, not two network layers.

Back to the full explanation in Lesson 36 →

T

The number of sequence positions scheduled for this round; check whether the particular formula includes the cache.

A concrete example: T=128 after padding does not prove every actual input has 128 tokens.

Back to the full explanation in Lesson 36 →

d / d_model

The width of the internal representation at each position.

A concrete example: d=4096 means a row of 4096 numbers.

Back to the full explanation in Lesson 36 →

N / V (vocabulary)

The number of vocabulary entries; some papers use V, which must be distinguished from the Value in attention.

A concrete example: an embedding parameter table with N=6 and d=4 is [6,4].

Back to the full explanation in Lesson 36 →

L (layer count)

The number of model layers stacked in series.

A concrete example: the cache formula multiplies by L because each layer has its own K and V.

Back to the full explanation in Lesson 36 →

Subscript x_i

The i-th number in vector x, or an object indexed according to its definition.

A concrete example: when x=[7,2,9] and indexing starts at 0, x_1 is 2.

Back to the full explanation in Lesson 36 →

Σ / summation

Add the terms in a given range one by one.

A concrete example: Σ_i x_i expands to x_0+x_1+….

Back to the full explanation in Lesson 36 →

∈ / R

∈ reads "belongs to"; R denotes the set of real numbers.

A concrete example: X∈R^(2×3) means X is a table of real numbers with two rows and three columns.

Back to the full explanation in Lesson 36 →

≈ / approximately equal

The two sides are close because of rounding or approximation, rather than identical digit by digit.

A concrete example:1/3≈0.3333.

Back to the full explanation in Lesson 36 →

Character

A written unit or encoded character in text, which cannot be equated directly with a token.

A concrete example: the UTF-8 encoding of "爱" occupies multiple bytes.

Back to the full explanation in Lesson 37 →

Byte

A storage unit consisting of 8 bits.

A concrete example: a float32 usually occupies 4 bytes.

Back to the full explanation in Lesson 37 →

UTF-8

A rule that encodes Unicode characters as variable-length byte sequences.

A concrete example: a network chunk may split the bytes of a Chinese character.

Back to the full explanation in Lesson 37 →

Token

The fragment unit used by the model's tokenizer.

A concrete example: it may be a word, part of a word, punctuation or some bytes.

Back to the full explanation in Lesson 37 →

Token ID / input_ids

The integer address of a token in its vocabulary.

A concrete example: [1,2,3] is first a list of IDs, not three degrees of meaning.

Back to the full explanation in Lesson 37 →

Tokenizer

A tool that converts between text and token IDs using the rules paired with the model.

A concrete example: a tokenizer cannot be swapped arbitrarily while keeping incompatible model parameters.

Back to the full explanation in Lesson 37 →

BPE

A class of methods that builds a subword vocabulary by progressively merging adjacent symbols.

A concrete example: the merge rules are trained first, then used to encode new inputs.

Back to the full explanation in Lesson 37 →

WordPiece

Another subword modeling method, often using longest-match encoding over a vocabulary.

A concrete example: its training objective differs from the BPE merge process; do not simply remember them as the same algorithm.

Back to the full explanation in Lesson 37 →

Unigram

A class of subword models that assigns probabilities to candidate subwords and selects a segmentation.

A concrete example: it does not always take the longest string in the vocabulary.

Back to the full explanation in Lesson 37 →

Chat template

Organizes messages with roles into the input format agreed for the model.

A concrete example: roles and end markers may use dedicated tokens.

Back to the full explanation in Lesson 37 →

Batch

A group of inputs organized for computation together.

A concrete example: an ordinary sample batch does not let different users read each other's content.

Back to the full explanation in Lesson 38 →

Padding

Adds placeholders to shorter sequences so a particular organization can be used.

A concrete example: right-padding [4,2] gives [4,2,0].

Back to the full explanation in Lesson 38 →

PAD

The special padding item in the model configuration.

A concrete example: this book uses PAD ID 0; real models need not use 0.

Back to the full explanation in Lesson 38 →

Truncation

Removes part of an overlong input rather than adding placeholders.

A concrete example: it may remove key constraints and must not be conflated with summary-based compaction.

Back to the full explanation in Lesson 38 →

Embedding

The parameter table, and the operation on it, that retrieves the learnable vector for an input ID.

A concrete example: E has shape [6,4], and ID 2 takes row 2 of E.

Back to the full explanation in lesson 39 →

One-hot encoding

An array of 0s and 1s the size of the vocabulary identifies an ID: only the selected position is 1 and all others are 0. This differs from an integer's binary storage and from the trainable floating-point vectors in an embedding table.

A concrete example: ID 2 in a 6-entry vocabulary is written as [0,0,1,0,0,0]; if E has shape [6,4], multiplying this one-hot vector by E is mathematically equivalent to taking E[2], but implementations usually look up the row directly.

Go to the full explanation and lookup example →

Lookup

Reads an entire entry by address rather than using the size of the address in a semantic computation.

A concrete example: ID 4 corresponds to [0.1,-0.5,0.9,0.3], rather than multiplying 4 by a vector.

Back to the full explanation in lesson 39 →

Distributed representation

A meaning is expressed jointly by several numbers and their combinations, rather than each column having a fixed semantic label.

A concrete example: we cannot assert that dimension 12 always represents happiness.

Back to the full explanation in lesson 39 →

dtype / data type

Specifies how each element is stored and used in computation.

A concrete example: integer IDs and floating-point representations usually have different dtypes.

Back to the full explanation in Lesson 40 →

Floating point

A computer format that approximates real numbers using a finite number of bits.

A concrete example: binary floating point cannot necessarily store 0.1 exactly.

Back to the full explanation in Lesson 40 →

FP32 / FP16 / BF16

Different 32-bit or 16-bit floating-point formats have different ranges and precision.

A concrete example: FP16 and BF16 both usually occupy 2 bytes, but they are not the same numeric format.

Back to the full explanation in Lesson 40 →

CPU

A general-purpose processor suited to many kinds of control and numeric tasks.

A concrete example: the foundational experiments in this package use the CPU and Python standard library.

Back to the full explanation in Lesson 40 →

GPU

A processor suited to large-scale parallel numeric computation.

A concrete example: moving data to the GPU does not change the meaning of IDs, but takes time and VRAM.

Back to the full explanation in Lesson 40 →

Device

The processor environment where data or computation resides.

A concrete example: model weights and input must satisfy compatible device constraints.

Back to the full explanation in Lesson 40 →

VRAM

GPU storage for parameters, inputs and intermediate results.

A concrete example: the embedding output's size alone is not the model's total VRAM use.

Back to the full explanation in Lesson 40 →

MiB / GiB

Binary storage units, equal to 2^20 and 2^30 bytes respectively.

A concrete example: 1,048,576 numbers of 2 bytes each occupy 2MiB.

Back to the full explanation in Lesson 40 →

Weight

A learnable coefficient that determines how input numbers are combined.

A concrete example: multiplying [1,2,3] by coefficients [2,0,1] and summing gives 5.

Back to the full explanation in Lesson 42 →

Dot product

Multiply two equal-length vectors element by element, then sum.

A concrete example:[1,2]·[3,4]=11.

Back to the full explanation in Lesson 42 →

Matrix multiplication / Matmul

Takes the dot product of each row of the left table with each column of the right table.

A concrete example: [2,3] multiplied by [3,4] gives [2,4].

Back to the full explanation in Lesson 42 →

Transpose / ᵀ

Swaps a matrix's row and column directions.

A concrete example: transposing [[1,2,3],[4,5,6]] gives [[1,4],[2,5],[3,6]].

Back to the full explanation in Lesson 42 →

Norm

A class of functions measuring vector size; the L2 norm is the square root of the sum of squares.

A concrete example: the L2 norm of [3,4] is 5.

Back to the full explanation in Lesson 42 →

Cosine similarity / Cosine

The dot product divided by the two vectors' L2 norms, comparing direction.

A concrete example: similar topic directions do not guarantee the same facts or permissions.

Back to the full explanation in Lesson 42 →

reshape

Changes the data view or organized shape while keeping the total element count the same.

A concrete example: 6 numbers can be arranged as [2,3] or [3,2], but transposition has its own rearrangement rule.

Back to the full explanation in Lesson 43 →

permute

Reorders multiple axes.

A concrete example: [B,T,h,d_h] becomes [B,h,T,d_h].

Back to the full explanation in Lesson 43 →

Broadcast

Expands compatible singleton dimensions by a rule for combined computation.

A concrete example: a bias for each column can be applied to every row of the table; many copies of the bias are not learned first.

Back to the full explanation in Lesson 43 →

Stride

The element spacing crossed in the underlying storage when an index moves by one along an axis.

A concrete example: a transposed view may be non-contiguous, and a later reshape may need a copy.

Back to the full explanation in Lesson 43 →

Probability

The share of likelihood assigned to an event under given conditions and a model.

A concrete example: a candidate token's probability is not the correctness probability of the final answer.

Back to the full explanation in Lesson 44 →

exp / e^x

The exponential function turns values into positive numbers; e is about 2.71828.

A concrete example: exp(0)=1,exp(ln2)=2.

Back to the full explanation in Lesson 44 →

ln / log

The inverse of exponentiation; when no base is specified, this book usually means the natural logarithm.

A concrete example: ln(1)=0 and ln(2) is about 0.6931.

Back to the full explanation in Lesson 44 →

softmax

Take the exponential of each score, then divide by the sum of all exponentials.

A concrete example: [2,1,0] after Softmax is about [0.6652,0.2447,0.0900].

Back to the full explanation in Lesson 44 →

Normalization

Adjusts scale by a chosen rule; the goal differs by context.

A concrete example: softmax makes the sum 1, while LayerNorm transforms using the mean and variance; they are different operations.

Back to the full explanation in Lesson 44 →

Linear layer

Often written XW+b: a weighted combination of the input, with a bias added.

A concrete example: the number of columns in W determines output width.

Back to the full explanation in Lesson 45 →

Bias (parameter)

The learnable constant term added by a linear layer.

A concrete example: it differs from statistical bias in evaluation.

Back to the full explanation in Lesson 45 →

Activation

May mean a layer's intermediate output or an activation function, depending on context.

A concrete example: ReLU turns negative numbers into 0; activation VRAM stores this run's intermediate results.

Back to the full explanation in Lesson 45 →

Nonlinearity

An operation that cannot be represented equivalently by a single linear transformation alone.

A concrete example: ReLU lets the network express more complex piecewise behavior.

Back to the full explanation in Lesson 45 →

ReLU / GELU / SiLU

Different nonlinear activation functions.

A concrete example: ReLU(x)=max(0,x), while the other two have smooth curves.

Back to the full explanation in Lesson 45 →

Hidden state

A row of representation numbers at a particular layer and position inside the network.

A concrete example: the same token may have different later-layer representations in different contexts.

Back to the full explanation in Lesson 45 →

Forward

Computes output from input according to the network definition.

A concrete example: both training and inference perform a forward pass; training also performs a backward pass and updates.

Back to the full explanation in Lesson 45 →

Attention

Computes matching shares between the query and readable candidates, then combines their content by those weights.

A concrete example: compute scores and weights first, then use the weights to mix V.

Back to the full explanation in Lesson 46 →

Q / Query

A set of numbers used by the current position to compare against candidates.

A concrete example: q=[1,0] is a projected representation, not the user's original words.

Back to the full explanation in Lesson 46 →

K / Key

A set of numbers at each readable position for comparison with a query.

A concrete example: its dot product with Q produces a matching score.

Back to the full explanation in Lesson 46 →

V / Value

The content representation at each readable position to be collected with weights.

A concrete example: V here is not the vocabulary size.

Back to the full explanation in Lesson 46 →

d_k / d_h

The Key width or width of each head, as defined in the particular formula.

A concrete example: a common dot-product scaling divides by sqrt(d_k).

Back to the full explanation in Lesson 46 →

Self-attention

The query and readable information come from representations of the same sequence.

A concrete example: generative models usually impose causal restrictions as well.

Back to the full explanation in Lesson 46 →

Attention mask

A constraint specifying which reads between positions are allowed.

A concrete example: an interface may use booleans or additive negative infinity; check the true/false convention.

Back to the full explanation in Lesson 47 →

Causal mask

Prevents the current position from reading positions that have not yet arrived.

A concrete example: position 1 can read 0 and 1, but not 2.

Back to the full explanation in Lesson 47 →
