先把“要预测什么”对齐

有一段Token序列[a,b,c,d]。下一Token训练可以组织为：

输入位置：a  b  c
目标标签：b  c  d

a所在位置根据a预测b，b所在位置根据ab预测c，c所在位置根据abc预测d。标签label是本次要比较的正确答案；teacher forcing是在训练中使用数据里的真实前缀，而不是总用模型自己刚生成的前缀。

为什么不是输入a就预测a？因为这个目标会变成拷贝已知输入，而不是学习接下来出现什么。实际模型API可能内部移动标签；外部代码再次移动会错两位，必须确认责任边界。

交叉熵从一个正确候选开始

假设正确下一Token是c，模型给它概率0.8。一种常用损失是−ln(0.8)≈0.2231。若只给0.2，则−ln(0.2)≈1.6094，错误更大。

这种对正确目标的负对数概率，是单一正确标签下的交叉熵损失。概率越接近1，损失越接近0；给真实标签的概率越小，惩罚越大。

若正确候选用one-hot表示，即词表长度的一排0里只有正确项为1，记作y，那么通式是L=−Σ_i y_i ln p_i。因为其他y_i为0，最后只留下正确项。

对softmax前分数z的导数简化为∂L/∂z_i=p_i−y_i。这解释了为什么训练会推动正确项分数提高、错误项分数下降；再经输出矩阵与各层反传到前面的参数。

多位置与填充怎样评分

对每个有效目标位置算损失，然后求和或平均。PAD位置通常不应当成真实语言目标；指令微调还可能只对助手输出部分计分。这就是loss mask。

如果每批真实长度不同，按样本平均和按有效Token平均可能得到不同权重。报告loss时，要知道分母是什么。不能只看数字变小就断言学习更好。

困惑度perplexity常为平均负对数似然的指数。只有分词、数据和计分条件可比时才适合直接比较，不是任意两个模型的统一聪明指数。

把一个优化步写完整

取一批训练样本
-> 准备输入、标签与mask
-> 用现有参数前向计算概率
-> 计算损失
-> 反向传播得到梯度
-> 按训练意图合并或清理梯度
-> 优化器更新参数
-> 进入下一批

梯度累积是先对若干小批计算并累积梯度，再更新一次，以模拟更大的有效批次；它不让单条超长输入的激活存储自动消失。梯度如何缩放必须与损失平均方式对应。

Adam为什么会保存额外状态

最简单梯度下降只用当前梯度g。Adam还保存梯度的平滑平均m和平方梯度的平滑平均v，帮助调整各参数步幅。示意式为：

m新 = β1×m旧 + (1−β1)×g
v新 = β2×v旧 + (1−β2)×g²

β是0到1之间的平滑系数，不是模型学到的词义。因为初值常为0，开始时平均偏小，所以会做偏差修正。例如首步g=2、β1=0.9：m=0.2，除以1−0.9得到修正后的2。

随后用修正m除以修正v的平方根再更新。AdamW把权重衰减作为解耦操作处理。完整公式在高级章节；本课先解释“为什么要多存m和v”，这也说明训练显存不能只算权重。

学会训练不等于已经学会泛化

训练集用于更新参数；验证集用于选择方案与调参；测试集用于相对独立地评估。把测试答案放进训练或反复按测试结果调Prompt，会污染评估。

在固定小序列上loss降很低，只说明这个训练过程学会了该分布，不能据此声称模型能理解任意语言。真正工程结果还要看新任务、新数据、稳定性和成本。

自检 2 · 答案直接展开

为什么恢复训练可能还需优化器状态而不只是权重？

Adam等优化器保存历史平滑量，此外步数和学习率状态也会影响后续更新。只恢复权重未必延续同一训练轨迹。
