F05｜Embedding查表：把一个编号换成一排数

本章通过小规模实例说明概念、计算步骤与适用边界。

为什么不能直接拿“编号大小”理解文字

模型需要一种可以进行加权、组合、比较和更新的数字表示。编号1只是一个地址；它与编号4相差3没有语言意义。最常见的输入方式是准备一张可学习的数字表，让每个词表编号对应一排数。这张表叫Embedding矩阵（嵌入矩阵），记作E。

可学习的意思是训练时这些数会被调整；普通推理时通常从训练好的参数中读取，不是看到一句新话才临时生成一张表。Embedding查表本身就是模型的一个层，不是某个额外联网检索服务。

用6行4列的表完整查一次

沿用6项教学词表，指定每个片段用4个数表示，写作d=4。下面的数字是人为构造，只用来解释运算，不代表“我”“你”的真实含义：

ID 片段 特征0 特征1 特征2 特征3
0 PAD 0 0 0 0
1 我 1 0 0 1
2 爱 0 1 0 1
3 学习 1 1 0 0
4 你 0 1 1 0
5 ！ 1 0 1 0

E的形状是[6,4]：6种Token，每种4个数。现在对[1,2,3]逐个编号找行：1取第1行，2取第2行，3取第3行，得到：

[[1,0,0,1],
 [0,1,0,1],
 [1,1,0,0]]       shape=[3,4]

对第二条[4,2,0]同样处理，得到：

[[0,1,1,0],
 [0,1,0,1],
 [0,0,0,0]]       shape=[3,4]

把两张表放在一起，结果H形状就是[2,3,4]。用一句可执行的定义表示：H中某条输入、某个位置的一排数，等于E中该位置Token编号对应的那一行。

为什么凭空多出一个轴

原来每个位置只有一个编号；现在每个位置被替换成4个数。所以句子轴B和位置轴T没变，末尾增加了表示宽度d：

[B,T] --逐编号查E--> [B,T,d]

这不是把一个ID复制d次，也不是把字符串分成d个字。更不是“补齐到d长度”。补齐改变位置数T；Embedding改变每个位置的表示方式。

扩大到一般配置B=2,T=128,d=4096：有2条输入，每条安排128个位置；每个位置的一个编号被换成4096个数，因此得到2张128行4096列的表。形状是[2,128,4096]，不是再生成了4096个Token。

隐藏维度到底“隐藏”了什么

隐藏表示指网络内部产生、不是直接提供给用户的中间数字表示；隐藏维度d是这种表示每个位置的宽度。隐藏不意味着神秘、加密或私人思考记录。

这一排数的各列通常没有人工指定的名称，不能擅自说第一维表示“动物”、第二维表示“快乐”。它们共同参与预测，可能以分布式方式表示多种信息。为了教学我们把列叫特征0到特征3，而不是捏造语义标签。

同一Token在标准固定查表中通常取同一行；经过位置处理和读取上下文的后续层，表示才会因句子不同而改变。输入Embedding、上下文化隐藏状态、整篇文档检索向量都可能是“一排数”，但来源、训练目标和用途不同。

PAD行是零，就能不用mask吗

不能由此保证。即使Value是零，若它参与概率归一化，仍可能分走注意力权重；位置处理、偏置等也可能让后续值不再为零。PAD是否参与，必须按掩码和损失约定处理。这里的零行是教学选择，不是完整隔离机制。

**对原文的一处措辞修正：**不能说查完Embedding“才进入神经网络”。查表层已是模型运算的一部分；更准确的边界是：此前主要做请求组织和编号转换，从Embedding开始进入模型的数值表示与后续网络计算。

自检 1 · 答案直接展开

E形状[100,8]，输入ID形状[3,7]，查表结果是什么？

结果[3,7,8]，共168个数。E有100行是词表容量，不等于本次输入有100个位置。
自检 2 · 答案直接展开

同一个“爱”出现在两句话里，为什么以后表示可能不同？

初始固定查表可相同；随后加入位置信息并通过注意力使用不同上下文，所以后续隐藏状态可能不同。
