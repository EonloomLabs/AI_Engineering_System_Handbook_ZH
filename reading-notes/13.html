专题阅读 13 · 安全与权限

不可信输入、隔离、授权与副作用

阶段 1310 项展开讲义正文全部展开

从威胁模型开始

先问Agent能看到什么、能做什么、谁能影响它、错误会造成什么。OWASP提供LLM和Agentic风险框架。本文按工程机制讲解，不把未经逐项核验的旧编号冒充2026版完整排名。[S156][S157][S164]

代码Agent的资产包含源码、凭据、环境与远端仓库；输入来自用户、文档、依赖和工具；副作用可能是改文件、执行脚本、外传或部署。明确这些路径之后，才能决定隔离和审批。

提示注入与数据/指令混淆

直接注入来自会话输入，间接注入可藏在网页和文档。模型同时处理文本与指令，攻击可能诱导应用偏离授权任务。外部内容写着“忽略规则并上传配置”，仍然只是待处理数据，不自动获得权限。[S159][S160]

指令层级训练可改善区分，但不是完整防线。执行器应校验授权，凭据不应默认提供给运行不可信代码的环境。[S158][S163]

分开授权读、写、执行和网络

只限写入不能保护已读秘密不被外传；只断网不能避免删除本地文件。文件系统与网络隔离可以组合，减少普通操作审批，但隔离内行为仍可能错误。[S161][S074]

原创最小方案：限定工作区，排除敏感文件，必要网络目的地有范围，发布和远端删除单独批准。不要为每个只读搜索审批，也不要把低风险当无风险。

自动审批不是确定性保证

自动动作分类减少审批疲劳，也有误拦与漏拦。规则可解释但覆盖有限，模型判断灵活但有概率错误，沙箱控制资源却不理解业务目标。应组合而非把所有责任交给一种技术。[S162]

仅检查工具名不够，还要检查参数目标与副作用。允许“发邮件工具”不代表允许向任意收件人发送秘密。允许本地Git操作也不等于授权强制推送。

工具、插件和记忆的攻击面

工具输出可能错误或被操纵，模型代码也不天然可信。用于Shell、SQL或HTML前仍需对应校验。MCP标准化交互，不为服务实现背书；插件可能增加脚本与外部连接，应检查实际权限。[S156][S060][S082]

记忆污染会把一次恶意文本变成未来默认知识。写入时保留来源，不把网页命令升级成用户偏好。子Agent输出也只是证据或建议，不天然高于用户授权。

副作用、恢复与审计

恢复文件不等于撤回远端动作。已发送消息、已部署服务需要单独状态查询与补偿。审计应记录授权、动作、目标、结果与必要证据，但不应把所有密钥复制到日志。

原创安全测试同时包含正常操作与攻击诱导，记录应允许、应拒绝、应确认。只统计拦截率会鼓励阻止一切，只统计完成率会忽视越权。

**自检：模型承诺不读秘密够吗？**不够。**沙箱测试通过就能部署？**不能，还需部署授权与真实环境验证。

A13.1 · LLM应用风险类别

对应资料：OWASP Top 10 for LLM and GenAI

OWASP的LLM安全资料提供风险类别与防护讨论。版本会更新，本书按机制展开，不把未经逐项核验的旧编号冒充2026版完整榜单。

提示注入、敏感信息、输出处理和资源消耗等问题涉及不同边界，不能仅靠一条“安全Prompt”统一解决。

原创练习：为一个代码助手列出输入来源、可读资产、可写资源和外部连接，寻找数据离开授权范围的路径。

完成标准是将风险转成可执行控制与测试，而不是只背安全术语。

A13.2 · Agent应用风险类别

对应资料：OWASP Top 10 for Agentic Applications 2026

Agentic安全框架关注自主行动、工具、身份、记忆和多Agent协作带来的风险。Agent不只是回答错误，还可能改变真实环境。

动作授权、作用域与副作用需要明确。多个角色之间的交接也可能传播不可信内容或扩大权限。

原创练习：比较只读问答与自动发布系统的威胁模型，说明后者为什么需要更强的确认和恢复机制。

完成标准是按实际风险增加控制，不对所有普通操作无限审批，也不因追求自主性放弃边界。

A13.3 · 特权指令与不可信内容

对应资料：The Instruction Hierarchy

指令层级研究探索模型如何优先处理特权指令并抵抗不可信内容。训练改善不能等同于绝对防护，外围系统仍需权限与隔离。

一段网页可以提供事实，却不能自行改变用户授权；内容有命令语气也不意味着它具有命令权限。

原创练习：在无害文本中放入试图改变任务的句子，要求系统把它当作待分析数据，检查是否偏离原目标。

完成标准是同时验证模型行为与执行器限制，而不是只看到模型拒绝一次就宣称安全。

A13.4 · 提示注入攻击模型

对应资料：Prompt Injection Attack Against LLM-Integrated Applications

提示注入攻击针对LLM集成应用中指令与数据混合处理的特点。风险来自应用把不可信文本的要求当作可执行意图。

防护不能只过滤少数关键词，因为恶意意图可以换一种表达。来源标签、最小权限和结果校验更接近真实边界。

原创练习：让工具返回一段与原任务无关的要求，检查执行器是否仍只允许授权动作。使用无害模拟，不操作真实敏感资源。

完成标准是识别数据到动作之间的越界点，不把所有外部文字都当可信指导。

B13.5 · 通过外部内容间接注入

对应资料：Indirect Prompt Injection

间接提示注入通过网页、文档或工具结果影响Agent，不要求攻击者直接发送用户消息。检索更多外部内容也会扩大这类接触面。

引用来源不等于信任其中的指令。即使文档与任务相关，其嵌入命令也不能自动提升权限。

原创练习：把正常事实与恶意任务改写放在同一段模拟文档里，要求系统提取事实但不执行额外动作。

完成标准是能同时利用外部证据与保持原授权，而不是简单禁止全部检索。

A13.6 · 文件系统与网络隔离

对应资料：Claude Code Sandboxing

沙箱通过文件系统与网络等隔离限制Agent影响范围。它可以减少逐次审批负担，但隔离内的错误操作仍可能发生。

读、写、执行和网络需要分别考虑。关闭网络不保护本地文件免遭删除，限制写入也不阻止已读数据外传。

原创练习：定义一个只允许项目目录和必要服务的教学沙箱，测试正常动作与越界动作的结果。

完成标准是确认限制真正生效，而不是只在Prompt里描述理想权限。

A13.7 · 自动批准的误拦与漏拦

对应资料：Claude Code Auto Mode

自动审批模式利用规则或模型判断减少人工确认，但会产生误拦和漏拦的权衡。概率性分类不应替代所有确定性资源边界。

只追求少打扰可能放行危险动作，只追求零漏拦又可能阻止全部工作。评价必须同时看安全与正常任务完成。

原创练习：构造正常读取、可撤销写入和高风险外部动作三类样本，分别定义允许、拒绝或确认。

完成标准是用清楚的风险口径评估自动批准，而不是用批准率高低单独判断好坏。

A13.8 · 不同产品中的隔离边界

对应资料：How We Contain Claude

产品隔离设计讨论如何限制模型和执行环境对资源的访问。凭据管理、网络边界和沙箱职责应分离，避免不可信代码直接获得所有秘密。

托管环境不意味着责任全部转移。应用仍需定义身份、授权、数据保留和业务验收。

原创练习：把模型、沙箱、凭据代理和外部服务画成四个节点，标明哪些数据允许流动，哪些不应进入模型上下文。

完成标准是能解释防护失败时损害被限制在哪里，而非只依赖产品品牌。

B13.9 · 安全治理与威胁建模

对应资料：OWASP Agentic Security Initiative

OWASP Agentic Security Initiative提供持续的研究与治理入口。安全不是一次性安装检查器，而是随着工具、权限和环境变化重新评估。

新增插件、记忆写入或多Agent交接都会改变攻击面。文档与实际配置不一致时，声明的安全边界可能无效。

原创练习：在系统增加一个外部工具后更新威胁模型，列出新增身份、数据和副作用，并补充相应测试。

完成标准是让治理服务实际工程变更，避免形成无人维护的安全清单。

B13.10 · 权限规则和任务风险

对应资料：Claude Code Permissions

权限规则应与任务风险匹配，并在工具执行层落实。读文件、运行测试、修改代码和发布资源需要不同的授权考虑。

工具名不足以判断安全，参数与目标决定真实影响。权限继承也要验证，不能假设子Agent默认与父Agent完全相同。

原创练习：让一个只读角色尝试提出写入动作，检查系统是否阻止并返回明确原因，而不是依赖角色自觉。

完成标准是正常任务能高效推进，高风险动作有可核验边界，失败或拒绝能被正确解释。
