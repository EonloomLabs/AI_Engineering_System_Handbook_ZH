8896	The StepContext binds the model settings, the MCP, the environment and the tool routing used to issue this request; the file-system accessor still combines the live session with this turn's grants. A consistent snapshot is not every permission frozen for good.
7168	C03 · Tool visibility, call conversion and routing
17774	Tool registration, direct exposure, deferred discovery and Code Mode are different surfaces. exposes_tool covers several paths; build_tool_call separates local from hosted search, and the dispatch carries the call_id and the original StepContext. A registration metric is no proof of being visible or executable.
7169	C04 · Parallel admission, execution, cancellation and results
28721	Read the creation, admission, execution and cancellation in ToolCallRuntime; a call may start immediately, and the future that consumes the result does not stand for the actual start time. The parallel-allowed flag only decides how work is scheduled; it is no proof that the read and write targets are independent of one another.
7170	C05 · Recording output items, dispatch and filling results back in
16769	Once the complete output item has arrived, the call is recorded first and then dispatched either immediately or later. A call already written into the history but canceled before it ran still needs a matching abort result, so that no orphaned call is left after recovery. A tool item finishing is not the whole response, nor the business task, finishing.
7171	C06 · The asynchronous compaction life cycle and candidate validation
15523	Background compaction is constrained jointly by the feature flag, by TokenBudget being disabled and by remote V2 support. The identity it starts from includes the history-rewrite generation, the model and compaction version, and the authorization generation. Canceling this turn only stops new work, while work already under way is managed by the session; discarding the result does not erase its cost.
7172	C07 · Installing a compaction candidate, and falling back
16518	Installation first checks the model and the compaction hash, converts the candidate through the shared path, and then hands it to the history-replacement primitive. After a candidate is installed the live suffix may still leave the window over budget, and one foreground fallback is allowed; this is not unlimited retrying.
7173	C08 · History versions, rewrites and baselines
9190	history_version records rewrites; reset_version is for a destructive reset; user_message_revision is independent of both. The model history, the retained facts and the review context also exist separately. Neither the number of messages nor a single version number can be taken for the identity of the whole state.
7174	C09 · Registration conflicts, admission, hooks and results
13937	A pre-execution hook can block the handler or rebuild its arguments; the post-execution check comes only after the handler has run. The pinned source makes it explicit that a post-execution block rejects the result without undoing the execution, and that on_tool_result_accepted is called after post-execution acceptance.
7176	C10 · Rule refresh, caching and sharing with child threads
25281	Rule refresh is serialized, but the call out to an external provider does not hold the state lock. A change of environment or of trust invalidates the old cache first, so that a failed refresh does not go on exposing the old rules. A sub-agent inherits the text already applied, and a dynamic thread provider has to allow sharing explicitly.
7177	C11 · Sub-agent input and message submission
19739	Submitting, or queuing in the mailbox, returns only an acceptance identifier. With no receiver loaded and trigger_turn=false it can merely queue, which does not mean it started, still less that the sub-task finished. The session identity and the tree runtime are separate.
7178	C12 · Creating a child thread, and filtering its history
18547	The fork filter function that was read keeps different message types by different rules, and it removes the parent thread's accumulated usage. One path being able to copy the history does not mean that every kind of sub-agent copies the parent's context, tools, permissions and cache in full.
7179	C13 · The conditions for starting the memory pipeline
15587	Starting memory has conditions: a root thread, a session that is not temporary, the feature flag, the database and the directory; the order of the cleanup and the staged tasks can be traced. It must not be written up as every conversation learning permanently.
7180	C14 · Memory extraction and candidate state
16918	The actual run creates the stage-one request context before claiming candidates, so the steps in the comments cannot be followed blindly. Candidates are constrained by source, age, idle time, an upper limit and a lease; concurrent extraction includes a "succeeded with no output" result, which should not be treated as an error to retry.
7181	C15 · Memory consolidation, leases and artifact verification
28789	Stage two first takes the global lease and prepares the Git baseline, and starts the consolidation agent only where that is needed; once it has finished, it shuts the agent down, checks the artifact, confirms the lease again, and only then resets the baseline and registers the success. The file baseline and the database completion record are not one atomic transaction; a failed shutdown leaves the lease in place to wait for expiry.
7182	C16 · Session-history replacement and the persistence entry point
19504	There is a lock order when the model and the environment are captured, and the slow preparation is moved outside the lock. The prefix install checks the generation, the length and the authorization inside the state lock and keeps the live suffix; only then does it persist. Returning true means that path accepted the in-memory replacement, which on its own cannot be taken as evidence of a successful recovery after power loss.
7183	C17 · Remote compaction parameters, hooks and fallback
14065	It separates the foreground, the background candidate, whether there is a foreground fallback, and the pre-execution hook. The constant 2 is the retry limit for the compaction transport in this snapshot, not a general agent retry standard.
