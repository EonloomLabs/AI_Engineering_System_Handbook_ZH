28016	Follow-up: what does gradient clipping change? And why can it not fix every NaN?
12956	Global-norm clipping scales the whole gradient vector down proportionally when the gradient norm exceeds a threshold, which limits very large updates. 21476	Why the gradients are asymmetric for the moment
25659	Let the output gradient be G. The gradient for A has to pass through B's transpose; if B=0, that gradient is 0 at the first step. The gradient for B passes through xA, which is usually non-zero when A is non-zero. Only once B has been updated for the first time can A receive a non-zero gradient at the second step.
20956	A local counterexample with real autograd: x=[1,2], A=[[1],[2]], B=[[0,0]], target=[1,1], sum of squared errors. xA=5, the initial increment is [0,0], A's gradient is [[0],[0]] and B's is [[-10,-10]]. This gives better judgment than changing the initialization the moment a grad of 0 is seen.
11723	When it really is a bug
25011	If neither side has changed after several update steps, check: whether they are in the optimizer's parameter groups, whether something was detached by accident, whether the right module was selected, whether that batch went through this path, whether the step was skipped on an AMP overflow, and whether the learning rate is 0. Not every initialization scheme has a zero B, so check the configuration before judging by what is shown in this section.
15317	Merging, quantization and caching have to be considered together
15315	Merging LoRA, which adds the increment back into the base weights, is one way to deploy it; quantizing and dequantizing low-precision weights, and quantizing them again, can make "merge first, then quantize" and "quantized base plus separate adapter" numerically inequivalent. Changing the adapter changes K/V, so an old prefix cache must not be reused merely because the tokens are the same. A prefix-cache design has to take in extra identity information such as the adapter.
27842	Follow-up: does freezing the base mean the base need not be stored?
10818	It does not. The forward pass still depends on W, and computing the gradients for the increment path still needs the relevant activations. What is saved is part of the trainable parameters, the gradients and the optimizer state, not all of the model's memory. When reporting VRAM, keep the weights, the activations, the gradients, the optimizer and the cache separate.
27886	Follow-up: if the increment's rank is small, why can it still be useful without being equal to full fine-tuning?
16502	It limits the space in which parameter updates can be expressed, yet it may happen to cover the important directions the task needs. Whether that is enough depends on the task, the target modules, the rank and the data. Do not push "fewer parameters" into "no loss of capability"; compare with a validation set at the same budget and by the types of task failure.
