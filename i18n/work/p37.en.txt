18345	Essential mathematics and implementation basics
15556	Vectors, matrices, conditional probability, logarithms, derivatives and the chain rule are entry points for understanding small language models. Deep-learning textbooks supply the basics, while CS336 and courses on implementation from scratch connect concepts to models. You need not finish all mathematics before experimenting, but should be able to explain the quantities in every formula.
15566	Vectors represent features, matrices transform them, dot products calculate compatibility, softmax normalizes scores, and negative log likelihood penalizes low probability for the true target. These computational roles do not mean every dimension corresponds to a concept a person can name.
10428	One gradient update
14231	Original example:
9999	. With x=2, t=5, w=1 and b=0, y=2 and L=9; the gradient is
10079	. Updating with learning rate 0.1 gives w=2.2 and b=0.6, making y exactly 5. This is a coincidence of these particular numbers, not a claim that one gradient-descent step always reaches the optimum.
24817	Autodiff propagates gradients through the computation graph; it does not judge whether the loss objective is right. Calculating gradients differs from an optimizer updating parameters; inference usually does not need the gradient graph used in training.
11856	Connect the full chain with a character model
14256	An original experiment can build a character vocabulary from your own short text, construct input and right-shifted targets, train a small autoregressive model and then sample. Character-level modeling suits teaching and is not a complete replacement for modern subword tokenizers.
8953	Token tensors are often B×T, becoming B×T×D after embedding; attention computes across sequence positions, and the output gives each position's vocabulary scores. The causal mask and right-shifted targets prevent looking at the answers. nanoGPT offers a concise implementation entry point; this book does not claim to have trained it or reproduced its results.
20038	Data splitting and generalization
25536	The training set updates parameters, the validation set selects configurations, and the test set offers relatively independent evaluation. Repeatedly inspecting the test set to change the model turns it into development data. Random splits of adjacent or near-duplicate content may leak information; consider splits by document, time or source.
14233	Original example: training on an old README and testing on its new version may involve substantial overlap and cannot prove generalization to a new project. Getting a pipeline to run also does not establish understanding of target alignment and overfitting.
11655	Five completion criteria
19372	Identify tokenizer output; trace embedding and attention dimensions; work out softmax by hand; explain the loss; state why inference does not update weights. Then run controlled experiments: does removing the mask leak information, what happens when targets are shuffled, does a small dataset overfit, and does temperature change a distribution or verify facts?
28414	The accompanying experiments need no API and help isolate mechanisms; they do not replace actual model evaluation. Basic knowledge ultimately serves engineering diagnosis: caching is not memory, compaction is not training, tool results are only new input, and a long window does not guarantee constraints hold.
24910	Self-check: training loss falls but test performance worsens?</strong> Overfitting or a distribution difference is possible; this cannot directly be called greater intelligence. <strong>Can a small experiment prove a commercial agent's quality?</strong> No; it can explain only a local mechanism.
