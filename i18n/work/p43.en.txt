6541	4. Significance, practical value and multiple trials
24500	Statistical significance does not imply a large enough benefit. A success-rate gain of 0.2 percentage points that doubles cost may not be worthwhile; a reduction in a high-risk error may merit attention even with few samples. Report effect size, intervals, cost and error consequences together.
14823	Trying ten prompts and reporting only the highest score creates selection bias. Use a development set for tuning and a test set not repeatedly inspected for final evaluation; control benchmark leakage as models or skills evolve. Adding failed test cases to a prompt can be a sensible improvement, but those same scores can no longer prove unseen generalization.
11179	Do not mechanically let one p-value decide every engineering change. A clear deterministic bug fix can be established by counterexamples and regression checks; complex capability optimization needs broader statistics. Evaluation effort should match decision uncertainty.
6646	5. Ablation and counterfactuals: why a change works
15471	Changing the model, tools, skill descriptions and tests together prevents attribution even if success improves. Define the most important question first to avoid a full-factorial explosion.
17245	For skill routing, compare description changes, specialist-body changes and default loading policies separately. For memory, compare no memory, retrieval only and retrieval with verification. 25957	Negative controls matter too: an unrelated rule should not yield the same benefit, and deliberately removing key evidence should harm the corresponding tasks. If evaluation ignores these changes, the tasks may be too easy or grading too superficial.
6704	6. Biases of LLM-as-a-Judge
21768	Model graders may be influenced by position, length, language style, their own preferences and prompt injection. Research such as MT-Bench discusses these limits; model grading can scale evaluation but is not objective truth.

25705	Graders need regression sets too: correct but brief, wrong but fluent, malicious grading instructions and insufficient information. Agreement with human judgments demonstrates calibration only within that sample scope, not reliability on every future task.
6788	7. Environment noise and cost accounting
12351	Dependency-installation failures, network variation and disk/CPU contention may change task results. 22934	User authorization enters the harness; the model reads context and proposes actions; the tool executor accesses files or services under an identity; results enter the model and logs. 23140	Direct injection comes from requests; indirect injection hides in content being read. 21576	Retrieval limits visible material; context labels untrusted content; execution restricts actions; output checks sensitive-data leakage; memory controls writes and lifecycle. No layer independently guarantees a complete solution, but layering reduces the consequences of one mistaken judgment.

15079	Read-only research usually needs only a sample directory or query API; code edits need bounded repositories and branches; deployment needs additional explicit approval. Do not provide arbitrary host Shell access, the entire user directory and every credential by default for convenience.
