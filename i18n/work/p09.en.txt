The better practice is to maintain one authoritative set of constraints and cite it accurately in the state handoffs that need it.

28103	Follow-up: is newer evidence always more trustworthy?
10648	Not necessarily. A new source may be a reprint or simply wrong, and an old specification may still hold for the current version. Judge the authority, the directness, the scope and the date it took effect. For a source-code task, the configuration actually in effect and the call path may explain the behavior better than the newest documentation.
28030	Follow-up: can a summary the model wrote itself become an authoritative source?
18427	A summary is derived material, and the original source should be kept. It can guide retrieval efficiently, but it cannot win unconditionally when it conflicts with the original evidence. After several rounds of summarizing in particular, source labels and uncertainty are easily lost, so go back to the original record and check it periodically.
27761	Follow-up: why not settle every conflict with one strong system prompt?
24221	A system prompt can teach the model principles, but it cannot replace external permission checks, reading the latest facts and consistency control. Natural-language constraints and deterministic boundaries complement each other. Writing all the business logic into one long prompt is usually harder to test and to update.
