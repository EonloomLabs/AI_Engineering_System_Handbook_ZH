16900	They are equivalent in real-number mathematics, while the order of floating-point additions, the accumulation precision and kernel fusion introduce tiny errors. 8391	Q096｜What exactly does PagedAttention "page"? And why does it raise concurrency?
27433	What to know first for this question</span> Paging puts a logically contiguous cache into physical blocks; a page table records the mapping, and a shared prefix has to take copy-on-write into account. It is not a summary that deletes historical tokens.
23829	Lesson 40 · What "putting it on the device" means</a><a class="pill" href="../foundations/19.html">Lesson 58 · KV cache explained from scratch</a><a class="pill" href="../foundations/21.html">Lesson 62 · Computing fast and fitting in memory
13801	Paging divides each sequence's logically contiguous KV into fixed-size blocks mapped onto a pool of physical KV blocks. Blocks are allocated on demand as the sequence grows, so no large contiguous stretch of VRAM has to be reserved; several requests and a shared prefix can use memory more flexibly. It mainly changes how KV is stored, managed and addressed; it does not change the order of tokens the model sees.

25830	Request B can use physical blocks 3 and 15, with no need to be contiguous with A at all. When a request ends, its references are released and the blocks return to the pool. The last block may have internal fragmentation, but that is usually easier to control than reserving a large stretch per request for the maximum length. The kernel uses the block table to access K/V along the logical sequence, and the positions, lengths and mask all have to stay correct.

Writing a new token into a shared, partially filled last block may require copy-on-write; otherwise A's append contaminates B. 27781	Follow-up: why is a smaller block not necessarily better?
17618	Small blocks reduce tail fragmentation but raise the cost of the block table, of addressing and of management; large blocks reduce metadata but waste more space at the tail. The best size depends on the length distribution, the kernel and the device. Paging is not free operating-system magic; it is a concrete trade-off in data layout.
27841	Follow-up: what can a service do when memory runs short?
15137	It can pause or preempt some requests, move state to other storage, recompute the prefix, or refuse new requests. Each policy affects tail latency and throughput. Simply raising the maximum concurrency can trigger repeated swapping out and recomputation, making everything slower overall. Watch KV occupancy, the number of preemptions, queuing time and the rate of successful completion.
27702	Follow-up: is PagedAttention the same as prefix caching?
13802	Paging provides infrastructure suited to sharing and management, while prefix caching decides when an identical prefix is recognized, retained and reused. The two are related but distinct: one can page without caching across requests, and prefix reuse can be implemented with other memory management as well. Do not credit one mechanism's gains to the other's name.
