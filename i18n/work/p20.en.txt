6861	9. Which pieces of "auxiliary information" also have to come along
24018	The first is the <strong>padding mask</strong>: it tells later computation which positions are real.
27383	The 0/1 here are not token IDs but markers for "can this count as valid content". Even if PAD's embedding happens to be all zeros, that does not mean later computation will naturally ignore it, so these positions still have to be handled properly.
24082	The second is the <strong>attention mask
22350	Attention</strong> is, to begin with, "picking out the positions the current position may refer to, then combining their numbers in differing shares". The mask decides "who may be referred to", not "how much". The latter is worked out with a weighted average in F09–12.
22807	When the next token is generated, both training and computation usually have to obey the rule against peeking at the future. For the three-position example, the positions that may be read are:
18234	Current query position
24785	Can it refer to position 0?
12164	Position 1?
12167	Position 2?
27288	This is the <strong>causal mask</strong>. For the second sentence, position 2 has to be excluded as well, because it is a padding item. Different interfaces inside a model do not necessarily use the same mask shape or the same meaning for true and false; the table on this page only explains the visibility relation and does not pose as the input argument of any particular API.
24067	The third is the <strong>position IDs</strong>. The three real positions, for instance, are recorded as 0, 1 and 2. A token ID answers "which fragment"; a position ID answers "where it occurs". They are not the same column. With left padding, or with a cache, the logical position and the table's column number can differ; F13 gives an example of each.
20532	Last, there may be a <strong>KV cache</strong>. A cache simply keeps results already computed that can be reused later. The first time something is processed from scratch there is usually no history cache; when generation continues, some of the numbers each layer computed earlier can be brought back, which avoids recomputing from the start. This is not long-term memory, and it is not new knowledge entering the model parameters. What K and V mean, why they can be reused, and which changes invalidate them, are covered by explaining attention in F11 first and then deriving it in full in F19; this page does not ask you to memorize the two letters first.
6105	10. A summary of the whole process
18754	Two independent inputs are computed together, and the shorter ID list is padded to the length laid out for this batch. That gives one table of two rows with 128 IDs each. From each ID the model fetches a row of 4096 numbers out of its own embedding parameter table, so the result is two tables of 128 rows and 4096 columns. At the same time the program prepares the valid positions, which positions may refer to which, and the position IDs of the real fragments; if this is continued generation, it also brings in reusable results from earlier computation. The attention and the other numeric transformations of each layer then begin. <strong>The embedding lookup is itself already a computation step in the model's numeric representation</strong>, not something that meets the neural network only once the lookup is done.
