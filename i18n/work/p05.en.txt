22853	Explaining TP and PP with one forward pass
10278	A large linear layer
15132	can be split across several devices by the output columns of W, with each card computing part of the output; if a later layer needs the complete Y, that takes communication or a matching sharded layout. Splitting along the input dimension instead produces several partial sums, which have to be reduced.
16281	heads and the
11439	intermediate dimension: how these are split decides when all-reduce/all-gather happens, and not every layer can simply concatenate the results.
8031	PP puts the first few layers on device A and the later ones on B. A micro-batch goes through A first, and its activations are then sent to B; several micro-batches can form a pipeline, but there are bubbles at the start and the end. Unbalanced computation across the stages makes the fast device wait for the slow one; and inference on a single autoregressive sequence still has to pass through every stage again at each token.
7384	DP suits parallel processing when there are several requests or samples; if a single model does not fit on one card, plain DP does not solve that. In training each replica has to synchronize gradients; in inference independent replicas can usually serve requests independently. ZeRO/FSDP shard the optimizer, the gradients and even the parameters, reducing duplication across training replicas, but they have to communicate to fetch the relevant part when the computation needs it.
8050	With prefill/decode separation, the prefill device finishes computing and then sends the KV and other necessary state to the decode device. The resources can be optimized separately for throughput and for bandwidth, but the KV transfer can be large: the example in lesson 60 gives 4GiB for a single 32k sequence. If the network is slow, the context short or the request volume small, the gain from separation may be offset by the transfer and the queuing.
15487	With the same two devices, what do DP, TP and PP each split
26170	Input and conditions.</strong> A schematic network has 4 layers, each layer's weights taking 100MB; activations, gradients and the optimizer are not counted. Two inputs A and B, and two devices.
11355	Both devices hold all 4 layers
21130	400MB of weights each; one handles A and the other B, and in training the gradients also have to be synchronized.
22038	Each layer's matrix computation is divided between the two devices
22785	With an ideal even split that is 200MB of weights each, but intermediate results have to be exchanged or reduced inside the layer.
22398	Pipeline parallelism PP
25637	Device 0 holds layers 1—2, device 1 holds layers 3—4
21129	200MB of weights each, with activations passed between the stages; a poor micro-batch arrangement leaves idle bubbles.

13807	Shard the copies of the optimizer, the gradients or the parameters

19061	Join the steps up.</strong> Behind the names of the parallelisms lie splitting the data, splitting the matrix, splitting the layers or splitting the state; only by drawing what each device actually holds can the gain be estimated.
26744	Limits and counterexamples.</strong> The even split of the weights is only a bookkeeping example; a real model has modules that cannot be split evenly, a communication topology, replication and extra caches.
27997	Follow-up: why can more GPUs be slower instead?
14131	Each card computes less, but synchronization, transfer and scheduling all increase; with a small model or a small batch, communication may dominate. Interconnect bandwidth differs greatly between nodes and within one machine. Compare the speed-up on a real task and the cost per successful task, rather than using the number of GPUs as a measure of capability.
27721	Follow-up: why can a change in the TP degree affect reproducibility?
13785	Sharding and reduction change the order of floating-point additions, and a tiny change in a logit can change which token wins at the margin. Different kernels may also be used. A correctness test should keep the three levels of numeric tolerance, generation distribution and task result apart, rather than demanding that every parallel topology agree character for character.
27929	Follow-up: do application engineers need to implement these kernels?
10662	Not necessarily, but they do need to know which bottleneck a setting affects. For example, when
18103	latency is dominated by a remote tool, studying TP will not fix it; when a local deployment runs out of KV, look at the context, the concurrency and state management. The point of going deeper into the principles is to be able to locate the boundary correctly, not to rewrite every layer yourself.

12942	First ask which boundary the error happens at
9464	"The model's output is wrong" is not enough on its own to tell whether the learning rate, attention or sampling is at fault. Confirm the identity of the input and the weights first, then check the shared forward pass, and then decide whether it is a training-only step or a generation-only step. Changing ten places at once makes even a correct fix hard to attribute.

11478	Why "the gradient is not 0" is nowhere near enough
28598	A wrong denominator, a missing residual path or a wrong mask can all produce non-zero gradients and make some losses go down. A test should check specific values, relations and an independent comparison, not merely whether there is a .grad.
20925	The gradient comparison in this package is done parameter by parameter at the same initial values and on the same batch; the hand-written backward pass uses the mathematical rules, autograd uses the framework's record, and the finite difference estimates from the difference between real forward passes. The three complement each other, but they can also agree if all of them use the same wrong training objective, so the input and the meaning of the objective still need human interpretation.
11545	Why negative controls are needed
21838	An implementation that passes one test may simply have assertions that are too weak. After deliberately turning the causal mask off, using the wrong cache position, applying softmax twice or mixing in stale KV, the test should observe a difference. That shows the test can at least identify these specific faults.
20847	The bad implementations in this book are used only for temporary local comparison; they are not saved as the default model and are not mixed into the official weights. The report states clearly which path is the deliberately wrong one, so that readers do not take a wrong formula for a recommended method.
20014	How to choose a numeric tolerance
9180	float64 on the CPU helps with comparison, but not every value has to agree to the last bit. A change in the order of softmax, normalization and matrix accumulation can cause small rounding differences; float16/bfloat16 or a fused kernel can differ more. Look at the absolute error, the relative error, the magnitude of the values and the task result together, and keep non-smooth places such as the ReLU kink in mind.
23424	Replacing every NaN with 0 and then declaring the test passed is forbidden. Confirm the cause first: a fully masked row, overflow, division by zero, contaminated data and so on. Asserting finiteness is where locating the problem starts, not a complete fix.

27877	Follow-up: which changes can claim to preserve the same computational objective?
15953	When the conditions are met, a causal KV cache, correct blocked exact attention and storage paging can preserve the same objective, allowing the floating-point differences the implementation causes; quantization introduces an approximation; Top-k and temperature change the decoding distribution; replacing GQA or the FFN changes the architecture; LoRA training changes the parameters. Identify the type first, and only then is it clear whether consistency, task quality or system performance is what should be evaluated.
16771	Full acceptance questions
20444	When VRAM runs short, are using no_grad and using activation checkpointing the same thing?
10850	No. Training has to keep or rebuild the chain for differentiation; no_grad turns off the recording that is needed and so breaks training. Activation checkpointing restores the necessary intermediate values by recomputing them before the backward pass, and the goal is still a correct gradient.
22417	A test finds a very small difference between the cache and the full computation — can it simply be ignored?
12863	Start with the magnitude of the error, the precision, the kernel and the gap between the candidate scores. If two candidates are almost level, a small error can change the greedy result; if a position or a mask is misaligned, the source has to be explained however small the difference. A tolerance needs its conditions; it cannot all be waved away as "floating-point error".

29060	Acceptance 5: the model is 30% faster on the GPU and the small CPU model's forward pass is unchanged — does that prove the deployment has no regression?
10993	No. The numeric behavior on the target hardware, the actual batch and length distributions, the cache and the mode, quality and tail latency all have to be checked. Consistency in the CPU teaching setup verifies only the mechanism concerned; it is not a guarantee of production quality or speed.
