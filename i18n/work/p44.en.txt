21462	Case one: a Skill appears loaded, but the code lacks domain expertise
25275	Observation: the log names the skill, but output ignores transaction timeouts. Explanations include metadata-only loading, a trimmed body, omitted content in a sub-agent, ineffective specialist content, visible but unused content, or tests not requiring this behavior.
20559	First inspect loaded scope and skill text, then relevant risks in execution traces, and finally tasks triggering the error. Do not begin with another routing agent when selection may be correct. A repair may need only concrete transaction-boundary knowledge and its test.
15678	Include transaction-handling and unrelated tasks in regressions so everything does not become distributed-systems analysis. Acceptance means fewer errors, not more mentions of "transactions".
21465	Case two: work changes direction after compaction
25273	Observation: "change only description" becomes executor refactoring after compaction. Explanations include lost prohibitions, promoted assumptions, overriding old memory, missing new user input or truncated subtask instructions.
14879	Compare task state before and after compaction for retained prohibitions, and compare downstream delegation with the current authoritative goal. If harness compaction is opaque, fork an identical prefix and continue to test specific constraints. First persist a few key constraints and evidence locations rather than build a second full-history summarization service by default.
15679	Include repeated compaction and new goal changes so old constraints do not prevent later authorized changes. Fidelity preserves time and authority correctly rather than freezing everything forever.
21464	Case three: relevant retrieval results are always outdated
25274	Observation: terminology is right but API fields are obsolete. Causes may include stale indexes, semantic preference for old long documents, versionless cache keys, missing time filters in reranking or old evidence mixed during generation.
22334	Trace current-document ingestion, candidate inclusion, post-filter retention, ranking / selection loss and final citations. Fixes may concern index generations and version filtering rather than a new embedding model.
15677	Add same-named versions, rollbacks and historical queries to regression tests. Always choosing the latest record fails questions about old migration reasons. Lesson 19's valid time and time of knowledge distinguish these needs.
21468	Case four: tests pass, but users still find problems
15200	Tests may never have run, key cases may be skipped or weakened by the model, versions may be stale, new requirements uncovered, or environments unlike production. Read actual commands, counts, exit codes and artifact versions rather than the model summary alone.

21466	Case five: slower tasks and more tokens

15684	Cover complex tasks so simple speedups do not hide oversimplification. Use cost per successful task as the main criterion rather than mean tokens.
21467	Case six: retries duplicate side effects
25277	Observation: two tickets appear after a network timeout. Retries may generate new operation IDs, or the server lacks idempotency while the client treats unknown as failure. Repair requires business idempotency / reconciliation rather than a "do not repeat" prompt.
22429	Disconnect after remote success but before client receipt, not merely before a call. This book's local-file crash experiment verifies a similar window, but remote operations need corresponding service capabilities; file hashes cannot simply be transferred.
21463	Case seven: more memory makes errors more persistent
25276	Observation: the system insists on old experience despite contrary current code. Inspect memory provenance, version, scope, write permissions and retrieval priority. A guess automatically saved as active may become a "verified rule" over repeated summaries.
12471	Correct false authority and applicability first, then assess write policies. Reduce memory if necessary rather than add complex graphs. Regressions should include new evidence overturning old claims, revocations, conflicts and no matches; the system must be able to leave memory unused.

6038	1. Questions on numerics and model internals
29020	Question: a Decoder works with full-sequence inference but fails token by token, while all tensor shapes are correct. Give a diagnostic order and explain it.
14771	Reference answer: fix parameters and disable stochastic operators; compare the first step, then locate the first divergence. Check cache concatenation axes, separate per-layer caches, position offsets, non-square causal masks, GQA mapping and dtype. Test consistency across whole-sequence, token-by-token and varied chunks; change future tokens to test causality. Reset positions corrupt RoPE relative positions; a top-left triangular mask prevents new queries seeing the full prefix.
26854	Meeting the standard means distinguishing causes with minimal counterexamples, not merely "check KV Cache". Explain why numeric tolerances cannot hide logical errors.
6292	2. Questions on training and post-training
29019	Question: SFT improves answer style but not code accuracy; DPO raises preference scores while unauthorized tool calls increase. How should this be assessed?
14774	Reference answer: objectives may reward style or superficial completeness. Check demonstration / preference coverage, loss masks, verifiers and task distributions before training-induced regressions. Add independent functional, permission and regression evaluation. Parameter training cannot replace executor authorization; deterministic boundaries should block unauthorized actions first. High overall preference scores alone do not justify release.
6417	3. Questions on context and compaction
29022	Question: a summary retains every keyword, but continued execution fails. How would you design stronger fidelity evaluation?
14769	Reference answer: include negations, hypotheses versus facts, revoked decisions, version freshness and unresolved side effects. Predefine recovery questions and continuation tasks; compare uncompacted history, compaction and manually minimal state; test repeated compaction and varied positions. Structural checks establish fields and source existence only; semantic support and completion need separate testing.
6544	4. Retrieval questions
29018	Question: ANN has 99% Recall@10 against exact vector search, but key source code remains missing. Why?
14775	Reference answer: this metric only says the approximate index retains vector neighbors; embeddings may not rank key source highly. Chunking, version filters, permissions or query wording may also fail. Start with exact symbols / BM25, inspect candidate-evidence recall, then reranking and context selection. High ANN metrics do not establish good retrieval.
6651	5. Memory questions
29025	Question: on day 30, a system learns configuration changed on day 20. How should it answer what it knew on day 25 versus what it now judges true on day 25?
14778	Reference answer: distinguish valid time from recorded/transaction time. Historical knowledge queries use only evidence recorded before day 25; today's retrospective can use later-arriving material valid on day 25. The teaching implementation has both time filters, but not full withdrawal history or concurrent merging; do not overstate it.
6719	6. Execution reliability questions
29026	Question: a remote action times out and the model requests a retry. When is it safe?
14770	Reference answer: read-only or known repeatable operations without side effects are usually easier to retry; writes need idempotency keys, state queries or reliable reconciliation.
