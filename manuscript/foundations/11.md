它想解决什么问题
--------

“苹果很好吃”和“苹果发布了电脑”中的同一词，需要根据其他位置形成不同表示。单独查Embedding只能提供该Token初始那一排数。\*\*注意力（Attention）\*\*提供一种让当前位置按不同权重吸收其他位置信息的办法。

不要先把它想成眼睛或意识。它是“计算分数→转为权重→加权求和”的数值过程，训练会调整产生分数和内容的参数。

Query、Key、Value各做哪一件事
---------------------

对当前输入表示X，通常分别用三个学到的矩阵变换：

```
Q = XWq   查询表示：当前用什么特征匹配
K = XWk   被比较表示：每个可读位置提供什么匹配特征
V = XWv   内容表示：匹配后要混合的那排数
```

Q、K、V来自同一个X，但Wq、Wk、Wv不同，因此不是简单复制三份。数据库的键值类比只能帮助认识“匹配”和“取内容”的分工，Attention并不是按某个字符串精确查数据库。

对两个位置手算一行
---------

为了把算术保持很小，直接给出某一头的Q、K、V；这些数字是教学构造：

```
当前q = [1,0]
k0 = [1,0]    v0 = [10,0]
k1 = [0,1]    v1 = [0,20]
```

第一步，点积得到对两个位置的分数：q·k0=1，q·k1=0。

第二步，常见缩放点积注意力会除以每头宽度的平方根。宽度是2，√2约1.414，得到`[0.7071,0]`。这里“平方根”是一个数乘自己得到2的那个正数。

第三步，经softmax得权重约`[0.6698,0.3302]`。

第四步，按这个权重混合Value：

```
输出第0格 = 0.6698×10 + 0.3302×0 ≈ 6.6976
输出第1格 = 0.6698×0  + 0.3302×20 ≈ 6.6048
结果约为[6.6976,6.6048]
```

结果不是“选了位置0”，而是一排融合后的数。权重最大的项贡献较大，但别的项也可以贡献。

把一行变成所有行，公式就出现了
---------------

若有T个查询、每个宽度d\_h，Q是`[T,d_h]`，K也是`[T,d_h]`。`QKᵀ`让每个查询与每个Key比较，结果`[T,T]`。每行softmax后再乘V=`[T,d_h]`，得到`[T,d_h]`。

```
Attention(Q,K,V) = softmax(QKᵀ / √d_h) V
```

这条公式没有新动作，只是把已经手算过的点积、缩放、归一化、加权求和批量表达出来。若还有mask，会在softmax前限制哪些格子可用，下一课解释。

self并不是“只看自己”
-------------

\*\*Self-Attention（自注意力）\*\*表示Q、K、V来自同一序列的表示，不是只允许读取当前位置。\*\*Cross-Attention（交叉注意力）\*\*可以让Q来自一份序列、K/V来自另一份，例如读取图像或编码器结果。

对生成式Decoder，某个位置通常只能读自己及前面的位置；这来自因果限制，而不是“self”这个单词。不同架构可以使用不同读取规则。

为什么缩放，以及为什么不能把权重当解释结论
---------------------

当参与点积的分量很多，未缩放分数的波动可能变大，softmax容易过于集中。F14会解释均值、方差；高级Q007再给出在特定独立同分布假设下的推导。这个解释不是说每个真实网络始终严格满足假设。

最后答案还要经过多个头、投影、残差、前馈和很多层，因此“某位置注意力最大”不能独自证明最终回答为什么出现。它只是中间计算的一部分。

停一下：能自己讲出来了吗
------------

**自检 1 · 答案直接展开**

**Q与K点积得到的是什么，V负责什么？**

点积得到对可读位置的分数；V提供按归一化权重聚合的内容向量。

**自检 2 · 答案直接展开**

**两个Key分数完全相同且均可读，权重是什么？**

各0.5。输出是两份Value的逐维平均，不是随机任选一个Value。
