03｜注意力的深入追问：位置、掩码、多头与反向传播
=========================

### 本章先修知识

掩码规定哪些位置可见，位置编码帮助区分顺序，多头把表示分组处理；反向传播则追踪最终误差怎样沿原计算回传。它们解决不同问题，不能靠一张架构图一起猜。

Q009｜因果mask、padding mask、分块解码mask到底如何构造？
----------------------------------------

这题先认识什么因果掩码禁止未来位置，填充掩码排除占位项；有旧缓存时，查询行数和可读列数不同，不能照抄方阵三角表。

[F04 · 组批和补齐](../foundations/04.html)[F12 · Mask不是黑箱](../foundations/12.html)[F16 · KV Cache从零解释](../foundations/16.html)

### 核心回答

因果mask禁止读取未来位置；[padding mask](../glossary.html#g079 "排除补齐项作为有效内容的标记。 例：PAD向量全0仍不保证其softmax权重自动为0。")排除没有实际内容的补齐位置；分块解码还要把新块的局部索引映射到已有前缀后的全局位置。判断某个键可否被读取，应看逻辑位置和有效性，而不是只画一个左上角三角形。[[TR]](../sources.html#src-TR "来源说明")[[CACHE]](../sources.html#src-CACHE "来源说明")

### 先看完整输入，再看缓存场景

一个4-[Token](../glossary.html#g027 "模型分词器使用的片段单位。 例：可能是词、词的一部分、标点或部分字节。")序列，行是查询位置，列是键位置，1表示允许读取：

```
       k0 k1 k2 k3
q0     1  0  0  0
q1     1  1  0  0
q2     1  1  1  0
q3     1  1  1  1
```

这里下三角是因为查询与键从相同的全局位置0开始。现在已有3个Token的缓存，新来2个Token。Q长度是2，K长度是5；新查询的全局位置是3与4，正确mask为：

```
       old0 old1 old2 new3 new4
new3     1    1    1    1    0
new4     1    1    1    1    1
```

通式是`key_position ≤ past_length + local_query_index`。如果直接创建`tril(ones(2,5))`，第一行只会看old0，第二行只会看old0与old1，历史的大部分被错误遮住。它仍是一个合法的2×5矩阵，所以不会靠shape检查暴露问题。

再加入[padding](../glossary.html#g035 "给短序列增加占位项，使指定组织方式可用。 例：[4,2]右补齐为[4,2,0]。")。两条序列长度分别为3和5，组批时短序列补齐。被补齐的键位置不应获得注意力权重；padding查询位置可能仍被算子计算，但不应作为有效答案或训练目标使用。左padding时，数组下标和真实Token位置更容易分离，位置编号应服从模型与实现约定，不能只用数组下标。

### 追问：训练时一次输入整段答案，不就是偷看答案吗？

不是，只要每个位置的可见范围正确。位置i的隐藏状态只能读到`x≤i`，拿它预测`x(i+1)`。标签存在于[batch](../glossary.html#g034 "一起组织计算的一组输入。 例：普通样本batch不让不同用户相互读取内容。")里不等于前向可以读取它。多个位置的预测可同时计算，因为正确前缀已经由训练数据提供。若mask删掉，训练loss可能异常漂亮，却学习了不符合部署条件的任务。

### 追问：两份文档拼接训练，只放一个EOS就完全隔离了吗？

不一定。[EOS](../glossary.html#g096 "模型约定的一种结束序列Token。 例：与最大输出长度、用户取消是不同结束原因。")是序列内容标记，不自动禁止注意力跨文档边界。若目标是严格隔离样本，需要分段[attention mask](../glossary.html#g077 "规定哪些位置间的读取被允许的约束。 例：接口可能用布尔值或加性负无穷，真假约定要核对。")，并同步处理位置和loss范围。若允许跨文档上下文，则可以有不同策略；关键是明确训练目标，不能把“出现分隔符”当成确定性隔离。

### 追问：如何写一个能抓住mask错误的测试？

固定权重、关闭dropout，先保存前缀输出；然后只改变未来Token，前缀对应[logits](../glossary.html#g091 "输出投影给各词表候选的未归一化分数。 例：可以是负数，还不是概率或Token编号。")不应变化。再比较整段、逐Token和多种分块推理的输出，三者应在合理浮点容差内一致。故意移除mask或重置位置，测试应失败；否则测试很可能没有覆盖目标错误。

Q010｜RoPE如何让注意力知道位置？为什么缓存位置不能每轮从零开始？
------------------------------------

这题先认识什么位置不是Token身份。RoPE将一对坐标旋转与位置相关的角度，使点积中出现相对位置关系，不是把位置数字直接加到词表编号。

[F07 · 模型最常做的算术](../foundations/07.html)[F13 · 位置编号与RoPE](../foundations/13.html)

### 核心回答

[RoPE](../glossary.html#g082 "通过按位置旋转成对坐标来引入位置信息的方法。 例：二维90度旋转把[2,3]变为[-3,2]。")把Q/K每一对分量按位置相关角度旋转，使两位置旋转后点积包含相对位置差。它不是简单把位置整数加到[Token ID](../glossary.html#g028 "某Token在对应词表中的整数地址。 例：[1,2,3]先是编号列表，不是三个语义强度。")上。缓存推理必须保持新旧Token的逻辑位置连续或符合指定位置策略，否则相对关系被改变。[[ROPE]](../sources.html#src-ROPE "来源说明")

### 从二维旋转推导相对位置

对二维向量`x=[a,b]`，位置p与频率θ对应：

```
R(pθ) x = [a cos(pθ) − b sin(pθ), a sin(pθ) + b cos(pθ)]
```

Q在位置p、K在位置t时，点积为`(R(pθ)q)ᵀ(R(tθ)k)`。利用`R(pθ)ᵀ=R(-pθ)`与旋转的组合性质，得到`qᵀR((t-p)θ)k`。因此位置信息通过差`t-p`进入相关性。高维向量按分量对应用不同频率，提供多尺度位置变化。

这并不意味着注意力只依赖位置差：q与k本身仍由文本内容和前层表示决定。RoPE提供相对位置结构，内容匹配仍由学习得到的投影负责。也不能说它让模型对任意长度天然泛化；超过训练分布的相位组合仍可能带来退化。

假设前缀长度P=100，新Token本应在位置100。如果错误地把它的Q/K按位置0旋转，而旧K仍按0到99存储，那么模型读到的“距离”已不是真实距离。张量长度、[dtype](../glossary.html#g041 "规定每个元素如何存储与运算。 例：整数编号与浮点表示通常不是同一dtype。")、缓存拼接轴都可能正确，但logits已经偏离整段前向。

### 追问：可以把全部位置同时平移吗？

在理想纯RoPE点积中，同时给Q/K位置加同一偏移，会保留相对差。但完整模型可能还有其他位置相关机制、滑窗规则、特殊位置或缩放策略；已旋转的缓存也不能只改一个position counter就完成一致变换。数学上的整体平移性质不能直接当任意缓存截断实现的安全证明。

### 追问：长上下文扩展是怎么做的？

常见思路包括位置插值、频率缩放、特定频段调整和长序列继续训练。它们试图让超出原训练长度的位置模式更接近可学习范围，同时保留局部区分。局部精度与长距离覆盖可能发生取舍，因此需测检索、跨段组合、代码定位等真实任务，不只测“接口是否接受更多Token”。

### 追问：为什么通常旋转Q/K而不是V？

这种设计把相对位置信号主要放到读取权重的计算里，[Value](../glossary.html#g074 "每个可读位置将被加权汇集的内容表示。 例：这里V不是词表大小。")仍提供被混合的内容。不同架构可有其他方案；不能把这个实现选择扩展成数学上所有模型都必须遵守的定理。阅读源码时应检查缓存里保存的是旋转前还是旋转后的K，以及重用时是否重复旋转。

Q011｜MHA、MQA、GQA到底少了什么？是不是把多头删掉了？
---------------------------------

这题先认识什么多头把表示分组；MQA/GQA让多个查询头共享较少的K/V头。查多少组和存多少组分开数。

[F08 · reshape、转轴、广播](../foundations/08.html)[F11 · Attention慢速版](../foundations/11.html)[F16 · KV Cache从零解释](../foundations/16.html)

### 核心回答

[MHA](../glossary.html#g127 "不同查询头与K/V头共享方式的注意力结构。 例：共享更多K/V可减少缓存，但不保证质量完全相同。")通常每个Q头有对应K/V头；[MQA](../glossary.html#g127 "不同查询头与K/V头共享方式的注意力结构。 例：共享更多K/V可减少缓存，但不保证质量完全相同。")让多个Q头共享一组K/V；[GQA](../glossary.html#g127 "不同查询头与K/V头共享方式的注意力结构。 例：共享更多K/V可减少缓存，但不保证质量完全相同。")在两者之间，让一组Q头共享一个K/V头。主要减少K/V投影输出和缓存量，不等于所有查询头变成同一注意力分布。[[GQA]](../sources.html#src-GQA "来源说明")[[CACHE]](../sources.html#src-CACHE "来源说明")

### 逐形状比较

设隐藏维度4096，查询头H=32，每头Dh=128。MHA有32个KV头；GQA假设只有8个KV头；MQA只有1个。忽略bias时：

| 对象 | MHA | GQA（8 KV头） | MQA |
| --- | --- | --- | --- |
| Wq输出宽度 | 4096 | 4096 | 4096 |
| Wk/Wv各自输出宽度 | 4096 | 1024 | 128 |
| 单层K缓存 | `[B,32,T,128]` | `[B,8,T,128]` | `[B,1,T,128]` |
| 每个Q头的注意力权重 | 各自计算 | 各自计算 | 各自计算 |

GQA中可以把Q头0—3分给KV头0、Q头4—7分给KV头1，以此类推。共享K不意味着Q相同；不同Q与同一K点积，仍可产生不同权重。共享V也不意味着输出相同，因为加权比例不同。

缓存空间从32组降为8组，理论上这部分减少为四分之一。但总显存还有权重、激活、工作空间和调度元数据，不会因此整机显存必然减少四倍。QKᵀ和AV仍需服务32个Q头；实际计算效率还依赖kernel如何避免重复加载共享KV。

### 追问：能否把一个训练好的MHA模型直接改配置成GQA？

不能只改头数。参数形状、权重组合和学习到的功能会变化。GQA论文研究了从多头检查点转换并继续训练的方式；这不是修改一个配置就获得等价模型。模型部署必须匹配权重与架构。

### 追问：为什么有的GQA代码还把KV重复成H个头？

这可能是为了兼容普通[attention](../glossary.html#g071 "计算查询与可读候选的匹配份额，再加权组合内容。 例：先计算分数和权重，再用权重混合V。")接口而做概念展开。若物理复制长缓存，会抵消内存收益；高效实现应通过映射、视图或专用kernel共享数据。阅读代码时要看实际内存分配与[stride](../glossary.html#g058 "沿某轴移动一个索引时底层存储要跨过的元素间距。 例：转置后的视图可能不连续，后续reshape可能需复制。")，而不是只看注释写了“共享”。

### 追问：MQA缓存最小，为什么不全部用MQA？

共享程度提高会改变表示容量与模型质量，硬件收益也受工作负载影响。GQA是在质量、训练成本与推理资源之间的一种折中。不存在不看模型与任务就永远最优的KV头数。

Q012｜Attention如何反向传播？为什么自动求导正常不等于模型实现正确？
----------------------------------------

这题先认识什么反向传播沿前向计算逐步计算梯度；转置用于把输出变化传回输入维度，softmax的不同候选因归一化彼此耦合。

[F07 · 模型最常做的算术](../foundations/07.html)[F09 · 概率、指数与softmax](../foundations/09.html)[F17 · 微积分只学用得上的部分](../foundations/17.html)[F18 · 一次训练从头到尾](../foundations/18.html)

### 核心回答

反向传播把输出误差沿Value内容路径和Q/K权重路径传回。自动求导能忠实计算当前计算图的梯度，却不能知道你的mask、标签或维度是否表达了正确任务。必须把数学梯度检查和语义不变性测试分开。[[TR]](../sources.html#src-TR "来源说明")

### 沿计算图逐步求导

定义`S=QKᵀ/√d`、`A=softmax(S)`、`O=AV`，设上游梯度`G=∂L/∂O`。先对最后一步矩阵乘法：

```
dV = AᵀG
dA = GVᵀ
```

第一个式子表示某历史Value从所有读取它的查询位置累计误差；第二个式子衡量某个读取权重改变时损失如何变化。接着对[softmax](../glossary.html#g062 "将各分数取指数，再除以所有指数之和。 例：[0,ln2,ln3]变成[1/6,1/3,1/2]。")，某行概率a与上游g对应：

```
ds = a ⊙ (g − sum(a ⊙ g))
```

这里减的是整行加权和，不能省略。其结果各分量之和为0，与“给整行分数加常数不改变softmax”的性质一致。最后：

```
dQ = dS K / √d
dK = dSᵀ Q / √d
```

若Q/K/V由同一X投影而来，X梯度是三条支路分别乘投影转置后的和，再加上残差直接回传的梯度。多头的换轴、拼接在反向中要走对应的逆变换。

一个有用的诊断：只让第一位置输出参与损失，在因果mask下，未来K/V不应通过这一损失得到梯度。如果未来位置有非零依赖，可能mask或索引错误。这个测试关注任务语义，不只是数值求导。

### 追问：有限差分怎样检查梯度？

对某输入维度j，把它分别改为`xj+ε`和`xj-ε`，用`[L(x+εej)-L(x-εej)]/(2ε)`近似导数。小矩阵用float64更容易定位错误。ε太大会有截断误差，太小则舍入误差占主导；不能仅通过不断放宽容差让测试通过。

### 追问：有限差分通过，是否证明模型对了？

它证明解析或自动梯度与当前前向函数一致；如果前向错误地允许看未来，两者仍可能一致。还需要标签移动、因果性、整段与缓存一致性等测试。因此“梯度正确”和“目标正确”是不同证据。

### 追问：推理时为什么不需要反向传播？

普通部署生成使用固定参数，只计算条件分布并选择Token，不需要计算损失和更新权重。长推理或多次工具调用增加的是前向计算与输入信息，不自动变成梯度训练。特定在线学习系统可以额外更新参数，但必须显式设计，不能从“模型越来越了解当前任务”推断发生了训练。
