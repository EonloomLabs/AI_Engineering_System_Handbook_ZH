## 模型实际接收的输入

消息接口包含角色、内容块、工具定义及其他配置，不只是一段自由文本。客户端可能加入仓库规则和任务状态，服务端也可能进行额外组织。可见聊天记录不等于完整请求，更不等于所有内部处理。[[S045]](sources.html#S045)[[S047]](sources.html#S047)[[S049]](sources.html#S049)

```
稳定约束：只改授权工作区
项目知识：构建入口、路径语义、测试命令
工具定义：搜索、读文件、补丁、测试
用户目标：修复exclude嵌套路径
工作状态：已复现，尚未修改
证据：当前源码与实际测试结果
```

这是厂商无关教学结构，不可直接当某个API请求。每条信息需要来源；模型假设不可悄悄进入“已确认事实”。

## 指令层级与可信边界

Model Spec是期望行为规范，不是运行时权限系统。本文依据可核验历史版本说明概念，不宣称它代表所有模型的最新行为。低信任内容可以提供事实，但不能自行授权；高优先级指令约束行为，也不使其中的外部事实永远正确。[[S028]](sources.html#S028)

源码注释要求上传环境变量，仍只是外部文本。工具执行器应检查权限，而不是仅在Prompt里写“请安全”。来源标签可帮助组织，但不能代替真正的访问控制。

## 结构化输出的三层保证

先认识这里的对象与符号

[Schema与Structured Outputs](../concepts.html#concept-schema)
:   Schema是一份字段和类型等结构规则；结构化输出机制让模型更容易返回符合规则的数据。字段合法仍不等于目标文件存在、已授权或业务正确。独立例：要求path为字符串；{"path":3}类型不合规则，{"path":"missing.py"}虽结构合规则仍可能找不到文件。

先认识这里的对象与符号

[JSON：结构化文本，不是执行动作](../concepts.html#concept-json)
:   JSON是一种用对象、数组、字符串、数字等表达数据的文本格式。花括号对象把字段名映射到值，方括号数组保留项目顺序。解析JSON只得到数据，不会自动执行其中的工具名称。独立例：{"path":"a.py","limit":3}有两个字段；"3"是字符串而3是数值，Schema可以要求其中一种。

合法JSON保证语法；Schema保证结构、类型和枚举等约束；字段中的事实、引用与业务状态仍需验证。Schema中应允许证据不足、工具失败等真实状态，避免强迫中间结果冒充完成。[[S048]](sources.html#S048)

```
{"status":"needs_evidence","suspected_file":"pipeline/filter.py",
 "evidence_ids":[],"next_action":"read_file"}
```

这是原创业务示例，不是任何产品规定。解析后还要检查截断、拒绝、字段引用是否存在、文件是否越界。0到1的confidence值只说明数值合法，不自动具有校准概率含义。

## 工具调用的完整协议

模型提出工具名与参数，应用验证并执行，结果用关联ID返给模型，模型决定继续或回答。调用被生成不代表已执行，调用返回成功也不代表整个任务完成。[[S047]](sources.html#S047)

```
候选调用 → 参数校验 → 授权与范围校验
       → 执行 → 记录成功或失败 → 回填观察
```

读取失败应区分不存在、无权限、超时和空文件。并行调用要检查依赖：独立搜索可并行，基于尚未读取代码产生的补丁不可无条件并行。

## 可发现与可授权

构造注册成功但未暴露的工具，再构造暴露成功但无权使用的工具，要求诊断报告给出不同修复路径。

**关键边界：**不以扩大权限修复发现问题，也不以提示词改写修复工具未加载。

**顺着源码或工程依据继续追：**解释工具路由的实际边界。 不只检查顺利路径，也核对取消、版本变化与结果未知时的行为。

完整机制与连续例子见 [工具存在、模型看见、能调用、获授权：四层检查](../chapters/11.html#agent-practice-tools)；本节仍保留原有推导与实验，两处说明使用不同层次而不互相替代。

**证据与理解边界：**直接、延迟发现和代码调用是不同暴露面；注册、可见、可调用与获授权不互相等同。

## 流式输出与推理状态

流式响应可能包含文本、参数片段和结束事件。半段JSON不是执行授权，必须按协议组装完整调用后校验。高风险写入尤其不能边收到参数边执行。[[S049]](sources.html#S049)

推理型模型可能使用不可见或受保护状态；应按接口要求传递，不能自行伪造。最终文字长度不等于全部推理消耗，解释也未必是内部过程的逐字记录。[[S037]](sources.html#S037)[[S051]](sources.html#S051)

## 协议边界与业务边界

把两个call\_id的参数交错分片，并在首个工具项完成之后断开流。分别检查参数不串线、已完成工具不丢账以及整次响应不被误判成功。

**关键边界：**网络EOF、单项完成和业务成功必须分别记录；自动恢复前先确认哪些副作用已经发生。

**顺着源码或工程依据继续追：**分开字节、事件、完整输出项和整次响应。 不只检查顺利路径，也核对取消、版本变化与结果未知时的行为。

## Prompt版本与实验

原创实验比较三种输入：仅一句修复要求；增加明确目标和必要源码；再叠加冗长固定流程。测正确率、漏测、总轮次与人工接管。更长版本可能改善复杂任务，也可能损害简单任务，需要分层统计。

至少记录Prompt版本、模型配置、工具Schema和任务样本。只保存最终回答无法解释为何退化。Prompt工具管理的是组织方式，不能代替评测设计。[[S046]](sources.html#S046)[[S144]](sources.html#S144)

**自检：模型说已执行测试能否视为测试证据？**不能，要有工具结果。**严格Schema能否防止编造引用？**不能，还需验证引用是否真实且支持结论。

### A4.5 · 结构化输出与约束

标记已读

对应资料：Structured Outputs

结构化输出约束格式与字段类型，不保证字段事实正确。合法JSON、符合Schema和符合业务是三个层次。

模式设计应包含真实状态，例如缺证据、未验证、工具失败。若只允许成功结论，可能迫使模型把中间状态塞入错误类别。拒绝与截断也需要独立处理。

运行示例 · R04-05

### 结构化输出通过仍要核对事实

**输入与条件。**输出{"version":"v8","tests\_passed":true}，实际测试记录为v7。

| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1schema | 字符串和布尔类型都对 | 结构通过。 |
| 2语义 | 版本对应不上 | 不能对v8宣称已测。 |
| 3处理 | 补测v8或把字段改为未知 | 不能只格式化JSON就算修复。 |

**把过程连起来。**JSON合法不等于业务事实正确。

**边界与反例。**本表是独立教学构造，用来解释该研究主题的一个局部机制，不是原论文实验或产品实测；完整方法与适用条件仍需结合本节正文。

原创练习：设计代码修复报告字段，要求变更文件、已运行测试和未验证事项，再加入验证器检查引用ID与文件是否存在。模型填了字段不代表证据真实。

### B4.6 · 流式响应与事件组装

标记已读

对应资料：Streaming API Responses

流式响应分批提供文本、参数或事件。接收到一部分不代表完整对象已成立，应遵循协议中的完成信号与错误状态。

工具参数可能跨多个片段，不能用脆弱字符串规则猜结束。高风险动作尤其应等完整参数、授权与校验后执行，不能边流式生成边无条件操作。

先认识这里的对象与符号

[SSE、chunk、delta：不同的分片层](../concepts.html#concept-sse)
:   SSE是服务端发送事件的文本协议；网络chunk是这次收到的一段字节；delta是某个输出项的增量内容。三者边界不保证重合。一个完整事件也未必意味着完整工具参数。参数可能先收到{"path":"a，后收到.py"}；必须组装并等协议规定的完成条件，不能见到片段就执行。

运行示例 · R04-06

### 网络分片与事件边界

**输入与条件。**一条event文本分两次到达，空行只在第二片末尾出现。

| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1第一片 | 缓冲不完整文本 | 不交给完整事件处理器。 |
| 2第二片 | 补足空行 | 此时才识别事件完成。 |
| 3参数delta | 事件完成后仍可能只是参数的一部分 | 还需按调用聚合。 |

**把过程连起来。**每层协议有自己的完成条件。

**边界与反例。**本表是独立教学构造，用来解释该研究主题的一个局部机制，不是原论文实验或产品实测；完整方法与适用条件仍需结合本节正文。

依据与适用范围：[[DERIVE]](../example-sources.html#ex-src-DERIVE)。示例输入和场景由本书明确设定。

### B4.8 · 扩展推理与状态连续性

标记已读

Extended Thinking涉及模型额外推理与其接口状态。可见推理摘要、最终回答和受保护状态不应混为一段普通聊天文本。
