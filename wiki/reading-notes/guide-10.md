# 从 CoALA 理解有效记忆

把当前状态、事实、经历和方法分别管理。

推荐阅读 10 / 12本地中文导读

先认识这里的对象与符号

[semantic、episodic、procedural记忆](../concepts.html#concept-memory-types)
:   语义记忆保存事实，情景记忆保存经历，程序性记忆保存有条件的方法；工作记忆服务当前任务。CoALA是分析这类认知架构的框架，MemGPT研究有限上下文与外部存储的组织。“p7补丁漏测失败”是经历；“当前需支持Windows”是事实；“改路径规则时检查分隔符”是有条件流程，不可直接升级成所有任务都跑全量测试。

## 记忆的目标不是存得最多

本篇对应CoALA。工作记忆支持当前任务，情景记忆保留经历，语义记忆保留事实，程序性记忆保留方法。分类用于设计不同存取规则，不是宣称Agent具有完整人类认知。[[S111]](sources.html#S111)

原创案例中，一次测试失败是事件；项目v3路径约定是事实；如何调查路径问题是方法；本轮做到哪里是状态。把它们全部存成“经验”会使更新与检索混乱。

## 什么值得写入

先问未来是否复用、是否有证据、重新获取是否昂贵。容易从最新源码重新读取的事实未必需要复制；代价高的调查结论可能值得保存，但必须带范围和依据。

```
结论：v3按仓库相对路径匹配
范围：构建模块，版本v3
证据：规范D1与测试T2
状态：已验证
失效条件：匹配约定改变
```

这是原创最小记录，不要求数据库。真正价值在于结论与条件一起被取回。

### 四类记忆放在不同地方，才不会把临时假设当永久规则

**本例条件：**独立仓库任务：正在定位Bug，曾经修过一次相似错误，项目规定API不能改，并有一套复现步骤。

工作记忆
:   当前任务暂时持有的状态。

情景记忆
:   某一次具体经历及其条件。

语义记忆
:   有来源和范围的事实或规则。

程序性记忆
:   可复用的做事方法。

四类记忆放在不同地方，才不会把临时假设当永久规则

| 信息 | 更合适的类型 | 使用限制 |
| --- | --- | --- |
| 当前怀疑是路径标准化 | 工作记忆 | 未验证，不升为项目事实 |
| 上周r5修过大小写问题 | 情景记忆 | 要核对是否同条件 |
| 公共API签名不改 | 语义规则 | 来源与有效版本可追溯 |
| 复现→反例→修复→回归 | 程序性步骤 | 按任务风险适当简化 |

各行是独立对象或条件的对照，不暗示上一行的结果自动进入下一行。

#### 怎样把图中的变化读明白

“我记得上次这样修好了”只是一次经历，不能直接推出所有相似报错都有同一根因。

工作状态随任务完成失效，项目规则可能长期适用，保存期限与检索方式因此不同。

记忆系统不要求先建复杂图数据库；先把类型、来源、适用范围和撤销办法定义好。

**不要混淆：**把模型自我反思中的猜测写入永久语义库，会让后续任务反复取到同一个错误。

机制依据：[[COALA]](../sources.html#src-COALA) [[MEMGPT]](../sources.html#src-MEMGPT)。本例数字和宿主场景为明确给定的教学设定，不是商业模型输出或生产性能测量。

工程机制与失败边界

## 租约过期后旧工作者回来

工作者A持有代际1，超时后B取得代际2；A恢复并试图发布，条件写入必须失败。

**关键边界：**进程仍活着不证明仍有发布权；模型输出完成也不证明产物有效。

**顺着源码或工程依据继续追：**区分源事件、抽取候选、整合产物与使用时核验。 不只检查顺利路径，也核对取消、版本变化与结果未知时的行为。

记忆流水线的发布条件阶段对象关键门槛抽取源事件→候选来源与范围整合候选→产物全局租约与工作区工作者完成候选产物还未等于发布成功发布有效产物+水位仍持有租约，验证成功

| 阶段 | 对象 | 关键门槛 |
| --- | --- | --- |
| 抽取 | 源事件→候选 | 来源与范围 |
| 整合 | 候选→产物 | 全局租约与工作区 |
| 工作者完成 | 候选产物 | 还未等于发布成功 |
| 发布 | 有效产物+水位 | 仍持有租约，验证成功 |

记忆流水线的发布条件。数值与状态属于本节明确设定的教学例；不是生产性能或商业模型实测。

完整机制与连续例子见 [记忆写入为什么是一条带租约与验收的流水线？](../chapters/18.html#agent-practice-memory)；本节仍保留原有推导与实验，两处说明使用不同层次而不互相替代。

**证据与理解边界：**生成产物后还要关停工作者、核验内容、确认租约与记录完成；长期记忆不是模型参数自动更新。

## 冲突不一定是谁错了

假设旧记忆说“相对配置文件”，新文档说“相对仓库根”。可能是版本变化，也可能是不同模块；不能仅按最新时间或最高相似度选一条。

检索先检查作用域和时间，再比较证据。证据不足时保留冲突状态，避免把两个相反规则揉成含糊摘要。[[S113]](sources.html#S113)[[S116]](sources.html#S116)

## 警惕自我强化

模型误判后写入记忆，下次检索到自己的结论，又把重复出现当作多源证实。五份来自同一次生成的摘要仍只有一个来源。

自动记忆方法提供抽取、链接和维护思路，但评价条件不同，不能根据某个分数断言任意工程都适合。[[S118]](sources.html#S118)[[S119]](sources.html#S119)

## 遗忘与恢复是两件事

过期规则可以退出活跃检索，重要历史仍可保留审计；隐私要求可能需要实际删除。Checkpoint用于恢复任务，长期记忆用于帮助新任务，两者不应混用。[[S112]](sources.html#S112)[[S114]](sources.html#S114)

**练习：**比较无记忆、固定规则、带证据的按需记忆三组，加入版本变化和同名不同项目任务。评价正确取用与错误取用，而不是只统计写入量。

运行示例 · G10

### 记忆一句“超时是3”，缺了什么才会在下次出错

**输入与条件。**项目A旧配置timeout=3秒，项目B配置timeout=8秒；项目A在10月10日改为5秒，记忆服务在10月12日才记录。

| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1保存旧事实 | project=A，value=3，来源r1 | 不能只存“超时3秒”而不存项目。 |
| 2记录新事实 | value=5，生效10月10日，记录10月12日 | 区分什么时候有效与什么时候才知道。 |
| 3问A当前规则 | 选A且适用当前日期 | 返回5秒并附来源。 |
| 4问B规则 | 必须按project=B筛选 | 返回8秒，不能拿最相似的A记忆。 |
| 5问历史 | 查询“10月9日A规则” | 旧事实仍有用，不能无条件全覆盖。 |

**把过程连起来。**有效记忆保存的是带适用范围和时间的命题，不是只保存一句话。

**边界与反例。**时间与配置均为构造例；真实纠错策略还要区分更正错误记录与正常版本更新。
