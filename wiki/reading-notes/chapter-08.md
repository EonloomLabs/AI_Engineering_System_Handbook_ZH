## 检索从证据需求开始

RAG连接外部检索与生成。原论文中的训练与推理设计，不等于今天所有“搜索后放入Prompt”的广义实践。工程系统还包含入库、切分、索引、查询、召回、重排和拼装。任何一层错误都可能使答案失真。[[S095]](sources.html#S095)

先区分任务要找精确符号、语义资料、历史变更还是运行结果。源文档过期，检索只能更快找到过期事实；切分丢掉条件，语义相似也不足以支持结论。

## 词项、稠密与晚交互

先认识这里的对象与符号

[BM25及N、df、k₁、b](../concepts.html#concept-bm25)
:   BM25是词项检索打分公式。常见记号N是文档总数，df是含该词的文档数，tf是当前文档词频，|D|是当前文档长度，avgdl是平均长度；k₁和b是词频饱和与长度修正的设置。k₁不是Key向量k₁，b也不是神经网络偏置。分数只用于给候选排序，不能把8.2解释为82%正确率。

[bi-encoder、cross-encoder与重排](../concepts.html#concept-rerank)
:   双编码器分别编码查询与文档，可以预存文档向量；交叉编码器共同处理一对查询与文档，做更细判断，通常每对都要算。重排仅排序已经召回的候选。遗漏的正确文档不在候选集内，再强的重排器也不能直接把它排第一；需要先补召回。

[ColBERT与MaxSim](../concepts.html#concept-colbert)
:   ColBERT类方法为查询和文档保留多个Token向量，再做后期交互。常见MaxSim让每个查询Token取与文档Token的最大相似度，再汇总。它不是“整篇文档只有一个向量”的双编码检索，也不是生成模型每层的自注意力输出。

先认识这里的对象与符号

[DPR、DPI与坐标单位](../concepts.html#concept-pixels)
:   DPR常表示设备像素与CSS像素的比例；DPI表示每英寸的点数。截图像素、界面逻辑坐标和屏幕坐标不一定同单位，还可能有缩放、裁剪与偏移。在明确DPR=2且其他映射一致的独立例中，CSS横坐标100对应200个设备像素；不能把这条条件化关系直接套到所有截图。

BM25等词项方法利用词出现与统计重要性；稠密检索把查询和文档编码为向量；DPR展示双编码器问答检索；ColBERT使用更细粒度Token表示与晚交互。向量距离不是事实正确率，`include`和`exclude`可能很近却含义相反。[[S096]](sources.html#S096)[[S098]](sources.html#S098)[[S099]](sources.html#S099)

切分应围绕可理解单位，代码可按函数/类并保留路径和签名。太小丢条件，太大增干扰；重叠帮助边界但产生重复，拼装时仍要去重。

## Contextual Retrieval

Anthropic方案给片段补充基于原文的简短背景，再结合词项、向量与重排。孤立的“默认值由false改为true”需要知道字段、项目和版本；补充上下文可以帮助召回，但错误补充也会污染索引。原文与来源必须保留。[[S096]](sources.html#S096)

这不是给每个片段编造合理背景。对完整符号和路径已经明确的代码，额外长描述未必有收益，应先测精确检索基线。文章的实验结果只适用于其测试条件，不应直接当任意仓库的提效保证。

## 融合、重排与查询改写

先认识这里的对象与符号

[RRF：按排名融合](../concepts.html#concept-rrf)
:   RRF对某文档在每条召回路径上的排名r贡献1/(c+r)，再相加。c是平滑常数，r通常从1开始；没进入某条路径的候选不凭空获得该路贡献。独立例：c=10，某文档两路排名1、3，得1/11+1/13约0.167832。不是把BM25和余弦的原始分数相加。

RRF对不同排序按`1/(k+r)`累加，避免直接相加量纲不同的BM25和余弦分数。排名融合不能补回所有召回器都遗漏的文档。Reranker对候选作更精细判断，成本较高，通常用于较小集合。[[S097]](sources.html#S097)

先认识这里的对象与符号

[HyDE：假设文本只用于找材料](../concepts.html#concept-hyde)
:   用模型生成一份假设性的回答或文档，将其表示用于检索。这份生成文本是寻找证据的辅助，不是已经找到的事实来源。模型猜“可能是缓存失效”，可以据此扩大搜索；没有真实证据前不能写成“缓存失效已确认”。

[GraphRAG、RAPTOR与组织层次](../concepts.html#concept-graphrag)
:   GraphRAG类方法利用实体关系及社区等组织信息；RAPTOR利用分层聚类与摘要支持检索。它们引入额外派生信息，也引入更新、来源和错误传播问题。源文档改变时，旧摘要或图中的关系可能过期。改了原文并不证明所有派生索引已同步更新。

HyDE生成假设文档帮助检索，但假设不是证据。RAPTOR建立层次摘要索引，GraphRAG组织关系与全局信息，两者适合不同需求，也会增加抽取误差与维护成本。[[S100]](sources.html#S100)[[S101]](sources.html#S101)[[S120]](sources.html#S120)

## 代码检索应利用结构

路径、正则、GitHub Code Search和ripgrep适合精确定位。Tree-sitter提供语法树与增量解析；LSP提供定义、引用、符号与诊断等语言服务。AST不自动拥有全部类型和运行时语义，LSP也依赖语言服务器与项目配置。[[S102]](sources.html#S102)[[S103]](sources.html#S103)[[S104]](sources.html#S104)[[S105]](sources.html#S105)

原创调查顺序：配置字段→解析点→过滤函数→调用者传参→测试→变更历史→最小复现。同名符号不一定在真实执行路径。Git说明能解释历史原因，但当前行为仍由当前源码与运行证据判断。

RepoCoder研究迭代检索与生成，RepoBench和CodeSearchNet评价不同仓库上下文任务。补全、搜索与Issue修复不是同一种能力，指标不能直接换算。[[S106]](sources.html#S106)[[S107]](sources.html#S107)[[S108]](sources.html#S108)

## 检索指标与下游成功

先认识这里的对象与符号

[Precision、Recall、MRR与nDCG](../concepts.html#concept-metrics)
:   精确率看返回结果中有多少相关；召回率看应找相关中找到了多少；MRR平均第一个正确项的排名倒数；nDCG考虑相关程度和排序位置并相对理想排序归一化。独立例：应找5篇，返回4篇其中3篇相关，精确率3/4，召回率3/5。不要把这两个分母互换。

```
Precision@k = 前k条相关数 / k
Recall@k = 前k条相关数 / 全部相关数
MRR = 各查询首条相关结果排名倒数的平均
```

MAP综合相关结果出现位置；nDCG支持分级相关性并按位置折损后归一化。若相关集未知，召回率本身也难精确测量。[[S110]](sources.html#S110)

原创例子：必须A、B两处证据，结果A、X、Y，Recall@3为1/2，Precision@3为1/3。若缺B无法判断兼容性，找到A不是任务成功。召回后被截断或误解释，仍会失败。BEIR提醒不同领域泛化需要独立评价。[[S109]](sources.html#S109)

## 失败排查顺序

检查源是否正确和新鲜→索引是否包含→查询是否准确→候选是否召回→重排是否误删→拼装是否截断→模型是否正确解释。权限过滤应在返回证据前执行，而非让模型看完再自觉保密。

**自检：相似度最高是否最可信？**不是。**检索好是否可以省测试？**不能，检索供证，测试验行为。

### A8.1 · 检索增强生成的基础

标记已读

对应资料：Retrieval-Augmented Generation

原始RAG研究把参数化生成模型与非参数化文档记忆结合，利用检索证据辅助知识密集任务。今天工程中的RAG用法更广，不能把所有“搜索后回答”都当成原论文的完整实现。

检索负责提供候选证据，生成负责利用证据形成输出；两者都可能出错。文档过期、片段缺条件或模型误读都会导致错误答案。

运行示例 · R08-01

### 检索不是把答案从模型里“挖出来”

**输入与条件。**用户问当前配置，参数记忆里可能只有旧值3，文件已为5。

| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1检索 | 读取当前文件 | 取得5及版本。 |
| 2增强 | 把证据放入当前请求 | 模型有了参数之外的信息。 |
| 3生成 | 答案受证据约束 | 仍需防止它混入旧值。 |

**把过程连起来。**RAG连接外部知识与生成，不改变模型参数本身。

**边界与反例。**本表是独立教学构造，用来解释该研究主题的一个局部机制，不是原论文实验或产品实测；完整方法与适用条件仍需结合本节正文。

### A8.2 · 上下文增强的混合检索

标记已读

对应资料：Introducing Contextual Retrieval

Contextual Retrieval给待索引片段补充来自原文的简短上下文，再结合词项、向量和重排。它帮助孤立片段保留指代与背景，不是允许模型为文档编造情境。

例如“该字段默认关闭”需要知道字段、版本和文档位置。补充这些信息有助于召回，也可能因摘要错误污染索引，所以必须保留原始内容与出处。

### 给片段补上下文，避免“它”失去指代

| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1缺背景 | 查询调试缓存时难匹配 | “它”没有具体对象。 |
| 2补上下文 | 标注“调试缓存：默认关闭”及来源 | 让片段可解释。 |

### A8.3 · 倒数排名融合RRF

标记已读

对应资料：Reciprocal Rank Fusion

RRF按不同检索结果中的名次融合，常见形式为对各列表累加`1/(k+rank)`。它避免直接相加不同量纲的原始分数，但不能恢复所有检索器都遗漏的文档。

平滑常数影响名次差异的权重；重复结果需要按真实文档身份合并，而不是只比较标题。融合之前还应完成权限过滤。

运行示例 · R08-03

### 排名融合按名次而非分数量纲

**输入与条件。**排名1=[A,B]，排名2=[B,A]，c=60。

| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1A | 1/61+1/62 | 约0.032522。 |
| 2B | 1/62+1/61 | 相同得分。 |
| 3平局 | 按稳定次序或额外信息处理 | 不能捏造A明显更优。 |

**把过程连起来。**RRF不是万能判优器，对称输入理应相同。

**边界与反例。**本表是独立教学构造，用来解释该研究主题的一个局部机制，不是原论文实验或产品实测；完整方法与适用条件仍需结合本节正文。

继续逐步计算：[Q061 · 两张排名表，逐行融合成RRF](../chapters/16.html#worked-Q061)

依据与适用范围：[[DERIVE]](../example-sources.html#ex-src-DERIVE)。示例输入和场景由本书明确设定。

原创练习：对两份包含相同与不同文档的排名手算RRF，观察一个在两边中等靠前的结果如何与单边第一竞争。

完成标准是理解融合依据与局限。RRF排名不是文档事实正确率，也不是最终回答的置信度。

### B8.4 · 稠密段落检索DPR

标记已读

对应资料：Dense Passage Retrieval

DPR使用稠密表示进行段落检索，查询与文档可以分别编码。预先计算文档向量有利于检索效率，但质量依赖训练数据、编码器与任务分布。

语义相近可以匹配不同表述，也可能混淆否定、版本或同名实体。精确词项与元数据过滤仍有价值。

运行示例 · R08-04

### 双塔检索把查询和文档分别编码

**输入与条件。**q=[1,0]，dA=[0.8,0.6]，dB=[0,1]。

| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1离线 | 先计算存储文档向量 | 不必每次与查询联合编码。 |
| 2在线 | 只编码q并计算点积 | A0.8，B0。 |
| 3训练 | 相关对比样本塑造距离 | 向量接近不自动证明版本和事实一致。 |

### B8.16 · 排序检索指标

标记已读

对应资料：Evaluation of Ranked Retrieval Results

Precision关注返回结果中有多少相关，Recall关注必要证据找到多少；MRR、MAP和nDCG进一步考虑排序与相关程度。它们衡量不同目标，不能互相替代。

相关性标签本身可能不完整，尤其是代码任务需要多份证据共同支持结论时。一个相关片段不足以完成全部推理。

运行示例 · R08-16

### 同样召回两条，排序质量可以不同

**输入与条件。**相关集合={A,B}，列表X=[A,B,C]，Y=[C,A,B]。

| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1Recall@3 | 两者都2/2=1 | 覆盖相同。 |
| 2首相关倒数排名 | X=1，Y=1/2 | MRR贡献不同。 |
| 3用途 | 用户只看首项时X更好 | 指标应贴合下游行为。 |

**把过程连起来。**排序指标衡量“多早看到”，召回衡量“是否看到”。

**边界与反例。**本表是独立教学构造，用来解释该研究主题的一个局部机制，不是原论文实验或产品实测；完整方法与适用条件仍需结合本节正文。
