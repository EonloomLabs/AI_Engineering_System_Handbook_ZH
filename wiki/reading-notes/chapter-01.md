## 从文本到Token与向量

LLM先把文本转换成Token ID。Token可能是词、词的一部分、标点、空白或字节片段；中文字符与Token不存在固定比例。同一文本在不同Tokenizer中长度可以不同，计数必须使用与目标模型配套的实现。[[S007]](sources.md#S007)

常见流水线包含规范化、预分词、子词模型、后处理。BPE逐步合并高频片段；其他方法采用不同目标。不能假设所有Tokenizer都转小写，也不能为减少Token随意删除代码空白。ID数字的大小不表达语义远近。

若词表大小V、隐藏维度d，Embedding矩阵形状为V×d。根据ID取一行得到初始表示。它不是固定释义，后续层会根据上下文更新表示。静态Word2Vec通常给词条固定向量；Transformer中的上下文化表示会随句子而变。[[S010]](sources.md#S010)[[S008]](sources.md#S008)

## 注意力的完整计算


<span id="concept-intro-1"></span>


先认识这里的对象与符号

[Query、Key、Value：三种中间数值表示](../concepts.md#concept-qkv)
:   q是接收信息的一行查询表示；k是可读位置提供的一行匹配表示；v是该位置供混合的一行内容表示。大写Q/K/V把多行收集成表。它们由输入与参数计算得到，分别承担打分与提供内容的职责。某个q与两个k点积得到两个分数；softmax得到两个份额；这些份额分别乘两行v，再相加。这里不生成搜索词，也不直接选答案。

设当前表示X有n个位置、d个特征，投影得到Query、Key、Value：


<span id="concept-intro-3"></span>


先认识这里的对象与符号

[d\_k、d\_v、Dh：每行表示的宽度](../concepts.md#concept-dk)
:   d\_k表示一个Query/Key向量有多少个分量；d\_v表示一个Value向量有多少个分量。Dh或d\_h在一些章节中是单头宽度。它们是尺寸整数，不是第k个Key或某个Value数值。形状微例：Q[2,3]、K[5,3]、V[5,4]，则分数[2,5]，输出[2,4]。Q/K配对宽度3，Value宽度4仍合法。

```
Q = XW_Q，K = XW_K，V = XW_V
A = softmax(QKᵀ / √d_k + M)
Attention(X) = AV
```

Q用于匹配其他位置，K用于被匹配，V提供组合内容。M是掩码：因果生成时禁止访问未来Token，通常把相应分数设为负无穷。注意力是模型内部的加权运算，不是数据库查询，也不是调用搜索引擎。[[S008]](sources.md#S008)[[S009]](sources.md#S009)

**原创演算：**分数为[0,1,2]，softmax约为[0.090,0.245,0.665]。若Value某一维为[10,20,30]，输出约25.75。这是组合，不一定复制最高权重位置。最大注意力权重也不等于完整决策原因，因为还有多个头、残差和后续层。


<span id="symbol-intro-1"></span>


先认识这里的对象与符号

[Concat、split与chunk：拼接与拆分](../concepts.md#concept-concat)
:   Concat把多份数组沿指定轴连接起来，不把元素相加；split或chunk按规定边界分组。所有未拼接轴需相容。这里chunk指数组块；网络中的chunk则是字节分片。独立例：两头各[2,3]，沿特征轴拼成[2,6]；沿位置轴拼会变[4,3]，语义已经不同。

多头机制在不同投影空间计算并拼接。不能把每个头固定命名为“语法头”“事实头”后当作完整解释。原始论文提出的是编码器—解码器架构；GPT类因果解码器是另一种组织方式，不能混画。[[S008]](sources.md#S008)[[S002]](sources.md#S002)

## Transformer层不只有Attention


<span id="concept-intro-2"></span>


先认识这里的对象与符号

[Norm、LayerNorm、RMSNorm：不是概率归一化](../concepts.md#concept-norm)
:   Norm在层公式中表示一个规范化函数。LayerNorm通常按一个Token的特征减均值、除标准差，再缩放平移；RMSNorm通常不减均值，按均方根缩放。它们不等于softmax。独立微例，忽略稳定分母用的小正数ε与可学缩放：LayerNorm([1,3])=[-1,1]；RMSNorm([1,3])=[1/√5,3/√5]。

注意力交换位置信息，前馈网络进行逐位置非线性变换，残差连接帮助信息与梯度传播，归一化控制内部尺度。一个教学用Pre-Norm块为：

```
H = X + Attention(Norm(X))
Y = H + MLP(Norm(H))
```


<span id="concept-intro-5"></span>


先认识这里的对象与符号

[MoE、专家与路由器](../concepts.md#concept-moe)
:   MoE是包含多套子网络的模型结构；路由器为当前Token表示选择或加权少数专家。专家通常是数值子网络，不是被赋予“数学老师”等提示词的聊天Agent。独立例：有4个专家，每Token选2个，表示某次只激活其中2条专家路径；仍需保存模型设计要求的参数与路由状态。

这不等于2017年原论文的全部排列。现代模型还可能使用不同归一化、激活、位置编码和MoE结构。学习部件之后，真实实现仍应检查具体架构。[[S008]](sources.md#S008)[[S016]](sources.md#S016)[[S017]](sources.md#S017)

没有顺序信号的自注意力难以区分排列。原始方法把位置表示加到输入；RoPE通过旋转Query/Key的成对维度，让点积包含相对位置信息。RoPE不保证无限长度泛化，仍受训练和扩展方式约束。[[S012]](sources.md#S012)

## 从隐藏状态到下一个Token

最后的隐藏表示经过输出投影，得到词表上的Logits，再通过概率变换与解码选择Token。Logits不是已经校准的事实置信度。自回归分解为：

```
P(x₁,…,x_T) = ∏ P(x_t | x₁,…,x_(t−1))
```

选择的新Token进入后续前缀，循环直到正常结束、工具调用、预算上限或外部中止。某个句子概率高，只说明它符合条件分布，不保证事实真实；不存在的API也可能听起来很合理。[[S034]](sources.md#S034)[[S179]](sources.md#S179)

训练时目标序列已知，可以并行计算各位置损失，因果掩码防止偷看答案；普通自回归推理中后一步依赖前一步选出的Token，存在串行依赖。因此“Transformer可并行”不等于“一次无条件生成整篇答案”。[[S009]](sources.md#S009)

## MHA、MQA、GQA与MoE


<span id="concept-intro-4"></span>


先认识这里的对象与符号

[MHA、MQA、GQA：头怎样共享](../concepts.md#concept-heads)
:   一个注意力头是一套匹配并聚合内容的路径。MHA常让每个Query头有自己的K/V头；MQA让多个Query头共用一组K/V；GQA在两者之间，分组共享。它们是结构选择，不是运行时随便改一个开关。独立形状例：8个Query头、2个K/V头，若均匀分组，每4个Query头共享1组K/V；缓存按K/V头数记账。

MHA通常为不同查询头提供独立KV；MQA共享单组KV；GQA让查询头分组共享。减少KV头有助于缓存和带宽，但不保证相同比例端到端加速。MoE是另一层面的稀疏性：路由器选择少数专家网络处理Token，不是多个聊天Agent开会。总参数与激活参数也不是同一个量。[[S013]](sources.md#S013)[[S014]](sources.md#S014)

Llama3、DeepSeek-V3、Qwen3提供不同系统案例。读报告要区分架构、数据、训练、后训练与服务优化，不能把整体表现归因于单个组件，也不把历史技术报告当当前排行榜。[[S016]](sources.md#S016)[[S017]](sources.md#S017)[[S018]](sources.md#S018)

## 从机制回到工程

窗口容量不保证每条约束都被利用。模型可能忽略否定条件、混淆版本或沿用强先验。对“默认行为必须保持”，可把要求转成回归测试，而不只在长Prompt中重复强调。这是工程迁移建议，必须在实际任务上验证。[[S085]](sources.md#S085)[[S088]](sources.md#S088)

**自检：温度为零是否消除幻觉？**不会，它改变选择方式，不补充证据。**GQA与多Agent是否同类？**不是，前者在模型内部，后者是外部执行组织。

### A1.2 · 分词流水线

对应资料：The Tokenization Pipeline

分词流水线可能包含规范化、预分词、子词学习和特殊Token后处理。BPE逐步合并常见片段，其他算法采用不同目标。不能把分词概括为按空格切开，更不能假设所有模型都转小写。

### A1.3 · 注意力与Transformer原始架构

对应资料：Attention Is All You Need

原始Transformer以注意力组织序列处理，包含缩放点积、多头、位置编码、前馈与残差等组件。核心计算是用Q与K产生权重，再组合V。因果生成还需阻止未来信息流入当前位置。

`QKᵀ/√d_k`控制匹配分数尺度，softmax按允许位置归一化。多头在不同投影空间计算，但不能永久把每个头命名为某一种人类功能。原论文任务与当前编码Agent是不同层面。

### 转轴后矩阵乘法才匹配

**输入与条件。**Q与K的形状都是[3,2]。


<span id="mechanism-original-worked-R01-04"></span>


| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1错误直接乘 | [3,2]乘[3,2] | 内维2和3不等，不能做普通矩阵乘法。 |

[MLA：学习得到的低维K/V表示](../concepts.md#concept-mla)
:   MLA指多头潜在注意力的一类架构。用较低维的潜在表示联合组织K/V相关内容，并按设计处理位置部分。它改变模型表示与参数结构，不只是把普通KV文件用ZIP压缩。读c=xW\_down时，c是这次计算的潜在向量，W\_down是学到的降维系数表；后续如何重构或吸收投影须按具体架构解释。

DeepSeek-V3报告讨论MoE、MLA和训练系统等设计。MLA与常规KV组织存在差异，提醒标准缓存公式不是所有架构通用。多Token预测训练目标也不等于部署时无需验证地一次输出多Token。

稀疏专家使总参数与激活计算分离，但通信与负载仍影响效率。训练成本、推理成本和模型效果必须分别看，不能混用报告口径作简单比较。

先认识这里的对象与符号

[RLHF、奖励模型与策略](../concepts.md#concept-rlhf)
:   RLHF泛指利用人类反馈训练行为的流程。奖励模型是对回答等行为打分的模型；策略是实际生成动作的概率模型。两者职责不同，得高奖励不自动等于事实正确。独立例：奖励器偏爱长回答，策略可能学会写长而不更准确；因此奖励判据需要验证。

阅读时记录每项技术属于哪一层、解决什么问题、依赖什么假设。RAG改变证据来源，RLHF改变训练行为，KV Cache改变计算复用，三者不是同类Prompt技巧。
