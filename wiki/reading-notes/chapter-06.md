## 产品机制与公开证据

先认识这里的对象与符号

[IDE、CLI、UI与DOM](../concepts.html#concept-interface-environment)
:   IDE是集成开发环境，CLI是命令行界面，UI是用户界面，DOM是网页文档的结构对象树。不同入口自动附带的代码、选区和页面信息可能不同。模型在IDE里看到选中函数，不代表同一任务在CLI里也已收到该函数；先检查本轮输入对象。

Codex、Claude Code、Copilot包含客户端、模型、工具和服务，并持续变化。公开文档说明能力，开源代码说明某版本实现，一次日志只证明某次运行。不能从界面表现推断隐藏Prompt，也不能把CLI规则套用到所有IDE或云端。[[S004]](sources.html#S004)[[S068]](sources.html#S068)[[S076]](sources.html#S076)

本章以核验日2026-10-17可获得的资料解释机制，不保证所有账号与版本相同。具体源码文件名、模型名单与默认阈值不在未核验时写成事实。

## Codex：每轮输入怎样形成

Codex公开Agent Loop描述了输入准备、模型输出分派、工具执行和结果回填。搜索、文件内容、补丁与测试结果是在循环中动态进入上下文，不是用户初始Prompt天然包含的全部知识。[[S004]](sources.html#S004)

对假想`exclude`任务，第1轮选择搜索，第2轮看到匹配后读代码，第3轮生成修改，第4轮检查测试。每轮可见内容不同，压缩前后也不同。因此排查失败要问“此时实际看到了什么”，而不只问“最初要求写得够不够长”。

开源仓库可用于跟踪配置、会话、消息构建、工具分派与状态保存。本书没有审计某个完整提交，不把文章中历史文件路径当当前固定接口。[[S066]](sources.html#S066)

## App Server与托管Harness

先认识这里的对象与符号

[Thread、Turn、Session：运行层次](../concepts.html#concept-threadturn)
:   这些通常是宿主对会话和工作轮次的划分，不是神经网络的层。Thread可指一条会话，Turn可包含响应一次用户任务所需的多次模型/工具循环；具体边界取决于产品。不能把“本轮完成”直接等同“所有外部工具都已结束”；需要看实际事件和结果。

Codex App Server公开说明以双向协议连接客户端与核心，并用Thread、Turn、Item组织交互。应理解长期会话、一次请求推进和中间事件的层次，而不只记字段名。客户端断线、取消、审批和重连都需要被表达。[[S064]](sources.html#S064)

原创启发：界面展示进度不应成为任务事实的唯一存储。终端与桌面界面可共享核心，但权限和任务状态必须稳定。托管Agents API把部分会话、编排和恢复交给服务，应用仍要提供工具与执行边界。[[S067]](sources.html#S067)

## Harness Engineering：环境也能提高质量

OpenAI的工程文章来自特定团队案例，强调知识在仓库中有组织地可发现，重要边界由可执行检查维护，而不是把全部规则堆进巨大入口文件。不能把案例结果外推成所有项目的效率承诺。[[S065]](sources.html#S065)

原创应用：入口告诉Agent项目结构、关键约束和测试入口；领域规则放相应目录；稳定且重要的限制用测试和静态检查落实。对`exclude`，明确路径相对仓库根还是配置目录，比反复写“你是专业工程师”更有用。

## Claude Code：上下文与记忆

官方说明围绕获取上下文、行动、验证组织工作。长会话会管理工具结果和历史；Skills可以按需展开；子Agent可在独立上下文完成工作后返回结果。这是Harness机制，不是模型注意力结构。[[S068]](sources.html#S068)[[S069]](sources.html#S069)[[S071]](sources.html#S071)

`CLAUDE.md`、自动记忆与`AGENTS.md`支持应看版本和配置。当前文档描述有条件的AGENTS.md加载，不能写成所有版本始终读取，也不能沿用永远不支持的旧结论。项目指令与自动记忆均属于上下文，不是不可违反的程序配置。[[S070]](sources.html#S070)

子Agent不应默认获得父Agent所有历史和权限。委派要给目标、边界、证据要求与结果格式。主Agent收到摘要仍要判断是否遗漏关键限制。Hooks在生命周期节点执行确定性动作；权限系统限制资源，Skill不能代替这些边界。[[S071]](sources.html#S071)[[S073]](sources.html#S073)[[S074]](sources.html#S074)

## Copilot：先确认使用表面

Copilot CLI、IDE交互与其他Agent能力不完全相同。Instructions、Skills、自定义Agent、Hooks、MCP、插件各有职责与支持范围，不能因为一个表面支持就推断全部支持。[[S076]](sources.html#S076)[[S079]](sources.html#S079)

CLI提供上下文查看和压缩能力，但一次压缩输出不能证明内部算法。自定义Agent组织角色配置，Skill组织任务方法和资源，插件负责组合分发。记忆跨哪些任务生效、如何验证证据，要看当前产品规则。[[S077]](sources.html#S077)[[S080]](sources.html#S080)[[S081]](sources.html#S081)[[S082]](sources.html#S082)

程序化调用还要处理退出码、输出结构、授权和非交互行为。终端最后一行“完成”不足以判脚本成功，应核验目标文件与测试。[[S083]](sources.html#S083)

## 三产品对照实验

原创实验固定仓库、Bug与验收，记录首次读取、必要证据、修改范围、工具失败、压缩、委派、总成本与结果。端到端比较允许模型和Harness不同；机制比较则应尽量固定变量。不能把组合差异全部归因于模型。

```
基线代码、任务与授权：
客户端、模型、配置、日期：
实际证据与变更：
运行过的验证：
压缩、委派和恢复事件：
成功、失败或阻塞：
总成本、耗时、人工接管：
```

**自检：界面没显示读取，就证明模型没看到吗？**不能，可能默认注入。**源码存在功能就代表当前能用吗？**不能，还受发布版本、后端和权限影响。

### A6.1 · Codex输入组装与执行循环

标记已读

对应资料：Unrolling the Codex Agent Loop

Codex的公开循环把输入准备、模型输出、工具执行与结果回填连接起来。模型可以提出搜索或修改动作，Harness负责分派、权限与状态；这不是模型直接拥有操作系统访问能力。

本条关注每轮输入的变化：规则与目标可能稳定，源码片段、错误日志和已完成状态不断新增。长任务中的压缩又会改变历史的表示方式，因此不能只检查最初一句用户Prompt。

### 输入中工具不可见时不能归因于模型漏选

**输入与条件。**实际请求只含read，不含search。

| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1请求清单 | 确认search未暴露 | 模型无法按正常工具定义调用它。 |

**把过程连起来。**诊断应沿可观察输入链，而不是只看最终未调用现象。

### A6.3 · 面向Agent的工程环境

标记已读

对应资料：Harness Engineering

Harness Engineering讨论如何为Agent构建容易发现知识、执行工作和验证结果的环境。它来自特定团队的实践，不能把其产出规模或效率外推到任意仓库。

入口指导适合提供地图，详细规则放在相关位置，稳定的重要边界可以用测试或静态检查落实。模型因此更容易取得必要信息，而不是通过一份无限增长的说明书记住一切。

### B6.4 · 如何阅读Codex的公开实现

标记已读

对应资料：OpenAI Codex Repository

Codex公开仓库适合研究配置、会话、输入构建、工具分派与状态管理之间的连接。本书没有对某个提交进行逐文件审计，因此不列未经确认的当前源码符号作为事实。

读源码应固定版本，从可运行入口向下追踪，再用测试或日志验证理解。文档中的架构描述与某一提交实现可能存在时间差，文件名也会变化。

先认识这里的对象与符号

[ToolRouter、ToolCall、ToolInvocation](../concepts.html#concept-tool-objects)
:   这些是所引用Codex源码快照中的程序类型名。ResponseItem表示一项模型响应；ToolCall表示待调用数据；ToolInvocation把调用与会话、取消等执行上下文组合；ToolRouter负责相关工具路径。这些对象由程序构造和分派，不是模型内部Q/K/V那样的张量。字段和权限处理需跟随所引用的固定源码，不凭名字推断。

运行示例 · R06-04

### 固定commit再追一条调用链

**输入与条件。**选择已存档Codex提交，查看router与registry。

| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1锁版本 | 记录完整commit与路径 | 避免跨版本拼接结论。 |
| 2追输入 | ResponseItem如何转ToolCall | 检查匹配的类型分支。 |
| 3追输出 | ToolInvocation怎样到dispatch | 同时保留错误/取消路径。 |

**把过程连起来。**只读一个成功分支不足以解释整个执行系统。

**边界与反例。**本表是独立教学构造，用来解释该研究主题的一个局部机制，不是原论文实验或产品实测；完整方法与适用条件仍需结合本节正文。

### A6.16 · Copilot CLI的任务流程

标记已读

对应资料：Using GitHub Copilot CLI

CLI工作流把用户输入、工具执行、状态展示和结束结果结合起来。理解它时应区分交互式确认、非交互自动化和任务恢复，不把某一种运行模式的默认行为推广到全部场景。

先认识这里的对象与符号

| 2判定 | 退出码代表运行失败或未完成 | 核查其具体含义。 |

## 继承矩阵

按规则、历史、模型、工具、权限、身份和环境分别列父子关系，明确每项继承、重新配置或禁止的条件。

**关键边界：**避免“默认继承全部”这种不可执行说明；验证的是实际运行配置。

**顺着源码或工程依据继续追：**逐项核对文件、层级、快照与运行时能力。 不只检查顺利路径，也核对取消、版本变化与结果未知时的行为。

完整机制与连续例子见 [规则文件加载与子Agent继承，为什么不能只说“自动继承”？](../chapters/12.html#agent-practice-rules)；本节仍保留原有推导与实验，两处说明使用不同层次而不互相替代。
