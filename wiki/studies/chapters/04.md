## 1. 预训练能力如何变成助手行为


<span id="concept-intro-5"></span>


先认识这里的对象与符号

[Schema与Structured Outputs](../../concepts.md#concept-schema)
:   Schema是一份字段和类型等结构规则；结构化输出机制让模型更容易返回符合规则的数据。字段合法仍不等于目标文件存在、已授权或业务正确。独立例：要求path为字符串；{"path":3}类型不合规则，{"path":"missing.py"}虽结构合规则仍可能找不到文件。

预训练优化文本分布，SFT通过示范数据强化某些条件下的回答形式与任务策略。给模型看到高质量“请求—回答—工具结果—继续行动”轨迹，可以让它学习这些模式；但格式学会不等于任何一次调用都有效。Schema验证、权限和完成核验仍在执行层。

SFT样本的关键并非只有最终文本，还包括任务分布、正确的工具调用与恢复过程、是否允许模型看到验证反馈。把失败轨迹全部删除，可能让模型只学到顺利路径；无选择地加入失败轨迹，又可能复制错误。数据设计应明示哪些动作值得模仿、哪些内容只是环境反馈。

训练时若只优化最终回答，长轨迹中间某个危险调用可能没有被直接约束。反过来，如果机械奖励每个步骤的形式，会诱导满足格式却没有推进任务。这里需要区分目标层级与可观测反馈，而不是简单追求更长推理。[[N61]](../sources.md#N61 "本地来源与核查范围")


<span id="c04-h2"></span>


## 2. RLHF中的奖励不是事实真值

典型偏好流程先对回答进行比较，训练奖励模型，再优化策略使奖励变高，同时约束偏离参考策略的程度。偏好可能综合帮助性、风格、遵循指令、安全等维度，不能假设一个标量完美表示全部业务目标。

模型可能利用奖励模型的缺陷，例如偏爱冗长、特定语气或表面完整性。工程上看见“答案更自信”不应推断“事实更正确”。需要外部可核验结果，例如编译通过、数据库最终状态、证据支持率，而不是仅凭另一个模型的满意度。

强化学习里的策略更新也不是每次用户聊天都即时更新模型参数。产品可能有独立的数据与训练流程；用户在当前会话纠正答案，直接改变的是上下文，是否进入后续训练是另外的问题。

## 3. DPO的目标函数为何出现参考模型

从一个带KL约束的理想化优化问题出发：


<span id="concept-intro-2"></span>


先认识这里的对象与符号

[π、π\_ref与β：偏好目标的符号](../../concepts.md#concept-beta-policy)
:   在策略与偏好优化中，π表示条件概率策略，π\_ref表示固定参考策略；β是控制目标尺度或约束强度的设置系数。完整回答的概率由各Token条件概率构成。这里π不是圆周率，β不是LayerNorm的偏移参数。DPO式子的w/l是偏好与非偏好答案标记，不是权重w与层数L。


<span id="symbol-intro-2"></span>


先认识这里的对象与符号

[E、Π、∼、∝：概率式的常用记号](../../concepts.md#concept-probability-symbols)
:   x∼p表示按分布p抽样，E表示依指定分布求期望，Π表示把指定项连乘，∝表示相差一个公共比例因子而非已经相等。这里E不是Embedding参数表。独立例：pᵢ∝exp(zᵢ)还需除以所有候选指数的总和；写∝时不能把未归一化值直接读作概率。

```
maxπ  E(y~π)[r(x,y)] − β KL(π(.|x) || πref(.|x))
最优分布：π*(y|x) ∝ πref(y|x) exp(r(x,y)/β)
因此 r(x,y) = β log[π*(y|x)/πref(y|x)] + β log Z(x)
```


<span id="symbol-intro-1"></span>


先认识这里的对象与符号

[σ：看清函数符号与统计量](../../concepts.md#concept-sigma)
:   在σ(XW+b)中，σ常泛指这一层选定的非线性函数；具体可以是ReLU等，不能仅凭σ认定是sigmoid。统计公式中σ常指标准差，σ²是方差。它们不是同一对象。独立例：σ若指定为ReLU，σ(-1)=0；若指定为sigmoid，则约0.268941。必须先给函数定义，才能算结果。

如果成对偏好概率采用Bradley–Terry形式`σ(rw−rl)`，同一提示下的`log Z(x)`在相减时消失，得到DPO损失：


<span id="concept-intro-1"></span>


先认识这里的对象与符号

[∂、∇：偏导与梯度](../../concepts.md#concept-gradient)
:   ∂L/∂w询问保持其他独立变量不变时，w小幅改变会让损失L怎样变化。多个参数的这些变化率合成梯度∇L。它们是导数记号，不是把两个普通数直接相除。独立微例：L=w²时，w=3处的梯度为6。最简单更新w←w−η×6中，η是学习率。

```
z = β[(logπ(yw|x) − logπref(yw|x))
     −(logπ(yl|x) − logπref(yl|x))]
L = −log σ(z)
∂L/∂logπ(yw|x) = −βσ(−z)
```

这解释了DPO为什么能够直接从偏好对优化，而不是只背诵“DPO比RLHF简单”。参考模型提供相对变化基准，β控制目标中的尺度。这里推导依赖特定奖励正则化与偏好模型假设，并非说明现实人类偏好严格遵循这个概率模型。[[N15]](../sources.md#N15 "本地来源与核查范围")

序列log概率通常由被计入的Token对数概率求和，长度和mask因此非常重要。把序列均值与求和随意互换，会改变偏好学习目标。`numerics.dpo_loss`检查的是单个偏好对的稳定损失和解析梯度；它不是一个完整DPO训练器，也没有证明偏好数据能提高你的编码任务成功率。


<span id="mechanism-S04-3"></span>



<span id="topic-8"></span>


### DPO比较的是“相对参考模型的偏好提升”

**本例条件：**独立一对回答：好回答y+与差回答y−针对同一问题。参考模型给序列概率0.2、0.1，当前模型为0.3、0.1；β=1。为看清公式，这些概率为教学设定。

序列概率
:   整段目标在同一条件下的概率，实际通常用对数累计。

参考模型
:   提供相对变化的基线。

偏好边际
:   好回答的相对提升减去差回答的相对提升。

DPO比较的是“相对参考模型的偏好提升”

| 对象 | 计算 | 结果 |
| --- | --- | --- |
| 好回答的相对变化 | ln(0.3/0.2) | ln1.5 ≈ 0.405465 |
| 差回答的相对变化 | ln(0.1/0.1) | 0 |
| 偏好边际 | 0.405465−0 | 0.405465 |
| sigmoid与loss | σ(0.405465)=0.6；−ln0.6 | 约0.510826 |

各行是独立对象或条件的对照，不暗示上一行的结果自动进入下一行。

#### 怎样把图中的变化读明白

不能只比较当前模型0.3和0.1的大小。公式还问：相对参考模型，两者分别变了多少。

若好坏回答都相对参考模型乘同一倍数，两项对数提升相同，边际相减为0，不会凭共同提升取得额外偏好优势。

偏好标签表达选择倾向，并不自动证明答案真实正确。数据收集与评测仍需要事实依据。

**不要混淆：**教学序列概率只为展示比值；真实训练要处理长度、有效Token、数值稳定与参考分布，不能直接乘很多小概率。

机制依据：[[DPO]](../../sources.md#src-DPO) [[RLHF]](../../sources.md#src-RLHF)。本例数字和宿主场景为明确给定的教学设定，不是商业模型输出或生产性能测量。

## 4. 可验证奖励与推理强化学习

当答案可以通过数学结果、单元测试或规则验证，训练可以获得比纯风格偏好更明确的反馈。但验证器的覆盖决定奖励质量：通过一个弱测试集不等于实现正确。若任务允许修改测试，模型还可能通过破坏验证过程获得奖励。

DeepSeek-R1相关报告提供了用强化学习形成推理行为的公开研究案例。其方法、冷启动数据、训练阶段和评测结果都有具体实验条件；不能把“RL产生了推理模式”扩大成“任何模型只靠奖励就会学会可靠的长期Agent行为”。[[N16]](../sources.md#N16 "本地来源与核查范围")

组相对优势的一种直觉是对同一题采样多条回答，以组内奖励均值/尺度为基准比较，减少对独立价值估计的依赖。若组内所有回答奖励相同，相对信号可能很弱；若奖励只看最终结果，步骤是否真实有效仍不明确。部署时的“多想一会”则是推理计算分配，与训练时优化策略是两件事。


<span id="mechanism-S04-4"></span>



<span id="topic-9"></span>


### 组内奖励只是相对比较，不是绝对正确证明

**本例条件：**独立GRPO直觉例：同一题生成3个候选，验证器奖励为[0,1,1]。只计算去均值的相对奖励，不把它当完整GRPO实现。

组
:   同一道题的多个候选，而非任意不同题混一起。

奖励
:   验证器产生的训练信号。

优势
:   相对基线更好还是更差的方向信号。

组内奖励只是相对比较，不是绝对正确证明

| 候选 | 奖励−组均值2/3 | 解释 |
| --- | --- | --- |
| A | −2/3 | 低于组内平均 |
| B | +1/3 | 高于组内平均 |
| C | +1/3 | 高于组内平均 |
| 另一组全为0 | [0,0,0]−0=[0,0,0] | 没有组内差异信号 |

各行是独立对象或条件的对照，不暗示上一行的结果自动进入下一行。

#### 怎样把图中的变化读明白

奖励为1只说明通过了当前验证器定义的条件。验证器若漏测边界，两个高奖励候选仍可能有同一个缺陷。

完整算法还可能有尺度标准化、概率比裁剪和KL等项；这里把减基线单独拿出来，是为了先理解方向而不是假装复现训练。

全相同奖励组不能凭空产生区分候选的相对信号；采样多样性、验证质量和任务难度都会影响训练。

**不要混淆：**把过程监督、结果奖励和推理时搜索混成一个流程，会把“训练改参数”与“推理多试答案”混淆。

机制依据：[[R1]](../../sources.md#src-R1) [[RLHF]](../../sources.md#src-RLHF)。本例数字和宿主场景为明确给定的教学设定，不是商业模型输出或生产性能测量。


<span id="c04-h5"></span>


## 5. 过程监督、结果监督与搜索的边界

结果监督便宜而直接，但很难指出长推理中第一个错误；过程监督可以更细，却需要可靠步骤标签，也可能奖励迎合评分格式的步骤。多路径采样、自洽投票、树搜索都在推理时花额外计算探索候选，而不是天然增加基础模型知识。

若多个候选共享同一错误前提，投票只会放大错误。若验证器只偏好语言流畅，搜索可能更稳定地找到错误但悦目的答案。因此搜索的收益需要两个条件共同支撑：候选有有效多样性，评估器能够识别更优结果。两者都应在任务层做消融。

对于代码任务，先让模型运行一个相关测试，往往比无证据地生成三份长分析更可核验。这不是任何情况下测试优于推理的定律，而是优先购买能排除错误假设的信息。在高风险跨模块改动中，更深入分析仍可能非常有价值。


<span id="c04-h6"></span>


## 6. 从模型选择落到工程决策

区分三种失败：没有相关知识、无法在给定条件下推理、无法可靠执行。第一类优先检索；第二类可能需要更强模型、不同分解或更好验证；第三类优先修复工具与状态管理。把它们全部交给微调，会浪费成本并掩盖执行系统缺陷。

比较不同推理强度时，保持任务、可用工具和判分一致，记录总成本、总时间、成功率及失败类型。不要只比较最终输出字数。内部推理内容不一定对客户端开放，也不应要求模型给出所谓完整内部轨迹作为正确性证明；可观察的证据链和可重复的结果更重要。


<span id="concept-intro-4"></span>


先认识这里的对象与符号

[PPO、GRPO、advantage](../../concepts.md#concept-ppo)
:   这些是策略优化相关概念。PPO常用新旧动作概率比和裁剪来限制更新；GRPO类方法使用组内奖励比较构造优势。优势是相对基线的表现，不是答案正确概率。独立原始差值例：奖励[0,1,1]，减组均值2/3得到[-2/3,1/3,1/3]。算法还可能再归一化，不能直接混用。

### PPO正优势被裁剪，负优势却不是同一种取法

**输入与条件。**PPO clipped surrogate中r=新策略概率/旧策略概率，ε=0.2，目标取min(rA,clip(r,0.8,1.2)A)，训练通常最大化它。


<span id="mechanism-original-worked-S04"></span>


| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1正优势例 | A=2，r=1.5 | 原项3，裁剪项2.4，取2.4。 |
| 2继续增r | r从1.5到1.6 | 裁剪分支仍2.4，不再奖励这一方向超幅增加。 |
| 3负优势例 | A=−2，r=0.5 | 原项−1，裁剪项−1.6，取更小的−1.6。 |
| 4符号意义 | 坏动作概率下降太多也被裁剪限制 | 不能忽略A的正负只“把r夹住”。 |
| 5完整训练 | 还需优势估计、样本、价值/熵项等配置 | 一个标量目标不是完整RLHF流水线。 |

**把过程连起来。**裁剪目标的min与优势符号共同影响优化，不是对策略概率简单做区间截断。

**边界与反例。**此为PPO目标局部算例，不是全局KL硬约束，也不保证每次更新都保持在信赖域。

### 便宜模型先试的收益，要减掉返工与漏检

**本例条件：**独立成本模型：直接强模型每任务10单位；先用小模型2单位，30%任务升级再花10单位。暂不含检测与返工，是一个理想化下界。

升级率
:   小模型阶段后需要强模型的比例。

检测器
:   判断是否升级的程序或模型。

漏检
:   错误答案被当成成功而未升级。

便宜模型先试的收益，要减掉返工与漏检

| 路线 | 期望花费 | 需要另核对 |
| --- | --- | --- |
| 直接强模型 | 10 | 基准成功率与延迟 |
| 理想级联 | 2+0.3×10=5 | 不是最终真实成本 |
| 加检测成本d | 5+d | 检测器能否抓住错误 |
| 加返工与失败费用 | 全部运行费用/成功任务数 | 漏检会降低最终质量 |

各行是独立对象或条件的对照，不暗示上一行的结果自动进入下一行。

#### 怎样把图中的变化读明白

升级率不是小模型失败率的自动同义词；只有失败能被检测器发现，才会进入升级路径。

路由应考虑任务风险、工具能力、上下文长度与历史结果，而非单看Prompt字数。

用同一任务集比较端到端成功、费用和尾延迟。级联省调用钱却让低频严重错误增加，可能不可接受。

**不要混淆：**用模型自报“我有95%把握”作唯一升级门槛，容易在最需要升级时留下过度自信错误。

机制依据：[[EVALS]](../../sources.md#src-EVALS) [[LATENCY]](../../sources.md#src-LATENCY)。本例数字和宿主场景为明确给定的教学设定，不是商业模型输出或生产性能测量。

## 7. 验收题

一组偏好数据总选更长答案，DPO训练后回答更完整，但功能通过率没变化。是否成功？相对于“长答案偏好”目标可能成功，相对于工程质量目标没有证据。应调整数据、评价维度或放弃该改动，而不是给结果补一个“智能提升”标签。

一个推理模型偶尔在简单任务上浪费很多轮。是否一定要新增复杂度评分器？不一定。先看提示、停止条件、工具反馈与默认推理配置；只有稳定的任务分层收益能够覆盖路由成本时，才引入模型或强度路由。模型能力是系统设计的条件，不应成为无限增加框架层的理由。
