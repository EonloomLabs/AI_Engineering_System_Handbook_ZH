# 23｜微调、量化与蒸馏：改变模型，还是改变输入系统

> 
<span id="concept-intro-1"></span>

>
> 先认识这里的对象与符号
>
> [LoRA、低秩及r](../../concepts.md#concept-lora)
> :   LoRA用两个较小矩阵的乘积表示一部分权重增量，而不是重新训练整个大矩阵。r是中间维度，限制这个乘积的最大秩。不同资料采用行/列向量约定时，A、B的左右次序可能不同。右乘约定微例：W[4,6]，增量A[4,2]B[2,6]仍为[4,6]；r=2。A在这里不是注意力份额表。
>

## 1. 先诊断知识缺口与行为缺口


<span id="concept-intro-3"></span>


先认识这里的对象与符号

[Schema与Structured Outputs](../../concepts.md#concept-schema)
:   Schema是一份字段和类型等结构规则；结构化输出机制让模型更容易返回符合规则的数据。字段合法仍不等于目标文件存在、已授权或业务正确。独立例：要求path为字符串；{"path":3}类型不合规则，{"path":"missing.py"}虽结构合规则仍可能找不到文件。

模型不知道最新接口，优先检索当前文档；模型反复使用错误输出格式，可先修Schema与示例；模型在稳定领域任务中系统性表现不足，才考虑微调。记忆解决跨会话信息利用，Skill提供程序性方法，Harness解决执行组织，它们与参数更新不是互相替代关系。

微调成本包括数据构建、训练、评测、部署、回滚和持续维护。几百条低质量示例未必比一份清晰工具接口有用。尤其不要把经常变化的仓库实现全部训练进模型，导致每次代码修改都面临模型过期。

## 2. LoRA的低秩更新

对权重矩阵`W∈R^(dout×din)`，LoRA冻结基础W，学习`ΔW=(α/r)BA`，其中`A∈R^(r×din)`、`B∈R^(dout×r)`。参数从`dout×din`变为`r(din+dout)`，当r较小时显著减少可训练参数。[[N38]](../sources.md#N38 "本地来源与核查范围")

前向可写成`Wx+(α/r)B(Ax)`。在适当条件下，部署时可把ΔW合并进W，减少额外计算；多适配器切换、量化基座和精度要求会改变最佳部署方式。低秩是参数化假设，不保证任何任务都能用很小r达到全量微调质量。

选择适配哪些层同样重要。只改注意力投影与同时改前馈层的容量不同；参数少不代表激活开销消失，反向仍需经过相应计算图。评测必须包含原有能力，以检测专业任务提升是否造成其他退化。

### LoRA、量化和蒸馏，分别改变不同对象

**本例条件：**独立尺寸例：原矩阵W为8×8，共64个数；LoRA秩r=2，增量A为8×2，B为2×8；量化演示从32bit改8bit，仅计算裸数据。

冻结
:   训练时不更新这一参数对象。

低秩增量
:   用AB产生一份受约束的修改量。

量化
:   用更少位数近似保存数值。

LoRA、量化和蒸馏，分别改变不同对象

| 方案 | 实际改变 | 没有省掉的部分 |
| --- | --- | --- |
| LoRA | 训练A与B共16+16=32个数 | 原W的64个数仍在 |
| W从FP32到INT8 | 裸W从256B到64B | 还需尺度、元数据与算子支持 |
| QLoRA思路 | 量化基座 + 训练适配参数 | 激活和训练计算不全是低位数 |
| 蒸馏 | 用教师信号训练另一学生模型 | 需要新训练和独立质量验证 |

各行是独立对象或条件的对照，不暗示上一行的结果自动进入下一行。

#### 怎样把图中的变化读明白

这些措施可以组合，因为作用对象不同。不能把“少训练32个参数”和“少存192字节”直接相加成一个百分比。

LoRA低秩只约束修改量，不要求原W本身低秩；把W直接替成AB会丢掉基座。

量化节省存储不保证任意硬件都更快；若需要频繁解量化且缺少高效核，端到端延迟可能没有改善。

**不要混淆：**这里忽略量化尺度和偏置等开销，因此4倍是裸权重字节对照，不是完整服务显存或速度倍数。

机制依据：[[LORA]](../../sources.md#src-LORA) [[QLORA]](../../sources.md#src-QLORA)。本例数字和宿主场景为明确给定的教学设定，不是商业模型输出或生产性能测量。

## 3. QLoRA的节省来自哪里

QLoRA结合低比特冻结基座与可训练适配器，研究中使用特定量化表示及内存管理方法。关键是基础参数低比特存储，计算时按算子需求反量化/使用较高精度，梯度更新主要作用在适配器。[[N39]](../sources.md#N39 "本地来源与核查范围")

它不意味着所有训练状态都变成4比特，也不意味着任意4比特模型都能无损微调。量化格式、分组尺度、计算dtype、优化器和序列长度共同决定显存与效果。报告“可以放进一张卡”时必须说明完整配置。

低比特部署还会受硬件核支持影响。理论权重字节变少，若执行时频繁转换或没有高效kernel，端到端速度未必提高。容量收益与速度收益要分别测量。

## 4. 量化误差为什么与激活分布有关

线性层误差可写成`δy=(Ŵ−W)x`。即使权重误差的普通均方值小，若它集中在输入x常用的大幅度方向，输出误差仍可能大。AWQ等方法利用激活信息设计权重量化，体现了只看权重自身分布不一定足够。[[N43]](../sources.md#N43 "本地来源与核查范围")


<span id="concept-intro-2"></span>


先认识这里的对象与符号

[混合精度、loss scaling与主权重](../../concepts.md#concept-mixed)
:   混合精度在不同计算或状态中采用不同数值格式。主权重可用较高精度保存更新基准；loss scaling在反传前放大损失，随后再把梯度缩回，降低某些低精度下溢风险。并不是把学习率随意乘大。实际是否需要主权重或loss scaling取决于精度格式、优化器和实现。

均匀量化通常把浮点映射到有限整数格点，需要尺度与可能的零点；按张量、按通道或按组共享尺度，存储与误差不同。离群值可能迫使范围变大，降低大多数值的有效分辨率。裁剪、分组和混合精度都有取舍，不存在对所有任务无损的默认配置。

校准集应覆盖真实激活分布。只用英文闲聊校准，再部署到长代码与结构化工具参数，可能产生不同退化。还应测试长上下文、罕见符号、精确数值和工具格式，不只测常规问答。

### 同样的量化误差，为什么在另一个输入上突然放大

**本例条件：**独立线性例：权重W=[1.00,0.26]，按0.1刻度量化并还原为Ŵ=[1.00,0.30]，所以ΔW=[0,+0.04]。分别测试输入xA=[1,1]与xB=[1,100]。

权重误差ΔW
:   近似权重减原权重。

输出误差Δy
:   同一输入下，近似输出减原输出。

激活分布
:   模型实际遇到的输入数值范围，不只是权重的范围。

同样的量化误差，为什么在另一个输入上突然放大

| 输入 | 原输出与近似输出 | 相同ΔW产生的输出误差 |
| --- | --- | --- |
| xA=[1,1] | 1+0.26=1.26；1+0.30=1.30 | +0.04 |
| xB=[1,100] | 1+26=27；1+30=31 | +4.00 |
| 检查误差来源 | Δy=x·ΔW | 第二个输入特征从1变100，误差放大100倍 |

各行是独立对象或条件的对照，不暗示上一行的结果自动进入下一行。

#### 怎样把图中的变化读明白

两次使用相同的权重和量化刻度，只有输入改变。第二格权重看似只错0.04，但矩阵乘法会把它乘上这一格的输入值；输入100就贡献4的误差。

这解释了为什么仅查看权重最大误差或平均误差，不足以判断真实任务是否安全。应该用代表实际输入的校准与评测样本，观察最终输出和任务指标。

不同层会继续混合这些误差，不能把这一小例子的100倍机械推广为整个语言模型的误差倍率。量化是否更快也还受硬件和计算内核影响。

**不要混淆：**这里没有声称采用某种量化方法便可保证无损。它展示的是线性计算中可以精确推导的输入敏感性。

机制依据：[[F-LINALG]](../../sources.md#src-F-LINALG) [[QLORA]](../../sources.md#src-QLORA)。本例数字和宿主场景为明确给定的教学设定，不是商业模型输出或生产性能测量。

## 5. 蒸馏：不仅复制最终答案

蒸馏可以使用教师输出的软概率或生成样本，让学生学习其行为。软目标包含非首选类别关系，但教师也会犯错；用错误答案做训练会把错误规模化。对于工具Agent，轨迹中的动作、观察和恢复策略也可能是学习对象，但必须保证环境结果真实。

教师产生的解释不必等同于其内部真实计算过程。把表面推理文本当作唯一知识来源，可能学到风格而非能力。应让学生在独立任务和可核验环境中评价，并测成本—质量曲线。


<span id="c23-h6"></span>


## 6. 数据与版本管理

保存基础模型、Tokenizer、聊天模板、适配器、训练数据版本、超参数、评测集与部署配置。只保存adapter文件不一定足以恢复行为。模板改变可能让同一权重接收不同角色标记，量化版本改变也可能影响结果。

数据划分按真实关联边界进行，例如仓库、时间或用户，而不是把高度相似片段随机分开。人工与模型生成数据应区分来源；去重与污染检查要在评估前定义。迭代中看过的测试应降级为开发集，不能无限重复调到高分还声称泛化。

### 权重误差一样大，激活不同使输出误差不同

**输入与条件。**标量乘法y=xw。两通道量化权重误差都是Δw=0.01，但激活分别x1=100、x2=0.1。


<span id="mechanism-original-worked-S23"></span>


| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1输出误差1 | 100×0.01 | 1。 |
| 2输出误差2 | 0.1×0.01 | 0.001。 |
| 3比较 | 权重绝对误差相同 | 输出影响相差1000倍。 |
| 4校准意义 | 收集代表性激活分布 | 有助于判断哪些通道更需要保护。 |
| 5边界 | 只调一个权重不等于实现AWQ | 完整算法还需等价缩放、量化粒度与硬件表示。 |

**把过程连起来。**量化不能只看权重误差，还要看它经过实际激活后如何影响输出。

**边界与反例。**教学线性误差是局部原理，非AWQ完整算法或精度性能复现。

### 一条训练样本怎样带着来源与标签进入计算

**本例条件：**独立数据管线：两份抓取文本其实来自同一文档修订；一个训练样本把完整答案意外混进用户字段。图追踪可审计的数据变换，不报告任何模型成绩。

来源ID
:   区分独立文档与重复转载。

样本边界
:   决定哪些片段组成一次训练输入。

污染
:   评测答案或未来信息进入训练可见范围。

一条训练样本怎样带着来源与标签进入计算

| 管线节点 | 具体对象变化 | 需要留存的证据 |
| --- | --- | --- |
| 去重 | docA/v1与转载A → 一份内容 | 内容指纹与来源映射 |
| 模板化 | user问题 + assistant答案 | 角色边界与模板版本 |
| 切块/打包 | 长样本分成序列窗口 | 是否跨文档可见 |
| 构造标签 | 只对期望目标计损失 | 有效位置掩码 |
| 划分训练与测试 | 同源文档不跨集合泄漏 | 分组键而非随机行号 |

各行是独立对象或条件的对照，不暗示上一行的结果自动进入下一行。

#### 怎样把图中的变化读明白

“洗数据”不是一句抽象建议：每个节点都会改变模型能看到的对象。去重错了，会把一个来源反复加权。

评测划分按行随机并不总是独立：同文档的相邻片段可能一部分训练、一部分测试，让测试看起来异常容易。

要记录原文ID、处理版本和样本ID的对应关系；否则发现坏样本后无法撤销它的派生块。

**不要混淆：**更长的语料列表不等于更多独立信息；语料质量和评测独立性必须单独验证。

机制依据：[[SCALING]](../../sources.md#src-SCALING) [[CHINCHILLA]](../../sources.md#src-CHINCHILLA)。本例数字和宿主场景为明确给定的教学设定，不是商业模型输出或生产性能测量。

## 7. 决策与验收

当基础模型加好检索已满足任务，微调未必值得。若微调能显著降低每次提示长度、提高稳定格式或专业任务成功率，需要用相同任务和总成本证明。回滚应能切回旧模型/适配器，并确认缓存与状态不会混用。

验收题：LoRA只有少量参数，是否不会遗忘基础能力？不能保证。少量参数也能显著改变输出分布。必须保留通用与专业双重回归，而不是根据可训练参数比例推断安全。
