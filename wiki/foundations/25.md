## MCP连起接口，不自动交出权限

连接、发现、模型可见和实际授权分别发生在哪里？

把MCP想成工具之间的共同接口语言，而不是新大脑。Host负责应用级选择与控制，Client负责协议连接，Server提供能力。接线完成以后仍要决定哪些工具暴露给模型、哪些资源允许访问、哪些动作需要确认。

**Host**承载模型、任务与权限策略的应用。

**Client**Host中的协议客户端。

**Server**提供工具、资源等能力的服务。

**授权**允许某个身份在某个范围执行某个动作。

## 先别把MCP理解成“给模型装了一个新大脑”

**MCP（Model Context Protocol）**规定AI应用与外部能力之间怎样通信。它帮助统一工具、资源等能力的描述和交互，不直接训练模型，也不会自动赋予无限权限。

**关键区别：**MCP提供连接结构，是否可调用和可执行仍由宿主控制。

**容易误解：**连上MCP Server不等于模型拥有全部权限。

**Host**是用户使用的宿主应用；**Client**是宿主内部与某个服务连接的协议参与者；**Server**提供工具或数据能力。例如编辑器是Host，内部MCP Client与代码搜索Server交互。

这里server不是一定在远方大机房，也可以是本机进程。谁连接谁、用哪种传输方式，是具体部署选择。

## 一次从连接到工具结果的逻辑次序

先建立连接，初始化并确认兼容的协议和能力；随后请求工具列表或其他能力说明；宿主把适合本任务的工具描述提供给模型；模型提出调用；宿主检查授权并发给服务；服务执行并返回结果；宿主再回填给模型。

一次从连接到工具结果的逻辑次序：逐项辨别

|  |  |
| --- | --- |
| 对象一 | MCP Host |
| 对象二 | MCP Client |
| 对象三 | MCP Server |

**关键区别：**Host负责整体应用，Client连接服务器，Server提供工具或资源。

**容易误解：**三者不是三个独立LLM模型。

这不是一个步骤。工具存在于服务端，不等于已经被发现；被发现不等于暴露给当前模型；暴露不等于本用户有权执行；调用返回也不等于业务目标已完成。

理解衔接

## 从工具名称到真实能力，中间有四道门

MCP可以提供发现与调用接口，但连接成功不等于所有工具已加载，更不等于所有动作都获授权。教学工具deploy虽然出现在目录中，没有部署批准就不能执行。工具read\_file虽已安装，若没有进入本轮可见目录，模型可能根本不知道它。先分清“存在、可发现、可执行、允许执行”，再定位到底哪一层有问题。

把这一页的具体对象分清之后，再进入系统机制：[工具存在、模型看见、能调用、获授权：四层检查](../chapters/11.html#agent-practice-tools)。这里不要求先知道完整源码；先能按状态表复述每一步发生了什么。

**证据与理解边界：**直接、延迟发现和代码调用是不同暴露面；注册、可见、可调用与获授权不互相等同。

## Tools、Resources、Prompts各是什么

**Tool**是可执行操作，例如`search_code(query)`；**Resource**是可供读取的数据或内容，例如某份说明文档；**Prompt**是服务提供的可复用消息模板。它们在协议中有不同角色，不能因为都能影响上下文就认为可以互换。

Tools、Resources、Prompts各是什么：逐项辨别

|  |  |
| --- | --- |
| 对象一 | Tools：可执行动作 |
| 对象二 | Resources：可读数据 |
| 对象三 | Prompts：提示模板 |

**关键区别：**三类能力的用途不同，不应全部当作可写入工具。

**容易误解：**读到一份Resources内容，不代表取得执行权限。

**Skill**通常是任务流程和相关资源的组织单位。Skill可能教Agent什么时候调用一个Tool，但Skill本身不天然获得操作系统权限。

## 工具Schema不应替代业务判断

工具描述要说清输入、输出、前提、错误和副作用。“处理项目”这样的大而模糊能力，容易让模型不知道具体能做什么；把每个微小动作拆成几十个工具，也会增加调用和上下文成本。

**关键区别：**Schema约束字段和类型，但真实业务边界仍要二次检查。

**容易误解：**参数符合类型不等于安全。

一个适度边界的接口可以同时返回文件片段、版本和下一段位置，减少“搜到了但不知道属于哪个版本”的问题。工具输出是否适合模型读取，是接口设计的一部分，不是只满足程序类型就够了。

## stdio、HTTP与JSON-RPC先只懂职责

先认识这里的对象与符号

[JSON-RPC、stdio与HTTP](../concepts.html#concept-jsonrpc)
:   JSON-RPC约定怎样用JSON表示方法、参数、标识和结果；stdio使用进程标准输入输出通信；HTTP是另一层网络请求协议。协议名称并不自带权限。用stdout承载协议消息时，普通调试日志应避免混入该数据流，通常写stderr；否则合法日志也可能破坏消息解析。

**stdio**指通过进程标准输入输出通信；如果协议消息走stdout，普通调试日志混在其中可能破坏解析。**HTTP**是常见网络请求协议；MCP可在具体版本约定下使用适合的传输。

stdio、HTTP与JSON-RPC先只懂职责：逐项辨别

|  |  |
| --- | --- |
| 对象一 | stdio：进程管道 |
| 对象二 | HTTP：网络传输 |
| 对象三 | JSON-RPC：调用格式 |

**关键区别：**传输通道与消息结构是两层，换传输不必改变每个工具的业务含义。

**容易误解：**不要把HTTP和JSON-RPC当成同一层的东西。

先认识这里的对象与符号

[JSON：结构化文本，不是执行动作](../concepts.html#concept-json)
:   JSON是一种用对象、数组、字符串、数字等表达数据的文本格式。花括号对象把字段名映射到值，方括号数组保留项目顺序。解析JSON只得到数据，不会自动执行其中的工具名称。独立例：{"path":"a.py","limit":3}有两个字段；"3"是字符串而3是数值，Schema可以要求其中一种。

**JSON-RPC**是一种用JSON表达远程方法、参数、请求标识与结果/错误的调用约定。它解决消息组织，不自动解决身份认证和操作幂等。

系统篇按照注明的协议版本说明具体生命周期。新版本字段会改变，所以阅读时区分稳定职责与版本特定细节。

## 身份、认证和授权

**认证authentication**是确定“你是谁”；**授权authorization**是决定“你能做什么”。连接成功不等于已经获准读取每份数据。

先认识这里的对象与符号

[OAuth、scope与授权](../concepts.html#concept-oauth)
:   在授权场景，OAuth使应用能按授权取得访问凭据；scope声明一类访问范围，资源服务仍应检查具体权限。在记忆或任务场景，scope又可只表示适用范围，不能混成登录凭据。获准“读取日历”不等于获准删除所有事件；连接成功也不证明操作被批准。

**OAuth scope**可以理解为一类授予访问范围的声明，但具体资源仍可能有自己的访问限制。**最小权限**要求只给完成当前任务必要的能力，而不是为了避免报错直接给全部权限。

工具说自己read-only也不能代替独立安全判断。服务端实现和宿主边界都可能存在错误，需要按风险验证。

## 子Agent为什么不一定继承全部工具

子Agent可能拥有独立上下文、不同工具白名单或连接配置。主Agent知道一个MCP服务，不代表子Agent自动收到它的工具说明或执行权。

排查应沿发现、暴露、授权、调用、返回逐层看。只在Prompt里反复写“你应该能用工具”，无法修复实际未配置的能力。

先认识这里的对象与符号

[Schema与Structured Outputs](../concepts.html#concept-schema)
:   Schema是一份字段和类型等结构规则；结构化输出机制让模型更容易返回符合规则的数据。字段合法仍不等于目标文件存在、已授权或业务正确。独立例：要求path为字符串；{"path":3}类型不合规则，{"path":"missing.py"}虽结构合规则仍可能找不到文件。

### 把一个MCP读取请求分成四道不同关口

**输入与条件。**连接一个只提供 `read_note(name)` 的教学MCP服务。固定使用2025-06-18协议快照，避免把示例当所有版本都相同。

| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1连接并初始化 | 客户端发initialize，服务端返回协议版本与能力 | 两端先同意怎样通信。 |
| 2确认就绪 | 客户端发notifications/initialized | 这是通知，没有请求id。 |
| 3发现工具 | 发tools/list | 返回read\_note及参数schema；发现不等于获准读取所有笔记。 |
| 4做授权 | 宿主确认用户只能读project-A | name来自模型也不能绕过范围检查。 |
| 5执行并关联结果 | 发tools/call，返回对应请求id的结果 | 执行成功后再把内容交给模型。 |

**把过程连起来。**连接、发现、授权、执行互不替代。能在列表看见工具不代表一定能调用，也不代表子Agent继承同样权限。

**边界与反例。**请求顺序参照固定官方规范；笔记工具为原创，没有声称某个服务实际提供这个名称。
