## 检索先找候选，再判断能否回答

倒排索引和向量索引分别在帮什么忙？

倒排像书后索引：从一个词跳到包含它的页面。向量检索则尝试把表达相近的内容放得接近，帮助不知道精确名称时找候选。二者都不负责自动确认权限、版本和事实正确性，仍要读取与核对证据。

**索引**为快速找候选而建立的数据结构。

**召回**从大集合中找出可能相关的候选。

**近似搜索**以少检查部分候选换速度，可能漏掉真实近邻。

**输入与适用条件：**三个文档为本书构造；倒排关系可精确核验，语义搜索只作流程说明，不编造向量服务实测分数。

## 检索先解决“从哪里找到候选”

**检索retrieval**是从一堆材料中找到可能与问题有关的条目。**索引index**是为此预先建立的组织结构，类似书末的词语索引，但可以包含位置、统计量和权限等信息。

**关键区别：**检索只是找证据的前半段，相关片段不一定足够支持具体结论。

**容易误解：**不要把检索分数当作事实真实性。

**离线建库**指在查询前准备材料和索引，不意味着机器必须断网；**在线查询**指用户问题到来时执行的检索，也不等于一定上公网。

## TF、IDF与BM25先认识职责

先认识这里的对象与符号

[TF、DF、IDF：词项统计量](../concepts.html#concept-tfidf)
:   TF计某词在当前文档出现次数；DF计包含它的文档数；IDF根据全库统计降低常见词、提高较罕见词的区分贡献。三者是统计量，不是模型的学习率。10篇文档只有2篇含某词时DF=2；该词在其中一篇出现3次，该篇TF=3。两个数字不能互换。

**TF（词频）**描述某个词在一篇文档出现多少次。**DF（文档频率）**描述多少篇文档含这个词；**IDF（逆文档频率）**通常让罕见、区分度更高的词占更大权重。

TF、IDF与BM25先认识职责：逐项辨别

|  |  |
| --- | --- |
| 对象一 | TF：词出现多少 |
| 对象二 | IDF：词有多稀有 |
| 对象三 | BM25：综合词匹配 |

**关键区别：**术语频率和稀有度帮助排序，但不是文章内容的真实性评分。

**容易误解：**BM25分数并不天然是0到1的概率。

若每篇都写“说明”，这个词不太能区分目标；只有少数文档写某个错误码，错误码更有定位价值。

先认识这里的对象与符号

[BM25及N、df、k₁、b](../concepts.html#concept-bm25)
:   BM25是词项检索打分公式。常见记号N是文档总数，df是含该词的文档数，tf是当前文档词频，|D|是当前文档长度，avgdl是平均长度；k₁和b是词频饱和与长度修正的设置。k₁不是Key向量k₁，b也不是神经网络偏置。分数只用于给候选排序，不能把8.2解释为82%正确率。

BM25把词频、稀有程度和文档长度等组合成排序分数。词频收益常有饱和：出现10次不一定是出现1次价值的10倍；较长文档也要考虑长度影响。完整公式在高级Q058逐项展开。

**排序分数不是概率**。BM25得到8.2不代表82%正确，也不能保证不同查询的分数可直接比较。

## 向量检索为什么能找同义表达

一个检索模型把问题或文档变成一排数字，希望相关内容在向量空间中更接近。这样查询“程序崩溃”和写着“进程异常退出”的文档即使词不同，也有机会匹配。

**关键区别：**向量检索能找到不同用词但语义相近的资料，但会受嵌入模型影响。

**容易误解：**向量接近不等于文档确实回答了问题。

最常见的比较之一是**余弦相似度**：点积除以两向量长度的乘积。长度是各分量平方求和后开方，即范数。若x=[1,0]、y=[2,0]，余弦为1；若y=[0,1]，余弦为0。零向量时需特殊处理，不能直接除零。

这比较的是表示方向，不是自动判定事实逻辑。“允许访问”和“不允许访问”可能话题很接近，但结论相反。

## 精确最近邻与近似最近邻

**最近邻**是按所选距离或相似度排名靠前的向量。逐个比较全部N条记录可得到精确结果，但规模很大时成本较高。

精确最近邻与近似最近邻：逐项辨别

|  |  |
| --- | --- |
| 方案／对象 A | 精确最近邻：找真前k |
| 方案／对象 B | 近似ANN：更快但可能漏 |
| 方案／对象 C | 需要召回率/延迟取舍 |

**关键区别：**ANN牺牲部分检索精度换规模性能，仍应评估具体数据分布。

**容易误解：**过滤条件很严格时，ANN后的候选可能不足。

先认识这里的对象与符号

[ANN与HNSW：近似检索结构](../concepts.html#concept-ann)
:   ANN在这里指近似最近邻搜索，不是泛指人工神经网络。HNSW是一种用分层近邻图缩小搜索范围的结构；参数影响召回、速度和内存。查得快不代表一定找全精确最近邻；ANN召回率也不等于最终回答正确率。

**ANN（近似最近邻）**用额外结构减少搜索范围，牺牲一定召回以换速度。HNSW通过分层近邻图导航：先在较稀疏层跳到接近区域，再在较细层扩大候选。具体过程高级章节展开。

近似算法的“召回率”是相对于精确邻居是否找全，不是答案是否真实正确；这些是两层不同的评估。

## 分块、清洗和版本为什么先于排名

长文档通常切成**chunk（内容片段）**。切得太小可能丢掉条件与例外；太大可能引入很多无关内容。标题、表头、适用日期和代码作用域都可能需要跟随片段。

若一条旧规定未删除或标失效，再好的检索也可能把它准确地找出来。若越权内容已经交给模型，再在最后隐藏引用，泄露仍可能发生。索引结构、权限与版本共同决定什么候选可以被使用。

### 三份文档怎样变成一个倒排索引

**输入与条件。**教学文档A=`排除 路径`，B=`排除 排除 路径 缓存`，C=`日志 输出`。用空格分词，已经明确每个词项。

| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1逐文档扫描 | 记录词项出现在哪份文档 | 排除→A、B；路径→A、B；缓存→B；日志→C；输出→C。 |
| 2保留词频 | “排除”在A为1，在B为2 | 倒排表也可以记录位置和次数。 |
| 3提交查询 | 查询“排除” | 直接定位A、B，不必把C当相关候选。 |
| 4计算区分度 | 总文档3，含词文档2 | BM25示例IDF为 `ln(1+1.5/2.5)≈0.470004`。 |
| 5长度修正 | A长2，B长4，平均8/3 | B出现两次并不意味着得分正好两倍。 |

**把过程连起来。**索引是为了从词快速回到文档。向量搜索是另一种找候选的方法，不会自动取代精确词和版本条件。

**边界与反例。**空格分词仅用于明确可计算性；不把它称为生产中文分词器。

## 同一个文档怎样变成两种索引

一份文档先解析，再切成块。词法索引记录词出现在哪里；向量索引把块映射成可比较的向量。块ID应能回到源文档、版本、权限和位置。查询向量的长度与索引相同，只能说明形状兼容，不能说明它们来自同一个模型空间。换嵌入模型之后，通常需要匹配的重新编码和索引切换。

RRF按名次贡献，不加原始分数文档词法名次 / 向量名次分数D11 / 30.03226646D22 / 10.03252247D33 / 20.03200205

| 文档 | 词法名次 / 向量名次 | 分数 |
| --- | --- | --- |
| D1 | 1 / 3 | 0.03226646 |
| D2 | 2 / 1 | 0.03252247 |
| D3 | 3 / 2 | 0.03200205 |

RRF按名次贡献，不加原始分数。数值与状态属于本节明确设定的教学例；不是生产性能或商业模型实测。
