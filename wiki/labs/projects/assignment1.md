# 作业01｜观察：把一次任务变成可检查的轨迹

先观察一个系统，再决定应该改哪一层。产物不是“成功”的截图，而是一份能把任务、调用、文件和验收对起来的运行记录。

**作业范围**

这是本教材的原创累积实验。默认离线路径仅操作生成的临时数据；真实模型、外部账号及GPU路径须自行配置，未运行项明确保留为NOT\_RUN。

<a id="goal"></a>

## 任务与交付物

资料索引助手的初始配置为 `{"exclude_dirs":[]}`。用户要求排除根目录 `vendor` 及其子树，但保留 `vendor2` 和 `src`。这不是实现复杂搜索引擎，而是选择一个能独立验收、能贯穿后续全部层次的小任务。

提交一条原始JSONL轨迹、一个可查看事件字段的页面、一份初始与最终配置，以及你亲自写的观察记录。此作业不作为后续性能比较的基线；第二次作业完成循环和测量契约后再冻结基线。

<a id="run"></a>

## 先运行，再解释

```
cd AI_Systems_Engineering_Textbook_ZH/labs/stack
python3 run.py observe
# 用浏览器打开 results/trace-viewer.html
```

无需联网或密钥。默认后端是确定性的 `ScriptedBackend`：它按已知任务规则产生工具提议，不是LLM。这能练习事件观察，却不能用于评估智能、泛化或商用模型性能。文件只在新建临时目录中修改；输出记录保留了最终配置和哈希，临时工作区随后清理。

<a id="section-f88f97f1593d"></a>

### 读懂一条轨迹

| 事件 | 谁产生 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| model\_requested | 宿主 | 准备发送一轮请求，以及请求字节数 | 模型已接受或理解 |
| tool\_proposed | 宿主记录模型提议 | 工具名、call\_id与参数 | 磁盘已经改变 |
| tool\_returned | 工具／宿主 | 这一调用返回的结果或错误 | 整个任务的所有条件满足 |
| host\_verified | 独立验收器 | 当前产物通过了哪些固定检查 | 所有未知场景均正确 |
| task\_finished | 宿主 | 终止原因及本次任务结果 | 模型内部推理过程 |

时间字段 `at_ms` 是从任务开始起的单调计时结果；`duration_ms` 是单步测量。不要把两者相加。`request_bytes`是序列化UTF-8字节数，不是计费Token。

<a id="inspect"></a>

## 三项观察练习

1. 先遮住结果字段，只看提议，预测哪次调用会改变文件。打开字段核对，并说明`expected_sha256`来自哪一次观察。
2. 找到第四次后端返回与`host_verified`之间的关系：模型不再调用工具，不等于验收可以省略。
3. 比较`a1-receipt.json`与`a2-early-final.json`。后者一开始就说done，但当前文件未满足要求；用它验证“最终文本＝成功”的UI是否会误导。

<a id="live"></a>

## 把观察方法用于真实Agent

有自己的Claude Code或Codex环境时，另开一次受限任务，导出产品支持的结构化事件，保留产品版本、权限设置和任务目录。不同产品的事件字段不能直接假定与本实验相同；先写一张字段映射表，再呈现工具、子任务和错误。

官方CS2680的A1展示仓库提供了学生项目及回放模式，但其中部分项目会绕过批准或监听所有网卡。不要把“工作目录”误当沙箱，不要将本机Agent控制界面无保护地公开到网络。本教材不自动安装、启动或授权这些项目。

<a id="accept"></a>

## 验收与复盘

合格页面必须区分提议、执行、结果、取消和未知；没有使用量时显示“未提供”，不能填0或猜费用。可以从页面定位到原事件与最终产物。观察报告必须来自你自己的运行：写出一件预期之外的事、一个定位依据和一个尚不能下的结论，不预填“我学到了……”的个人经历。

<details class="quiz-answer" open=""><summary>自检参考答案：为何17条事件不等于17次模型调用？</summary><div class="answer"><p>事件包括请求、返回、工具提议、工具结果、启动和验收。本实验有4次脚本后端调用、3次工具调用及其他状态事件。数量和含义来自记录结构，不可用事件总数估算模型调用费用。</p></div></details>

<a id="review-assignment-1-handoff"></a>

### 观察结果交给下一作业之前，先固定这些身份

保存任务ID、初始文件指纹、工具事件call\_id、最终文件指纹与独立验收。模型自述不作成功标签；缺失轨迹不能补写成好看的过程。

| 最小交接字段 | 含义 |
| --- | --- |
| task\_set\_revision | 任务集合与拆分，不只任务数量 |
| artifact\_before / artifact\_after | 待处理与交付工件的版本 |
| system\_revision | 代码、模型、模板、工具/检索设置 |
| run\_mode | script\_fixture / local\_numeric / live\_model |
| budget / seed / environment | 可控条件；不支持或未测写明 |
| outcome / evidence | 成功、失败、未知、未运行与对应原始记录 |

这些字段用于对照，不要求为小练习搭建数据库或复杂平台。一份JSON和已有日志足够；没有改变的输入用同一版本，新增资料不要悄悄覆盖旧结果。
