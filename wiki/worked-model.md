# 贯通算例：两句话怎样穿过一层模型

同一词表、同一组参数、两句有标签的输入：从数字表示走到概率，再走一次带缓存的解码。

建议先读F01—F19。每张表的行对应哪个Token、列对应哪个特征均写明。显示数值保留六位小数，计算用未舍入值。这里不要求模型生成有意义的中文。


<span id="worked-X01"></span>


运行示例 · X01


<span id="topic-1"></span>


### 沿用“我爱学习／你爱”，把一层模型真正算到底

**输入与条件。**两句话仍采用六行四列Embedding表。下面指定一个未训练的教学模型：一层、隐藏宽度4、两个注意力头，每头宽度2，前置LayerNorm、残差、SwiGLU前馈和绑定Embedding的输出投影。为减少变量，本例不加位置编码、偏置或dropout。


<span id="mechanism-original-worked-X01"></span>


| 步骤与对象 | 内部动作 | 中间结果 / 新状态 |
| --- | --- | --- |
| 1分别查表 | “我／爱／学习”取第1、2、3行；“你／爱”取第4、2行 | 两句分别是3×4和2×4。PAD只用于批次展示，实际数值见证逐条处理有效Token。 |
| 2逐位置归一化 | 每一排4个数分别减均值、除以标准差 | 归一化不会混合两句话，也不会把不同Token平均成一句话。 |
| 3计算两头注意力 | 各头分别生成分数、因果掩码、概率和Value混合 | 两个头每个位置各产出2个数，拼回4个数后，加回原来的Embedding。 |
| 4经过前馈层 | 再次归一化，再计算0.25×SiLU(z)×z并加残差 | 每个位置有4个更新后的数；最后位置才用于本轮下一个Token的预测。 |
| 5投影回词表 | 最后位置的4个数与每个词表行点积，再做softmax | 本例解码规则显式禁止PAD；“我爱学习”末尾产生的最高概率项是“爱”，约0.307383。 |
| 6继续一次 | 把刚选出的“爱”编号2输入，同时带入旧K/V | 增量最后状态与对“我／爱／学习／爱”全量重算相同，数值误差小于1e−12。 |

**把过程连起来。**下方逐表展示全部中间张量以及每个矩阵的取值。不能只从“预测出爱”理解模型；真正要观察的是同一份输入怎样经过每一个算子。

**边界与反例。**权重全部人为设置，预测重复的“爱”不体现语言能力。没有位置编码的这个简化模型也不代表现代商业模型的完整架构。

## 自检：缓存为什么不能直接换另一句话的

第二句“你爱”的最后一个Token也是“爱”。是否可以把第一句三个位置的缓存接到第二句后面？请先自己判断。

<details class="quiz-answer"><summary>查看参考答案</summary><div class="answer"><p>不能。Token编号相同只说明初始Embedding行相同，不说明两个前缀一样。K/V保存了对应前缀在该层的计算结果；跨句混用会把“我／爱／学习”的历史注入“你／爱”，改变可见信息与结果。</p></div></details>
